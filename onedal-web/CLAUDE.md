## 검증 스크립트

🔴 **스크립트를 새로 만들기 전에 이 표에서 먼저 찾는다** (기사님 지시 2026-09-14)
- 비슷한 일을 하는 명령이 있으면 **새 파일을 만들지 않고 그 명령에 인자를 하나 더한다**
  (예: DB 에서 새로 볼 것이 생기면 `scripts/lib/db-<이름>.mjs` 를 두고 `pnpm db <이름>` 으로 부른다)
- 정말 새로 만들어야 하면 **왜 기존 명령으로 안 되는지**를 표의 «잡는 것» 칸에 한 줄로 적는다
- 이 규칙이 생긴 까닭: 요청마다 하나씩 만들다 보니 DB 보기 셋 · 도달 계수 둘 · 화면 찍기 둘이
  따로 자랐다 (2026-09-14 전수 조사 — 셋과 둘은 `pnpm db` · `pnpm reach` 로 묶었다)

🔴 **스크립트를 만들면 이 표에 올린다** (기사님 지시 2026-09-14) — `package.json` 명령 이름 ·
잡는 것 · **못 잡는 것** · **검수**(일부러 틀린 것을 넣어 빨간불을 본 방법, 못 봤으면 왜).
`server/tests/rules/scriptsListed.test.ts` 가 문다 — 표에 안 올리면 게이트가 빨간불이다.
🔴 **초록불은 «잡는 것» 칸만 맞다는 뜻이다.** «못 잡는 것»을 읽고 쓴다 — 2026-09-14 에
`audit:docs` 가 초록인데 루트 `CLAUDE.md` 구성 표가 틀려 있었다.
⚠️ 개수·소요 시간은 적지 않는다 — 반드시 낡는다 (루트 `CLAUDE.md` 「이 문서에 무엇을 적나」).

판정을 갈아탄 뒤 `docs/지금/판정.md` 가 여전히 옛 채점기를 가리켰는데 **감사 넷이 다

🔴 **그래서 규약이 하나 생겼다** — 「지금」 문서가 파일을 가리킬 때는 **«그 파일의 무엇»인지
이름을 함께 적는다**(`judge()` · `CRITERIA`). 파일 이름만 적으면 그 파일이 살아 있는 한
감사가 못 잡는다.

**`pnpm lab` 은 «화면이 두 말을 하는 것»을 잡는다** (2026-09-10 신설).

그날 기사님이 잡아 주신 것이 전부 같은 모양이었다 — **두 자리가 다른 말을 한다.**
지도 순번 ⑧ ↔ 시트 10 · 화면 «그물 352동» ↔ 아웃풋 «351» · 시트 «152분» ↔ 심사석 «÷177분».
🔴 **vitest 는 순수 함수만 본다** — 화면이 무엇을 적는지는 안 본다. 그래서 이 문제는
**DOM 에 실제로 찍힌 글자끼리** 대조한다. 코드가 아니라 **화면이 답한다.**

```bash
cd onedal-web && pnpm lab           # 문제를 끝까지 돌고 통과/실패를 적는다
SHOTS=1 pnpm lab                    # 단계마다 화면을 /tmp/onedal-lab/ 에 찍는다
KEEP=1 pnpm lab                     # 끝나도 크롬을 안 닫는다 (직접 들여다볼 때)
```

- 🔴 **문제 목록은 화면에 산다** (`client-app/src/pages/labProblems.ts` → 실험실 **상단 🧪 버튼 여섯**).
  `pnpm lab` 은 **그 버튼을 누른다** — 기사님이 누르는 것과 **글자 그대로 같은 것**이 돈다.
  ⚠️ 처음엔 좌표를 스크립트에 박았다가 *"나도 화면에서 볼 수 있게 만들어 줘야지"* 를 들었다 —
  **나만 돌릴 수 있으면 그건 문제가 아니라 내 메모다.**
- 문제 여섯: **🌅 볼트 오전 · 🌆 볼트 저녁**(기사님이 실제로 돈 하루) +
  **🔽 이천행 ✅🔴 · 🔼 복귀 ✅🔴**(경충대로 한 줄 길 — 방향마다 «잘 되는 판» 하나와
  «상차지가 반대편 차선인 판» 하나. 2026-09-12).
  ⚠️ `pnpm lab` 이 실제로 도는 것은 **첫 버튼(볼트 오전)** 하나다 — 나머지는 기사님이 눌러 보는 자리다.
  요금이 낮으면 색이 «똥»이 되어 문구·버튼 비율이 달라진다 — **재현이 안 되면 문제가 아니다**
- 📄 **끝나면 보고서를 연다** (`/tmp/onedal-lab/index.html`) — 검사 결과와 단계별 화면이 한 장에.
  `OPEN=0` 이면 안 연다
- 🔴 **통과해도 «본 것»을 함께 적는다** — 숫자가 안 보이면 기사님과 내가 같은 것을 본 게 아니다
- ⚠️ `pnpm dev` 로 관제웹(3000)이 떠 있어야 한다. 크롬을 쓰므로 **로컬 전용**이다
- ⚠️ **첫 판은 이가 없었다** — «더 쓰는 시간»이 화면에 세 곳인데 `match`(첫 줄)만 봐서,
  시트를 틀리게 고쳐도 초록불이었다. 지금은 **그 숫자를 전부 모아 하나인지** 본다.
  **검사를 만들면 변이로 빨간불을 확인한다** (그때 `["133","108"]` 로 잡혔다)

🔴 **`pnpm lab:both` 은 2026-09-13 에 지웠다 — 「같은 것을 보자」를 「같아 보이는 것을 만들자」로 바꿨다.**

기사님 지시는 *"내가 보는 화면을 너가 보지 못하니까 **브라우저 열어서 이미지 캡처해서 보라**는
의미였어. **너랑 나랑 똑같은 걸 봐야지** 너가 만든 똑같은 문제지를 본다고 같은 건 아니잖아"* 였다.

그런데 만든 것은 **콜을 지어내 양쪽에 세우고 DOM 글자를 `===` 로 맞춰 보는 도구**였다.
게다가 세우던 요금이 문제지의 **4배**(200,000 ↔ 50,050)라, 「같은 조건」이라 적어 놓고
**기사님한테 일어날 수 없는 조건**을 보고 있었다. 색이 달라지면 문구·버튼 비율도 달라진다.

**대조는 내가 화면을 보는 것이지 스크립트가 글자를 세는 것이 아니다.**
같은 것을 보려면 **기사님이 보시는 그 화면**을 찍어서 봐야 한다 — 지어낸 판이 아니라.

**`pnpm drive` 는 «주행에서만 보이던 것»을 책상에서 잡는다.**

2026-08-29 에 고친 것 중 셋이 **기사님이 나가 봐야만** 확인되는 것이었다 —
경로 순서 · 도착 감지 · 궤적의 `stop_type`. 그러면 **하루에 한 번밖에 못 고친다.**

```bash
cd onedal-web && pnpm drive          # 40초. 폰·카카오 키·개발 서버 전부 불필요
DRIVE_LOG=1 pnpm drive               # 서버 로그까지 보고 싶을 때
```

`scenario` 와 다르다 — 그건 **첫 상차지 하나만** GPS 로 찍고 나머지 단계는
버튼(`report-milestone`)으로 넘긴다. `drive` 는 **모든 정거장을 GPS 로 걸어간다.**
그래야 «정거장이 넘어가는가»(`nextStopOf`)를 실제로 본다.

문제지는 **2026-08-25 기사님 실측 그 상황**이다 (좌표도 그때 지점) —
곤지암 하차가 4km 앞인데 가남 상차가 30km 밖. 「상차 먼저」 규칙이면 30km 부터 간다.

## 기존 DB 사본으로 부팅 — 스키마·`shared` 를 고쳤을 때

빈 DB 는 문제를 숨긴다. 떠 있는 `pnpm dev` 는 건드리지 않고 **따로** 띄운다.

```bash
cd onedal-web/server
cp local.db smoke-copy.db
PORT=4099 DB_FILE=smoke-copy.db npx tsx src/index.ts     # 다른 창에서 curl -s localhost:4099/api/health
# 확인 뒤: 끄고 rm -f smoke-copy.db smoke-copy.db-wal smoke-copy.db-shm
```

- 🔴 `DB_FILE` 은 **`server/` 폴더 기준 파일 이름**만 받는다 — 절대 경로를 주면 «directory does not exist»로 안 뜬다
- `smoke-copy.db` 는 git 이 무시한다 · 포트 `4099` 는 코드에 안 박는다 (「포트」 표 밖의 임시 번호)

## `pnpm e2e:app` — 앱 구간을 검사하는 유일한 수단

`scenario` 는 서버·관제웹만 본다. **앱이 화면을 읽고 → 필터를 걸고 → 터치하는 구간**은
검사할 방법이 없어서, 실제 배차망에 꿀콜이 뜨기를 기다려야 했다.

배차망 **시뮬레이터**(레포 안 `onedal-sim/`)를 띄우면 그 구간이 열린다.

```bash
cd onedal-sim && pnpm dev          # 시뮬레이터 (172.30.x.x:5173)
# 폰에서 픽업 지역을 한 번 고른 뒤
cd onedal-web && pnpm e2e:app
```

7단계를 순서대로 확인하고, **어디서 끊겼는지**를 그대로 알려준다.
그중 5번째(`AUTO 로 보고`)가 가장 중요하다 — 2026-08-12 유령 콜 사고가 정확히 거기서 났다.

### 🔴 **반드시 크롬으로 열어야 한다**

| 브라우저 | 앱이 읽는 텍스트 |
|---|---|
| 크롬 `com.android.chrome` | **41개** — 페이지 안 글자가 전부 |
| 삼성 인터넷 `com.sec.android.app.sbrowser` | **2개** (URL·탭 수). **웹 콘텐츠를 접근성 트리에 안 올린다** |

기본 브라우저가 삼성이면 아무것도 안 읽히는데, 겉보기엔 **"앱이 고장난 것"** 처럼 보인다.
`e2e:app` 은 크롬을 명시적으로 지정해서 연다.

> 터치는 걱정 없다 — 앱이 `dispatchGesture`(화면 좌표 탭)를 쓰므로
> 브라우저든 네이티브든 똑같이 눌린다. 실측으로 확인했다.

## 서버 로그는 파일에도 남는다

```
onedal-web/server/logs/server-YYYY-MM-DD.log      평소(4000)
onedal-web/server/logs/server-YYYY-MM-DD-4012.log 다른 포트(검사·재현용)
```

터미널 출력은 **그대로** 있다 — 파일은 추가지 대체가 아니다.
**3일치만 남고 부팅 때 자동 정리**된다. `.gitignore` 에 들어 있다.

왜 필요했나: *"🏁 도착 감지가 몇 번 찍혔나"* · *"isActive 가 언제 꺼졌나"* 를 확인하려면
매번 터미널을 복사해야 했다. 콘솔은 스크롤이 지나가면 사라진다.
2026-08-14 에 서버 로그를 함께 보고서야 *"앱을 손으로 만져 리스트로 나오면 콜 잡기가 죽는다"* (당시 표현: 사냥)
를 찾았다 — 브라우저 콘솔만으로는 안 보이던 것이다.

**읽을 때는 `pnpm log`** — 요약·콜별 흐름·장부 대조 (위 표). grep 을 손으로 짜지 않는다.

⚠️ **파일을 지우면 서버를 다시 띄울 때까지 안 쌓인다** (열려 있던 스트림이 지워진 파일을 계속 문다).

## 🔴 `jest` 는 **`Test Suites:` 줄까지 본다**

```
Test Suites: 30 passed, 30 total     ← 이 줄을 안 보면 통째로 안 도는 스위트를 놓친다
Tests:       452 passed, 452 total
```

**컴파일이 안 되는 테스트 파일은 "실패"가 아니라 "없는 것"이 된다.** `✕` 도 안 찍히고
`Tests:` 숫자에서도 빠진다 — 그냥 조용히 사라진다.

2026-08-15 에 `filterHunt.test.ts`(지금 이름은 `tests/shared/callFilterBlocker.test.ts` — **fail-open 차단** 안전 검사 6건)가 타입에 없는 키 한 줄
때문에 **이틀째 안 돌고 있었다**(08-13 `c609e95` 이후). 그동안 커밋 게이트는 매번 통과했다.
빈 필터로 콜 잡기가 나가는 것을 막는 검사였는데, 그게 죽은 줄 아무도 몰랐다.

→ 결과를 `grep "Tests:"` 로만 보지 않는다. **`Test Suites:` 의 `passed` 와 `total` 이 같은지**
  확인한다. `npx jest` 의 종료 코드도 0 인지 본다 (파이프로 넘기면 코드가 가려진다).
