# onedal-web — 웹 워크스페이스 (pnpm)

`server` · `client-app` · `logbook` · `shared` 를 묶는 자리. **검증 스크립트가 여기 있다.**
루트 [CLAUDE.md](../CLAUDE.md) 가 먼저다.

## 검증 스크립트

🔴 **스크립트를 새로 만들기 전에 이 표에서 먼저 찾는다**
- 비슷한 일을 하는 명령이 있으면 **새 파일을 만들지 않고 그 명령에 인자를 하나 더한다**
  (예: DB 에서 새로 볼 것이 생기면 `scripts/lib/db-<이름>.mjs` 를 두고 `pnpm db <이름>` 으로 부른다)
- 정말 새로 만들어야 하면 **왜 기존 명령으로 안 되는지**를 표의 «잡는 것» 칸에 한 줄로 적는다
- 까닭: 요청마다 하나씩 만들면 같은 일을 하는 도구가 따로 자란다

🔴 **스크립트를 만들면 이 표에 올린다** — `package.json` 명령 이름 ·
잡는 것 · **못 잡는 것** · **검수**(일부러 틀린 것을 넣어 빨간불을 본 방법, 못 봤으면 왜).
`server/tests/rules/scriptsListed.test.ts` 가 문다 — 표에 안 올리면 게이트가 빨간불이다.
🔴 **초록불은 «잡는 것» 칸만 맞다는 뜻이다.** «못 잡는 것»을 읽고 쓴다.
⚠️ 개수·소요 시간은 적지 않는다 — 반드시 낡는다 (루트 `CLAUDE.md` 「이 문서에 무엇을 적나」).

| `pnpm db` | DB 를 본다 — 인자로 고른다: `ledger [건수]` 콜별 단계와 출처(직접·자동·건너뜀) · `options [갈래]` 콜 옵션 선택지와 값 · `track [콜 id 앞부분]` GPS 궤적(점·끊긴 구간·상하차지 근접) · `parse [배차망]` 앱이 화면을 제대로 읽었나(반쪽 읽힘·주소 칸의 낯선 글자·모르는 배지 — 새 배차망을 붙일 때) · `dict [배차망]` 그 배차망의 낱말 사전 초안(갈래·**배지로도 주소로도 쓰이는 낱말**·안 쓰이는 낡은 낱말·사전에 붙일 조각). **인자 없이 부르면 목록을 찍는다** | 판정이 없다 — 보는 도구 · 메모리에만 있는 콜은 안 보인다 · `parse`·`dict` 는 장부(`intel.rawText`)만 본다: 앱이 **서버로 안 보낸 화면**은 여기 없다 · 🔴 **둘 다 «앱이 이미 칸에 담은 낱말» 을 빼고 센다** — 사전에서 낱말을 빼도 여기엔 안 뜬다(폰이 새로 읽어 올려야 드러난다) · `dict` 의 갈래는 지도 명부(법정동)에 기대므로 행정동만 있는 이름은 미분류로 뜬다 | 다섯 다 돈다 · 모르는 인자는 목록을 찍고 exit 1 · `parse` 는 판정이 없어 변이 검수가 없다 — 실전에서 날짜 배지·반쪽 읽힘·도보 콜 구조 셋을 찾은 것이 검수다 · `dict` 는 DB **사본**의 원문 끝에 «뿅뿅배지» 를 붙이자 미분류 3→4 로 잡았다 (사전에서 낱말을 빼는 변이는 **안 잡혔다** — 위 «못 잡는 것») (2026-09-16) |
| `pnpm log` | 서버 로그 파일을 읽는다 — 부팅(시각·커밋) · 소켓 연결/해제 · 수상한 줄(WRN·ERR·❌🚨💥🔴⚠️, 같은 모양은 접는다) · **콜별 장부 대조**(로그에 «🌱 출생»이 찍힌 단계가 장부에 없으면 🔴 exit 1). **`pnpm log call <id 앞부분>`** 은 그 콜의 흐름을 ☁️ 서버 / 🖥️ 관제웹 줄로. 옵션 `--date` · `--port` · `--since` · `--until` · `--db`. `pnpm db` 는 장부만 읽고 로그 파일을 읽는 명령이 없었다 | 판정이 틀린 것 · 로그에 안 찍힌 일 · 장부 대조는 포트 4000(또는 `--db`)만 — 날짜가 지난 로그는 **지금** 장부와 견준다 · id 의 앞 8자·뒤 6자가 두 콜에 겹치면 못 가린다 | DB 사본에서 한 콜의 «하차 완료» 행을 지우자 🔴 exit 1 · 멀쩡한 사본은 exit 0 (2026-09-14) |
| `pnpm reach` | 쌓인 표본(`reach_samples`)으로 도달 계수(직선 km → 카카오 분) 역산 · **`pnpm reach sweep`** 은 기준점 쌍을 카카오로 재 표본을 쌓는다 | 필터에 자동 반영 안 된다 (계수 확정은 기사님) · `sweep` 은 돌린 시각의 교통이다 | 역산은 돈다 (2026-09-14) · `sweep` 은 미실행 — 카카오 API 비용 |
| `pnpm route:order` | 「상차 먼저」 vs 「지나가는 길」 순서 비교 | 직선거리다 — 카카오 실주행과 다르다 | 돈다 (2026-09-14) |
| `pnpm net:compare` | 그물 두 벌(지도 `callNet` ↔ 서버 turf)의 통과 동 목록 차이 | 두 계산은 같은 질문이 아니다 — 차이의 크기일 뿐 · 판정이 없다 | 돈다 (2026-09-14) |

🔧 **도구를 손볼 때**
- `lint:gate` 규칙은 **하나씩 캐서** 늘린다 — 한꺼번에 켜면 늘 빨간불이라 아무도 안 본다
- `audit:dead` 가 경고해도 **캐기 전에 지우지 않는다** — 잇는 자리가 따로 있을 수 있다

**`pnpm audit:docs` 의 ⑤ 는 «파일은 있는데 그 일을 더 이상 안 한다»를 잡는다**.

🔴 **그래서 규약이 하나 생겼다** — 문서가 파일을 가리킬 때는 **«그 파일의 무엇»인지
이름을 함께 적는다**(`judge()` · `CRITERIA`). 파일 이름만 적으면 그 파일이 살아 있는 한
감사가 못 잡는다.

**`pnpm lab` 은 «화면이 두 말을 하는 것»을 잡는다** — 한 화면의 두 자리가 같은 값을 다르게 적는 것
(예: 지도 순번 ↔ 시트 순번 · 시트의 분 ↔ 심사석의 분).
🔴 **vitest 는 순수 함수만 본다** — 화면이 무엇을 적는지는 안 본다. 그래서 `lab` 은
**기사님이 누르는 실제 문제 버튼**을 눌러 DOM 에 찍힌 글자끼리 대조한다.

```bash
cd onedal-web && pnpm lab           # 문제를 끝까지 돌고 통과/실패를 적는다
SHOTS=1 pnpm lab                    # 단계마다 화면을 /tmp/onedal-lab/ 에 찍는다
KEEP=1 pnpm lab                     # 끝나도 크롬을 안 닫는다 (직접 들여다볼 때)
```

- 🔴 **문제 목록은 화면에 산다** (`client-app/src/pages/labProblems.ts` → 실험실 **상단 🧪 버튼**).
  `pnpm lab` 은 **그 버튼을 누른다** — 기사님이 누르는 것과 **글자 그대로 같은 것**이 돈다.
  좌표를 스크립트에 박지 않는다 — **나만 돌릴 수 있으면 그건 문제가 아니라 내 메모다.**
- 문제는 기사님이 실제로 돈 하루(🌅 볼트 오전 · 🌆 볼트 저녁)와 경충대로 한 줄 길(🔽 이천행 · 🔼 복귀 —
  방향마다 잘 되는 경우와 상차지가 반대편 차선인 경우)이다.
  ⚠️ `pnpm lab` 이 실제로 도는 것은 **첫 버튼(볼트 오전)** 하나다 — 나머지는 기사님이 눌러 보는 자리다.
  요금이 낮으면 색이 «똥»이 되어 문구·버튼 비율이 달라진다 — **재현이 안 되면 문제가 아니다**
- 📄 **끝나면 보고서를 연다** (`/tmp/onedal-lab/index.html`) — 검사 결과와 단계별 화면이 한 장에.
  `OPEN=0` 이면 안 연다
- 🔴 **통과해도 «본 것»을 함께 적는다** — 숫자가 안 보이면 기사님과 내가 같은 것을 본 게 아니다
- ⚠️ `pnpm dev` 로 관제웹(3000)이 떠 있어야 한다. 크롬을 쓰므로 **로컬 전용**이다
- 🔴 같은 값이 화면 여러 곳에 찍히면 **첫 줄만 보지 말고 전부 모아 하나인지** 본다 — 첫 줄만 보면 나머지를 틀려도 초록불이다.
  **검사를 만들면 변이로 빨간불을 확인한다**

🔴 **기사님과 같은 화면을 보려면 기사님이 보시는 그 화면을 찍어서 본다** (`pnpm shot`).
기사님 말씀: *"너랑 나랑 똑같은 걸 봐야지"*.
콜을 지어내 두 화면에 세우고 글자를 맞춰 보는 도구는 만들지 않는다 — 지어낸 조건(요금 등)은
기사님께 일어날 수 없는 조건이고, 요금이 다르면 색·문구·버튼 비율부터 달라진다.
(`lab` 과 다른 점: `lab` 은 기사님도 누르는 실제 문제 버튼을 쓴다.)

**`pnpm drive` 는 «주행에서만 보이던 것»을 책상에서 잡는다** —
경로 순서 · 도착 감지 · 궤적의 `stop_type`. 나가 봐야만 확인되면 **하루에 한 번밖에 못 고친다.**

```bash
cd onedal-web && pnpm drive          # 폰·카카오 키·개발 서버 전부 불필요
DRIVE_LOG=1 pnpm drive               # 서버 로그까지 보고 싶을 때
```

`scenario` 와 다르다 — 그건 **첫 상차지 하나만** GPS 로 찍고 나머지 단계는
버튼(`report-milestone`)으로 넘긴다. `drive` 는 **모든 정거장을 GPS 로 걸어간다.**
그래야 «정거장이 넘어가는가»(`nextStopOf`)를 실제로 본다.

문제지는 **기사님 실측 상황**이다 (좌표도 그때 지점) —
곤지암 하차가 4km 앞인데 가남 상차가 30km 밖. 「상차 먼저」 규칙이면 30km 부터 간다.

- 전용 포트 **4014** · 전용 DB `drive.db` (빈 DB 로 시작해 끝나면 지운다)
- `server/local.db` 와 개발 서버(4000)는 **건드리지 않는다** (실행 전후 지문 확인함)
- ⚠️ 이벤트 이름을 틀리게 들으면 **멀쩡한 제품을 «안 울린다»고 오진한다** —
  `pnpm audit:socket` 목록과 대조할 것 (예: 다음 정거장 알림은 `next-stop-approaching`)

**`pnpm db ledger` 는 "화면이 말하는 것"과 "장부에 남은 것"을 대조한다.**
기사님 말씀: *"장부에 남았는지 내가 어떻게 알지?"* — 화면은 메모리에서, 장부는 DB 에서 오므로
**화면엔 있는데 장부는 빈** 갈라짐이 생긴다. 저장 결과를 눈으로 볼 수 있어야 먼저 잡는다.
출처가 함께 보인다 — `✍️ 직접`(실측 통계에 씀) · `🛰️ 자동`(참고값) · `⏭️ 건너뜀`(믿을 수 없음).

**`pnpm audit:dead` 는 "고쳤는데 안 돌고 있는 것"을 잡는다.**
호출부가 멀쩡해도 세션에서 사라진 필드를 읽으면 조용히 `null` 만 돌려준다 —
파라미터가 `session: any` 면 `tsc` 가 못 잡는다. → **`any` 로 세션을 받지 않는다.**

**`pnpm scenario` 는 다른 검사가 전부 통과한 결함을 잡는 유일한 수단이다.**
`tsc`·`jest`·`vite build`·`audit:socket` 은 콜 생애를 끝까지 돌려 보지 않는다 —
상차한 콜이 새로고침에 사라짐 · 짐 신고 무시 · 착불 미기록 같은 결함은 이것으로만 드러난다.

→ **콜 흐름(상태·복구·적재·정산)을 건드렸다면 반드시 돌린다.**

## 기존 DB 사본으로 부팅 — 스키마·`shared` 를 고쳤을 때

빈 DB 는 문제를 숨긴다. 떠 있는 `pnpm dev` 는 건드리지 않고 **따로** 띄운다.

```bash
cd onedal-web/server
cp local.db smoke-copy.db
PORT=4099 DB_FILE=smoke-copy.db npx tsx src/index.ts     # 다른 창에서 curl -s localhost:4099/api/health
# 확인 뒤: 끄고 rm -f smoke-copy.db smoke-copy.db-wal smoke-copy.db-shm
```

- 🔴 `DB_FILE` 은 **`server/` 폴더 기준 파일 이름**만 받는다 — 절대 경로를 주면 «directory does not exist»로 안 뜬다
- `smoke-copy.db` 는 git 이 무시한다 · 포트 `4099` 는 코드에 안 박는다 (「포트」 표 밖의 임시 번호)

## `pnpm e2e:app` — 앱 구간을 검사하는 유일한 수단

`scenario` 는 서버·관제웹만 본다. **앱이 화면을 읽고 → 필터를 걸고 → 터치하는 구간**은
검사할 방법이 없어서, 실제 배차망에 꿀콜이 뜨기를 기다려야 했다.

배차망 **시뮬레이터**(레포 안 `onedal-sim/`)를 띄우면 그 구간이 열린다.

```bash
cd onedal-sim && pnpm dev          # 시뮬레이터 (172.30.x.x:5173)
# 폰에서 픽업 지역을 한 번 고른 뒤
cd onedal-web && pnpm e2e:app
```

단계를 순서대로 확인하고, **어디서 끊겼는지**를 그대로 알려준다.
그중 `AUTO 로 보고` 단계가 가장 중요하다 — 자동으로 잡은 콜이 MANUAL 로 보고되면 서버가 안전취소 흐름을 안 탄다.

### 🔴 **반드시 크롬으로 열어야 한다**

| 브라우저 | 앱이 읽는 텍스트 |
|---|---|
| 크롬 `com.android.chrome` | 페이지 안 글자가 **전부** |
| 삼성 인터넷 `com.sec.android.app.sbrowser` | URL·탭 수**뿐**. **웹 콘텐츠를 접근성 트리에 안 올린다** |

기본 브라우저가 삼성이면 아무것도 안 읽히는데, 겉보기엔 **"앱이 고장난 것"** 처럼 보인다.
`e2e:app` 은 크롬을 명시적으로 지정해서 연다.

> 터치는 걱정 없다 — 앱이 `dispatchGesture`(화면 좌표 탭)를 쓰므로
> 브라우저든 네이티브든 똑같이 눌린다. 실측으로 확인했다.

## 서버 로그는 파일에도 남는다

```
onedal-web/server/logs/server-YYYY-MM-DD.log      평소(4000)
onedal-web/server/logs/server-YYYY-MM-DD-4012.log 다른 포트(검사·재현용)
```

터미널 출력은 **그대로** 있다 — 파일은 추가지 대체가 아니다.
보관 기간은 `server/src/utils/fileLogger.ts` 의 `KEEP_DAYS` — 부팅 때 자동 정리된다. `.gitignore` 에 들어 있다.
콘솔은 스크롤이 지나가면 사라진다 — «몇 번 찍혔나»·«언제 꺼졌나»는 파일로 본다.

**읽을 때는 `pnpm log`** — 요약·콜별 흐름·장부 대조 (위 표). grep 을 손으로 짜지 않는다.

⚠️ **파일을 지우면 서버를 다시 띄울 때까지 안 쌓인다** (열려 있던 스트림이 지워진 파일을 계속 문다).

## 🔴 `jest` 는 **`Test Suites:` 줄까지 본다**

```
Test Suites: N passed, N total     ← 이 줄을 안 보면 통째로 안 도는 스위트를 놓친다
Tests:       M passed, M total
```

**컴파일이 안 되는 테스트 파일은 "실패"가 아니라 "없는 것"이 된다.** `✕` 도 안 찍히고
`Tests:` 숫자에서도 빠진다 — 그냥 조용히 사라진다.

타입에 없는 키 한 줄로 안전 검사(예: 빈 필터로 콜 잡기가 나가는 것을 막는 `callFilterBlocker`)가
통째로 빠져도 커밋 게이트는 초록이다.

→ 결과를 `grep "Tests:"` 로만 보지 않는다. **`Test Suites:` 의 `passed` 와 `total` 이 같은지**
  확인한다. `npx jest` 의 종료 코드도 0 인지 본다 (파이프로 넘기면 코드가 가려진다).

## 함정

- ⚠️ 검사 포트에 옛 서버가 남아 있으면 시드하지도 않은 DB로 검사가 돌아 **멀쩡한 제품이 실패로 나온다**
  (`bootedAt` 확인은 루트 「무엇이 실제로 돌고 있는가」). `scenario` 는 먼저 포트를 비우고,
  기동 시각보다 이른 서버가 응답하면 검사를 중단한다

- `pkill -f "PORT=4012"` 는 **안 잡힌다** (환경변수는 명령줄에 안 보인다).
  `lsof -ti :4012 | xargs kill -9` 로 포트를 쥔 프로세스를 죽인다
