# 주행 검수

[주행시나리오](../주행시나리오/SKILL.md) 가 만든 문제지를 **돌리고 검수**한다.

## 순서

```
① drive 실행  →  ② 로그 검수  →  ③ 변이 검증  →  ④ 리허설 등록  →  ⑤ 실행법 문서화
                       ↓ 실패
                  주행시나리오로 되돌아간다
```

## ① 돌린다

```bash
cd onedal-web && pnpm drive          # 40초 · 폰·카카오 키·개발 서버 불필요
DRIVE_LOG=1 pnpm drive               # 서버 로그까지 보고 싶을 때
```

## ② 로그로 검수한다 — **화면 말고 로그가 근거다**

```bash
python3 .claude/skills/주행검수/scripts/audit_run.py --since "12:30"
```

이 스크립트가 답하는 다섯 가지:

| | 무엇을 | 어디서 |
|---|---|---|
| **방문 순서** | 코앞 정거장을 먼저 가는가 | `🧭 [경로 순서]` |
| **판정 색** | 무슨 색이 왜 나왔나 | `order-evaluated … '꿀' · N점` |
| **도착 감지** | 정거장마다 1회씩 찍혔나 | `🏁 [도착 감지]` |
| **궤적** | `stop_type` 이 pickup·dropoff 둘 다인가 | `gps_tracks` |
| **실제 km** | 궤적을 이어 잰 거리 · 이상적 순서와의 차이 | `gps_tracks` 좌표 합 |

🔴 **«한 사이클을 최소 km 로 돌았는가»** 가 최종 판정이다. 방문 순서만 맞아도
   실제 주행이 길면 다른 데서 새는 것이다.

## ③ 변이 검증 — **통과만 보고 믿지 않는다**

검사가 초록불인 것과 검사가 **일을 하는 것**은 다르다. 규칙을 일부러 되돌려
그 검사가 **터지는지** 본다.

```bash
cd onedal-web/server && cp src/services/routeComposer.ts /tmp/rc.bak
# orderByNearest → optimizeWaypoints(상차 먼저) 로 되돌린 뒤
cd .. && pnpm drive          # 🔴 방문 순서 검사만 터져야 정상
cp /tmp/rc.bak server/src/services/routeComposer.ts
```

**안 터지면 검사가 그 규칙을 안 보고 있는 것**이다. 2026-08-29 에 이 방법으로
문제지가 엉뚱한 것을 통과시키고 있었음을 잡았다.

## ④ 통과하면 리허설에 등록한다

기사님이 **화면으로** 같은 상황을 보실 수 있게 `scripts/rehearsal.mjs` 의 문제지에
**같은 좌표로** 넣는다. drive 와 좌표가 같아야 결과를 나란히 놓고 볼 수 있다.

```js
{ key: '17', label: '🚚 [1] 첫짐 · … — KEEP 하고 **출발**까지 누른다',
  pickup: pick('초월읍행정복지센터'), dropoff: pick('쿠팡 곤지암2센터'),
  fare: 50000, vehicleType: '1t',
  start: { label: '집', lat: 37.3900, lng: 127.2600 },   // 📍 현위치를 옮긴다
  expect: [ '무엇을 볼지 (기대 색은 단정하지 않는다)' ] },
```

- `start` 를 넣으면 콜을 올리기 전에 **현위치를 그 자리로 옮긴다** — drive 와 같은 자리에서 시작한다
- `expect` 는 콜을 올리기 **전에** 화면에 찍힌다. 기대를 모르고 보면 «뭔가 이상한데» 로 끝난다
- 🔴 **기대 색을 단정하지 않는다** — 2026-08-29 에 «🟡 이 정상» 이라 적었는데 **🔵 꿀 73점**이
  나왔다. 우회가 커도 시급·버퍼·경유 적중이 좋으면 꿀이다

## ⑤ 실행법을 적는다

기사님이 혼자 돌리실 수 있게 **순서와 무엇을 볼지**를 남긴다.

```
1. 브라우저: http://localhost:3000/?speed=3      ← 3배속 (기본 15배속은 3km 를 6초에 지난다)
2. 터미널  : pnpm rehearsal  →  17 올림
3. 화면    : 색 확인 → KEEP → 상차 완료 → 출발
4. 터미널  : 「하차지 3km 앞」 신호가 뜨면 18 올림
5. 화면    : 색 확인 → KEEP/CANCEL → **방문 순서** 확인
6. 검수    : audit_run.py 로 로그 검산
```

## 함정 — 전부 2026-08-29 에 실제로 밟았다

- 🔴 **기본 15배속은 너무 빠르다.** 근접 예고(3km 앞) → 도착이 **6초**다. 합짐을 올릴
  틈이 없다. `?speed=3` 으로 켠다 (개발 빌드에서만 읽는 URL 옵션)
- 🔴 **앞 판의 주행 상태가 남는다.** `pnpm reset:calls` 는 콜만 비운다 — 브라우저는
  위치와 주행 상태를 들고 있다. 판을 새로 시작할 때는 **⌘+Shift+R** 도 함께
- 🔴 **근접 예고는 상차지에서도 울린다.** 집에서 상차지가 3km 안이면 시작하자마자 울린다.
  «하차지» 신호만 골라 들을 것
- 🔴 **궤적에는 앞 판이 섞여 있다.** 거리를 잴 때 **이번 판의 시각으로 잘라야** 한다
  (안 자르면 178km 같은 값이 나온다 — 실측)
- ⚠️ 리허설은 **개발 서버(4000)와 local.db 에 진짜로 기록한다.** 그게 목적이다.
  끝나면 `pnpm reset:calls`
