## 2. 되돌리는 법 — **먼저 만든다**

되돌릴 자리가 없으면 배포하지 않는다.

### 코드
```bash
git tag live-2026-05-11 origin/main        # 지금 라이브에 이름을 준다
git push origin live-2026-05-11
```
롤백:
```bash
git push origin +live-2026-05-11:main      # 5월 코드로 되돌림 → 자동 재배포
```

🔴 **`main` 은 "지금 라이브에 있는 것"이다.** 작업은 브랜치에서 하고 배포할 때만 합친다.
`main` 에서 직접 작업하면 롤백이 한 줄로 끝나지 않는다.

### DB
배포 스크립트가 **코드 갱신 전에** 자동으로 뜬다 (§4-1). 손으로 하면 잊는다.

## 3. F 먼저 — 관제앱이 라이브를 보게 한다 (배포 전, 로컬)

관제앱(`client-app/android/`, `kr.co.onedal.dashboard`)은 `dist` 를 품고 돈다.
API 주소가 상대경로(`/api`)라 **그대로 빌드하면 웹뷰 자기 자신에게 요청한다.**

- [ ] **F-1** `VITE_API_URL=https://1dal.altari.com/api` 로 빌드
- [ ] **F-2** `npx cap sync android` → APK 빌드 → 설치
- [ ] **F-3** 앱에서 로그인 → **소켓이 붙는지** (Cloudflare WS 를 여기서 미리 본다 = D 도 같이 검증)
- [ ] **F-4** 위치 권한 허용 → 좌표가 서버로 나가는지
- [ ] **F-5** 화면 꺼짐 방지(`KeepAwake`)가 실제로 도는지

⚠️ 웹뷰 origin 이 `https://localhost` 라 라이브(HTTPS)와 **혼합 콘텐츠 문제가 없다.**
   반대로 `server.url` 로 라이브를 직접 띄우면 **GPS 가 막힌다** (http/https 아닌 원격 origin은
   보안 컨텍스트 판정이 달라진다). **dist 를 품는 지금 구조를 유지한다.**

> 예비책: 같은 주소를 **폰 크롬**으로 열면 그대로 관제웹이다 (라이브가 HTTPS 라 GPS 된다).
> 앱이 안 되면 즉시 갈아탄다. 단 화면이 꺼지면 추적이 멎으므로 **화면 자동 꺼짐을 "안 함"** 으로.

## 3-B. 리허설 배차망 — `rehearsal.altari.com` (기사님 제안 2026-08-23)

기사님: *"지금 올라가 있는 건 **리스트 컨트롤을 할 수 없거든.** 그래서 구로동 쪽으로
배달 가능한 콜을 하나 확실히 넣어야 이동 중에 콜을 잡을 걸 확인할 수 있어."*

**맞다.** 배포본(`map.altari.com`)은 옛 map 레포가 올린 것이라 **랜덤**이다. 문제지
(`?preset=`)는 이번에 레포로 들인 `onedal-sim` 에만 있다. 랜덤으로는 *"구로행 콜을
주행 중에 잡았다"* 를 **만들 수 없고, 안 나오면 시험 자체가 성립하지 않는다.**

### 3-B-1. 주소를 어떻게 붙이나

**추천: 서브도메인** (`rehearsal.altari.com` → 같은 EC2, Express 가 Host 로 분기)

| | 서브도메인 (추천) | 경로 (`1dal.altari.com/rehearsal/`) |
|---|---|---|
| DNS | Cloudflare 에 A 레코드 하나 (기사님 5분) | **불필요** |
| 인증서 | Universal SSL 이 1단계 서브도메인을 덮는다 | 그대로 |
| **`onedal-sim` 코드** | **안 건드림** (루트로 서빙) | `vite base` + `BrowserRouter basename` 손봐야 함 |
| 로컬(5173)과 차이 | 없음 | 생긴다 (배포본만 base 가 붙는다) |

시뮬레이터 코드를 안 건드리는 쪽이 낫다 — **로컬과 배포본이 갈라지면 문제지가 로컬에서만
맞는 일이 생긴다.** DNS 가 안 풀리면 경로 방식으로 되돌린다.

- [ ] **기사님**: Cloudflare 에서 `rehearsal` A 레코드 → 1dal 과 같은 EC2 IP (프록시 켬)
- [ ] Express 에 Host 분기 + `onedal-sim/dist` 정적 서빙
- [ ] `deploy.yml`: `onedal-sim` 빌드 단계 추가 + **경로 필터에 `onedal-sim/**` 추가**
      (지금은 `onedal-web/**` 만 배포를 깨운다 — 안 넣으면 시뮬만 고쳐도 안 올라간다)

### 3-B-2. 🔴 문제지는 **다 내면 멈춘다**

```ts
// 문제지를 다 냈으면 null(더 안 낸다) — 랜덤으로 되돌아가면 채점이 흐려진다.
if (!p) return null;
```

**채점에는 맞지만 주행에는 안 맞는다.** 16문제 × 45초면 **12분**이고, 나머지 50분은
조용하다. 주행은 1시간이다.

- [ ] `?loop=1` 옵션 추가 — 있으면 문제지를 **처음부터 되돌려 흘린다**.
      **없으면 지금과 똑같다** (채점 모드는 안 건드린다)

### 3-B-3. 구로 문제지 (`?preset=구로&loop=1`)

주행 시험용이라 `expect`(채점 정답)는 비운다 — 그날 필터 상태에 달렸기 때문이다
(`presets.ts` 가 이미 그렇게 구분해 둔다).

- [ ] **① 초월 → 구로** · 1t · 넉넉한 요금 — **오늘의 주인공.** 이게 잡혀야 §7-3 도착 감지로 간다
- [ ] ② 초월 → 구로 인근(금천·영등포) — 합짐 후보
- [ ] ③ 초월 → 성남/분당 — 경유 판정 시험
- [ ] ④ 초월 → 반대 방향(파주 등) — **떨어져야 정상.** 화면에 `도착지 N` 로 뜨는지 확인
- [ ] ⑤~⑧ 요금·차종을 흔든 것 — `훑음 N→N` 의 축이 바뀌는지

⚠️ 문제지의 상차지는 **고정 좌표**다 (§7-0-1). 주행하면 뒤로 멀어지므로 `오늘만` 으로
상차지 반경을 넉넉히 여는 것이 여전히 필요하다.

## 5-B. 라이브 수용 시험 — **집에서, 출발 전에** (약 30분)

> 배포가 "떴다"와 "된다"는 다르다. **차에 타기 전에 여기서 다 걸러 낸다.**
> 순서가 중요하다 — 아래로 갈수록 앞의 것에 기댄다. 막히면 **거기서 멈추고** 고친다.

| # | 확인할 것 | 통과 신호 | 막히면 |
|---|---|---|---|
| ① | 서버가 새 코드인가 | `/api/health` 가 **JSON**, `git.commit` 일치 | §4-4 로 |
| ② | 로그인 | 구글 로그인 → 대시보드 진입 | OAuth 도메인 설정 |
| ③ | **소켓** | 관제웹이 새로고침 없이 갱신 | `polling` 폴백 추가 (코드 수정 필요) |
| ④ | 설정 저장 | 저장 후 **새로고침해도 남아 있다** | DB 쓰기 문제 |
| ⑤ | 스캐너 도달 | 폰 카드에 A24, `수집` 이 올라감 | `isLiveMode`·5G |
| ⑥ | **판정(카카오)** | 콜 하나 잡아 색이 🔵🟢🟡 중 하나 | **전부 🔴 이면 키가 없다** |
| ⑦ | KEEP → 경로 | 지도에 경로가 그려짐 | 경로 연산 |
| ⑧ | **관제앱 GPS** | S23 에서 내 위치가 지도에 찍힘 | §3 으로 |
| ⑨ | 좌표 전송 | 관제웹 시각이 움직임 | 테더링·소켓 |

🔴 **⑥ 이 오늘 조용히 무너지기 쉬운 자리다.** 카카오 키가 라이브 `.env` 에 없으면
판정이 전부 🔴 로 뜨는데, 화면은 멀쩡히 도니 *"원래 그런가"* 로 넘어가기 쉽다.
**색이 하나라도 🔵🟢🟡 로 나오는 것을 눈으로 본다.**

### "관제앱이 새것인가"를 확인하는 법

스캐너 앱은 화면에 `📦 v…` 를 띄우지만 **관제앱에는 그런 표시가 없다** (`versionName 1.0` 고정).
대신 **어제 만든 기능이 보이는지**로 확인한다 — 폰 카드에 이게 있으면 새것이다:

```
1234  콜 리스트  합짐 탐색  20:39:13 (수집:16 수락:3 취소:1 · 훑음 6→0 도착지4)
```

`· 훑음 …` 조각과 **앞의 시각**은 2026-08-23 에 생겼다. 5월 빌드에는 없다.

주행 중에 판단하면 늦는다. **시각으로 못박아 둔다.**

| 시각 | 상태 | 결정 |
|---|---|---|
| 출발 **3시간 전** | §5-B ①②③ 이 안 되면 | **롤백** (`git push origin +live-2026-05-11:main`) 후 오늘은 로컬로만 시험 |
| 출발 **2시간 전** | ⑥ 판정이 전부 🔴 이면 | 키를 넣거나, **GPS 시험만** 하기로 범위를 줄인다 (콜 없이 좌표만) |
| 출발 **1시간 전** | ⑧ 관제앱 GPS 가 안 되면 | **폰 크롬으로 갈아탄다** (같은 주소, 화면 자동 꺼짐 "안 함") |
| 출발 직전 | 지도에 내 위치가 없으면 | **출발하지 않는다** |

🔴 **되돌리는 것은 실패가 아니다.** 5월 라이브는 지금도 돌고 있고, 태그와 DB 백업이
있으니 언제든 그 자리로 간다. **차에서 고치려 하는 것이 실패다.**

## 5-D. 문제가 나면 무엇을 보나

- [ ] **배포 전에 SSH 로 들어가지는지 미리 확인한다.** 주행 중에 처음 시도하면 늦는다
- 브라우저 콘솔은 스크롤이 지나가면 사라진다 — 이상하면 **화면 캡처**부터
- 주행 중 관찰은 §7-4 표로, 기록은 §9 에

## 5-E. 오늘 실패해도 얻는 것

전부 안 되더라도 **버리는 시간이 아니다.** 아래는 오늘이 아니면 알 수 없다.

- 375 커밋이 EC2 에서 **빌드되는가** (다음 배포의 절반은 여기서 끝난다)
- Cloudflare 가 **WebSocket 을 통과시키는가**
- 라이브 DB 를 새로 만들었을 때 **국면 5탭이 시드되는가**
- 관제앱이 **웹뷰에서 GPS 를 읽는가** (앞으로 사진·하드웨어의 전제)
- 두 폰이 **서로 다른 망에서** 같은 서버를 보는가

## 7. 저녁 실주행 (초월 → 구로 고려대병원)

### 7-0. 콜은 **주행 중에도 온다** — 배차망도 라이브다

기사님 확인 2026-08-23: *"`https://map.altari.com/` 에 라이브 되어 있는 시뮬레이터가
붙어 있어. **가는 중에 콜을 잡아야** 작동하는 것을 우리가 로그에 남겨 둘 수 있어."*

```
A24 화면    시뮬레이터 앱  →  https://rehearsal.altari.com/inseong/dispatch?preset=구로&loop=1
A24 접근성  원달앱이 그 화면을 읽고 자동 터치
            → https://1dal.altari.com 로 보고  →  S23 관제앱에 뜬다
```

> 🔴 **주소는 `rehearsal` 이다** (§3-B). 기본값인 배포본(`map.altari.com`)은 **랜덤**이라
> 구로행 콜이 안 나올 수 있다. 시뮬레이터 앱 **볼륨 위 → 주소 직접 입력**으로 바꾼다.
> rehearsal 이 제때 안 서면 배포본으로 폴백하되, **그때는 구로행이 안 나올 수 있음을 안고 간다.**

**A24 한 대가 두 몫을 한다** — 화면에는 시뮬레이터가 떠 있고, 접근성 서비스가 그걸 읽는다.
셋 다 인터넷을 타므로 집 랜이 필요 없다. **오늘 시험의 사슬이 끊기는 데가 없다.**

> 시뮬레이터 앱은 **볼륨 위 버튼**으로 주소를 바꾼다. 기본값이 배포본이라 **그대로 두면 된다.**
> ⚠️ **문제지(16콜 `?preset=오탐`)는 배포본에 없다** — 그건 레포의 `onedal-sim` 에만 있다.
> 오늘은 **랜덤 콜**이 흐른다. 시험 목적(실제 주행 중 왕복)에는 그게 맞다.

### 🔴 7-0-1. 조정 하나 — 시뮬레이터의 "기사 위치"는 **GPS 를 안 본다**

시뮬레이터는 콜을 **설정 화면에서 고른 위치** 기준으로 만든다 (`InseongSetupPage` 의
`📍 기사 현재 위치`). 실제 GPS 를 따라오지 않는다.

그래서 초월로 두고 출발하면, **구로에 가까워질수록 상차지가 뒤에 남아** 콜이 상차지
거리에서 떨어지기 시작한다. 관제앱에 이렇게 뜬다:

```
· 훑음 8→0 상차지 8      ← 콜이 끊긴 게 아니라 "너무 멀어서" 떨어진 것이다
```

**이것 자체가 정상 동작이고 좋은 로그다.** 다만 *"가는 중에 콜을 잡는 것"* 이 목적이므로
출발 전에 한쪽을 넉넉히 열어 둔다.

- [ ] 출발 전 **`오늘만`** 으로 **상차지 반경을 넉넉히** (40km 안팎) — 초월 기준 콜이
      주행 내내 통과한다. `오늘만` 이라 자정에 저절로 돌아온다
- [ ] 시뮬레이터 설정에서 **기사 위치 = 초월**, **목적지 방향 = 서울/구로**

### 🔴 7-0-2. 주행 중 결재는 **하지 않는다**

콜이 잡히면 관제앱에 **안전취소 30초** 안에 결재가 뜬다. **운전 중에는 누르지 않는다.**
안 누르면 안전취소로 정리되고, **그 과정도 그대로 로그에 남는다** — 오늘 필요한 것은
*"콜이 잡히고 판정까지 왕복했다"* 이지 KEEP 자체가 아니다.

- 누르실 거면 **신호 대기 중에만**
- 시뮬레이터라 취소가 실제 배차망 취소 횟수에 들어가지 않는다

### 7-0-3. 그래도 경로 하나는 만들어 두고 나간다

**도착 감지**를 시험하려면 목적지가 구로인 콜이 하나 살아 있어야 한다.

- [ ] 출발 전 집에서 **구로 방면 콜 하나를 KEEP** → 지도에 경로가 그려진 것을 눈으로 확인
- [ ] 그 상태로 출발한다 (주행 중 잡히는 콜은 그 위에 얹히거나 안전취소된다)

### 7-1. 출발 전 (집 앞, 시동 걸기 전)

- [ ] 🔴 **관제앱 지도에 내 위치가 찍히는가** — 안 찍히면 **출발하지 않는다**
- [ ] 좌표 옆 시각이 **움직이는가** (멈춰 있으면 테더링이 끊긴 것)
- [ ] 경로가 지도에 그려져 있는가
- [ ] A24 카드가 초록이고 시각이 움직이는가

### 7-2. 주행 중 (약 1시간)

- [ ] 좌표가 따라오는가 (지도에서 내 점이 움직인다)
- [ ] **지나온 구간이 지워지는가**
- [ ] 남은 거리·예상 도착이 줄어드는가
- [ ] 신호 약한 구간(터널 등)을 지난 뒤 **스스로 복구되는가** ← 소켓 재연결
- [ ] 두 폰 다 화면이 꺼지지 않는가
- [ ] 🔴 **콜이 계속 잡히는가** — 관제앱에 새 카드가 뜨고 색(🔵🟢🟡)이 붙는가.
      **이게 오늘 로그에 남기려는 것**이다
- [ ] 폰 카드의 `· 훑음 N→N` 이 **스캔마다 바뀌는가** (어제 만든 것의 실전 첫 확인)

### 7-3. 도착 (구로 고려대병원)

- [ ] 🔴 **도착 감지가 뜨는가** — 오늘의 가장 큰 관문
- [ ] 하차 처리 → 콜이 종료로 넘어가는가
- [ ] 집에 와서 `pnpm ledger` 로 **장부 대조** — 화면은 메모리, 장부는 빈 사고가 네 번 있었다

### 7-4. 무엇이 잘못됐는지 아는 법 (주행 중)

| 증상 | 어디가 문제 |
|---|---|
| 지도 점이 안 움직임 · **시각은 움직임** | GPS 가 안 잡힌다 (권한·실내·정확한 위치 꺼짐) |
| 지도 점도 시각도 **둘 다 멈춤** | **테더링이 끊겼다** (아이폰 확인) |
| 좌표는 가는데 **경로가 안 줄어듦** | 서버 연산 문제 — 돌아와서 로그를 본다 |
| A24 카드가 회색 | A24 데이터(5G)·접근성 토글 |
| A24 가 `알 수 없는 화면` | **시뮬레이터 앱이 앞에 없다** (다른 앱이 덮었거나 화면 꺼짐) |
| **콜이 안 잡힘** · `훑음 N→0 상차지 N` | 정상이다 — 초월이 뒤로 멀어졌다 (§7-0-1). 반경을 더 열었어야 하는 것 |
| **콜이 안 잡힘** · `훑음 0` 또는 줄 없음 | 시뮬레이터가 콜을 안 흘리고 있다 (앱을 다시 앞으로) |

⚠️ **주행 중에 고치려 하지 않는다.** 증상만 기억(가능하면 화면 캡처)하고 §9 에 적는다.

## 8. 남은 위험 — 알고도 안 막는 것

**막을 수 있는데 안 막는 것이 아니라, 오늘 범위 밖이라 안고 가는 것**이다. 나중에 놀라지 않으려고 적는다.

- **소켓 폴백이 없다** (`transports: ["websocket"]`). 5-B ③ 이 통과하면 오늘은 넘어가되,
  통과 못 하면 코드를 고쳐야 배포가 의미 있다
- **아이폰 테더링은 단일 실패점이다.** 끊기면 관제앱이 서버와 끊긴다 (GPS 는 계속 잡힌다)
- **관제앱에 버전 표시가 없다** (`versionName 1.0` 고정). *"무엇이 도는가"* 를
  기능 유무로 판단해야 한다 (5-B 참조). 다음 판에 버전 표시를 넣는 것이 맞다
- **시뮬레이터의 기사 위치가 GPS 를 안 본다** (§7-0-1). 주행하면 상차지가 뒤로 남는다.
  오늘은 반경으로 덮지만, 제대로 하려면 시뮬레이터가 실제 좌표를 따라가야 한다
- **배포본에는 문제지가 없다.** 재현 시험(16콜)은 여전히 집 랜에서만 된다
- **증거 사진 없음** (§0). 카메라 플러그인부터 없다

## 9. 로그 분석 계획

> 🔴 **주행이 끝나면 다시 못 만든다.** 무엇을 남기고 무엇을 물을지 **가기 전에** 정한다.

### 9-1. 무엇이 남고 무엇이 사라지나

| 로그 | 어디에 | 주행 뒤에 남나 |
|---|---|---|
| **서버 로그** | EC2 `~/onedal/onedal/onedal-web/server/logs/server-YYYY-MM-DD.log` | ✅ **주력.** 단 **3일치만** 남고 부팅 때 정리된다 |
| **장부(DB)** | EC2 `data.db` → `pnpm ledger` | ✅ 콜별 단계·신고·약속 |
| **FilterTally** | 서버 로그·기기 세션 | ✅ **앱의 판단이 요약되어 올라온다** |
| A24 앱 로그 | `Log.d` → **logcat 뿐** | ❌ **사라진다.** 파일에도 안 쌓고 서버로도 안 보낸다 |
| 관제앱 콘솔 | 웹뷰 | ❌ (원격 디버깅을 붙여야 보인다) |

🔴 **앱 내부 로그는 못 건진다.** 케이블로 노트북에 매달고 달릴 수는 없다.

✅ **그래서 어제 만든 `FilterTally` 가 여기서 값을 한다.** *"왜 안 잡았나"* 의 답이
축별 숫자로 **서버까지 올라와 남는다.** 이게 없었으면 오늘 주행은 *"안 잡히더라"* 로
끝났을 것이다.

- [ ] 그래도 **화면 캡처**를 남긴다 — 이상한 장면은 그 자리에서 찍는다 (§7-4)

### 9-2. 로그에 물을 것 — **미리 정한 질문**

돌아와서 뒤지지 않는다. 아래 질문의 답을 찾는다.

| # | 질문 | 어디서 |
|---|---|---|
| ① | 스캔이 **끊기지 않고** 돌았나 | 서버 로그의 `/api/scrap` 간격 — 빈 구간이 통신 끊김이다 |
| ② | 콜이 **몇 건 올라와 몇 건 통과**했나 | `FilterTally` 의 `seen`/`passed` 추이 |
| ③ | 떨어진 이유가 **주행에 따라 바뀌었나** | 축이 `도착지` → `상차지` 로 옮겨 갔는지 (§7-0-1 예상) |
| ④ | 판정 **색이 나왔나** | 🔵🟢🟡 중 하나라도. 전부 🔴 면 카카오 키 (§5-B ⑥) |
| ⑤ | **구로행 콜(문제지 ①)** 이 실제로 잡혔나 | 장부에 그 콜이 있는지 |
| ⑥ | 좌표가 **몇 초 간격**으로 들어왔나 | `dashboard-gps-update` 수신 간격 — 터널·음영 구간이 보인다 |
| ⑦ | 소켓이 **몇 번 끊기고 붙었나** | 연결/해제 로그. 잦으면 폴백이 필요하다 |
| ⑧ | **도착 감지**가 언제 떴나 | 실제 도착 시각과 몇 분 차이인지 |
| ⑨ | 화면과 장부가 **갈라지지 않았나** | `pnpm ledger` ↔ §10 실행 기록 |

### 9-3. 받아오는 법 (귀가 직후)

```bash
# ① 서버 로그 — 날짜를 확인하고 통째로
scp <EC2>:~/onedal/onedal/onedal-web/server/logs/server-$(date +%Y-%m-%d).log ./logs-drive.log

# ② 장부 — EC2 에서
cd ~/onedal/onedal/onedal-web && pnpm ledger
```

- [ ] 🔴 **로그가 3일치만 남는다.** 다음 부팅 때 지워질 수 있으니 **당일에 받아 둔다**
- [ ] 받은 로그는 `docs/` 가 아니라 별도 보관 (레포에 커밋하지 않는다)

### 9-4. 무엇을 성공으로 볼 것인가 — **가기 전에 정한다**

| 등급 | 조건 |
|---|---|
| **성공** | 주행 중 콜이 잡히고, 판정 색이 나오고, 도착 감지가 떴다 |
| **부분 성공** | 좌표·스캔은 끊김 없이 돌았으나 콜 또는 도착 감지가 안 됐다 |
| **실패** | 통신이 끊겨 로그에 빈 구간이 크다 (원인 분석 자체가 불가) |

**부분 성공도 충분하다** — 오늘 얻으려는 것은 *"라이브에서 사슬이 이어지는가"* 다.
안 된 것은 §10 에 적고 다음 판에서 잡는다.
