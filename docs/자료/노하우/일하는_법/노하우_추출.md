## 1. 첫짐 — 하루의 방향과 예산을 한 번에 정한다

| 노하우 | 1DAL |
|---|---|
| 첫짐 고르는 **세 기준: 동선 · 금액 · 뒤에 더 뜰까** | 앞 둘 ✅ / 🔴 셋째 없음 → 🔧 **후속 콜 빈도** |
| *"첫 콜이 하루의 운명을 결정한다"* — 잘못 고르면 오전이 1콜로 끝난다 | ✅ 「첫짐이 그날 예산을 정한다」와 같은 결론 |
| **전날 밤 예약콜을 잡아 두면** 아침에 기다릴 일이 없다 | 🔴 **없음** → 🔧 지금 필터는 «지금 뜬 콜» 만 본다 |
| **개인 고객에게 가는 짐**은 급하지 않아 시간 협의가 된다 → 첫짐으로 무난 | — 화주 유형이 시간 유연성의 신호 |
| **금액의 유혹**에 빠져 동선을 무시하면 실력이 안 는다 | ✅ 콜 필터·판정이 그 기준 |
| 🔴 **첫짐에 거리 하한이 필요하다** — 먼 첫짐은 비싸도 나쁘다 (합짐 예산이 안 남는다) | 🔴 **없음** → 🔧 지금은 요금 하한만 있다 |

## 2. 합짐 — 예산 안에서 붙이고, 순서가 값을 정한다

| 노하우 | 1DAL |
|---|---|
| **3콜이 균형점** — 차종이 **횟수**를 가른다 | ✅ [수입_시급](../수입_시급/노하우_추출.md) §1 에서 숫자로 확인됨 |
| **1~2번째는 잘 안 물어보고 싣고, 3·4합짐부터 상차지 통화**로 사이즈 확인 | ✅ 적재 확신도 + 통화 시트 |
| 짐 조합은 **큰 것 하나 + 작은 것 여럿** | ✅ 「마지막 자리는 작은 짐에」 |
| **중간 기착지마다 한 번 더** — 하차 10분 전부터 다음 방향을 고른다 | ✅ 근접 예고 + 하차지 주변 유지 |
| **하차지를 한 줄로 늘어놓으면** 거리가 짧아도 여럿이 붙는다 | 🔴 판정이 «하차지가 모여 있나» 만 보면 이 조합을 놓친다 → 🔧 |
| **픽업 순서는 잡은 순서가 아니다** — 가까운 것을 먼저 | ⚠️ `planArrivalStops` 가 상차 순서까지 최적화하는지 확인 필요 |
| **시간 제약이 다른 콜을 섞는다** — 급송 하나 + 예약 하나. 기다리는 동안 급송 처리 | 🔧 대기 시간을 다른 콜의 재료로 쓰는 발상 |

## 3. 동선 — 서울을 피하고, 꺾이는 콜을 버린다

| 노하우 | 1DAL |
|---|---|
| **단가보다 동선이 먼저다** | 🔧 판정이 요율 위주라 이 축이 약하다 |
| 🔴 **뭘 안 잡느냐가 더 중요하다** — 비싸도 동선이 안 맞으면 버린다 | ✅ 「경로를 꺾는 콜은 결국 손해」 |
| **서울 관통은 피한다** — 막히고, 묶을 융통성이 죽는다 | ✅ 경유 재파생 · 📖 사용설명서 |
| 대기는 **모서리**에서 · 하차 후에는 가운데가 좋다 | — 대기와 재출발의 기준이 다르다 |
| **노선(루트 족보)** — 콜은 산업단지 → 산업단지로 뜬다 | 🔧 후속 콜 빈도의 데이터적 실체 |
| **바운더리** — 첫짐 방향이 정해지면 하차 후보 범위가 넓어진다 | 🔧 첫짐 판정에 이 값어치가 안 들어간다 |

## 4. 시간 — 150% 선과 통화 타이밍

| 노하우 | 1DAL |
|---|---|
| 🔴 **150%** — `내비 × 1.5` 안에 도착. **픽업 시각마다** 콜별로 마감을 따로 잰다 | ✅ `deadline_ratio_pct` = 150 |
| 🔴 못 지키면 **배차 제한·기사 평가**가 남는다 (배상은 없어도) | 🔧 시한이 둘인 근거 |
| 🔴 **모든 콜에 150% 를 똑같이 주지 않는다** — 부품·카센터는 *"일반으로 불러 놓고 급송처럼"* | 🔴 **긴급도 개념 없음** → 🔧 적요 파서가 재료를 이미 읽는다 |
| **예약 픽업은 당길 수 있다** | 🔧 예약 시각을 하드 제약으로 두면 안 된다 |
| **통화 타이밍 셋** — 나오기 **전에** 주선사 · 픽업까지 **절반**에 출발지 · 도착 **30~40분 전**에 도착지 | 🔧 *"지금 통화할 때입니다"* 알림 · 📖 사용설명서 |
| **오전 픽업은 10시 전에 끝낸다** → 1시까지 하차 → 1시부터 2회전 | — 하루 모델과 부합 |
| **점심을 긴 주행에 겹친다** — 콜이 적은 시간이라 그때 먼 구간을 달린다 | 🔧 «점심 1시간» 이 별도 블록이 아닐 수 있다 |

## 5. 자리와 시간대 — 파도를 타고, 갇히면 나온다

| 노하우 | 1DAL |
|---|---|
| 🔴 **콜 뜨는 시각 = 그 지역 출근 시간** — 공단과 지식산업센터가 다르다 | 🔴 **없음** → 🔧 `지역 × 시간대` 콜 패턴 (`intel` 타임스탬프) |
| 🔴 **파도** — 콜이 뜨는 지역이 시간대별로 옮겨 다닌다 | 🔴 **없음** → 위와 같은 데이터 |
| 🔴 **갇힘이 실제로 터진다** — 머물까 옮길까를 판단해야 한다 | 🔴 판정이 *"여기 있으면 다음 콜이 있는가"* 를 못 답한다 |
| **탈출 두 가지** — ⓐ **브릿지 콜**(싼 콜이라도 잡아 이동) ⓑ **빈 차 이동** | 🔴 **없음** → 🔧 |
| **홈그라운드** — 건물 구조·주차 자리까지. *"한 달 이상 그 지역을 파야"* 생긴다 | ✅ `places` 거래처 장부가 이것의 시스템화 |
| **가지 말라는 곳** — 차종으로 못 가는 상하차 지점 | 🔧 `places` 에 기피 표시 |

## 6. 적재와 통화 — 우리가 푸는 문제가 여기 있다

| 노하우 | 1DAL |
|---|---|
| 🔴 **적요가 안 맞는다** — 작다더니 크고, 박스라더니 이사짐 | ✅ **1DAL 이 푸는 문제**. 인터뷰어도 *"시스템으로 보완되면 좋겠다"* 고 말한다 |
| 애매하면 전화, 확실하면 그냥 들어간다 | ✅ 느슨한 1차 필터 + 통화 확정 (규칙 ⑤) |
| 🔴 **수작업은 시간이 아니라 돈으로 판단한다** — *"수작업을 할 만큼 배송료가 받쳐 줘야"* | 🔴 우리는 상하차를 **비용(분)** 으로만 넣고 운임과 견주지 않는다 → 🔧 |
| 🔴 **도착지 주소가 뭉뚱그려져 온다** — 시 이름만 오고 실제는 외곽이라 시간이 더 걸린다. **원본이 그런 것**이지 파서 버그가 아니다 | 🔴 **표시가 없다** → 🔧 규칙 ⑤-2 «주소 불명확» |
| **미리 전화해 나와 있게** 만든다 | 🔧 도착전 통화 |
| **장소마다 통화 필요 여부가 다르다** | 🔧 `places` 에 한 줄. **새 스키마가 거의 필요 없다** |
| 🔴 **적요에 현장 제약이 없으면 기사가 당한다** — 하차지 점심시간이 안 적혀 담당 부재와 마주쳤다 | ✅ **적요 품질이 기사 판단의 상한**이다. 규칙 ⑤-2 가 우리 답 |

## 8. 시간당 효율 — 합짐의 손익분기 (ep14 · QP 개발자)

> 화자가 QP(퀵파일럿) 개발자다 — 우리와 같은 문제를 푸는 사람의 운용론이라
> 겹치는 결론은 «교차 검증»으로 읽을 수 있다. ep11(테스터 모집)은 제품 소개라
> 노하우가 아니어서 임시폴터에 남겨 뒀다.

| 노하우 | 1DAL |
|---|---|
| 🔴 **km당 단가는 거리에 반비례** — 장거리를 km당 고정 기준으로 재면 좋은 콜을 못 알아본다 (*"직선 200km 에 km당 1,000원짜리는 은퇴할 때까지 못 본다"*) | 🔴 앱 단가식(`ratePerKm`)이 **거리 무관 고정** → 🔧 거리 구간별 보정 |
| 🔴 **판단의 제1 기준은 «오더 하나의 시간당 효율»** — 확정~완료 소요시간으로 나눈다. 하루 시급이 아니다 (일이 끊기는 특성과 안 맞는 계산). 성남→강릉 10만/3시간 = 3.3만/h → 잡는다 | ✅ **판정 «돈» 축이 정확히 이 계산** (돈 ÷ 분·`꿀 70/보통 40`) — 교차 검증됨 |
| 🔴 **합짐의 손익분기** — 같은 6만 원 묶음도 90분이면 효율↑ · 2시간이면 제자리 · **대기 포함** 3시간이면 효율↓. 대기·픽업·완료 시간을 전부 센다 | ✅ 우회 비용 순위 / 🔧 **«다음 합짐을 기다린 시간»도 비용인가** — 상차지 버퍼와 견줄 것 |
| **나쁜 효율로 피크 타임을 태우는 것이 진짜 손해** — 매출 총액이 늘어도 | 🔧 판정에 시간대(피크) 가중 없음 — §5 «파도»와 같은 데이터 |
| **합짐보다 «하나씩 빠르고 정확하게»가 선행** — 합짐 강박이 무리한 픽업·붙잡고 대기를 만들면 독 | ✅ 서버는 순위만, 결정은 기사님 (규칙 ①) |
| 🔴 **자동배차 운용 원리** — 픽업거리·금액 **둘만** 걸고 항시 ON → 뜬 콜은 이미 기준 통과 → **«갈지 안 갈지»(방향·동선)만** 판단, 판단 시간 반감 | ✅ **우리 구조 그대로** — 느슨한 1차 필터(요금·상차거리) + 경로 순서·판정. 교차 검증됨 |
| 빈차면 웬만하면 잡고 출발 → 달리며 거르다 보면 *«안 가져가면 안 될 것»* 이 뜬다 — 그게 합짐 | ✅ 첫짐→합짐 국면 모델과 일치 |
| 🔴 **자동배차는 집 앞 주차까지 끄지 않는다** — 만차여도 복귀길 **예약콜·야간상차**가 걸린다 | ⚠️ 우리는 **적재 만석이면 콜 잡기를 끈다**(`capacityFullHold`) — 예약콜(하차 후 실을 짐)은 지금 못 받는다 → 🔧 검토 |
| 지지기(매크로)의 상한 — 강제확정→취소 반복, **취소 5회당 노출 30초 지연** 페널티 | ✅ 안전취소 카운트를 세는 이유 · 알람 모드의 존재 이유 |
| 낀 빨간날(연휴 아닌 공휴일)은 물량 기대 낮음 — 묶으려 기다리지 말고 수도권 방향으로 이동하며 하나씩 빠르게 | — 달력 감각. §5 시간대 데이터에 요일·공휴일 축 |

## 🔧 여기서 나온 기획 후보

- **후속 콜 빈도** — 첫짐의 «뒤에 더 뜰까» 를 데이터로
- **지역 × 시간대 콜 패턴** — 파도와 갇힘을 답한다
- **긴급도** — 적요에서 읽어 시한을 예산으로 바꾼다
- **통화 타이밍 알림** — 셋 중 지금이 언제인가
- **`places` 에 한 줄** — 통화 필요 여부 · 기피 · 점심시간
- **단가식 거리 보정** (ep14) — km당 단가 하한을 거리 구간별로 낮춘다. 장거리 꿀콜이 지금 요금 축에서 억울하게 떨어질 수 있다
- **만석에도 예약콜은 받기** (ep14) — `capacityFullHold` 가 «지금 실을 수 없음»과 «앞으로도 못 받음»을 한 값으로 답하고 있지 않은지 (⑤-4 ⑤ «누가 읽는가»)
- **대기 시간의 비용화** (ep14) — 합짐을 기다린 시간이 판정에 비용으로 들어가는가
