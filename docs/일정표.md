## 0. 🔴 먼저 — 임계 경로는 **코드가 아니라 사업자다**

지금까지 시험한 배차망은 **전부 우리가 만든 시뮬레이터**다. 실제 인성콜·화물24 화면은
**한 번도 본 적이 없다** — 사업자가 없어 앱을 설치할 수 없기 때문이다.

그래서 이렇게 된다.

```
사업자 등록 → 배차망 가입 → 실제 화면 확보 → 파서 검증 → 실전
                                    ↑
                        여기 없이는 ①번을 고쳐도 실전에서 또 막힐 수 있다
```

🔴 **1회차 최대 문제(①콜 카드가 빈 껍데기)는 "화면을 어떻게 읽나" 다.**
우리 시뮬 화면에 맞춰 고쳐도, **실제 화면이 다르게 생겼으면 헛일**이다.

## 3. 🔴 9월을 어떻게 시작하나 — **"완성 후 시작"이 아니다**

앱이 다 되고 나서 일을 시작하는 그림은 **성립하지 않는다.**

- **실제 배차망 화면 없이는 파서를 못 고친다**
- **실전 콜 없이는 판정 기준을 못 맞춘다** (지금 요율·거리는 전부 시뮬 값이다)
- 규칙 ① 대로 **기사님이 결재**하는 구조라 처음엔 어차피 손이 간다

그러니 **일을 하면서 앱을 키운다.** 순서는 **신뢰를 단계로 넘긴다.**

| 단계 | 앱이 하는 일 | 기사님이 하는 일 | 넘어가는 조건 |
|---|---|---|---|
| **0** | **보기만 한다** (MANUAL) | 평소대로 손으로 다 한다 | 실제 화면을 파서가 **읽는지** 확인 |
| **1** | 콜을 **올려만 준다** | 기사님이 고르고 잡는다 | 올라온 콜이 **쓸 만한지** — 헛것이 적은지 |
| **2** | **색을 붙인다** | 색을 참고해 고른다 | 색이 **맞는지** — 며칠 대조 |
| **3** | **자동으로 잡는다** (AUTO) | 결재만 | 색을 믿을 수 있을 때 |

🔴 **0단계가 9월 1일이다.** 앱이 완벽해서가 아니라, **실제 화면을 봐야 다음이 열리기 때문**이다.
그날 얻는 것은 매출이 아니라 **실제 화면 표본**이다.

⚠️ **각 단계는 "며칠 해 보고" 넘어간다.** 안 되면 한 단계 내려온다. 되돌아오는 것이
   실패가 아니다 — 되돌아올 수 없게 만드는 것이 실패다.
