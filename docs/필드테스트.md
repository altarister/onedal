### 🔴 발견 1 — 콜 카드가 **빈 껍데기**로 잡힌다 (최우선)

`💸 [요금 못 읽음]` 뒤가 **공백**이다. 요금을 못 읽은 게 아니라 **카드에 글자가 하나도 없다.**
한 번 스캔에 **약 30개**씩 빈 카드가 나온다 (12,467 ÷ 413).

```kotlin
// InsungParser.kt:500  groupListNodes
val fareNodes = allNodes.filter { it.text.matches(차종정규식) }  // 차종 글자로 카드를 찾고
val rowNodes  = allNodes.filter { y좌표가 겹치는 것 }             // 같은 줄 글자를 묶는다
```

**필터가 나쁜 게 아니었다. 필터까지 갈 기회조차 없었다.**

가설(미확정): ① `rect` 가 비어 y 비교가 아무것도 못 고른다 ② 정규식이 화면의 딴 글자에
걸려 가짜 카드를 만든다 ③ 웹뷰 스크롤로 노드가 재사용되며 좌표가 어긋난다.

→ 확인하려면 **그룹의 좌표와 원본 노드 수**를 로그에 같이 남겨야 한다.
  지금 로그는 *"비었다"* 까지만 말하고 *"왜 비었나"* 는 안 말한다.

### 🔴 발견 2 — 관제앱은 **평상시를 안 남긴다** (사건만 남긴다)

주행 시간대 `Capacitor/Console` **0줄**.

처음엔 *"관제앱이 로그를 안 남긴다"* 로 읽었는데 **절반만 맞았다.** 확인해 보니:

- `logRoadmapEvent` 는 **조건 없이 `console.log`** 를 부르고,
  Capacitor 웹뷰의 `console` 은 **그대로 logcat 에 `Capacitor/Console` 로 찍힌다.**
  (그날 낮 `⚠️ [계약 불일치]` 경고가 실제로 그렇게 찍혔다) → **길은 열려 있다**
- 부르는 자리도 **34곳**이나 된다

**그런데 그 34곳이 전부 "사건" 이다.**

```
order-evaluating · order-detail-received · order-evaluated   ← 콜이 잡혀야 찍힌다
KEEP · CANCEL · 국면 전환 · 필터 저장 · 지도 버튼            ← 눌러야 찍힌다
```

그날 콜은 **1건** 잡혔고 그마저 안전취소됐으며, 운전 중이라 **버튼을 안 눌렀다.**
그래서 **찍을 일이 없었다.** 0줄은 로그가 죽어서가 아니라 **아무 일도 안 일어나서**다.

## 3-2. 무엇이 좋아지나

- **재현된다.** *"그때 그 자리에서 이상했다"* 를 **같은 좌표로 다시** 돌릴 수 있다
- **채점이 된다.** 지금은 로그를 사람이 읽어야 알지만, 정답이 적혀 있으면
  **몇 점인지 자동으로** 나온다. 회차끼리 비교도 된다
- **국면을 시험한다.** 같은 콜이 갈 때는 떨어지고 올 때는 잡히는지 —
  **위치를 안 쓰면 물어볼 수 없는 질문**이다

## 3-3. 🔴 목업이면 실주행이 필요 없나 — **아니다. 둘은 다른 것을 잡는다**

기사님이 마지막에 스스로 던지신 질문이 이 설계의 핵심이다.

| | **목업 GPS** (책상) | **실주행** |
|---|---|---|
| 무엇을 잡나 | **로직** — 필터·판정·국면 전환이 옳은가 | **물리** — 그 로직이 진짜 세상에서 도는가 |
| 잡히는 것 | 잘못된 판정 · 국면이 안 넘어감 · 경유 계산 오류 | GPS 튐·끊김 · 음영 구간 · 발열 · **운전 중에 읽히는가** · 배터리 |
| 못 잡는 것 | 위의 오른쪽 전부 | 반복이 안 되어 **원인을 좁히기 어렵다** |
| 얼마나 자주 | **하루에도 여러 번** | 2일에 한 번 |
| 비용 | 0 | 3시간 + 기름 |

**그래서 이렇게 나눈다.**

```
목업으로 매일 돌려 로직을 좁힌다  →  좁혀진 것을 2일에 한 번 실주행으로 확인한다
```

1회차에서 나온 것들을 이 잣대로 보면 갈래가 분명하다.

- **콜 카드가 빈 껍데기** → 목업으로 잡힌다 (화면 읽기 문제라 좌표와 무관)
- **판정을 신뢰할 수 없다** → 목업으로 잡힌다 (같은 콜을 몇 번이고 다시)
- **GPS 튐 · 이벤트 스크롤 · 발열 · 느림** → **실주행에서만** 잡힌다

🔴 **목업은 실주행을 대신하지 않는다. 실주행의 횟수를 줄여 줄 뿐이다.**

## 3-4. 좌표를 어디서 넣나 — 세 갈래

셋 다 **같은 문제지·같은 채점**을 쓴다. 다른 것은 **좌표의 출처**뿐이다.

| 갈래 | 좌표 출처 | 언제 쓰나 |
|---|---|---|
| **① 목업 재생** | 미리 그려 둔 경로를 배속으로 재생 | 매일. 로직 시험 |
| **② 서버 중계** | 관제앱이 보낸 **실제 좌표**를 시뮬앱이 서버에서 받아 씀 | 실주행. 지금 구조에 가장 가깝다 |
| **③ 시뮬앱 직접** | 시뮬앱이 폰 GPS 를 직접 읽음 | 실주행. 서버를 안 거쳐 지연이 없다 |

- **②가 유력하다** — 서버가 이미 `driverLocation` 을 들고 있다.
  시뮬앱이 그걸 받아 쓰면 **관제앱·원달앱·시뮬앱이 같은 좌표를 본다**
- ⚠️ ③은 시뮬앱 웹뷰에서 위치 권한을 또 받아야 하고, **셋이 각자 다른 좌표**를 볼 위험이 있다
  (이 레포가 반복해 당한 형태 — 같은 값을 두 곳에서 만들면 갈라진다)

## 3-5. 코드를 짜기 전에 정할 넷 (규칙 ⑤-4)

**하나라도 비어 있으면 시작하지 않는다.**

| | 정할 것 | 비면 생기는 일 |
|---|---|---|
| **① 스키마** | 문제에 트리거를 어떻게 적나 — `{lat, lon, radius, expect}`? 반경은 문제마다 다른가 | 코드 상수로 태어나 영영 못 바꾼다 |
| **② 값** | 반경 기본값은 몇 m 인가 · **근거는 무엇인가** (도심과 외곽이 다르다) | 누군가의 감으로 정해지고 아무도 못 고친다 |
| **③ 시점** | 반경에 **들어올 때 한 번**인가, 머무는 동안 계속인가. 지나쳤다 되돌아오면 다시 뜨나 | 되돌아올 때 같은 콜이 쏟아진다 |
| **④ 화면** | 채점 결과를 **어디서 보나**. 주행 중에도 보이나, 끝나고 보나 | 만들어 놓고 아무도 안 본다 |

## 3-6. 코스 초안 — 광주 → 이천 → 여주 → 광주

기사님 동선이라 **실제 지형과 통신 환경**이 같이 시험된다.

| 구간 | 무엇을 시험하나 |
|---|---|
| 집(초월) 출발 전 | **첫짐** — 잡아야 할 것 하나, 미끼 하나 |
| 광주 → 이천 | **합짐** — 경로 위 상차지 · 경로 밖 미끼 |
| 이천 부근 | **운행 중 합짐** — 경유 반경 안/밖을 나란히 |
| 이천 → 여주 | **적재 한계** — 만차에서 더 들어오는지 |
| 여주 → 광주 | **복귀** — 갈 때 떨어진 콜이 **올 때 잡히는가** (같은 콜, 다른 답) |

🔴 **마지막 줄이 이 설계의 값어치다.** 같은 콜에 **위치에 따라 다른 정답**을 매길 수 있고,
그건 **시간순 문제지로는 물어볼 수 없는 질문**이다.

      채점이 전부 0점이다 — 1회차가 정확히 그랬다

# 4부 · 하드웨어 — 업무용 태블릿 (2026-08-23 검토)

기사님: *"관제앱을 폰에서 꼭 해야 하는 건 아닐 듯한데.. **전화 가능한 태블릿** 같은 건 없나?
그럼 큰 글씨로 많은 정보를 줄 수 있을 듯한데."*
→ *"**지금 쓰는 폰과 업무용 폰을 구분하고 싶어.**"*

## 4-1. 확인한 사실

| | |
|---|---|
| 갤럭시 탭 LTE 통화 | ✅ **된다.** 유심 꽂으면 통화·문자 가능 |
| ⚠️ 요금제 | **데이터쉐어링은 통화·문자가 막혀 있다.** 통화 되는 **단독 요금제**를 넣어야 한다 |
| ⚠️ 통화 방식 | 본체는 **스피커폰만**. 귀에 대려면 이어폰·블루투스 |
| 탭 액티브5 **배터리 없음 모드** | ✅ 사실. 배터리를 빼고 전원만으로 상시 구동 — **차량 고온**에서 셧다운·부풀음을 없앤다 |
| ⚠️ 그 대가 | **9V 2.3A · PD 2.0 이상** 전용 전원 필요 · 이 모드에선 **CPU·밝기·볼륨이 제한**된다 |

> 처음에 *"국내 갤탭은 음성통화가 대개 안 된다"* 고 적었으나 **틀렸다.** 찾아 고쳤다.

## 4-2. 왜 이게 "업무용 분리"와 맞물리나

통화 되는 요금제를 넣으면 **번호가 하나 더 생긴다.** 그게 곧 **업무용 번호**다.

```
개인 폰       개인 통화만 — 화주·사무실이 안 건다
업무 태블릿   관제앱 + 업무 통화 (자체 번호)
A24폰         스캐너 (자체 5G)
```

일이 끝나면 태블릿을 끄면 된다. **기기 수는 그대로인데 개인과 업무가 갈린다.**

⚠️ 차 안에서는 **스피커폰이 오히려 맞다** — 운전 중 귀에 대지 못한다. 블루투스로 차 스피커에 물리면 핸즈프리가 된다.

## 4-3. 🔴 함정 — *"큰 글씨로 **많은 정보**"*

**1~2초 제약은 화면 크기가 아니라 눈에서 온다.** 화면이 두 배가 돼도 곁눈질에 읽히는 것은
여전히 **두세 개**다. 큰 화면의 값어치는 *더 많이 보여주는 것*이 아니라 —

- 같은 정보를 **두 배 크게**
- 버튼을 **두 배 크게**
- 그래서 **더 멀리서, 더 짧게** 봐도 되는 것

정보를 늘리면 **큰 화면을 얻고 1~2초를 잃는다.**

## 4-4. 모델 비교

| | 통화 | 차량 고온·상시전원 | 값 | |
|---|---|---|---|---|
| **탭 액티브5** | ✅ | ✅ **배터리 없음 모드** · 방수방진 | 비쌈 | **차량 상시 거치에 최적** |
| 탭 A9+ (11인치) | ✅ | ❌ | 중간 | 무난 |
| 탭 S9/S10 FE | ✅ | ❌ | 비쌈 | 분할 창은 우리 화면에 과함 |
| 아이뮤즈 K11/K8 | 모델별 — **사양서 확인** | ❌ | 쌈 | 시험용으로는 가능 |

## 4-5. 결론과 순서

**탭 액티브5 가 맞다.** 통화 · 업무 번호 분리 · **여름 대시보드에서 안 죽는 것** 셋을 한 번에 푼다.
다른 모델은 세 번째가 없고, 그게 **여름 내내 매일** 걸릴 문제다.

- [ ] 사기 전 확인 ② **9V 2.3A PD** 차량 충전기
- [ ] 🔴 **①(카드가 빈 껍데기)·②(판정 신뢰)를 먼저 고친다** — 큰 화면에 **틀린 색**을

# 5부 · 왜 느린가 — **느림과 발열은 한 몸이다** (2026-08-23 진단)

기사님: *"근데 우리 관제앱은 왜 그리 느린 거야? 스크랩폰은 좀 늦어도 상관없어서 **post 방식**으로
만들고 관제앱은 빨라야 해서 **소켓 통신**으로 만든 건데.. 완전 실망했어."*
→ *"그래 **넘 뜨거워지더라구.. 그래서 약간 겁났어. 터질까 봐.**"*

## 5-1. 잰 것

```
주행 3시간(19~21시) 동안 웹뷰가 화면을 다시 그린 횟수: 59,679회 = 초당 5.5회
```

(`S23_관제앱_logcat` 의 `setRequestedFrameRate` 를 셌다)

**화면이 한 번도 쉬지 않았다.** 콜이 없어도, 아무 일이 없어도 계속 그렸다.
그게 CPU·GPU 를 계속 돌리고 **그 열이 폰에 쌓였다.**

🔴 **느림 = 발열이다.** 하나를 고치면 둘 다 낫는다.

## 5-2. 🔴 소켓 설계는 틀리지 않았다

```
스크랩폰 → POST   (늦어도 됨)
관제앱   → 소켓   (빨라야 함)
```

**이 판단은 맞았다.** 소켓은 이벤트가 올 때만 일하고, 그날 로그에서도 **소켓은 제때 도착했다.**

**배신한 것은 소켓이 아니라 화면이다.** 소켓이 아무리 빨리 갖다줘도 화면이 이미 자기 일로
바쁘면 그릴 틈이 없다. **기사님이 실망하실 대상은 설계가 아니라 화면 쪽이다.**

## 5-3. 범인 셋

| | 무엇 | 증거 |
|---|---|---|
| **①** | **쉬지 않는 애니메이션 19개** | `animate-pulse` 13 · `animate-spin` 5 · `animate-ping` 1. 하나만 있어도 화면 전체가 계속 다시 그려진다 |
| **②** | **매초 도는 타이머 6곳** | 그중 `Header.tsx` 의 시계 — `setInterval(() => setTime(new Date()), 1000)`. **맨 위**라 매초 그 아래가 다시 그려질 수 있다 |
| **③** | **지도가 상시 떠 있음** | 좌표가 올 때마다 다시 그린다. 그날 GPS 는 초 단위로 들어왔다 |

(첫 로딩이 느린 것은 별개 — `index-*.js` **775KB 단일 번들**)

## 5-4. 고치는 순서 — 싸고 효과 큰 것부터

| | 무엇 | 값 | 효과 |
|---|---|---|---|
| **1** | 상시 보이는 곳의 **애니메이션 걷어내기** | 아주 쌈 | 큼 — 느림·발열 둘 다 |
| **2** | Header 시계를 **분 단위**로 또는 따로 떼어내기 | 쌈 | 큼 |
| **3** | **지도 접기** (⑦과 같은 일) | 중간 | 큼 |
| **4** | 번들 쪼개기 | 중간 | 첫 로딩만 |

🔴 **1·2 만 해도 초당 5.5회가 크게 떨어진다.** 그리고 이것은 기사님이 지적하신
*"화려하기만 하다"* 와 **같은 자리**다 — **화려함을 덜어내면 빨라지고 시원해진다.**
⑤(느림) · ⑥(스크롤) · 발열이 **한 번에** 풀린다.

## 5-5. 다음 주행 전까지 (태블릿 오기 전) 열 줄이기

- **직사광선을 피해** 거치 (대시보드 위보다 송풍구 쪽)
- **에어컨 바람**이 닿게
- **케이스를 벗긴다** — 열이 못 빠진다
- **화면 밝기를 낮춘다** (밝기가 발열의 큰 몫이다)
- 너무 뜨거우면 **충전을 잠깐 뺀다** — 충전 + 고온이 가장 나쁜 조합

> 리튬 배터리는 고온에서 부풀고 드물게 사고가 난다. **겁내신 것이 맞다.**
> 탭 액티브5 의 *배터리 없음 모드*가 이 걱정을 통째로 없애는 이유가 이것이다.

# 6부 · 차 안 배치

기사님: *"관제앱 거치대가 필요하다.. **운전 중 계속 불안했음.**
크롤링앱폰은 **충전만 시키고 어디 숨겨 둬도** 될 듯."*

## 6-1. 🔴 A24폰(스캐너)은 **안 보여도 된다**

기사님이 **볼 일이 없다.** 원달앱은 접근성으로 화면을 읽으므로 **화면만 켜져 있으면** 되고,
그것이 **시야 안에 있을 필요는 없다.**

```
A24폰(스캐너)   전원 + 화면 켬 + 시야 밖      ← 숨겨도 된다
관제 기기       시야 안 · 흔들리지 않게        ← 거치대 필요
```

⚠️ 숨길 때 **열이 빠지는 자리**여야 한다. 콘솔 박스처럼 막힌 곳에 넣고 충전까지 하면
   더 뜨거워진다. **조수석 발밑·시트 옆처럼 트인 곳**이 낫다.
⚠️ 화면이 꺼지면 못 읽는다 — 관제 화면에 `💤 화면 꺼짐` 으로 뜬다.

## 6-2. 거치대 — 태블릿은 조건이 다르다

폰 거치대로는 **탭 액티브5(400g대)를 못 버틴다.** 흔들리면 운전 중 불안이 그대로 남는다.

| 방식 | 태블릿에 |
|---|---|
| 송풍구 | ❌ 무게를 못 버틴다. 날개가 부러진다 |
| **컵홀더 지지대** | ✅ 아래에서 받쳐 **가장 튼튼** |
| **시트레일 볼트 고정** | ✅ 가장 확실. 시공 필요 |
| 대시보드 흡착 | △ 여름 고온에 흡착판이 떨어진다 |

- **컵홀더 방식이 무난하다**
- **1인치 볼헤드(RAM 마운트 규격)** 로 고르면 기기가 바뀌어도 거치대는 그대로 쓴다
- ⚠️ **에어컨 바람이 닿는 위치**로 잡으면 발열까지 같이 잡힌다
