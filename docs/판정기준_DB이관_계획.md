## 2. 🔴 이관 전에 먼저 고쳐야 하는 것

**값을 DB 로 옮겨도 아래 셋이 남아 있으면 색은 계속 틀린다.** 순서를 지킨다.

### 2-1. 같은 판단이 두 곳에 — 재탐색이 자기 숫자를 쓴다

```
최초 평가   똥 = 60분 이상 OR 30km 이상   (dispatchConfig)
재탐색      똥 = 30분 초과 OR 10km 초과   (dispatchEngine.ts:203 에 직접)
```

**같은 콜이 재탐색만 해도 색이 바뀐다.** 이 레포의 반복 실패 그대로다.

### 2-2. 여유가 0 이면 모든 합짐이 똥이 된다

```ts
allowedDetourMinutes:  Math.max(0, Math.min(...known))   // 음수를 0 으로 깎는다
OrderEvaluator:        shitTime = slackLimit ?? 60        // 0 이면 한계도 0
                       → cost.total >= 0  → 언제나 똥
```

2026-08-15 실측: 요금 99,000원 · 우회 **+1.1km** · 주행 **+6분** 짜리가 🟡 로 떴다.
**0 은 "한계 0분"이 아니라 "모른다"이다.**

### 2-3. 모르는 값을 불리하게 잡는다

`DWELL_UNKNOWN_MINUTES = 20` 의 주석이 *"낙관하지 않는다"* 라고 **비관을 명시**한다.
상차 20 + 하차 20 = 40분이 주행 시간에 더해진다.

실제 신고 데이터: **수작업 44건 · 지게차 12건 — 78% 가 수작업(15분)** 이다.
20분은 수작업보다 높고 호이스트와 같다. → 규칙 ⑤-2 *"모르는 값은 **일반값**으로 계산하고
'미확인'으로 표시한다"*.

## 3. 스키마 설계

### 3-1. 컬럼을 11개 늘리지 않는다 — **JSON 한 칸**

명세 §2-4-7 이 이미 정한 방식이다: *"DB 컬럼을 3×5=15개로 늘리지 않는다.
`vehicle_rates` 와 같은 방식으로 JSON 한 칸이다."*

```sql
ALTER TABLE user_filters ADD COLUMN judgment_config TEXT;   -- JSON (v9)
```

같은 그릇에 두는 이유: 판정 기준은 **"오늘만" 바꿀 수 있어야** 한다
(오늘은 급하니 빡빡하게 / 한가하니 느슨하게). `user_filters` 는 이미
`baseFilter`(DB·평소) ↔ `activeFilter`(메모리·오늘) 두 그릇 구조를 갖고 있다.

### 3-2. 모양

```ts
export interface JudgmentConfig {
    solo:  { honeyMaxMin: number; shitMinMin: number };
    merge: { honeyMaxMin: number; honeyMaxKm: number; shitMinMin: number; shitMinKm: number };
    /** 모르는 값을 채울 **일반값** — 불리한 값이 아니다 (규칙 ⑤-2) */
    unknown: { dwellMin: number; slackMin: number };
    /** 방법별 정차 시간 */
    dwell: { base: Record<string, number>; perPoint: Record<string, number> };
}
```

### 3-3. 어디로 내려보내는가

| 대상 | 보내나 | 왜 |
|---|---|---|
| 앱(피기백) | ❌ | **앱은 색 판정을 하지 않는다.** 규칙 ⑤-1 — 앱은 `요금 ≥ 거리 × 단가` 만 본다. 규격을 안 건드리므로 **재설치 불필요** |
| 관제웹(소켓) | ✅ | `filter-updated` 페이로드에 `judgment` 를 형제로 추가. 화면이 기준을 보여주고 고칠 수 있어야 한다 |

`AutoDispatchFilter` 평면은 **건드리지 않는다** — 그건 앱 규격이다.

### 3-4. 화면

필터 설정 팝업에 **판정 기준** 섹션(공통 · 탭 밖 — 다섯 국면 공통이므로 제외 단어와 같은 자리).
읽기 전용이 아니라 **편집 가능**하게 두되, 저장은 기존 `오늘만` / `계속` 버튼을 그대로 쓴다.

## 4. 단계와 증명

각 단계는 **어느 등급까지 갔는지** 함께 적는다 (L1 규칙 · L2 값 · L3 시나리오 · L4 실물).

| # | 무엇 | 증명 |
|---|---|---|
| **1** | 재탐색의 자기 숫자 제거 → `dispatchConfig` 하나로 | L1 판정 임계값을 읽는 곳이 한 곳 · L2 같은 입력에 같은 색 |
| **2** | 여유 0 버그 — 0 을 "모름"으로, 폴백은 `slackMin` | L2 여유 0/음수/미확인 세 경우 · **L4 `+1.1km` 콜이 🔵** |
| **3** | 일반값으로 교체 (`dwellMin` 20 → 15) | L2 · 화면에 `미확인` 배지 |
| **4** | `judgment_config` 컬럼 + 기본값 시드 | L3 부팅 스모크 (기존 DB 사본) |
| **5** | 코드 상수 → DB 값 읽기 (`?? 리터럴` 폴백 금지) | L1 상수를 직접 읽는 곳이 없다 |
| **6** | 관제웹 소켓 전달 + 팝업 섹션 | L1 소켓 계약 · 눈으로 확인 |

**1~3 은 값 이관 없이도 색을 고친다.** 4~6 은 그 값을 기사님이 바꿀 수 있게 만드는 일이다.
급한 것은 1~3 이다 — 지금 이 순간에도 꿀콜이 똥으로 표시되고 있다.
