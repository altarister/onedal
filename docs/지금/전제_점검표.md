## 🔴 뒤집힌 것 넷

### ① #4 — **3콜은 상한이 아니다**

> *"내 시간적, 적재함 공간적 여유가 맞으면 **최대한 많이 합짐하면 매출이 많아진다.**
> 통화로 상하차 시간을 미루는 약속을 하고, 오토바이 콜이 많다면 공간적인 여유가 많아진다."*

**상한을 정하는 것은 «3»이라는 숫자가 아니라 «시간 여유»와 «공간 여유» 둘이다.**
그리고 **둘 다 늘릴 수 있다** — 시간은 통화로, 공간은 작은 콜로.

🔴 **내가 세운 «한 판 = 3콜 = 경유 5개» 유도가 깨진다.** 4콜이면 경유 7개, 5콜이면 9개다.

⚠️ **여기서 «그러니 한 구간씩 보내는 게 유일한 답»이라고 적었는데 그것도 뒤집혔다**
   (같은 날 저녁). 기사님: *"매번 내비를 찍는 것이 기사에게 너무 부담스러울 것 같아."*
   폰에서 재 보니 **카카오내비가 경유 3개를 받고 물방울까지 찍혔다** — 12동작이 4동작이 됐다.
   👉 지금 답: **경유 3개씩 보낸다.** 한 판이 3콜을 넘으면 나눠 보낸다
   ([경로.md](../기획/경로.md) §4-1).

그리고 자동 재호출에는 **비용**이 있다 — 달리는 중에 **지도 선이 갑자기 바뀐다.**

👉 **내 안: 안 만든다.** 09-03 에 요청하신 **새로고침 버튼**만 두면 필요할 때 누르시면 된다.
   실주행에서 거슬리면 그때 만들어도 늦지 않다. — **이대로 갈까요?**

## ⏳ Q9 — 풀어 쓰면 이런 것이다 (기사님 판단 대기)

「1판/2판」은 내가 만든 말이라 안 통했다. 풀어 쓰면 둘이었다:

```
뺄셈    관제웹이 GPS 마다 「선 위 남은 거리」를 다시 재서 상태바 분을 갱신
        → 서버도 카카오도 안 건드린다
재호출  벗어나면 서버가 카카오에 다시 물어 선을 새로 받는다   ← Q8 에서 «안 만든다»
```

**Q8 이 «안 만든다»로 정해지면 남는 것은 뺄셈 하나뿐이라 나눌 게 없어진다.**
→ **Q9 는 Q8 에 딸린 물음이다.** Q8 을 정하시면 함께 정해진다.

**뺄셈이 고치는 것** — 지금 상태바는 *"카카오에 물어본 그 순간부터의 누적"* 을 적는다.
30분을 달려도 `~30분` 그대로다. 뺄셈이 들어가면 GPS 마다 줄어든다.

## 🔴 Q12 — 설정값을 또 물었다

> 기사님: *"상차 반경은 사용자가 설정창에서 바꾸는 건데 **왜 자꾸 너가 신경써!!!**"*

이 문서 맨 앞에서 **A(사실)과 B(설정값)를 갈라 놓고**, 설정값을
「내가 답을 못 찾은 것」에 **또 넣었다.** 두 번 같은 잘못이다.

### 🔴 그런데 잘못이 한 칸 더 앞에 있었다

> 기사님: *"이걸 **너가 어떻게 올릴 건데?** 코드에 상수로 넣는다는 거야?"*

**내가 할 수 있는 길이 셋인데 셋 다 틀렸다:**

| 할 수 있었던 것 | 왜 틀린가 |
|---|---|
| 코드에 상수로 | **규칙 ⑤-4 ① 위반** — 박히면 기사님이 못 바꾸신다. 이 레포가 *"지금 판정 기준 11개가 그렇다"* 고 경고하는 그것 |
| DB **기본값**을 15 로 | 기사님 행은 **이미 10** 이다. 기본값은 행을 새로 만들 때만 쓰여 **아무 일도 안 일어난다** |
| 기사님 행을 UPDATE | **기사님 설정을 내가 덮어쓰는 것**이다 |

**답을 들어도 내가 할 일이 없거나 규칙을 어기는 것뿐이었다.** 그러면 질문이 아니다.

### 👉 그래서 규칙 둘

**① 질문을 만들기 전에 «답을 들으면 내가 무엇을 하는가»를 먼저 본다.**
   할 일이 없거나 규칙을 어겨야 한다면 **그건 질문이 아니라 잡담이다** — 기사님 시간만 쓴다.

**② 설정값은 묻지 않는다.** «지금 얼마인가»는 DB 를 읽으면 되고,
   «얼마여야 하나»는 **기사님이 설정창에서 정하시는 것**이다.

**설정값에 대한 내 몫은 따로 있다** — *"그 값이 실제로 돌아가게 잇는 것"*:
```
지금       기사님이 「유료도로 회피」를 켜도 → 카카오 URL 에 안 실린다 (아무 일도 안 일어남)
내 일      그 설정값을 실제 동작에 잇는다
```

# 5부. 이 문서를 어떻게 쓸 것인가

**«다음에 내가 틀린 전제로 판을 짜기 전에 여기서 걸리는 것»** 이다.

# 7부. 아키텍처 상식과 다른 시스템 전제 및 저장소 경계

엔지니어가 통상적인 웹/앱 개발 상식대로 짰을 때 시스템과 충돌을 일으키는 구조적 특이점 목록이다.

| 전제 (상식) | 실제 1DAL 구조 | 어기면 터지는 사고 | 올바른 접근법 |
|---|---|---|---|
| **세션에 기기 정보가 들어있다** | 사용자 세션(`UserSession`)과 기기 세션(`DeviceSession`)은 물리적·메모리상 완전히 분리되어 있다. | `session.devices.get()` 호출 시 `TypeError` 발생, 배차 판정 및 토스트 팝업 마비 | 기기 모드는 `getDeviceMode(deviceId, userId)`를 통해서만 접근한다. |
| **단위 테스트 통과 = 렌더링 무결점** | 관제탑(`client-app`) 다수 테스트가 소스 정규식 검사나 로직 검사에 의존하여 가상 DOM 마운트를 생략한다. | 미선언 변수(`ReferenceError: filterAlarm`)가 720개 테스트를 통과하고 브라우저 화면이 하얗게 멈춤 | 핵심 UI 수정 시 마운트 스모크 테스트와 브라우저 육안 확인 필수 |
| **호출하는 곳에서 알아서 취소 판단** | 취소 발생 경로가 5가지에 달해 호출부마다 분기하면 누수가 발생한다. | 가상 콜 취소 시 실제 기사의 10회 취소 페널티가 차감되고 DB에 유령 취소건 기록 | 모든 취소·유지 로직은 `core/cancelCount.ts` SSOT 내부에서 처리 |
| **메모리에 콜이 있으면 DB에도 있다** | 가상/체험 모드 콜은 RAM(`myOrders`)에만 존재하고 SQLite `orders` 테이블에는 저장되지 않는다. | 마일스톤 생성(`birthFirstStep`) 등 DB 조회를 호출하면 외래키/조회 예외 연쇄 폭발 | DB 작업 수행 전 반드시 `!isSimulated` 조건으로 격리 가드 |
| **소켓 이벤트는 필요한 곳에서 듣는다** | 동일 소켓 이벤트를 여러 훅/컴포넌트에서 직접 리슨하면 상태 불일치와 메모리 누수가 발생한다. | `audit:socket` 멀티 리스너 계약 위반 빨간불 발생 | 소켓은 단일 리스너가 듣고 Zustand 전역 스토어 구독으로 데이터 전파 |
