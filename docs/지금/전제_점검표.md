### Q1 · Q2 — **금액은 이미 판정 색을 바꾸고 있다**

`shared/src/criteria.ts` 의 `MONEY` 기준:
```

점수   = hourly ÷ 목표시급(30,000) × 100
```
가중치 `revenueDetour = 1.0` 이고 `CRITERIA` 에 들어 있으니 **색에 그대로 반영된다.**
👉 **Q1 ○ · Q2 ○ — 이미 그렇게 동작한다.**

🔴 **그럼 무엇이 문제였나** — CLAUDE.md ⑤-1 의 **전제 문장**이다:
   *"앱이 요금 ≥ 배송거리 × 단가로 이미 통과시킨 콜만 올라온다"*.
   기사님 말씀대로 **알림·직접 콜은 앱 필터를 안 거친다** — 그 전제가 참이 아니다.
   👉 고칠 것은 «금액을 보느냐»가 아니라 **«왜 보느냐»의 설명**이다 (4부 7번).

### Q4 · Q5 — **데드라인은 코드에 있다**

`shared/src/judgment.ts` 의 `callDeadlineMs`:
```
데드라인 = 상차 완료 시각 + (상차지→하차지 주행 × 150%)
```
`soloDriveMin` 이 «그 콜 혼자 갈 때의 주행»이라 **상차지→하차지가 맞다.**
기산점이 **상차 완료**인 것은 [용어집](용어집.md) 에 기사님 확정으로 적혀 있다(2026-08-21).
👉 **Q4 ○ · Q5 ○** — 기사님이 쓰신 *"주행시간 × 150%"* 는 **허용치 부분**이고, 코드가
   그걸 상차 완료에 더한다. 같은 말이다.

🔴 **대신 CLAUDE.md 가 낡았다** — ⑤-5 에 *"하차 마감 = 상차 마감 + 주행 + 30분"* 이 있는데,

   라고 적고 있다. **60분 주행에서는 우연히 같고**(60+30 = 60×150%) 30분에서는 갈린다
   (+60 vs +45). 👉 4부 8번.

| 8 | 🔴 ⑤-5 의 **「하차 마감 = 상차 마감 + 주행 + 30분」을 뺀다** — 코드가 「폐기됐다」고 적고 있다. 지금 원천은 데드라인(상차 완료 + 주행×150%) | CLAUDE.md ⑤-5 | ⬜ |

# 5부. 이 문서를 어떻게 쓸 것인가

🔴 **한 번 찍고 끝이 아니다.** 값어치는 «지금 맞추는 것»이 아니라
**«다음에 내가 틀린 전제로 판을 짜기 전에 여기서 걸리는 것»** 이다.

👉 **판을 시작할 때** — 기획서 맨 앞에 «이 판이 참이라고 보는 전제»를 적고
   이 문서의 번호를 가리킨다. 표에 없는 새 전제면 **여기에 줄을 하나 더한다.**

⚠️ **이걸 해도 다 안 나온다.** 내가 «묻지 않은 것»은 목록에도 없다.
   그래도 하나씩 부딪히는 것보다 낫다.
