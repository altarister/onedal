# 필터 — 콜을 집기 전에 거르는 것

> **필터는 «무념(無念)의 하루»를 만드는 자동 문지기다.**
> 기사님이 매 콜을 읽고 판단하지 않아도 좋은 콜만 올라오고 나쁜 콜은 걸러지는 상태 — 그게 완성형이다.
>
> 🔴 **필터는 «집기 전», 판정은 «집은 뒤»다.** 둘은 완전히 격리되어 각각 따로 작동한다.
> 판정은 [판정 문서](판정.md)에 있다. 말의 원천은 [용어집](용어집.md).

---

## 1. 무엇을 위해 있나

> *"돈 많이 벌려면 **높은 단가의 최적의 경로 콜을 많이 수행**해야 한다."*

이 한 문장을 풀면 필터가 지켜야 할 다섯이 나온다.

| | 조건 |
|---|---|
| ① | **단가 중간 이상** — 싼 콜을 안 올린다 |
| ② | **짐 많은 지역을 향해** — 첫짐은 방향 선택이다 |
| ③ | **길 위의 짐을 최대 합짐** — 가는 길에 가까운 짐을 최대한 |
| ④ | **약속을 지키는 한도 안에서** — 상차 시계와 배달 마감 |
| ⑤ | **내 차 공간 안에서** — 라면박스 100칸 |

**느슨하게 올리고 정밀하게 구분한다** (규칙 ⑤). 앱은 애매하면 올리고, 서버가 판정에서 가른다.
확실히 불가능한 것만 거른다.

## 2. 두 그릇 — 서로 남남이다

```
baseFilter    DB · 평소 설정          saveBaseFilter()      DB 만 건드린다
activeFilter  메모리 · 오늘의 콜 필터  updateActiveFilter()  메모리만 건드린다
```

로그인할 때 `base → active` 로 **1회 복사**되고, 그 뒤로는 격리된다.
설정을 바꿔도 진행 중인 콜 잡기가 안 흔들리는 이유가 이것이다.

🔴 **`오늘만` 버튼은 필터에만 있다.** 판정 기준에는 없다 — 바꾸면 계속 적용된다.

🔴 **파생값은 `filterManager` 한 곳에서만 만든다.** 호출부는 **입력만** 넘긴다
(`destinationCity` · `destinationRadiusKm`). 키워드를 직접 채워 넘기면
`recalculateDerivedFields` 가 자기 계산을 건너뛰어 **다른 파생값이 안 채워진다.**

## 3. 국면 다섯 — 옵션의 원천

콜 필터는 **국면(phase)마다 한 벌**이다. 행 = (사용자, 국면).

```sql
user_filter_phases (
    user_id, phase,              -- phase ∈ first · merge · drive · local · home
    destination_city,            -- 도착 목표
    pickup_radius_km,            -- 상차 반경 (km)
    detour_allow_km,             -- 우회 허용 (km)
    dropoff_radius_km,           -- 하차지 주변 (km)
    discount_pct                 -- 콜할인율 (%)
)
```

### 국면마다 보이는 칸이 다르다

`PHASE_FIELDS` 가 유일한 원천이다 — **화면이 이걸 읽어 그리고, 서버도 이걸로 «그 국면에서 안 쓰는 값»을 판정에서 뺀다.**

| 국면 | 도착 목표 | 상차 반경 | 우회 허용 | 하차지 주변 | 콜할인율 |
|---|---|---|---|---|---|
| **first** 첫짐 | 입력 | 입력 | 숨김 | 입력 | 입력 |
| **merge** 합짐 | 자동 | 숨김 | 입력 | 입력 | 입력 |
| **drive** 주행중 | 자동 | 숨김 | 입력 | 숨김 | 입력 |
| **local** 관내 | 덮어쓰기 | 숨김 | 숨김 | 숨김 | 입력 |
| **home** 복귀 | 자동 | 숨김 | 입력 | 숨김 | 입력 |

- **자동** = 첫짐에서 상속한다. **보이되 못 고친다** — 안 보이면 화면이 조용히 거짓말한다
- **덮어쓰기** = 자동값이 있지만 이 국면에서만 바꿀 수 있다
- 노선인 동안 목적지는 안 바뀌므로 따로 저장하지 않는다 (규칙 ③)

### 국면의 닻

```
첫짐   작업 시작 지역/방향        신림에 있어도 가산 콜을 잡는다
합짐   지금 경로
복귀   최종 하차지 기점            현위치가 아니다
공통   상차 시계
```

## 4. 세 축 — 금액 · 시간 · 짐

필터는 **금액·시간·짐** 셋을 본다.

### 금액

```
통과 = 요금 ≥ 배송거리 × 단가(차종) × (1 − 콜할인율)
```

- 하한 입력이 없다. **단가표(DB) × 콜할인율에서 파생**된다
- 단가의 원천은 DB(`user_filters.vehicle_rates`). 코드 상수는 폴백이다
- **콜할인율은 자동으로 안 내려간다** — 콜의 주인은 기사님이다
- `100%` = 금액 무관(순증 매출). 합짐·관내·복귀합짐이 그 자리다

### 시간

상차 시계 안에 닿을 수 있는가. **지금은 `pickup_radius_km`(km) 로 잰다.**
분(分) 축으로 바꾸는 일은 §8 에 있다.

도달 시간을 반경으로 바꾸는 함수는 있고, **판정의 딱지에만 쓴다** — 거르는 데는 안 쓴다.

```
reachRadiusKm(분) = 분 ÷ 계수        계수 잠정 1.5분/km
```

🔴 **계수가 근거 없는 값이라 콜을 떨어뜨리지 않는다.** 실측 표본(`reach_samples`)이
쌓이면 역산해 확정하고, 그때 이 상수는 판정 기준처럼 DB 칸으로 올라간다.
역산 보고서는 `pnpm reach`.

### 짐

적재 여유(라면박스) 안에 들어가는가.

```
1t 100박스 · 1t짐 80 · 라보 40 · 다마스 30 · 승용차 5
```

## 5. 앱이 실제로 거르는 여섯 축

앱은 콜을 **집기 전에** 여섯을 다 본다. **전부 AND 이고 중간에 멈추지 않는다** —
어느 축에서 몇 개가 떨어졌는지를 세야 *"이 축을 풀면 몇 개가 들어오나"* 를 읽을 수 있다.

| 축 | 무엇 |
|---|---|
| `vehicle` | 차종이 맞는가 |
| `region` | 도착지가 목표 안인가 |
| `fare` | 요금 ≥ 배송거리 × 단가 |
| `pickup` | 상차지가 반경 안인가 |
| `blacklist` | 제외 단어가 있는가 |
| `routeOrder` | 경로 순서 — 역주행이 아닌가 |

🔴 **한 콜은 «첫 번째로 걸린 축»에만 센다.** 다 세면 합이 본 수를 넘어 뜻을 잃는다.
그릇(`FilterTally`)은 **호출자가 만들어 넘긴다** — 파서 안에 두면 갱신 시점이 호출 순서에 달린다.

---

## 6. 취소 예산 — 한 판 10회

취소는 **리셋 없는 예산**이다. 페널티는 피할 수 없는 영업 비용이고, 관리할 것은 **빈도**다.

- **한 판 = 10회** (`CANCEL_BUDGET_PER_ROUND`), 배차망별로 따로 센다
- 다 쓰면 **토스트로 알리고 새 판**을 연다
- 🔴 **총량은 사라지지 않는다** — 판수가 남는다. `3/10 · 2판째` = 지금까지 13회
- 리셋 시각만 저장한다 (`cancel_budget_resets`). 카운트는 `orders` 에서 센다 (규칙 ③)

**소진 속도가 «필터를 조여라»의 신호다.** 그래서 화면에 상시 뜬다.

⚠️ 카운터에 들어가는 것은 **안전취소뿐**이다. 취소 세 갈래는 [용어집 §2-1](용어집.md).

## 7. 성과 기록 — 이 설정이 얼마를 벌었나

영업일이 넘어갈 때(자정) 어제치를 **1회** 집계한다.

```sql
filter_day_results (
    user_id, day,
    settings,     -- 그날 국면 설정 스냅샷
    revenue,      -- 그냥 매출 (관제앱은 업무 단위 — 정산 아님)
    calls,        -- 완료 콜 수
    cancels,      -- 취소 소진 (망별)
    colors        -- 판정 색 분포
)
```

콜할인율을 감이 아니라 **성과로** 정하기 위한 재료다. 화면은 운행일지(logbook)에 있다 —
관제앱은 1~2초 결재 화면이라 여기에 안 둔다.

---

## 8. 수집 — 흘려보낸 콜도 모은다

`intel` 표에 **잡을 콜만이 아니라 떨어뜨린 콜까지** 쌓는다.
지역 × 시각 × 요일 × 계절의 콜 수급 지도가 목표다.

🔴 **지금은 수집과 기록까지만 한다.** 필터 자동 조정은 데이터가 쌓인 뒤의 일이다 —
콜할인율 수동 원칙과 같은 줄기다.

---

## 9. 모니터링 — 무엇이 실제로 돌고 있는가

지금 앱에 내려가 있는 필터 값이 관제웹에서 **항상 보인다.** 파생값(도달 반경·키워드·단가표)도
원값과 함께 보인다.

이 레포가 반복해서 당한 사고(*"고쳤다고 생각했는데 옛 값이 돌고 있다"*)의 필터판 방어다.

🔴 **빈 필터는 «제한 없음»이 아니라 «고장»이다.**
🔴 **`destinationKeywords` 를 넘길 땐 `customCityFilters` 도 같이** 넘긴다. 안 넘기면 옛 별칭이 남아 멀쩡한 콜을 조용히 거른다.

## 10. 어디를 고치나

| 무엇 | 어디 |
|---|---|
| 국면 옵션 칸 목록 (라벨·단위·범위·근거) | `shared/src/phases.ts` — `FILTER_FIELDS` |
| 국면별 노출 규칙 | 같은 파일 — `PHASE_FIELDS` |
| 도달 계수 · 반경 환산 | 같은 파일 — `REACH_COEF_MIN_PER_KM_TEMP` · `reachRadiusKm()` |
| 취소 한 판의 크기 | `shared/src/index.ts` — `CANCEL_BUDGET_PER_ROUND` |
| 파생값 만드는 곳 | `server/src/services/filterManager.ts` |
| 앱의 여섯 축 판정 | `onedal-app/…/plugins/insung/InsungParser.kt` — `shouldClick()` |
| 성과 조회 | `server/src/routes/logbook/filterDays.ts` |
| 화면 (국면 5탭) | `client-app/…/dashboard/OrderFilterModal.tsx` |
| 요약줄 | `client-app/…/dashboard/OrderFilterStatus.tsx` |

### 검사

```
tests/rules/phaseSettings.test.ts        국면 값이 저장·복원되는가
tests/rules/phaseApply.test.ts           국면 전환 때 값이 적용되는가
tests/rules/phaseUi.test.ts              PHASE_FIELDS 대로 그려지는가
tests/rules/filterPhaseRows.test.ts      DB 행 ↔ 설정 왕복
tests/rules/filterTally.test.ts          축별 탈락 수를 한 번만 센다
tests/rules/destinationSurvivesPhase.test.ts   도착 목표가 국면 전환에 살아남는가
tests/rules/cancelBudget.test.ts         한 판 10회 · 판수 누적
tests/rules/filterHunt.test.ts           🔴 빈 필터로 콜 잡기가 나가는 것을 막는다
```

⚠️ `jest` 결과는 **`Test Suites:` 줄까지** 본다. 컴파일이 안 되는 검사 파일은 실패가 아니라
**«없는 것»** 이 된다 — `filterHunt.test.ts` 가 실제로 이틀간 조용히 죽어 있던 적이 있다.

## 11. 아직 없는 것

| 무엇 | 지금 | 남은 일 |
|---|---|---|
| **시간 축** | 상차 반경이 `km` 입력 | `pickup_reach_min`(분) 칸을 얹고 반경을 파생으로. 계수 확정이 선행 |
| **도달 계수** | 잠정 `1.5분/km` — 거르는 데 안 씀 | `reach_samples` 20건+ 모아 1차식 적합 → 기사님 확정 → DB 칸으로 승격 |
| **`min_fare` · `max_fare`** | `user_filters` 에 칸이 남아 있음 | 화물24 파서에 단가식을 넣은 뒤 폴백으로 강등. **DTO 필드는 남긴다** — 지우면 앱이 fail-open |
| **동승 조합** | 적재 여유만 봄 | 짐끼리 같이 실을 수 있는지 |
| **모니터 시트** | 요약줄까지 | 파생값 전체를 펼쳐 보는 화면 |

### 미확인

- 배차망 표시 금액이 **실수령**(수수료 공제 후)인가 — 실콜 정산 대조가 필요하다
- 도달 시간의 속도 모델 — 앱 1차 필터는 오프라인이라 근사가 필요하다
