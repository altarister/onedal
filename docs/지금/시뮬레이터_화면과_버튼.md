# 시뮬레이터 — 배차망별 페이지 순서와 버튼이 하는 일

> 2026-09-14 작성. 시뮬레이터(`onedal-sim`) 코드 · 실물 캡처 · 원달앱이 누르는 버튼 · 기사님 답을 나란히 놓고 정리했다.
> 계기: 테스트 안내에 «탁송을 누르면 수락»이라고 적었는데 기사님이 *"탁송은 아무 일도 하지 않는다. 확정이 콜을 내 것으로 하고, 확정을 누르면 확정 페이지로 간다"* 고 짚으셨다.
> 버튼 이름만 보고 짐작해 쓴 안내였다 — **시뮬레이터로 테스트를 안내하기 전에 이 표를 본다.**

### 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 시뮬레이터 | 원달앱이 읽을 가짜 배차망 화면 (`onedal-sim` · 폰에서는 시뮬레이터 앱이 띄운다) |
| 원달앱 | 폰에서 배차망 화면을 읽고 누르는 우리 앱 |
| 실물 | 진짜 배차망 앱 (인성콜 · 화물24시 · 카카오T픽커) |
| 시뮬레이터 전용 | 실물에 없는 동작 — 시험을 편하게 하려고 시뮬레이터에만 붙인 것 |

## 1. 인성콜

### 1-1. 페이지 순서

```
리스트(신규 탭) ─콜을 누른다→ 상세(확정 전) ─「확정(10)」→ 확정 페이지 ─「닫기」→ 리스트
                              │                                   └「취소」→ 잡은 콜에서 빠지고 리스트
                              ├ 10초 동안 아무것도 안 누르면 → 리스트
                              ├「취소」→ 리스트
                              └「적요상세」· 출발지 줄 · 도착지 줄 → 팝업 → 「닫기」로 상세
```

- **상세(확정 전)는 여러 기사가 함께 보는 페이지다.** 10초가 지나면 리스트로 돌아가고, 그 사이 다른 기사가 가져갈 수 있다 (기사님 2026-09-14)
- **확정 페이지는 이미 내 콜이다** — 실물 캡처 `상세-확정(다른사람 못잡음, 취소+1)` : 다른 기사가 못 잡고, 취소하면 취소 횟수가 하나 는다

### 1-2. 원달앱이 인성 화면에서 누르는 것

```
상세(확정 전)  →「적요상세」→ 적요 팝업 →「닫기」
               →「출발지」 → 출발지 팝업 →「닫기」
               →「도착지」 → 도착지 팝업 →「닫기」
               →「확정」(확정·배차 글자)
확정 페이지    → 서버 판정 KEEP 이면「닫기」 · 취소면「취소」
```

🔴 원달앱은 **「탁송」을 누르지 않는다** — 원달앱·서버·관제웹·검증 스크립트 어디에도 탁송 버튼을 누르는 코드가 없다 (2026-09-14 코드 검색).

## 3. 카카오픽커

근거: `packages/ui-simulators/src/kakaopicker/*` · 실물 캡처 글 `ex_images/카카오픽커/README.md`(11~32 는 레포에 없다) · 원달앱 `KakaoPickerKeywords.kt`(`STAGE_WORDS` · `clickSafe`) · 계획서 [카카오픽커_시뮬레이터.md](../기획/카카오픽커_시뮬레이터.md) §8

### 3-1. 페이지 순서

```
홈 ─「시작하기」→ 리스트(신규) ─카드→ 상세(수락 전) ─「수락하기」→ 내 오더 탭 ─카드→ (퀵) 픽업 출발 ─「픽업 출발하기」→ 픽업 이동 ─「픽업 완료하기」→ 배송(흰 페이지) ─「배송 완료하기」→ 인증사진 촬영 · (도보) 픽업 이동 ─창 올리기→ 「밀어서 픽업 완료」→ 배송 중
                  │                  ├「넘기기」·「←」→ 리스트                     └「배정 취소」→ 「배정 취소 불가」 팝업
                  │                  └ 원달앱이 상세 대기 시간(서버 · 기본 60초) 뒤 뒤로 가기 → 리스트
                  └ 오래 떠 있던 카드 → «이미 배정이 완료된 오더입니다» 토스트
배송 중 ─창 올리기→ 「밀어서 사진 촬영」→ 인증사진 촬영 ─「인증사진 촬영」→ 촬영 확인 ─「문자 전송」→ 문자 전송 ─「배송 완료」→ 배송 완료 ─「오더 목록 보기」→ 리스트
```

- 수락한 콜은 **«내 오더» 탭**에 있다. 누르면 수락 뒤 단계를 이어서 연다

## 4. 테스트 안내 — 이 순서로 한다

**인성콜:** 시뮬레이터 첫 화면에서 «인성콜» → 시작 → 콜을 누른다 → 상세가 열린다 → **「확정(10)」** → 확정 페이지로 바뀐다 → **「닫기」** → 리스트 위 **«완료» 탭**에 그 콜이 있다 · 리스트 아래 **«메뉴»**가 열린다

**화물24시:** 첫 화면에서 «화물24시» → 시작 → 콜 카드를 누른다 → 상세가 열린다 → **「하차완료」**(지금 시뮬레이터에서 수락 역할) → **«배차내역» 탭**으로 넘어간다

**픽커:** 첫 화면에서 «픽커» → 시작 → 홈 **「시작하기」** → 카드를 누른다 → 상세(지도 위 시트 · 손잡이를 누르거나 끌면 하·중·상) → **「수락하기」** → 곧바로 내 오더 탭 · 방금 수락한 콜 카드 → 🚚 퀵 카드: 흰 페이지 **「픽업 출발하기」** → **「픽업 완료하기」** → **「배송 완료하기」** → 인증사진 촬영 / 🚶 도보 카드(리스트 «도보배송» 탭에서 수락): 지도 위 시트 픽업 이동 → **아래 창 끌어 올리기** → **「밀어서 픽업 완료」** → 배송 중 → **아래 창 끌어 올리기** → **「밀어서 사진 촬영」** → **「인증사진 촬영」** → **「문자 전송」** → **「배송 완료」** → **「오더 목록 보기」** → 리스트

첫 화면으로 돌아가기: 인성은 아래 «설정», 화물24시는 주황 «오더검색», 픽커는 리스트 위 «메뉴».

## 6. 콜이 목록에 들어오는 길 — 랜덤콜 · 시나리오콜 · 개별콜

기사님(2026-09-15): *"시나리오콜, 랜덤콜, 개별콜 이렇게 하면 3가지 종류의 콜을 만들수 있을꺼 같아"*.
셋 다 **시뮬레이터 목록에 뜨고**, 폰 원달앱이 다른 콜과 똑같이 읽고·거르고·잡는다. 다른 것은 «콜 내용을 누가 정하나» 하나다.
시뮬레이터 설정 화면(메인 메뉴)에서 **탭으로 입구를 고른다** — 🔴 한 화면에는 한 종류만 흐른다 (섞이면 폰이 무엇을 거르고 잡았는지 떼어 볼 수 없다).

| 탭 | 내용을 정하는 쪽 | 들어가면 | 설정 |
|---|---|---|---|
| 🎯 시나리오콜 | 문제지가 순서대로 (`presets.ts`) | 간격마다 문제지 콜이 저절로 흐른다 | 문제지 · 수신 간격 · 채움 콜 수 · 되돌려 흘리기 |
| 🎲 랜덤콜 | 시뮬레이터 (`generateBaseCall`) | 5건이 깔리고 간격마다 붙는다 | 기사 위치 · 목적지 방향 · 상차 반경 · 최소 요금 · 수신 간격 |
| 🚚 개별콜 | 기사님이 현황판에서 한 건 | **빈 리스트** · 현황판에서 보낸 콜만 쌓인다 (`?calls=individual`) | 없다 |

«이천 왕복 하루» 설계서([docs/기획/문제지_이천왕복.md](../기획/문제지_이천왕복.md))는 아직 코드가 없다 — 줄마다 보내는 방식이라 개별콜과 같은 길(서버)로 올릴 계획이다.

**개별콜 쓰는 법**
1. 시뮬레이터에서 배차망을 고르고 **«🚚 개별콜» 탭 → 시작** → 빈 리스트가 뜬다 (픽커는 홈 «시작하기» 뒤)
2. 관제웹 오른쪽 현황판 맨 위 «🧪 테스트용» → **«🚚 개별콜»** 칸에서 상차·하차 주소를 **동·읍·면까지** 적고 «🔎 찾기» → «상차 동 초월읍 · 좌표»가 초록으로 뜬다
3. 요금을 적는다 — 인성·화물24시는 원, 픽커는 P
4. «🚚 시뮬레이터에 내기» → «✅ #번호 서버가 들고 있다»면 3초 안에 리스트 맨 위에 뜬다

| 이렇게 뜨면 | 뜻 |
|---|---|
| ⚠️ 시뮬레이터가 아직 안 물었다 | 시뮬레이터를 «🚚 개별콜»로 시작하지 않았거나(랜덤·시나리오 화면은 안 묻는다) 다른 서버를 본다 (`?api=`) |
| ⚠️ 시뮬레이터가 N초째 안 묻는다 | 개별콜 화면을 나갔다 |
| 동·읍·면이 없는 주소다 | 도로명만 적었다 — 목록의 지역 칸이 동 이름이라 받지 않는다 |

- 🔴 **개별콜 화면을 열기 전에 낸 콜은 안 뜬다** — 시뮬레이터는 «처음 물은 뒤»에 낸 콜만 받는다 (늦게 연 화면이 옛 콜을 다시 내지 않게)
- 🔴 **서버를 다시 띄우면 들고 있던 콜이 사라진다** — 메모리에만 둔다
- 상차 거리는 문제지 콜처럼 **그 순간 기사님 위치**에서 잰다 · 차종은 시뮬레이터가 고른다
- «버린 콜» 칸 아래 **«🖐️ 콜 생성»은 다르다** — 서버에 바로 넣어 폰 원달앱을 건너뛴다 (필터를 볼 수 없다)

코드: 현황판 `client-app/src/statusboard/simCall.ts` → 서버 `server/src/core/simCallQueue.ts` (`POST`·`GET /api/sim/calls` · 개발 빌드만) → 시뮬레이터 `useSimInjectedCalls` · `injectedCall.ts`. 세 곳의 칸 이름은 서버 검사 `simCallQueue.test.ts` 가 대조한다.
