> 2026-08-30 알람 모드 검증에서 **실측으로 확정된 절차**다. 그날 Claude 가 헤맨 것
> (엉뚱한 레포 뒤짐 · 리셋 순서 뒤집어 유령 콜 · 시뮬 선택지를 모름)을 다음 세션이

## 판의 구성 — 넷이 한 세트다

| 무엇 | 어디 | 살아 있나 확인 |
|---|---|---|
| 배차망 시뮬레이터 | **`onedal-sim/`** (레포 안! `~/reps/map` 아님) · :5173 | `curl -s localhost:5173` 에 `1DAL 배차망 시뮬레이터` |
| 스캐너 폰 | `onedal-app` 설치본 (`com.onedal.app`) | `adb shell dumpsys package com.onedal.app \| grep versionName` |

```
시뮬(5173)이 가짜 인성 화면을 그림 → 폰의 시뮬레이터 앱(WebView)이 띄움

```

## 폰 쪽 설정 — 두 앱이 따로 논다

**① 시뮬레이터 앱** (`com.onedal.simulator` · 화면 껍데기)
- **볼륨 위 버튼** → 주소 선택: `로컬 · 인성콜` 을 고른다
- 🔴 **기본값이 «배포본»(S3)** 이다 — 안 고치면 이 맥이 아닌 옛 배포본을 본다

**② 원달앱** (`com.onedal.app` · 읽고 보고하는 쪽) — 설정은 `OneDalPrefs` 에 산다:
```bash
adb shell "run-as com.onedal.app cat /data/data/com.onedal.app/shared_prefs/OneDalPrefs.xml"
#  localPcIp   = <이 맥의 IP>:4000  ← `ipconfig getifaddr en0` 로 확인. 바뀌면 앱 설정 화면에서
#  isLiveMode  = false              ← 로컬
```
- 🔴 **IP 는 폰 세 곳에 따로 산다** (원달앱 · 시뮬 앱 · 관제앱). `adb install -r` 은
  이 저장값을 안 지우므로 **소스만 고치고 재설치해도 옛 IP 그대로**다.
  세 곳을 어디서 고치는지는 [로컬_개발_안내 §0-⑤](로컬_개발_안내.md) 에 표로 있다
- 접근성 확인: `adb shell settings get secure enabled_accessibility_services | grep onedal`
- 재설치: `adb install -r onedal-app/app/build/outputs/apk/debug/app-debug.apk` — **버전 이름을 올려서** 깔았는지 구분한다 (`1.9-alarm2` 식)

**③ 관제웹(관제앱)** 이 어느 서버를 보는지는 **관제앱에서 볼륨 위** → ServerSwitch (2026-08-25 신설)

## 문제지 — 시뮬 화면에서 고른다 (URL 손타이핑 금지)

시뮬레이터 첫 화면 → **🎯 시나리오콜 탭** → 문제지 선택 → 간격 → 시작.
`?preset=` 손타이핑은 2026-08-23 에 문제지가 중간에 랜덤으로 바뀐 사고가 있어 탭이 생겼다.
채움 콜 수 기본 **0** (기사님 확정 2026-08-30).

**「7지점 한 바퀴」** (기사님의 7지점 · drive 검사와 같은 실측 좌표) 정답:
- **정지 상태(잡지 않음): 알람 2번 — 01·03.** 05는 «주행 중»에만 잡히는 콜
- 요금 차단 문제는 **단가식**이 기준이다 (`min_fare` 2만은 보류 칸 — 용어집 §11)
- 🔴 **콜을 잡는 순간 국면이 합짐으로 바뀌어 이후 정답이 달라진다** — 채점 판은
  «안 잡는 판»과 «잡는 판»을 갈라서 돌린다

## 📍 거리는 «지금 현위치»에서 잰다 (2026-08-31 신설)

콜 화면의 «현위치 ➔ 상차지 N KM» 은 **앱 상차 반경 축이 먹는 입력**이다. 예전에는 시뮬이
그 값을 **URL 로 한 번 고른 고정 좌표**에서 쟀다 — 기사님은 달리는데 숫자는 그대로라,
실측 0831 에 적요 «7.2km» 인 상차지가 실제로는 11.4km 뒤였고 22.4km 뒤 상차지도 통과했다.
**필터는 정직했고 거짓말을 한 것은 문제지다.**

지금은 시뮬이 서버(`GET /api/sim/driver-location` · **개발 빌드에서만 열린다**)에 3초마다
«지금 어디»를 물어 그 좌표에서 잰다. 실제 인성이 하는 일과 같다.

### 📍 축 문제지 — 어디서 돌려도 정답이 같다 (서울 나들이용 · 2026-08-31 신설)

```
시뮬 첫 화면 → 🎯 시나리오콜 탭 → «📍 축 문제지 · 어디서든» 선택
```

주소를 박지 않고 **거리 띠**(반경 안/밖)로 내므로, 출제 순간의 현위치에서 실제 주소를
골라 붙인다. 6문제 — 상차반경 2 · 차종 1 · 요금/단가 2 · 축 간섭 1.
**정답: 올려야 하는 것은 ②⑤ 둘뿐** (나머지 넷은 차단). 서울이든 어디든 이 정답은 안 바뀐다.

위치 출처는 두 겹이다 — ① 서버(`/api/sim/driver-location`, 모의 주행 중이면 **가상 위치**를
준다) ② 폰 GPS(서버가 못 답할 때 · 라이브 서버는 이 문을 닫아 둔다).
시뮬 화면의 지역 이름이 `기사님 현위치`/`기사님 현위치(폰)` 이면 추종 중이다.
⚠️ 폰 GPS 를 쓰려면 **시뮬레이터 앱을 2026-08-31 빌드 이후로 깔아야 한다**(위치 권한 신설).

🔴 **그래서 정답표는 «집에서 시작하는 판» 기준이다.** 한 사이클을 돌고 이천 한복판에서
같은 문제지를 다시 흘리면 **거리가 달라져 정답이 달라진다** — 채점 판은 리셋 후
집(초월)에서 시작한다. 시뮬 화면의 지역 이름이 `기사님 현위치`(또는 GPS 가 없으면
`기사님 내 주소`)로 바뀌어 있으면 추종 중이라는 뜻이다.

## 리셋 — 순서가 생명이다

```
① 장부 비우기 (백업 먼저)  →  ② 서버 재기동  →  ③ (같은 문제지 재판이면) 접근성 토글
```
🔴 **반대로 하면 유령이 남는다** — 재기동이 옛 장부를 메모리로 복구한 «뒤에» 지우면
화면은 메모리를 보므로 새로고침해도 콜이 살아 있다 (2026-08-30 실사고 · 버그 대장 #40 동형).
리허설의 `x` 는 이 순서를 강제한다 — **손으로 하지 말고 그 길로 갈 것.**

🔴 **③이 빠지면 재판이 무효가 된다** (2026-08-30 실사고 · 같은 함정으로 08-25 에도 두 판 잃음).
앱은 본 콜의 지문(상차+하차+요금)을 기억해 «이미 본 콜»로 건너뛰는데, 같은 문제지는
지문이 같아서 **지난 판의 기억이 새 판의 콜을 평가 없이 삼킨다** — 화면엔 뜨는데 로그에
판정이 없으면 이것이다. 기억은 **접근성 토글(껐다 켜기)로 서비스가 새로 떠야** 비워진다.
앱을 최근앱에서 밀어내도 안 지워진다 (`HijackService.kt` `processedOrderHashes` 주석).

리셋 후 관제웹: **⌘+Shift+R + 화면 1클릭** (클릭 없으면 브라우저가 소리를 막는다) ·
**탭은 하나만** (둘이면 알람을 두 번 받는다 — 실측).

## 채점 — 로그 어디를 보나

| 무엇 | 어디 |
|---|---|
| 서버 알람 발신 | `server/logs/server-*.log` 의 `🔔 [알람]` |
| 폰 알람·테두리 | `adb logcat -d \| grep 1DAL_ALARM` (걷힘 사유까지 찍힘) |
| **축별 판정** (왜 걸렀나) | logcat `타겟 콜 필터 결과` — 차종·도착지·요금/단가·상차거리·블랙 |
| 경로 순서 차단 | logcat `[경로 순서] 차단` |
| 미리보기·확정 흐름 | logcat `[미리보기]` · `복귀 감지` |
| 장부에 남은 것 | `pnpm ledger` 또는 `orders` 직접 조회 |

⚠️ **logcat 버퍼는 짧다** — 판이 끝나면 바로 뽑아 둔다. 몇 분 지나면 앞부분이 밀려 사라진다.
⚠️ 앱이 받는 필터 실물은 폰과 같은 방식으로 물어본다:
`curl -X POST localhost:4000/api/scrap -d '{"deviceId":"<기기ID>","data":[],"screenContext":"LIST","filterVersion":"","targetApp":"insung"}'` → `dispatchEngineArgs`.
기기 모드는 `user_devices.mode`(DB)와 응답의 `deviceControl.mode` 로 본다.
