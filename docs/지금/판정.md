# 판정 — 콜을 집은 뒤 색을 내는 것

> **색이 곧 결정이다.** 기사님은 🔵🟢🟡🔴 를 보고 1~2초 안에 누른다. 설명 문구는 그다음이다.
> **그러므로 색을 틀리는 것이 이 시스템의 가장 큰 사고다.**
>
> 🔴 **판정은 «집은 뒤», 필터는 «집기 전»이다.** 둘은 완전히 격리되어 각각 따로 작동한다.
> 필터는 [필터 문서](필터.md)에 있다. 말의 원천은 [용어집](용어집.md).

---

## 1. 판정이 답하는 질문

앱이 `요금 ≥ 배송거리 × 단가` 로 **이미 걸러서** 올린 콜만 여기 온다.
그러므로 판정의 일은 *"이 콜이 돈이 되는가"* 가 **아니다.**

> **"지금 이 경로에 붙일 때 얼마나 좋은가"**

우회 비용으로 순위를 매기는 것이 판정이다.

🔴 **모르는 값은 가장 흔한 값으로 계산하고 «미확인»으로 표시한다.**
불리하게 잡으면 잡을 수 있었던 콜을 놓친다 — 잡은 뒤 통화로 확정하는 것이 이 제품의 순서다.
표시 없이 값만 쓰면 규칙 위반이다.

🔴 **물리적으로 불가능해 보여도 서버가 미리 버리지 않는다.** 시간은 통화로 조정된다.

## 2. 색 넷

| 색 | 이름 | 뜻 |
|---|---|---|
| 🔵 | **꿀** | 잡아라 |
| 🟢 | **보통** | — |
| 🟡 | **똥** | 별로다 |
| 🔴 | **사고** | **잡지 마라** |

```
총점 ≥ honeyMin(70)      → 꿀
총점 ≥ normalMin(40)     → 보통
그 아래                  → 똥
「무조건 빨간불」 기준이 0점  → 사고 (점수와 무관)
잴 수 있는 기준이 하나도 없음 → 사고 (점수는 null — 0 이 아니다)
```

🔴 **실패가 빨강인 이유** — 예전엔 회색(무해해 보임)이었다.
**나쁜 걸 아는 것보다 아무것도 모르는 게 더 위험하다.** 경로도 요율도 못 구한 콜은 판단 근거 자체가 없다.

## 3. 채점 — **기준 다섯이 각자 값을 만들고, 엔진이 모은다**

기사님 확정 (2026-08-29): *"각각의 기준이 서로 섞이지 않도록 스마트하게 만들어줘.
기준이 추가될 수도 삭제될 수도 있어."*

```
사실 = { money{}  promise{}  space{}  nature{}  geography{}  notes[] }
           ↓         ↓         ↓        ↓          ↓
          돈       약속      공간     성질       지리     ← 각자 **자기 칸만** 받는다
                        ↓
                엔진이 가중평균 → 색
```

### 📦 적재는 «함께 실리는 최대»다 — 잡은 콜의 합이 아니다

경로의 정거장을 순서대로 걸으며 **상차에 더하고 하차에 뺀 그 동안의 최대값**이다 (`shared` 의 `peakLoadPoints`).
3번 콜을 싣기 전에 1번을 내리면 그 자리가 돌아온다 — 다 더해 세면 하루 6~7콜을 도는데 3~4콜에서 «만재»가 된다.
순서는 경로를 실제로 잰 콜이 들고 있고(`sectionStops`), **모르면 다 더한 값으로 물러선다** (규칙 ④).

자리가 모자랄 때 색을 덮는 것은 **신고·실측**일 때만이다 (`capacityConfidence`). 차종에서 추정한 값이면 점수만 0 이다 —
차종 글자를 오독하면 멀쩡한 콜이 🔴 가 되기 때문이다.

🔴 **섞이지 않는 것을 «조심»이 아니라 «구조»로 막는다.** 기준은 자기 몫의 사실만 받고,
남의 사실은 **타입에 아예 없어서 못 본다.**

### 기준 다섯

| 열쇠 | 이름 | 무엇을 보나 | 가중치 칸 | 기본 |
|---|---|---|---|---|
| `money` | 돈 | 이 시간 써서 얼마 버나 | `weight_revenue_detour` | 1 |
| `promise` | 약속 | 이미 잡은 콜에 늦지 않나 | `weight_promise_guard` | 1 |
| `space` | 공간 | 실을 자리 있나 (**신고·실측**이면 못 싣는 것이 🔴) | `weight_slots` | 1 |
| `nature` | 성질 | 같이 실어도 되는 짐인가 | `weight_cargo_compat` | 1 |
| `geography` | 지리 | 목적지로 전진하나 (첫짐의 **배수**) | `weight_geography` | 1 |

### 🔴 「돈」의 눈금은 국면마다 다르다

```
합짐   보통 시급에서 50점 → 꿀 시급에서 100점   (두 점 꺾은선 · 100 에서 자른다)
첫짐   첫짐 기준 시급에서 100점                  (한 점 · 합짐 눈금보다 후하다)
       × 목적지 전진 배수                        (「지리」가 낸다 — 아래)
우회 0분(길목)                     100점
```

시급은 `요금 ÷ 더 쓰는 시간 × 60` 이다. 어느 국면인지는 사실의 `money.firstLoad` 가 말한다 —
**판정 함수는 하나고 갈리는 것은 눈금뿐이다.** 까닭은 기회비용이다: 합짐은 안 잡아도 잃는 것이 없고,
첫짐은 안 잡으면 그 시간이 0원이다. 세 기준선은 판정 기준 탭에서 고친다
(`shared/src/criteria.ts` 의 `MONEY` · 설계와 검산은 [실전 콜 판정 설계](../기획/실전_콜_판정_설계.md) §4-2·§4-3).

🔴 **합짐을 한 점 비율로 재면 안 된다** — 보통 기준에서 천장을 쳐 3만/h 와 5만/h 가 같은 꿀이 되고,
우회 235분짜리도 요금만 크면 보통으로 올라온다.

### 🧭 「지리」는 첫짐의 **목적지 전진 배수**다 — 평균의 한 항이 아니다

```
전진율 p = (dist(현위치, 목적지) − dist(하차지, 목적지)) ÷ dist(현위치, 하차지)     −1 ≤ p ≤ 1
배수     = clamp(1 + (최대 − 1) × p,  최소,  최대)
첫짐 총점 = min(100, 돈점수 × 배수)
```

세 점은 지금 쓰는 자리에서 온다 — 현위치 `originOf` · 하차지 지오코딩 · 목적지 `goalCityOf` 의 시내(`cityCenter`).
모으는 곳은 `server/src/core/engine/judgeFacts.ts` 의 **`destProgressOf`** 하나고, 셈은 `shared/src/callNet.ts` 의
**`destProgressRatio`** 하나다.

🔴 **덧셈이 아니라 곱셈이다** — 더하면 요금 0원짜리가 방향만 맞아도 보통색이 된다.
🔴 **합짐에는 안 붙는다** — 그쪽 지리는 우회 시급이 이미 센다 (같은 사실을 두 번 세지 않는다).
🔴 **못 쟀으면 배수 1.0 + 까닭**이다 (규칙 ⑤-2) — 목적지를 안 정하셨다고 콜을 떨어뜨리지 않는다.
   목적지 반경 안에 있으면 아예 안 잰다 (도착했으니 전진할 것이 없다).
⚠️ 직선으로 잰다 — **방향 지표**이지 거리가 아니다. 기본 가중치는 켜져 있다.

### 기준은 **세 가지로 답한다**

| 대답 | 뜻 | 어떻게 되나 |
|---|---|---|
| **점수** | 쟀다 (0~100) | 평균에 든다 |
| **잴 게 없다** | 잴 **대상**이 없다 — 첫짐엔 지킬 약속이 없고, 빈 차엔 자리 문제가 없다 | 조용히 빠진다. 정상이다 |
| **잴 수 없다** | 잴 **재료**가 없다 — 카카오가 터졌다, 주소를 못 찾았다 | 🔴 + 「잴 수 없음」 딱지 |

🔴 이 셋을 뭉뚱그리면 두 사고가 난다 — ① 재료가 없는데 «괜찮다»고 넘어간다
② 잴 게 없는 첫짐이 «못 쟀다»로 빨간불이 된다.

⚠️ 이 구분 덕에 **첫짐/합짐 갈래가 없다.** 실린 콜이 없으면 약속·공간이 저절로 「잴 게 없다」다.

### 「무조건 빨간불」

점수와 무관하게 색을 덮는 것 — **기준 안에 있다.** 따로 뜬 개념이 아니다.

| 어디 | 언제 |
|---|---|
| 약속 | 이미 잡은 콜의 약속이 깨진다 |
| 성질 | 같이 못 싣는 조합 · 제외 키워드 |

⚠️ **가중치가 0 이면 이것도 안 본다** — 경로만 보려는 검사에서 끄려고 그렇게 뒀다.

### 딱지 (`notes`)

판단 없이 사실만. **색을 안 건드린다.**
«정차 미확인» · «배송주행 추정» · «통화 필수» · «차종 불일치» · «요금 초과» · «경유 미확정»

🔴 **차종 불일치가 딱지인 이유** — 그건 «기사님이 평소 받는 차종 목록»이지 물리 제약이
아니다. 게다가 **앱이 같은 목록으로 이미 거른다** (규칙 ⑤-1). 진짜 «못 싣는다»는
**자리**로 잰다 — 정원을 넘으면 여유가 음수가 되고 「공간」이 0점이다.

### 기준을 더하거나 빼려면

`shared/src/criteria.ts` 의 **목록 한 줄**만 고친다. 엔진(`judge.ts`)은 안 고친다.
🔴 새 기준을 넣을 때는 **가중치 칸을 `JUDGMENT_FIELDS` 에 함께** 넣는다 —
안 그러면 기사님이 못 고치는 값이 또 태어난다 (규칙 ⑤-4 ①).

## 4. 기준값 — 원천은 DB 다

`user_judgment` 한 행이 사용자 한 명의 기준이다. 칸 수는 `JUDGMENT_FIELDS` 가 답한다 (`grep -c "col: '" onedal-web/shared/src/judgment.ts`).

| 무리 | 칸 | 기본값 |
|---|---|---|
| **색 경계** | `color_honey_min` · `color_normal_min` | 70 · 40 |
| **가중치** | `weight_revenue_detour` · `weight_promise_guard` · `weight_slots` · `weight_cargo_compat` · `weight_geography` | 1 |
| **여유 곡선** | `slack_full_min` · `slack_zero_score` | 30분 · 95점 |
| **지연 곡선** | `slack_late_soft_min` · `slack_late_warn_min` · `slack_late_zero_min` | 5 · 15 · 30분 |
| **합짐 눈금** | `target_hourly_krw`(보통 50점) · `honey_hourly_krw`(꿀 100점) | 30,000 · 50,000원/h |
| **첫짐 눈금** | `solo_hourly_krw` | 25,000원/h |
| **데드라인** | `deadline_ratio_pct` | 150% |
| **모를 때 · 정차** | `unknown_pickup_dwell_minutes` · `unknown_dropoff_dwell_minutes` | 15분 · 10분 |
| **모를 때 · 상차 약속** | `pickup_promise_minutes` | 20분 |
| **모를 때 · 속도** | `speed_short_kmh` · `speed_mid_kmh` · `speed_long_kmh` | 25 · 46 · 56 |

### ⏰ 지연 곡선 — «늦는다»도 한 번에 떨어뜨리지 않는다 (규칙 ⑤-4 의 다섯)

통화로 굳힌 약속이 깨지면 그건 **무조건 빨간불**이다 (건드리지 않는다).
여기서 재는 것은 **아직 통화 전인 임시 지연**(`bufferAfterMin < 0`)이다.
🔴 **한 번에 떨어뜨리면 몇 분 밀리는 콜을 다 버린다** — 정차 중에 3~4콜을 모으려면 몇 분씩은 밀린다.

| | 정한 것 |
|---|---|
| ① 스키마 | `user_judgment` 의 `slack_late_soft_min` · `slack_late_warn_min` · `slack_late_zero_min` (`JUDGMENT_FIELDS` 세 줄) |
| ② 값 | **5 · 15 · 30분** (기사님 확정). 그 자리의 점수 **90 · 60 · 0** 은 코드 상수다 — 우회 감쇠와 같은 모양으로 **분은 설정, 계수는 코드** |
| ③ 시점 | 판정할 때마다 세션의 판정 기준에서 읽는다 (저장하지 않는다) |
| ④ 화면 | 판정 기준 탭 «정차·여유» 무리 — 기사님이 고치신다 |
| ⑤ 읽는 곳 | 「약속」 기준 하나 (`criteria.ts` 의 `PROMISE`) |

🔴 **`slack_zero_score`(95) 는 지연 첫 자리(90점)보다 높아야 한다.** 낮으면
«지연 5분»이 «여유 0분»보다 좋아져 **늦는 콜이 딱 맞춘 콜보다 높은 점수**를 받는다.
🔴 **색은 안 덮는다** — 통화 전 지연은 서버가 지레짐작한 시간이라 0점까지만 간다
(덮는 것은 통화로 굳힌 약속뿐 · `hardFailIsConfirmed`).
⚠️ 눈금을 올리기 전에 만든 DB 에는 옛 값이 남아 있다 — 판정 기준 탭에서 올려야 새 눈금이 돈다.

### 🔴 **정차 값(박스당 분·검수 분)은 여기 없다 — 콜 옵션 표가 원천이다**

2026-08-29 낮에 판정 기준 탭으로 올렸다가 **저녁에 되돌렸다.** 그 셋은
«어떻게 잴 것인가»가 아니라 **화면의 칩에 붙는 숫자**다 — 통화 시트가
「수작업 10분」·「검수 60분」이라 그리는 그 값이고, `call_options` 표에 **이미 칸이 있었다.**

```
판정 기준 탭 (user_judgment)  →  «어떻게 잴 것인가»            가중치 · 색 경계 · 시급 눈금 셋 · 여유 곡선
콜 옵션 표   (call_options)   →  «무엇을 고를 수 있고 몇 분인가»   칩과 그 숫자
```

⚠️ 두 그릇에 담았더니 **화면 10분 / 판정 19분** 같은 두 목소리가 났다 (버그 대장 #71).

🔴 **고쳐 저장할 때는 셋을 한 번에 한다** — ① DB ② **서버 기억 버리기** ③ 세션·화면 갱신.
   ②를 빠뜨리면 화면만 새 값이 되고 **판정은 옛 값을 계속 쓴다.**

### 🔴 값이 하나 늘면 표에 한 줄만 더한다

`shared/src/judgment.ts` 의 **`JUDGMENT_FIELDS`** 가 유일한 원천이다.
**DB 컬럼도, 관제웹 폼도, 기본값도 전부 이걸 읽는다** — 화면 코드와 서버 판정 코드는 안 고친다.

역할이 갈려 있다:

```
DB          지금 값이 얼마인가            ← 진실
JUDGMENT_FIELDS  라벨 · 단위 · 범위 · 근거   ← 폼의 칸 아래 그대로 뜬다
docs        왜 그렇게 정했나              ← 값은 안 적는다
```

**그래서 이 문서에는 값을 적지 않는다.** 위 표는 «어떤 칸이 있는가»를 보이려는 것이고,
지금 값은 관제웹 «판정 기준» 탭이나 DB 가 답한다.

## 5. 색이 화면까지 가는 길

```
OrderEvaluator          judge(기준 다섯, 사실, 설정) → { color, score, criteria, notes }
   ├→ order_judgments   심사 1회 저장, 불변 (재탐색해도 색은 안 바뀐다)
   ├→ pros / reasons    색이 «잡을 이유»와 «버릴 이유»를 가른다
   ├→ order.judgment    🔵 **값으로** 내려간다  ← 화면이 이걸 읽는다
   └→ kakaoTimeExt      문구 (사람이 읽는 설명)
                            │
관제웹 lib/verdict.ts       └→ 값이 있으면 값, 없으면 **예전처럼 문구를 뒤진다**
```

🔴 **2026-08-29 에 «문구 뒤지기»에서 «값»으로 바꿨다.** 예전에는 화면이 문구 안의
`'꿀'` 이라는 **글자를 찾아** 색을 정했다. 그래서 **재탐색 버튼을 누르면 꿀콜이 초록**이
됐다 — 재탐색은 같은 색을 `🍯 (꿀)`(괄호)로 적는데 화면은 따옴표만 찾았다 (버그 대장 #63).
🚨 `(사고)` 도 마찬가지라 **잡으면 사고인 콜이 초록**으로 보였다.

⚠️ 문구 뒤지기는 **아직 폴백으로 남아 있다** (옛 서버·재시작 직후를 위해). `verdict.ts` 의
`source` 가 «값»인지 «문장»인지 말해 준다 — 늘 «값»인 것을 확인하면 그때 지운다.

🔴 **재시작해도 색이 남는다** — 복구가 `order_judgments` 스냅샷을 콜에 되살린다.
안 그러면 화면이 문구 뒤지기로 떨어져 위 사고가 그대로 난다.
