## 2. 어젯밤에 바뀐 것 — «상세를 열면 관제웹에 뜬다»

**전에는** 픽커 콜을 잡아도 관제웹이 조용했다. 알람은 «본 1건 중 통과 1건» 숫자 둘만
보냈고 어느 콜인지가 없었으며, 상세에 들어가도 서버는 그 콜의 존재를 몰랐다.

**이제는** 이렇게 돈다:

```
알람이 울림
  → 앱이 그 콜의 상세로 들어간다 (전부터 하던 것)
  → 🆕 서버에 «미리보기 콜»로 올린다  → 관제웹에 카드가 뜨고 판정 색이 나온다
  → 기사님이 「수락하기」를 누르면
     → 🆕 앱이 수락 후 화면을 알아보고 «잡은 콜»로 승격시킨다
  → 안 누르고 30초 지나면 자동으로 리스트 복귀 (전부터 하던 것)
```

**계약은 여전히 기사님 손가락뿐이다** — 앱은 「수락하기」를 누르지 않는다.

### 확인해 둔 것 (어젯밤 실제로 서버에 넣어 봤다)

- ✅ 픽커 상세 원문이 `intel.rawDetailText` 에 저장된다
- ✅ **인성은 오염되지 않는다** — 인성 574건 중 원문이 들어간 것 0건
- ✅ 🔴 **미리보기는 취소 카운트를 안 올린다** — 로그가 그렇게 말한다:
  `👀 [미리보기] … 확정 전이라 인성엔 취소가 없다. 카운트에 넣지 않는다`
  → **상세를 몇 번을 열어 봐도 하루 5번 제한을 안 깎는다**

## 3. 🔴 아직 «추정»인 자리 — 캡처 오면 여기만 갈아끼운다

수락 **뒤** 화면은 **2023년 남의 자료로 만든 추정**이다. 실물을 못 봤다.

**갈아끼울 곳은 한 곳뿐이다** —
[`KakaoPickerKeywords.ACCEPTED_SCREEN_WORDS`](../../onedal-app/app/src/main/java/com/onedal/app/plugins/kakaopicker/KakaoPickerKeywords.kt):

```kotlin
val ACCEPTED_SCREEN_WORDS = listOf(
    "픽업 완료",      // 「픽업 완료하기」(추정) · 「밀어서 픽업 완료」(2023 실물)
    "픽업지로 이동",
    "배송 완료",
    "배송지로 이동",
)
```

그리고 화면을 가르는 낱말 둘:

| 무엇 | 지금 값 | 근거 | 실물로 확인할 것 |
|---|---|---|---|
| «상세인가» | `detailKeywords = ["픽업"]` | 실물 덤프 12종 — 리스트에 «픽업» 0회 | 수락 **후** 화면에도 «픽업»이 있는가 |
| «수락 전인가» | `confirmKeywords = ["수락하기"]` | 실물 03_상세 | 수락 후에는 그 글자가 **없는가** |

**구조는 안 흔들린다** — 낱말만 바꾸면 된다 (기사님 방침).

### 캡처해 주시면 좋은 화면

1. 「수락하기」를 누른 **직후** 화면 (첫 화면)
2. 픽업지 도착해서 픽업 완료를 누르기 **전**
3. 픽업 완료 **직후** (배송 단계로 넘어간 화면)
4. 배송 완료 **직후**
5. 혹시 **「픽업 출발하기」 버튼**이 보이면 그 화면 — 노하우 문서는 *이 버튼이 돈을 가른다*
   고 했는데 실물(2026)에서 못 봤다. 있는지 없는지가 취소 보상 규칙을 가른다

## 4. 차종은 «다마스»로 통일했다 — 화면에 «차종미확인»이 함께 뜬다

픽커에는 차종 축이 없다(물품 크기로 가른다). 그런데 서버 판정·장부는 차종 칸을 쓰므로
빈칸으로 두면 그 아래가 전부 «모름»이 된다.

기사님 지시대로 **하나로 통일**하되(`"다마스"`), 규칙 ⑤-2 를 지켜 **«차종미확인» 표시를
함께 싣는다.** 관제웹 콜 카드의 태그 자리에 그 글자가 보이면 «이 차종은 실제 값이 아니다»
라는 뜻이다. 표시 없이 값만 쓰면 숫자가 거짓말을 한다.

## 5. 로그에서 볼 것

```bash
# 서버
tail -f onedal-web/server/logs/server-$(date +%F).log | grep -E "픽커|알람|미리보기"

# 앱
adb logcat -d | grep -E "1DAL_PICKER|1DAL_ALARM"
```

| 이 줄이 보이면 | 뜻 |
|---|---|
| `🔔 [알람] … 통과 N건` | 필터를 통과한 콜이 있어 울렸다 |
| `🚪 [알람 상세] …원 … 상세로 이동` | 앱이 그 콜의 상세로 들어갔다 |
| `👀 [미리보기 전송] …원 · N자` | 서버에 올렸다 → **관제웹에 떠야 한다** |
| `📄 [픽커 상세 보관] …원 · N자` | 서버가 원문을 저장했다 |
| `✅ [수락 확인] 기사님이 「수락하기」를 누르셨다` | 수락 후 화면을 알아봤다 |
| `👀 [미리보기 보류] 리스트 원본이 없다` | ⚠️ 리스트를 거치지 않고 상세로 들어갔다 — 안 올린다 |

🔴 **`✅ [수락 확인]` 이 안 뜨면** 수락 후 화면 낱말이 틀린 것이다. 그때 그 화면을
캡처해 주시면 §3 의 목록만 고치면 된다.
