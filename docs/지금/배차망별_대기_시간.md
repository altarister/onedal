# 배차망별 대기 시간 — 안전취소 시간 · 픽커 알람 상세 대기 시간

> **쓴 날**: 2026-09-14 · **상태**: 규칙 ⑤-4 의 다섯을 정했다 — **코드는 아직이다** (아래 «지금 코드» 표가 그 증거)
> **정한 분**: 기사님 (2026-09-14)

## 0. 기사님이 정하신 것 (2026-09-14)

- *"설정에 배차망에 따른 설정이 필요할꺼 같군.. 그래야 인성은 30초 픽커는 1분 이렇게 정할수 있겠어"*
- *"서버가 30초란걸 알고 있고 그걸 받아서 스켄앱이 그렇게 작동해야 하는거야. 시뮬레이터는 진짜 픽커 처럼 작동해야 하는거고."*
- 값을 **뜻이 다른 둘로 가른다** (아래 §1) — 기사님 확정
- 인성 안전취소 시간에 **상한을 걸지 않는다.** 대신 설정 칸 옆에 **«인성 취소 가능 시간 1분»** 을 적어 기사님이 보고 정하신다 — 기사님 확정

## 지금 코드 — 30초가 서로 모른 채 흩어져 있다

| 자리 | 값 | 원천 |
|---|---|---|
| 원달앱 설정 화면 «안전취소 시간» (`SettingsScreen.kt`) | 30·40·50초 중 고름 | **폰 안 저장소** (`safeCancelTimeout`) — 서버가 모른다 |
| 원달앱 알람 상세 자동 복귀 (`HijackService.kt` 의 `scheduleAlarmDetailBack`) | 30초 | 코드 숫자 |
| 서버 첫 보고 감시 타이머 (`onedal-web/server/src/routes/orders.ts`) | 30초 | 코드 숫자 |
| 서버 둘째 보고 경고·강제 해제 (`DISPATCH_CONFIG` 의 `WAITING_WARNING_MS` · `WAITING_TIMEOUT_MS`) | 30초 · 35초 | 코드 숫자 |
| 관제웹 판정석 안전취소 장막 (`JudgmentSeat.tsx`) · 홀드 진행 막대 (`PinnedRouteCard.tsx`) | 30초 | 코드 숫자 |
| 시뮬레이터 «남이 가져간 콜» (`PICKER_TAKEN_AFTER_MS`) | 30초 | 코드 숫자 — 🔴 원달앱의 30초에 맞춰 넣었다. 진짜 픽커는 원달앱의 시간을 모르므로 **떼어 낸다** |

## 1. 왜 둘로 가르나 — 규칙 ⑤-4 ⑤

| 배차망 | 이 시간이 답하는 질문 |
|---|---|
| 인성 · 화물24시 | **잡은 뒤 위약금 없이 취소할 수 있는 시간** — 안전취소 시간 (용어집 «안전취소») |
| 픽커 | 수락하기가 곧 계약이라 **안전취소가 없다.** 필요한 것은 **알람이 연 상세를 얼마나 띄워 두나** |

질문이 다르니 한 값에 두 역할을 맡기지 않는다 — `picker_alarm_min_fare` 를 만들 때 인성 `min_fare` 를 쓰지 않은 것과 같은 까닭 ([픽커_수집.md](픽커_수집.md) 3단계).

## 2. ① 스키마 — 어디에 사는가

| 값 | DB 칸 |
|---|---|
| 인성 안전취소 시간 | `user_settings.safe_cancel_sec_insung` (신설) `INTEGER DEFAULT 30` |
| 화물24시 안전취소 시간 | `user_settings.safe_cancel_sec_hwamul24` (신설) `INTEGER DEFAULT 30` |
| 픽커 알람 상세 대기 시간 | `user_settings.picker_alarm_detail_sec` (신설) `INTEGER DEFAULT 60` |

- 칸은 `ensureColumns` 로 붙인다 — `picker_alarm_min_fare` 와 같은 자리 (`onedal-web/server/src/db.ts`)
- 기본값은 DB 칸의 `DEFAULT` 에 둔다 (규칙 ③)

## 3. ② 값 — 기본값과 근거

| 값 | 기본 | 근거 |
|---|---|---|
| 인성 안전취소 시간 | 30초 | 지금 코드 값. **인성 취소 가능 시간은 1분이다** (기사님 2026-09-14) — 30초는 그 안에서 여유를 둔 값이다. 상한은 걸지 않는다 |
| 화물24시 안전취소 시간 | 30초 | 지금 코드 값을 옮겼다 — **화물24시의 실제 취소 가능 시간은 확인하지 못했다** (미확인) |
| 픽커 알람 상세 대기 시간 | 60초 | 기사님 말씀 «픽커는 1분» (2026-09-14) |

- **서버가 콜을 치우는 시각 = 안전취소 시간 + 5초** — 지금의 30초 경고 · 35초 강제 해제 간격을 그대로 둔다.
  원달앱이 먼저 취소하고, 서버는 그 뒤에 메모리를 치운다

## 4. ③ 시점 — 언제 쓰고 언제 읽나

- **쓰기**: 관제웹 설정에서 저장할 때만 (`onedal-web/server/src/routes/settings.ts` — 픽커 하한과 같은 자리)
- **서버 읽기**
  - ⓐ 원달앱에 보낼 응답을 조립할 때 — 셋을 모두 싣는다 (`onedal-web/server/src/routes/scrap.ts` — `pickerAlarmMinFare` 옆)
  - ⓑ 인성·화물24시 콜에 타이머를 거는 순간 — **그 콜의 배차망** 값 (`orders.ts` · `detail.ts`)
- **원달앱 읽기**: 응답을 받으면 기억하고, 타이머를 거는 순간 그 값을 쓴다. **이미 도는 타이머는 건 순간의 값으로 끝까지 간다**
- **서버가 죽었을 때**: 원달앱 안 기본값 (30초 · 30초 · 60초) — 규칙 ③ 의 앱 예외

## 5. ④ 화면 — 어디에 어떤 이름으로 보이나

**관제웹** ⚙️ 설정 → «일반 설정» — «픽커 알람 요금 하한» 바로 아래 세 칸 (기사님이 고친다):

| 칸 이름 | 칸 옆 안내 |
|---|---|
| 인성 안전취소 시간 (초) | **인성 취소 가능 시간 1분** |
| 화물24시 안전취소 시간 (초) | 화물24시 취소 가능 시간은 미확인 |
| 픽커 알람 상세 대기 시간 (초) | 알람이 연 상세를 이 시간 뒤 닫고 리스트로 돌아갑니다 |

- **원달앱 설정 화면의 «30·40·50초» 고르기는 없앤다** — 원천이 둘이 되기 때문이다 (규칙 ③). 받은 값을 **보여 주기만** 한다
- **관제웹이 숫자로 박은 30초 두 곳도 이 값을 읽는다** — 판정석 안전취소 장막 · 홀드 진행 막대

## 6. ⑤ 읽는 곳 — 누가, 무슨 질문의 답으로

| 누가 | 어느 값 | 무슨 질문 |
|---|---|---|
| 원달앱 안전취소 타이머 (`SafeCancelTimer`) | 인성 · 화물24시 | 서버 결재가 이 시간 안에 안 오면 스스로 취소하나 |
| 서버 타이머 (`orders.ts` · `detail.ts`) | 인성 · 화물24시 (+5초) | 원달앱이 취소할 시간이 지났는데 메모리에 남은 콜을 언제 치우나 |
| 관제웹 판정석 · 홀드 진행 막대 | 인성 · 화물24시 | 기사님께 몇 초 남았다고 보여 주나 |
| 원달앱 알람 상세 자동 복귀 (`scheduleAlarmDetailBack`) | 픽커 | 알람이 연 상세를 언제 닫고 리스트로 돌아가나 |
| 서버 — 픽커 미리보기 콜 | **읽지 않는다** | 규칙 ① — 서버는 스스로 치우지 않는다. 원달앱이 «리스트로 돌아왔다»고 알리면 치운다 |
| 시뮬레이터 | **읽지 않는다** | 진짜 픽커는 원달앱의 시간을 모른다 |

- 🔴 규칙 ① — 기사님이 직접 누른 인성 콜에는 지금처럼 자동 취소를 걸지 않는다 (원달앱 타이머는 필터콜에만 돈다)

## 7. 짝 — 같이 고칠 곳

| 이걸 바꾸면 | 같이 |
|---|---|
| 원달앱에 내려가는 키 셋 (`safeCancelSecInsung` · `safeCancelSecHwamul24` · `pickerAlarmDetailSec` — 신설) | `APP_FILTER_KEYS` + 원달앱 `FilterConfig` (✅ `appFilterKeys` 검사) |
| 서버 타이머 | `DISPATCH_CONFIG` 의 두 숫자와 `orders.ts` 의 숫자를 이 값으로 |
| 시뮬레이터 | `PICKER_TAKEN_AFTER_MS` 를 원달앱 시간과 떼어 낸다 |
