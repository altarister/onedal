# 상태 명세 — 앱·서버·관제웹의 모든 상태값 (통일 7열)

> **2026-08-17 코드 실측.** [이벤트_명세.md](이벤트_명세.md)와 짝이다 —
> 이벤트 명세의 "결과" 열이 여기의 "들어오는 길"과 맞물린다.
>
> **컬럼은 UML 상태표 관행(State·Entry·Do·Exit)을 이 레포 어법으로 옮긴 7열 고정:**
>
> | 상태값 | 뜻 | 들어오는 길 | 하는 일 | 나가는 길 | 화면에 보이는 것 | 원천 |
> |---|---|---|---|---|---|---|
>
> - **들어오는/나가는 길** = 무엇(이벤트·행동)이 이 상태로 만들고, 무엇이 내보내나
> - **원천** = 어디 저장되나. `파생` 표시는 저장하지 않고 계산으로만 나온다 (규칙 ③)
> - 용어는 [용어집](용어집.md) — 상태값 키는 코드 실측

# 0부. 스코프 지도 — 상태의 주인이 누구인가 ⭐ 먼저 볼 것

**상태는 주인(스코프)이 있다.** 어느 스코프를 건드리는 개발인지 먼저 보면
파급 범위가 미리 보인다 (기사님 2026-08-17: *"범위를 미리 생각해 개발할 수 있고
사이드이펙트를 줄일 수 있을 것 같아"*).

```
📱 기기 (앱폰 한 대)                    ← 콜과 무관하게 기기가 갖는 것
   콜 필터 스위치(mode) · 화면 인식 · 홀드 · 안전취소 타이머 · 온라인/오프라인

🗓️ 기사님의 하루 (세션 = user 한 명)     ← 콜이 생기고 죽어도 이어지는 것
   타겟(callTarget) · 배차 단계(dispatchPhase) · 국면(파생) · 콜 필터(base/active) ·
   isActive · isSharedMode · 적재 합계(slotsUsed) · 적재 확신도 · departedAt · 도착 감지 플래그

📦 콜 하나 (order)                      ← 콜이 태어나서 죽을 때까지
   status 10종 · 출신(필터콜/직접콜 = matchType) · 판정 색+점수 · 마일스톤
   └ 📍 정거장 (콜당 상차지+하차지)      ← 콜보다 작은 단위
        신고(DECLARED/ACTUAL/SKIPPED) · 완료 약속(deadlineAt) · 도착/예고 발화 여부

🖥️ 관제웹 (화면)                        ← 서버 상태의 투영 + 화면만의 것
   카드 4벌 · 시트 6단계 · 탭 · 연결 상태 · (그림자 상태 주의 — 3-6)
```

🔴 **경계를 넘는 개발이 사고를 낸다** — 예: 타겟은 하루의 것인데 콜 이벤트에서 바꾸면
콜 취소가 하루를 뒤집는다. 표마다 「원천」 열이 이 스코프를 가리킨다.

🔴 **기기가 N 대여도 하루는 하나다** (2026-08-17 기사님 확인 — 인성 폰 + 화물24시 폰).
콜 필터·isActive·타겟·경유 지역은 **세션 하나를 모든 기기가 피기백으로 공유**한다 —
한 기기가 선점하면 `isActive: false` 가 다른 기기도 멈추고(다음 폴링 ~5초),
경로가 바뀌면 다른 기기도 새 지역으로 거른다. 기기별로 따로 사는 것은
홀드·모드(콜 필터 스위치)·화면 인식뿐이다. 폴링 한 주기의 경쟁 창에 두 기기가
동시 선점하면 후보콜 2장이 되고 **결재로 해결한다** (다중 배차 유지 — 설계).

> 뒤 증거가 앞을 함축한다 (2026-08-17 실측: 상차완료 안 누르고 하차완료 → 정상 성립).

|---|---|---|---|---|---|---|

## 1-4. 국면 (`PhaseKey` — 타겟 × 배차 단계의 **진리표 파생**)

```
                 STANDBY      GATHERING    DELIVERING
DEST(노선)        first        merge        drive
LOCAL(관내)       local        merge        drive        ← 콜을 잡으면 어디서 출발했든 합짐
HOME(복귀)        home         merge        drive        ← 출발하면 어디서 출발했든 운행중
```

| 상태값 | 화면에 보이는 것 (`PHASE_FIELDS` 가 정한다) | 기본값 |
|---|---|---|
| `first` 첫짐 | 도착 도시(직접 입력)·상차/하차 반경·콜할인율 | 상차 5 · 하차 5 |
| `merge` 합짐 | 경유·하차 반경·콜할인율 (도착 도시 숨김 — 가는 길이 기준) | 경유 5 · 하차 3 |
| `drive` 운행중 | 경유(기본 0)·콜할인율만 | 경유 0 |
| `local` 관내 | 기준 지역만 · 할인 20% | 하차 0 (같은 시) |
| `home` 복귀 | 집 주소 표시·경유 | |

## 1-6. 기사 행동 (`driverAction` — 참고용, 국면 판정이 안 본다)

`WAITING`(콜 대기) · `DRIVING`(이동) · `LOADING`(상차 중) · `UNLOADING`(하차 중 — 도착 감지가 자동 전환) · `RESTING`(휴식). 원천: activeFilter. 🔴 정류장마다 바뀌는 값이라 **국면 파생에 쓰지 않는다** (traveledTrim 규칙).

## 1-6-1. 경로 우선순위 — 🔴 스코프가 둘로 갈린 상태값 (2026-08-17 기사님 실측으로 발견)

같은 "추천/시간/거리"가 **두 스코프에 따로 산다** — 그래서 "시간을 눌렀는데 다음 콜은
이전(추천) 경로를 기억하는 것 같다"는 현상이 생긴다. 버그가 아니라 스코프 차이다.

| 상태값 | 스코프 | 들어오는 길 | 적용 범위 | 원천 |
|---|---|---|---|---|
| `default_priority` (RECOMMEND/TIME/DISTANCE) | 🗓️ 하루(설정) | ⚙️ 설정 → 기본 경로 탐색 (`PUT /settings`) | **모든 새 콜**의 판정·경로 | DB `user_settings` |
| 지도 버튼 추천/시간/거리 | 📦 콜 하나 · 일시 | 지도 좌상단 버튼 (`recalculate-route` + priority) | **그 콜의 지금 경로만** — 저장 안 됨. 새 콜은 다시 기본값 | 없음 (일시) |

→ 서울 통과를 계속 피하려면 지도 버튼이 아니라 **⚙️ 설정의 기본 경로 탐색을 "시간"으로** 바꿔야 한다.

## 2-2. 콜의 출신 (`isAutoActive` → `matchType` — 콜 단위)

| 상태값 | 뜻 | 들어오는 길 | 나가는 길 | 결과 | 원천 |

## 2-3. 상세 수집 (`SurfingState` — 팝업을 차례로 넘긴다)

| 상태값 | 뜻 | 들어오는 길 | 나가는 길 |
|---|---|---|---|
| `IDLE` | 수집 전 | 세션 시작 | 확정 화면 진입 |
| `WAITING_FOR_MEMO_POPUP` | 적요 팝업 대기 | 수집 시작 | 적요 읽음 |
| `WAITING_FOR_PICKUP_POPUP` | 상차지 팝업 대기 | 〃 | 주소 읽음 |
| `WAITING_FOR_DROPOFF_POPUP` | 하차지 팝업 대기 | 〃 | 주소 읽음 |
| `DONE` | 수집 완료 | 셋 다 읽음 | `POST /orders/detail` 발신 → IDLE |

원천: 앱 `SessionManager`. ⚠️ 동명이동 3단계 검증에서 못 빠져나오는 문제가 여기 걸려 있다 (todo).

## 2-4. 안전취소 타이머 (`SafeCancelTimer`)

| 상태값 | 뜻 | 들어오는 길 | 하는 일 | 나가는 길 |
|---|---|---|---|---|
| 대기 | 타이머 없음 | — | — | 확정 클릭 |
| 카운트다운 | 30초 세는 중 | 확정 클릭 순간 | 판결 피기백 폴링 (직접콜+AUTO 면 1초 고속) | KEEP 수신 → 해제 / CANCEL 수신 → 뒤로가기 |
| 만료 | 판결이 안 왔다 | 30초 경과 | 🔴 **앱이 스스로 취소** (최후의 안전장치 — 절대 제거 금지) | 리스트 복귀 |

## 2-5. 화면 인식 (`ScreenContext` — 9종)

`LIST` · `LIST_COMPLETED`(🔴 이것도 "리스트 복귀"다 — 유령 카드 사고의 교훈) · `DETAIL_PRE_CONFIRM` · `DETAIL_CONFIRMED` · `POPUP_PICKUP` · `POPUP_DROPOFF` · `POPUP_MEMO` · `POPUP_ERROR` · `UNKNOWN`.
들어오는 길: 접근성 트리 텍스트 변화. 하는 일: 화면별 행동 분기(리스트=필터 검사, 팝업=상세 수집). 원천: `TelemetryManager` → 텔레메트리로 서버 전달. **"손을 뗀 화면"의 정의는 shared `isListScreen` 하나뿐이다.**

## 2-6. 홀드 (`isHolding`)

`true` = 콜 처리 중이라 콜리스트 읽기 중지 (확정 클릭 ~ 결재). 서버는 이 동안 필터를 비활성(`isActive: false`)으로 내린다. 원천: 텔레메트리 필드.

## 3-5-4. ⑧-1 콜 아이템 — 6단계별 노출 (`StopCallSheet` + 진행 바)

단계는 증거(마일스톤)에서 **파생**된다 — 뒤 증거가 앞을 함축 (통화 건너뛰고 상차해도 안 되돌아감).
공통 골격: 진행 바 6칸 + 「지금 할 일」 헤더(단계 이름·담당자·전화 바로걸기) + 적요 줄.
이미 지난 단계의 버튼은 `✓ 시각 · 취소`(되돌리기)로 바뀐다.

| 단계 | 이 단계에서 보이는 것 | 누르면 → 다음 |
|---|---|---|
| **1. 상차지 통화** (선택) | 단위(파레트·라면박스·마대·서류봉투·기타)·수량·방법(지게차 10분/수작업 15분/호이스트 20분/검수 90분)·성질 · **"몇 시까지 실어 보낼 수 있나요?"** 30분 격자 — 추천 칸 **미리 눌림** + 근거 한 줄 · 「이어서 — 하차지도 지금 정하기」 블록 · 건너뛰기 | 저장(`DECLARED`) → 2 · 건너뛰면(`SKIPPED`) → 2 |
| **2. 하차지 통화** (선택) | 방법 + **"몇 시까지 가면 되나요?"** 격자만 — 🔴 **부피는 안 묻는다** (상차지에서 이미 파악, 설계) | 저장 → 3 |
| **3. 상차지 도착** | `[📍 도착]` 버튼 (GPS 가 먼저 찍으면 `✓ 도착 HH:MM · 취소` 로 미리 바뀜 — `source: GPS`) · 현장 실측 폼(단위·수량·방법 = `ACTUAL` — 통화값이 미리 눌려 있음) · `[현장 내용 저장]` | 도착 → 4 |
| **4. 상차 완료** | `[📦 상차 완료]` (누르면 실측 저장 + `PICKED_UP` — 결박까지 끝났다는 뜻) · `[× 상차 취소]` — **방출**로 처리되고 장소에 사유 기록 경고 | 완료 → 5 · 상차지가 경유지에서 빠짐 · 적재 가산 |
| **5. 하차지 도착** | `[📍 도착]` (GPS 선기록 동일) · 하차 방법 실측 | 도착 → 6 |
| **6. 하차 완료** | 🔴 **착불이면 `[받았음]` 버튼이 완료 버튼 바로 위** (*"착불현금은 완료 누르기 전에 내가 받을 거야"*) — 안 누르고 완료하면 **미수금 경고** · `[하차 완료]` | 완료 → `DELIVERED` · 카드가 완료 탭으로 · 활성 0건이면 사이클 리셋 + 타겟 자동 순환 |

**부속 — 출발 카운트다운 (`DepartureCountdown`, 지도 아래)**: `GATHERING`(출발 전) + 상차완료 약속이 있을 때만 — `HH:MM 뒤에는 출발해야 합니다 (주행 N, 상차 N, 대기 N분)` — 이 자리에서 합짐을 잡을 수 있는 시간(상차버퍼)을 알려준다. 🚀 출발하면 사라진다.
