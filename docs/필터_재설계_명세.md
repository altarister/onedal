## 1. 핵심 원칙 (2026-08-13 기사님 확정)

1. **필터는 돈만 본다.** 시간(상하차·우회 시간)은 필터 계산에 넣지 않는다 — 시간 약속은 통화에서 확보된다. "원가(시간값)" 개념 폐기.
2. **판정식은 하나다.** 첫짐·합짐·운행중·관내·복귀 전부:
   ```
   통과 = 요금 ≥ 배송거리 × 단가(차종) × (1 − 눈높이)
   ```
   단계의 차이는 판정식이 아니라 **어느 콜을 보느냐**(키워드)뿐.
3. **하한 금액을 입력하지 않는다.** 단가표(고정)와 눈높이(다이얼)에서 파생된다.
   기존 특수값 전부 폐기: 첫짐 5만 · 합짐 2만 · ×0.8 사다리 · 관내 8천 · ±8% 거리 여유.
4. **눈높이는 자동으로 내려가지 않는다.** 콜이 안 잡히면 기사가 직접 한 단계 내린다 (콜의 주인은 기사님).
5. **합짐·관내·복귀-합짐은 순증 매출** — 바닥이 "전부"(금액 무관). 빈 칸으로 출발하는 것만 손해다.

### 2-2. 적재 칸

```
내 1t 트럭 용량 = 5   (정규 4칸 + 자투리 1칸 — 파레트 2개를 놓아도 660mm가 남는다)
1t짐 4 · 라보 2 · 다마스 1 · 승용차 1 · 오토바이 0(조수석)
남은 칸 = 5 − Σ 칸(잡은 콜)
```

- 근거는 바닥 면적이 아니라 **부피·중량의 최소값** (다마스는 실내높이 1.05m·450kg가 깎는다).
- **통화가 칸을 갱신한다**: 표시 차종은 "최소 필요 차종"이지 짐 양이 아니다.
  1t 콜이 실제 라면박스 20개면 1칸 → 여유 증가. 통화 확인 3요소: 양·성질(파레트/박스)·무게.
- **넘치면 기사가 포기한다** — 예외를 모델에 넣지 않는다.
- 허용 차종은 입력이 아니라 **파생값**: `칸(v) ≤ 남은 칸`인 차종. 수동 차종 토글 삭제.
- 내부 30점 스케일과 환산: 1칸 = 7.5점. ⚠️ 현재 코드 `VEHICLE_CAPACITY` 다마스 10점(=1/3)은 이 확정과 어긋남 — 수정 대상.

#### 2-4-1. 국면은 두 축의 조합이다

```
huntPhase      기사님이 버튼으로 고른다    DEST · LOCAL · HOME
dispatchPhase  콜 상태에서 파생된다        STANDBY · GATHERING · DELIVERING
```

| `huntPhase` | `dispatchPhase` | → **탭 (PhaseKey)** |
|---|---|---|
| **DEST** | STANDBY (콜 0건) | 🚚 **첫짐** `first` |
| **LOCAL** | STANDBY (콜 0건) | 🏘️ **관내** `local` |
| **HOME** | STANDBY (콜 0건) | 🏠 **복귀** `home` |
| *어느 쪽이든* | GATHERING (콜 1건↑) | 📦 **합짐** `merge` |
| *어느 쪽이든* | DELIVERING (출발 후) | 🛣️ **운행 중** `drive` |

**첫짐 3종 + 합짐 + 운행중.** 기사님: *"합짐·운행중은 무조건 **경로가 생기고 난 이후**에
발생하니까"* — 경로가 있으면 회랑이 그 경로에서 파생되므로 어디서 출발했든 같은 기준이면 된다.
(합짐을 3종으로 나누는 안은 이 근거로 기각했다)

```ts
function resolvePhaseKey(hunt: HuntPhase, dispatch: DispatchPhase): PhaseKey {
    if (dispatch === 'DELIVERING') return 'drive';
    if (dispatch === 'GATHERING')  return 'merge';
    return hunt === 'LOCAL' ? 'local' : hunt === 'HOME' ? 'home' : 'first';
}
```

#### 2-4-2. 하루 흐름 (기사님, 2026-08-14)

> *"첫짐 - 합짐 - 운행중 - 관내 - 합짐 - 운행중 - 복귀 - 합짐 - 운행중
> 이렇게 하루 일과가 작동할 것 같아."*

```
🚚 첫짐 ──잡음──▶ 📦 합짐 ──출발──▶ 🛣️ 운행중 ──다 내림──▶
🏘️ 관내 ──잡음──▶ 📦 합짐 ──출발──▶ 🛣️ 운행중 ──다 내림──▶
🏠 복귀 ──잡음──▶ 📦 합짐 ──출발──▶ 🛣️ 운행중 ──끝
   ↑
   기사님이 버튼으로 고르는 것은 이 셋뿐 (huntPhase). 나머지는 콜 상태에서 파생.
```

**관내·복귀는 "첫짐의 자리"다** — *어디서 첫 콜을 찾을 것인가*. 그다음은 어느 쪽에서
출발했든 똑같이 합짐 → 운행중으로 흐른다.

**쓰는 방법 두 가지 (기사님 예시)**
- *"오후에 약속이 있으니 관내만 하고 일찍 끝내자"* → 아침에 국면을 🏘️ 관내로 두고 시작
- *"어제 저녁에 안산 도착 내일짐을 수락했다"* → 첫짐 탭의 도착 도시를 안산으로 하고 **오늘만** 저장

🔴 **이 표 자체를 코드로 만든다** (`PHASE_FIELDS`). 화면은 이걸 읽어 그리고, 서버도 이걸로
"그 국면에서 안 쓰는 값"을 판정에서 뺀다. **규칙이 한 곳에만 있어야** 나중에 갈라지지 않는다.

🔴 **🤖 는 저장하지 않는다.** 파생값을 저장 슬롯에 넣으면 낡은 값이 남는다 —
오늘 관내에서 뽑힌 "파주시"가 내일 아침에 그대로 남는 식이다.

#### 2-4-6. 타입

```ts
export type PhaseKey = 'first' | 'merge' | 'drive' | 'local' | 'home';

/** 국면 하나가 기억하는 값 — 다섯 국면이 **같은 모양**이다 */
export interface PhaseSettings {
    destinationCity: string;   // 🖊️ first 만 저장. 나머지는 런타임 파생
    pickupRadiusKm: number;
    detourAllowKm: number;
    dropoffRadiusKm: number;
    discountPct: number;
}
export type PhaseSettingsMap = Record<PhaseKey, PhaseSettings>;

/** 국면마다 어느 필드를 어떻게 다루는가 — 위 표(2-4-5)를 그대로 옮긴다 */
export type FieldMode = 'input' | 'auto' | 'hidden';
export const PHASE_FIELDS: Record<PhaseKey, Record<keyof PhaseSettings, FieldMode>>;
```

#### 2-4-7. 저장과 적용

| 무엇 | 어디 | 언제 | 되돌아감 |
|---|---|---|---|
| **평소값** | DB `user_filters.phase_settings` (JSON) | `📌 계속` | — |
| **오늘값** | 메모리 `session.phaseSettings` | `🟢 오늘만` | **자정에 평소값으로** |
| 🤖 파생 | 저장 안 함 | 국면 진입 때 계산 | — |
| 공통 (제외 단어 · 집 주소 · 차종) | 기존 그대로 | — | 국면과 무관 |

```
로그인      DB ──복사──▶ 오늘값 (5국면 전부)
국면 전환    오늘값[탭] ──펼침──▶ activeFilter 평면 ──피기백──▶ 앱
            (🤖 필드는 런타임 계산으로 덮어쓰고, 키워드·별칭·허용차종은 filterManager 가 재계산)
🟢 오늘만    노란 점 붙은 탭들의 조각만 오늘값에 반영 (DB 불변)
📌 계속      위 + DB phase_settings 갱신
🔄 평소값    DB ──▶ 폼으로 되돌림
자정        오늘값 = DB 값
```

**DB 컬럼을 3×5=15개로 늘리지 않는다.** `vehicle_rates` 와 같은 방식으로 JSON 한 칸이다.
**`AutoDispatchFilter` 는 지금처럼 평면을 유지한다** — 국면이 바뀔 때 조각을 펼쳐 넣는다.
그래야 앱(`InsungParser`)과 기존 코드가 안 깨진다.

#### 2-4-8. 누가 그 값을 쓰는가

| 필드 | 앱 (1차 필터) | 서버 (데스밸리 판정) |
|---|---|---|
| 도착 도시 | ❌ (키워드로 변환돼서 옴) | ✅ 키워드·시 별칭 생성 |
| 상차지 반경 | ✅ `상차거리 ≤ 반경` | — |
| 경유 허용 | ❌ | ✅ 회랑 폭 → 키워드 |
| 하차지 반경 | ❌ | ✅ 하차지 주변을 회랑에 합침 |
| 단가 할인율 | ✅ (단가표로 변환돼서 옴) | ✅ 요율 판정 |

#### 2-4-9. 이 기준이 고쳐 주는 것

- **출발하면 회랑이 0 으로 굳는 버그** — 운행중의 `0` 과 합짐의 `5` 가 따로 산다
- **관내에 갔다 오면 반경이 0 으로 남는 버그** — 국면마다 자기 값을 갖는다
- **화면이 거짓말하던 것** — 지금은 합짐 탭에서 반경을 고치면 첫짐 것도 같이 바뀐다
- **매일 같은 루틴** — 국면이 바뀌면 그 국면의 저장값이 자동으로 적용된다.
  특별한 날만 `오늘만` 으로 덮어쓰고 자정에 돌아온다

## 3. 경유 (용어 확정)

- **경유 +N km** = 카카오 **총거리 증가분** (100km → 105km면 +5km). 옆으로 벗어난 반경(회랑)이 아니다.
- 사용자는 경유 허용(+N km)만 설정. **회랑 반경 = 경유 허용 ÷ 2** 로 서버가 파생 (최악: 갔다 와야 하므로 ×2).
- 정확한 판정은 데스밸리 30초 동안 서버가 카카오로 잰 **콜별 실제 경유 증가분**으로.
- 경유를 넓혀도 비용이 아니다 — 후보가 늘 뿐. 좁히는 이유는 운전 중 조작 최소화(운행중 +0)뿐.
- ⚠️ **화면 표기는 "우회 허용"이다** (2026-08-14 기사님: *"목업에 만들어둔 명칭도 그대로 사용해"*).
  이 문서의 본문은 뜻을 설명하느라 "경유"라고 쓰지만, **기사님이 보는 화면과 코드 라벨은 "우회 허용"** 이다.
  (내부 키 이름은 `detourAllowKm` 로 그대로 — 화면 라벨과 키 이름은 별개다)

## 4. 화면 구조

### 4-1. 관제웹 메인 = 상태·조작

```
┌ 요약줄 (스와이프 카드 3장) ─────────────────────────────┐
│ 🎯 여기서 반경 10km → 파주시 10km 반경으로 필터링 [첫짐] │   탭     → 필터 설정 팝업
│ 💰 금액 -10% (1t ≥ 693원/km) · 📍 지역 122동 · 📦 0/5칸 │   스와이프 → 다음 국면
│                    ● ○ ○                              │
├ 지도 ─────────────────────────────────────────────────┤
│ [🚀 지금 출발]  ← 좌하단 플로팅 버튼 (운행중 전환·경유 +0) │
└───────────────────────────────────────────────────────┘
  콜 카드 (KEEP/CANCEL 결재)
```

**하루 국면 = 스와이프 카드 3장** — 스와이프 순서가 하루의 흐름과 같다:

| # | 카드 | 제목줄 (필터를 사람 말로) | 사냥 대상 | 팝업 탭 |
|---|---|---|---|---|
| 1 | 🎯 목적지행 | "여기서 반경 10km → 파주시 10km 반경으로 필터링" | 첫짐·합짐 | 첫짐/합짐/운행중 |
| 2 | 🏘️ 이 동네에서 찾기 | "이 동네(파주시) 안에서 끝나는 콜 찾기" | 관내 | 관내 |
| 3 | 🏠 복귀행 | "여기서부터 집으로 10km 범위로 필터링" | 복귀 | 복귀 |

- **사냥은 언제나 한 방향** (동시 두 필터 없음). 관내 병행 토글은 폐지 — 관내는 토글이 아니라 카드다.
  투트랙은 순차 전환으로 커버된다: 관내 콜을 **잡고 나면**(수행=배달은 사냥과 무관) 복귀행으로 스와이프.
  아침에 목적지 콜이 없으면 이동네 카드로 스와이프하면 된다.
- **카드 형식 (고정)**: 제목줄 = 필터 문장 + 단계 뱃지(`첫짐`/`합짐 N번째`/`관내`/`복귀`) + 상태(사냥 중/잠깐 멈춤/꺼짐+이유).
  아랫줄 = 항상 같은 순서 **① 💰 금액(할인율) ② 📍 지역(동 수) ③ 📦 적재(x/5칸)**.
- 🔴 **스와이프 전환은 폐기했다 (2026-08-14).** 기사님: *"드래그로 바꾸면 안 될 듯싶다.
  이렇게 필터가 쉽게 바뀌면 오작동이 될 가능성이 있을 것 같다. 버튼을 누르게 하고
  알럿창으로 확인받는 것이 안전할 듯하다."*
  국면 전환은 목적지·반경을 바꾸고 **회랑을 통째로 재계산**한다(지리 연산 수 초 + 앱 필터 교체).
  운전 중 스크롤하다 손가락이 스치면 사냥이 엉뚱한 방향으로 간다. 임계값(80px)·탭 판정(6px)을
  넣어도 완전하지 않았다. 하루 두 번 하는 조작이라 **확인 한 번이 부담이 아니다.**
- **국면 전환 = 버튼 3개 + `confirm`**: 요약줄 아래 `🎯 목적지행 / 🏘️ 이 동네에서 찾기 / 🏠 복귀행`.
  지금 국면 버튼은 비활성. 확인창에 "잡아 둔 콜은 그대로 있습니다 (필터만 바뀝니다)"를 적어
  콜이 사라지지 않는다는 것을 분명히 한다. 전환 후 토스트.
- 요약줄 본문을 누르면 필터 설정 팝업.
- 출발 감지: GPS가 상차지 200m 벗어나 60초 → **알림만** ("출발하셨나요?"). 자동 전환 없음.

### 4-2. 필터 설정 팝업 = 기준

```
┌ 필터 설정                × ┐   ← 슬림 타이틀바 (한 줄)
│ 제외 단어 [착불, 수거]      │   ← 공통은 이것 하나
│ 첫짐● 합짐 운행중 관내 복귀  │   ← 탭 부제 없음 · 초록점=지금 · 노란점=미저장 변경
│ ── 탭 내용 ──              │
│  입력: 목적지·반경·눈높이    │
│  하한표: 차종별 단가·N/5칸  │   ← 자동 계산, 읽기 전용
│  동 미리보기 (359개 동…)    │   ← 유지 (숫자 피드백)
│ [평소값][오늘만 적용][계속]  │   ← 전역 저장 + "N곳 변경" 표시 · 자정에 평소값 복귀
└───────────────────────────┘
```

- **팝업에서 삭제된 것** (메인으로 이동 또는 파생화): 방향 스위치·관내 토글(→ 메인 버튼),
  🚀 출발·🏠 복귀 전환 버튼(→ 메인), 허용 차종 수동 토글(→ 칸 파생), 모든 설명 문구 박스.
  ✅ 2026-08-14 이행 완료. 한 번 어겼다가 되돌렸다 — 팝업 안 전환 버튼은 **요약줄에만 있는
  `confirm` 을 우회**했고, `onClose()` 로 **저장 안 한 값을 조용히 버렸다**.
  규칙 테스트로 고정(`phaseUi.test.ts` — 팝업에 `set-hunt-phase` 가 없다).
  ⚠️ **🏠 귀가콜 만들기는 남겼다** — 국면 전환이 아니라 *가상 오더 생성*이고, 지금 부르는 곳이 여기뿐이다.
- **지역 카드는 접지 않는다.** 아코디언에 접혀 있으면 반경을 바꿔도 뭐가 걸리는지 안 보인다.
  숫자(`359개 동`)와 시/구 칩을 항상 띄우고, 값을 바꾼 뒤 `🔍 미리보기` 로 다시 센다.
- **제외 단어는 탭 위**다. 다섯 탭 공통인 값이 탭 안에 있으면 "이 탭에만 걸리나"로 읽힌다.
- 하한표 행 형식: `차종  시세 N원/km · N/5칸  |  ≥ N원/km  (거리 예시 금액)`.
