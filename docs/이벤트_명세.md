# 이벤트 명세 — 앱·서버·관제웹의 모든 이벤트 (6하원칙)

> **2026-08-17 코드 실측.** 원천은 코드다 — `pnpm map`(소스에서 추출)과 `pnpm audit:socket` 이
> 살아 있는 지도이고, 이 문서는 거기에 **언제(트리거)와 왜(목적)** 를 붙인 스냅샷이다.
> 코드가 바뀌면 `pnpm map` 을 다시 돌려 이 문서와 대조할 것.
>
> - **주어를 반드시 쓴다** — 앱(안드로이드) · 서버 · 관제웹 셋이 같은 값을 다르게 쓴다
> - 어떻게(채널)는 절 제목이 말한다: §2 REST · §3 피기백 · §4·§5 소켓
> - ⚠ = 짝이 없는 이벤트 (쏘는데 아무도 안 듣거나, 듣는데 아무도 안 쏨) — 죽은 문 후보

## 1. 큰 그림 — 통신은 세 길뿐이다

```
앱 ──── REST(POST /api/scrap 등) ────▶ 서버          앱은 소켓을 안 쓴다 (모바일 웹소켓 끊김 회피)
앱 ◀─── 피기백(응답 꼬리에 명령) ───── 서버          서버는 앱을 먼저 부르지 못한다 — 응답에 실어야 한다
서버 ◀──────── Socket.IO ────────▶ 관제웹           io.to(userId) 개인 룸 — 전역 방송 0곳
```

## 2. 앱 → 서버 (REST)

| 무엇을 (엔드포인트) | 언제 (트리거) | 무엇을 싣나 | 왜 | 어디서 받나 |
|---|---|---|---|---|
| `POST /api/scrap` | 앱이 배차망 화면을 읽을 때마다 (수 초 간격 텔레메트리) | 콜 목록 · deviceId · 화면 종류 · GPS · 홀드 상태 · **판결 ACK** | 서버가 콜을 알고, 기기 생사를 알고, 피기백 회신 통로가 되게 | `routes/scrap.ts` |
| `POST /api/orders/confirm` | 확정 버튼이 눌린 직후 (1차 선점 — 필터콜이든 직접콜이든) | 콜 기본 정보 · `matchType`(AUTO/MANUAL) · capturedAt | 선점 사실을 즉시 알리고 안전취소 30초를 시작 | `routes/orders.ts` |
| `POST /api/orders/detail` | 무인 서핑으로 2차 상세 화면을 다 읽었을 때 | 온전한 주소 · 적요 · 요금 상세 | 서버가 좌표·경로·판정을 계산할 재료 | `routes/detail.ts` |
| `POST /api/emergency` | 앱이 비상 상황을 감지했을 때 | 사유 · orderId | 서버가 콜을 정리하고 관제탑에 경보 | `routes/emergency.ts` |
| `POST /api/devices/pair` | 앱 첫 연결(기기 등록) | deviceId | 기기 ↔ 기사 짝짓기 | `routes/devices.ts` |
| `POST /api/devices/:id/offline` | 앱 종료/백그라운드 진입 | — | 기기 꺼짐을 관제탑에 표시 | `routes/devices.ts` |

## 3. 서버 → 앱 (피기백 — REST 응답 꼬리)

| 무엇을 | 언제 | 무엇을 싣나 | 왜 |
|---|---|---|---|
| **판결** `decision` | 기사님이 결재한 뒤 **다음 텔레메트리 응답**에 | `KEEP`/`CANCEL` + **orderId** (앱이 대조) | 안전취소 30초 안에 콜을 살리거나 버리게. 🔴 **앱이 ACK 할 때까지 큐에서 안 지운다** — 유실 방지 |
| **콜 필터** | 필터가 바뀐 뒤 다음 응답에 | 타겟 도시 · 반경 · 허용 차종 · 단가표(`ratePerKm`) · 제외어 | 앱의 1차 필터를 갱신 — 느슨하게 잡아오게 |
| **상세 진행 지시** | `/orders/confirm` 응답 즉시 | "상세 스크래핑을 진행하라" | 2차 상세를 무인으로 읽어 오게 |

## 4. 서버 → 관제웹 (소켓 emit — `io.to(userId)`)

### 콜의 일생

| 이벤트 | 언제 | 무엇을 싣나 | 왜 |
|---|---|---|---|
| `order-evaluating` | 1차 선점 수신 직후 | 콜 요약(주소는 아직 축약) | "지금 이 콜을 잡았다"를 즉시 보여줌 — 카드가 뜬다 |
| `order-detail-received` | 2차 상세 파싱 완료 | 온전한 주소·적요·요금 | 카드를 상세로 채움 |
| `order-evaluated` | 판정(색) 계산 완료 | 색(꿀/보통/똥) · 점수 · 사유 · 경로 폴리라인 | **기사님이 색만 보고 1~2초 안에 결재**하게 (⑤-3) |
| `order-confirmed` | KEEP 결재 처리 완료 | 확정된 콜 | 카드가 "내 콜"로 바뀜 |
| `order-canceled` | CANCEL/방출/사무실취소/자동정리 | orderId · 사유 | 카드를 취소/방출 탭으로 이동 (사라지지 않는다) |
| `sync-active-orders` | 상태가 바뀔 때마다 + 주기 보정 | 진행/종료 **나눠서** 전체 목록 | 새로고침·유실에도 화면과 서버가 같은 목록을 보게 (자동 치유) |
| `safecancel-warning` | 안전취소 30초가 위험해질 때 (서버 타임아웃 임박) | orderId | 결재를 서두르라는 경보 |

### 필터 · 판정 기준 · 국면

| 이벤트 | 언제 | 무엇을 싣나 | 왜 |
|---|---|---|---|
| `filter-init` | 소켓 접속 순간 + `request-filter-init` 요청 시 | baseFilter + activeFilter + 국면 설정 | 관제웹이 첫 화면을 채울 근거 |
| `filter-updated` | 필터가 실제로 바뀌었을 때만 (직전 전송본과 같으면 안 보냄) | activeFilter 전체 | 요약줄·필터 팝업 갱신 |
| `judgment-init` / `judgment-updated` | 접속 시 / 저장 후 | 판정 기준 전체 (콜 필터와 **다른 이벤트** — 격리 설계) | 「판정 기준」 탭 폼 채움 |
| `create-home-return` 응답 (`home-return-ack`/`-error`) | 귀가콜 생성 성공/실패 | 가상 오더 | 귀가콜은 국면 전환이 아니라 오더 생성 |

### 통화 시트 · 마일스톤 · 정산

| 이벤트 | 언제 | 무엇을 싣나 | 왜 |
|---|---|---|---|
| `cargo-report-saved` | 통화/현장 신고 저장 완료 | 신고 내용 (DECLARED/ACTUAL/SKIPPED) | 시트·적재 표시 갱신 |
| `cargo-mismatch` / `-resolved` | 통화 대비 현장 실측이 1.5배 이상 다를 때 / 해소 | 비율 · 양쪽 값 | 🚨 배너 — 차종이 좁아질 수 있다는 경고 |
| `milestone-log` | 도착·상차완료·하차완료 기록 시 | 마일스톤 · 시각 · 예상 대비 차이 | 진행 바(6단계) 전진 |
| `settlement-updated` | 착불 수금 등 정산 항목 변경 | 정산 상태 | 시트의 수금 표시 |

| `settings-updated` ⚠ | (서버에 쏘는 곳 없음) | | 죽은 문 후보 |

## 5. 관제웹 → 서버 (소켓 emit)

| 이벤트 | 언제 (기사님이 무엇을 했을 때) | 무엇을 싣나 | 왜 |
|---|---|---|---|
| `decision` | 결재 카드에서 KEEP/CANCEL 누름 | orderId · action | **이 제품의 핵심 행위** — 피기백으로 앱까지 전달 |
| `update-filter` | 🔍 필터 팝업에서 값 저장 (오늘만) | 바뀐 키만 | activeFilter 갱신 → 파생 재계산 → 앱 피기백 |
| `save-phase-settings` | ⚙️ 국면별 설정 저장 (평소) | 국면 키 + 조각 | baseFilter/phase_settings 저장 |
| `set-call-target` | 요약줄 스와이프로 타겟 전환 | DEST/LOCAL/HOME | 국면 전환 — 콜은 건드리지 않는다 |
| `save-judgment` | 「판정 기준」 탭 [적용] | 판정 기준 전체 (한 번에) | 트랜잭션 하나로 저장 |
| `save-cargo-report` | 통화/현장 시트 저장 | 단위·수량·방법·성질·약속 시각 | 적재·정차·마감 계산의 원료 |
| `set-stop-deadline` | 카드에서 약속 시각 확정 | 정거장 · 시각 | 완료 약속 갱신 → 버퍼 재계산 |
| `report-milestone` / `undo-milestone` | [도착]·[상차 완료]·[하차 완료] / 되돌리기 | 마일스톤 | 6단계 전진/후퇴 — 증거로 상태 파생 |
| `cod-collected` | 착불 [받았음] | orderId · 금액 | 수금 기록 |
| `cancel-at-stop` | 시트에서 [상차 취소] | orderId · 사유 | 방출 처리 + 장소에 사유 기록 |
| `resolve-cargo-mismatch` | 🚨 배너에서 해소 선택 | 선택 | 경고 닫고 적재 재계산 |
| `create-home-return` | 필터 팝업에서 귀가콜 생성 | 집 주소 | 집까지 가상 오더 |
| `recalculate-route` | 카드에서 경로 재계산 | orderId | 카카오 경로 다시 |
| `dashboard-gps-update` | GPS 브리지가 위치 변화 감지 (실 GPS 또는 시뮬레이터) | 좌표 + **출처** | 서버가 위치 기반 판단 (도착 감지·트림) |
| `request-filter-init` / `request-judgment` / `request-cargo-reports` / `request-milestones` / `request-settlement` | 첫 이벤트를 놓쳤거나 재접속 | — | 놓친 초기값 재요청 (자동 치유) |

## 6. 콜 상태 전이 (`orders.status` — 10종)

```
[심사]  ORDER_PRE_SECURED ──확정버튼──▶ ORDER_SECURED_EVALUATING ──판정──▶ ORDER_AWAITING_DECISION
                                          (여기부터 버리면 패널티)              (안전취소 30초 · 후보콜)
[확정]  ──KEEP──▶ ORDER_CONFIRMED ──상차──▶ ORDER_PICKED_UP ──하차──▶ ORDER_DELIVERED (관제앱의 끝)
[취소]  ORDER_CANCELED(거절) · ORDER_RELEASED(방출) · ORDER_FORCE_CANCELED(콜전화취소/사무실취소 — 패널티 X)
[정산]  ORDER_COMPLETED — 정산 페이지 소관 (관제앱은 안 본다)
```

- 상태를 **손으로 정하지 않는다** — 마일스톤(증거)에서 파생 (`deriveStatusFromMilestones`)
- 🔴 콜전화취소(내 의지)와 사무실취소(당함)는 **같은 상태로 저장돼 구분 안 됨** — 주선사 분석 하려면 구분 저장 필요 (todo)

## 7. 마일스톤 (`order_milestones` — 배송 단계의 증거)

| 마일스톤 | 언제 (누가) | 왜 |
|---|---|---|
| `ARRIVE_PICKUP` | 상차지 도착 — 관제웹 버튼 또는 GPS 500m 감지 | 접근 끝 — 정차 시작 |
| `LOADED` | 상차+결박 완료 — 관제웹 버튼 | `ORDER_PICKED_UP` 파생 · 상차지가 경유지에서 빠짐 |
| `ARRIVE_DROPOFF` | 하차지 도착 | 배송 끝 임박 |
| `DELIVERED` | 하차 완료 — 관제웹 버튼 | `ORDER_DELIVERED` 파생 · **매출 집계는 내린 날 기준** |

통화 두 단계(`CALL_PICKUP`·`CALL_DROPOFF`)는 마일스톤이 없다 — 보고할 일이 아니라 선택 단계다.
뒤 증거가 앞을 함축한다 (통화 건너뛰고 상차해도 되돌아가지 않는다).

## 9. ⚠ 볼 곳 — `pnpm map` 이 표시한 비대칭 (규칙 위반이 아니라 점검 목록)

- **듣는데 아무도 안 쏨**: `auto-arrived` · `stale-orders-dropped` · `settings-updated` — 죽은 문 후보
- **쏘는데 아무도 안 들음**: `call-target-ack` · `decision-ack` · `milestone-result` · `recalculate-route-ack`
- **여러 파일이 같은 이벤트를 쏨**: `order-canceled`(3파일) · `order-evaluated`(3파일) · `sync-active-orders`(2파일+주기) — 순서·중복 사고가 나면 여기부터 볼 것
