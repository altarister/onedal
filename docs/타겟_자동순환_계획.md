# 타겟 자동 순환 — 사이클이 끝나면 다음 타겟을 미리 눌러 둔다 (⑤-4 계획)

> 기사님 발의 (2026-08-17): *"노선을 따라 다 수행했으면 복귀로 바뀌어야 할 것 같은데..
> 일반적으로 복귀가 맞을 것 같고, 사용자가 시간이 많이 남았다 판단하면 관내로 스와이프.
> 복귀가 끝나면 다시 노선으로."*
>
> 방식은 **"미리 눌러 두고 기사님이 확정"** — 강제 전환이 아니라 제안이다 (콜의 주인 원칙).
> ⑤-4: 아래 넷이 확정되기 전에 코드를 시작하지 않는다.

## 순환 규칙 (제안)

```
노선 사이클 끝 (활성 콜 0 · 마지막 하차 완료)
   ├─ 마지막 하차지가 집 반경 안  → 타겟 유지 (노선) — 복귀가 무의미
   └─ 그 외                      → 복귀를 미리 눌러 둠 + 배너
                                    "🏠 복귀행으로 바꿔 뒀습니다 — 시간이 남으면 관내로 스와이프"
복귀 사이클 끝 (복귀콜 하차 완료)  → 노선으로 되돌림 + 배너
관내                              → 자동 진입 없음 — "시간이 남았다"는 기사님만 아는 판단
취소·방출로 0건이 된 경우          → 전환 없음 — 일이 끝난 게 아니라 무산된 것이다
```

## ① 스키마 — 새 저장값 없음

- 타겟(`callTarget`)은 이미 세션(하루 스코프)에 있다 — 자동 순환은 **전환 트리거**만 추가
- 전환 알림은 기존 `filter-updated` + 새 소켓 이벤트 `target-auto-switched` 1개 (배너용)

## ② 값 — ❓ 기사님 확정 필요

| 값 | 제안 | 근거 |
|---|---:|---|
| 집 반경 (복귀 무의미 판정) | **5km** ❓ | 첫짐 상차 반경 기본값과 같은 감각 |
| 전환 시점 | 사이클 리셋 직후 (STANDBY 복귀 불변식 안) | 필터 재계산이 이미 도는 자리라 **한 번에 겹쳐서** — 재계산 2번 방지 |
| 배너 지속 | 20초 + 닫기 | 근접 예고와 같은 패턴 |

## ③ 시점 — 언제 읽고 쓰나

| 언제 | 무엇 |
|---|---|
| 하차 완료로 활성 0건 → STANDBY 복귀 순간 | 마지막 하차지 vs 집 좌표 거리 → 규칙대로 타겟 결정 → 국면·필터 재계산 (기존 흐름에 얹음) |
| 복귀콜 하차 완료 | 노선으로 되돌림 |
| 스와이프 (`set-call-target`) | **언제나 이긴다** — 자동은 제안일 뿐 |
| 자정 | 기존 규칙대로 (어제 상태가 오늘 안 되살아남 — 타겟도 기본 DEST) |

## ④ 화면 — 어디에 어떤 이름으로

- 요약줄 타겟 버튼이 자동으로 이동 (노선행 → 복귀행) — 기존 UI 그대로
- 배너 (Dashboard, 근접 예고와 같은 자리): `🏠 복귀행으로 바꿔 뒀습니다 — 시간이 남으면 관내로 스와이프` / `🎯 집에 도착했습니다 — 노선행으로 돌아갑니다`
- 되돌리기 = 스와이프 그 자체 (별도 버튼 없음)

## 사이드이펙트

| # | 위험 | 방어 |
|---|---|---|
| ① | 사이클 리셋과 필터 재계산 겹침 — 자동 전환이 재계산을 또 돌리면 2중 | 전환을 **리셋 불변식 안에서** 처리 — 재계산 한 번에 합침 |
| ② | 취소·방출로 0건 됐을 때 오전환 | "하차 완료로 끝난 사이클"에만 발동 (마지막 이벤트 확인) |
| ③ | 복귀 타겟인데 집 좌표 미설정 | 집 좌표 없으면 전환 안 함 (지어내지 않는다) |
| ④ | 자동 전환 직후 기사님 스와이프와 경합 | 스와이프가 항상 이김 — 서버는 마지막 `set-call-target` 을 존중 |

## 검증

- L1: "취소로 끝난 사이클은 전환하지 않는다" · "스와이프가 자동을 이긴다" 규칙 테스트
- L2: 전환 판정 순수함수 (마지막 하차지·집 좌표·종료 사유 → 다음 타겟)
- L3: scenario — 하차 완료 사이클 끝 → 타겟 HOME 확인 · 취소 끝 → 유지 확인
- L4: 모의주행 — 노선 2콜 완료 → 복귀행 배너 · 복귀콜 완료 → 노선행 복귀
