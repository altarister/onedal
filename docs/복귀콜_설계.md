# 복귀콜 — 언제, 어떻게 잡는가

기사님(2026-08-24): *"3콜을 묶어서 **목적지 도착 즈음에** 집으로 가는 콜을 잡아두면 좋겠다는
생각이었지."*

> 이 문서는 **«언제 어떻게 복귀콜을 잡는가»** 하나만 다룬다.
> 판정 색·적재·요금은 여기 없다.

---

## 1. 왜 지금 구조로는 안 되는가

지금은 **하차가 다 끝나 빈차가 된 뒤에** 복귀를 시작한다.

```
지금:  ▓▓▓ 3콜 하차 완료  →  활성 0건  →  그제서야 복귀행  →  빈차로 찾기 시작
의도:  ▓▓▓ 달리는 중      →  마지막 하차 즈음 복귀콜 확보  →  실어서 귀가
```

🔴 **«콜 0건»을 신호로 쓰면 이미 늦다.** 그 순간엔 빈차이고, 여주에서 집까지 빈차로 온다.
기사님이 저장해 두신 노하우 자막이 같은 말을 한다 — *"들어가기 전에 나올 계획을 세운다"*,
*"천안에서 빈차로 나와 본 적이 없다"*.

### 실제로 오늘 이렇게 나왔다 (2026-08-24 로컬 시뮬)

```
16:33:08  🔗 [불변식] dispatchPhase DELIVERING → STANDBY (활성 콜 0건)
16:33:08  🧭 [국면 설정] drive → first · 상차 15km · 하차 5km          ← 첫짐으로 잘 돌아감
16:33:09  🧭 [국면 전환] DEST → HOME                                   ← 그런데 곧바로 복귀행
16:33:09  🧭 [국면 전환] 완료 → 복귀행 · 목적 광주시 · 콜 0
```

목적지가 **여주 → 광주**로 갈아치워져서, 그다음 여주행 콜(①)이 도착지에서 전부 걸렸다.

원인은 «타겟 자동 순환»의 판단 규칙 하나다 (`shared/src/phases.ts`).

```ts
if (cur === 'DEST' && distToHomeKm <= HOME_RADIUS_KM) return null;   // 집 5km 안이면 그대로
return 'HOME';                                                        // 그 밖은 무조건 복귀
```

**«집까지 거리»만 본다.** 여주 7.6km 앞에서도 20km 떨어진 집으로 돌아가자고 한다.
기사님이 정한 노선(여주)도, *"여주에 콜이 많다"*는 판단도 보지 않는다.

> ⚠️ 이건 **버그가 아니다.** 2026-08-17 에 기사님이 확정한 기능이고, 주석에도
> *"자동은 제안이다 — 스와이프가 언제나 이긴다"* 고 적혀 있다.
> 다만 **전제가 바뀌었다** — *"한 바퀴 끝났으니 집에 갈 시간"* 에서
> *"콜이 많은 곳에 왔으니 거기서 또 잡는다"* 로.

---

## 2. 규칙 — 한 줄

```
남은 하차가 1건이 되면
  → 그 마지막 하차지에서 출발하는 콜을 찾기 시작한다
  → 자동으로 바꾸지 않고 30초 토스트로 묻는다
```

**«마지막 하차지»가 복귀콜의 상차지다.** 어디까지 갔는지는 상관없다.

---

## 3. 두 시나리오 — 실제로 같은 구조다

전제: **목적지 = 여주** (기사님이 *"여주는 콜이 많다"* 고 판단해 정한 노선)

### A. 아직 여주에 안 감

```
야탑→이천 · 야탑→광주 를 싣고 출발
  → 광주 하차 완료 → 남은 1건(이천행) → 마지막 하차지 = 이천
```

### B. 여주 도착 예정

```
야탑→여주 · 야탑→이천 을 싣고 출발
  → 이천 하차 완료 → 남은 1건(여주행) → 마지막 하차지 = 여주
```

**둘 다 «남은 하차 1건 → 그 하차지가 상차 기점»** 으로 설명된다.

---

## 4. 세 갈래와 필터 값 — 예시

지명을 둘씩만 놓고 든 예다 (실제로는 시마다 수십 개).

```
여주시: [가남읍, 점동면]   이천시: [부발읍, 대월면]
광주시: [태전동, 초월읍, 곤지암읍]  성남시 분당구: [야탑동, 정자동]
```

### 🏙️ 성남처럼 **구가 있는 시**는 어떻게 들어가나

지리 데이터는 **시와 구를 한 문자열로** 묶어 부모 이름으로 쓴다. 동은 법정동 이름만 쓴다.

```
parentName = "성남시 분당구"      ← 시+구가 한 덩어리
동         = "야탑동", "정자동"   ← 구를 안 붙인다
```

별칭(`customCityFilters`)은 `cityAliases()` 가 자동으로 만든다.

```
"성남시 분당구"  →  ["성남시 분당구", "성남시 분당", "분당구", "분당"]
```

🔴 **`분당구`·`분당` 단독형이 들어가는 이유** — 배차망 리스트가 시를 생략하고
**`분당구`** 라고만 주기 때문이다 (기사님 지적 2026-08-23). 이게 없어서 합짐 국면에서
구 단위 콜이 전멸한 적이 있다.

⚠️ **이름이 겹치는 구는 단독형을 안 넣는다.** `중구` 는 서울·인천 양쪽에 있어서,
단독형을 실으면 서울 중구를 지날 때 인천 중구 콜을 잡는다. 유일한 구인지는
**지도에서 세어** 판단한다 (`isUniqueDistrictName`).

### 앱이 거르는 방법 — 두 단계를 **둘 다** 본다

```
콜의 도착지 텍스트 = "경기 여주시 가남읍 본두1길 17"

[1단계] customCityFilters 검사 : «여주» 또는 «여주시» 가 있나?      → ✅
[2단계] destinationKeywords 검사: «가남읍» 또는 «점동면» 이 있나?   → ✅
                                 둘 다 있어야 통과
```

**왜 둘 다 보나** — 동 이름만 보면 «신촌동»이 서울·파주 양쪽에 있어 엉뚱한 콜이 통과하고,
시 이름만 보면 «광주»가 경기 광주·광주광역시 둘 다 걸린다.
(`destinationGroups` 는 앱 판정에 안 쓴다 — 관제웹 화면 표시와 서버가 별칭을 뽑는 데 쓴다)

### A. 마지막 하차지 = **이천**

| 고른 것 | `destinationKeywords` | `customCityFilters` | 상차 기점 | 잡히는 콜 |
|---|---|---|---|---|
| **여주 계속** (노선행) | `[가남읍, 점동면]` | `[여주, 여주시]` | **이천** | 이천 → 여주 |
| **복귀** (복귀행) | `[야탑동, 정자동]` | `[성남시 분당구, 분당구, 분당]` | **이천** | 이천 → 성남 |
| **둘다** | `[가남읍, 점동면, 야탑동, 정자동]` | `[여주, 여주시, 성남시 분당구, 분당구, 분당]` | **이천** | 이천 → 여주 · 이천 → 성남 |

### B. 마지막 하차지 = **여주**

| 고른 것 | `destinationKeywords` | `customCityFilters` | 상차 기점 | 잡히는 콜 |
|---|---|---|---|---|
| **여주 관내** (관내) | `[가남읍, 점동면]` | `[여주, 여주시]` | **여주** | 여주 → 여주 |
| **복귀** (복귀행) | `[야탑동, 정자동]` | `[성남시 분당구, 분당구, 분당]` | **여주** | 여주 → 성남 |
| **둘다** | `[가남읍, 점동면, 야탑동, 정자동]` | `[여주, 여주시, 성남시 분당구, 분당구, 분당]` | **여주** | 여주 → 여주 · 여주 → 성남 |

### 🔴 A와 B의 필터 값은 **완전히 같다** — 다른 건 상차 기점뿐

```
A ①  keywords=[가남읍,점동면]  alias=[여주,여주시]  기점=이천  →  이천→여주  (노선)
B ①  keywords=[가남읍,점동면]  alias=[여주,여주시]  기점=여주  →  여주→여주  (관내)
```

**같은 필터인데 기점이 어디냐에 따라 노선이 되기도 하고 관내가 되기도 한다.**
그래서 노선/관내를 따로 만들 필요가 없다 — 기점만 옮기면 저절로 갈린다.

### 그래서 기사님이 이미 쓰시는 세 국면 그대로다

```
A.  여주 계속 = DEST(노선행)  ·  복귀 = HOME  ·  둘다 = DEST + HOME
B.  여주 관내 = LOCAL(관내)   ·  복귀 = HOME  ·  둘다 = LOCAL + HOME
```

**새 개념이 하나도 없다.** 지금 스와이프로 고르는 `DEST → LOCAL → HOME` 이 팝업의 세 갈래와 같다.
달라지는 것은 **고르는 시점**(스와이프 → 팝업이 물음)과 **상차 기점**, 그리고 **«둘다»가 생기는 것**뿐이다.

## 4-1. 🚚 한 판을 끝까지 — 필터가 시점마다 어떻게 바뀌나

기사님 요청(2026-08-24)으로 **집에서 나가 팝업이 뜰 때까지** 전 구간을 적는다.

```
집 = 다이소 분당서현점        첫짐 상차지 = 성남 야탑(장미로86번길 17)
목표 노선 = 여주시            차 = 1t (100박스)

⚠️ **집과 첫짐 상차지가 다르다** — 집(서현)에서 바로 실으면 경로가 남쪽으로 돌아
   용인 포곡·양지를 지나 **광주를 아예 안 밟는다** (2026-08-25 실측).
   야탑에서 출발해야 성남이천로를 타고 태전 → 초월 → 곤지암 → 부발로 간다.
   야탑은 집에서 3.2km 라 상차 반경 15km 안에 든다.
```

⚠️ 아래 값 중 **`상차 기점`만 지금 없는 것**이다 (§6). 나머지는 지금 코드가 실제로 만든다.
국면별 반경은 `user_filter_phases` 실측값을 썼다.

---

### 0️⃣ 집에서 대기 — **첫짐(`first` · STANDBY)**

목적지 여주를 넣고 크롤링폰을 연결한 직후.

```
callTarget          = DEST (노선행)
dispatchPhase       = STANDBY
destinationCity     = "여주시"
destinationKeywords = [가남읍, 점동면]
customCityFilters   = [여주, 여주시]
progressKm          = {}                  ← 경로가 없다 → 경로 순서 검사 안 함
allowedVehicleTypes = [오토바이, 승용차, 다마스, 라보, 1t]   ← 빈차라 전부
isSharedMode        = false
pickupRadiusKm      = 15                  ← 기점은 «현위치(집·서현)». 야탑까지 3.2km
dropoffRadiusKm     = 5
```

**잡히는 콜**: 집에서 15km 안에서 실어 **가남읍·점동면**에 내리는 콜.
→ `(야탑 → 가남, 다마스)` **통과** ✅

---

### 1️⃣ 첫짐을 잡았다 — **합짐(`merge` · GATHERING)**

`(야탑 → 가남, 다마스 30박스)` KEEP 직후. **경로가 처음 생긴다.**

```
callTarget          = DEST
dispatchPhase       = GATHERING
destinationCity     = ""                  ← 🔴 합짐은 «도시»를 안 쓴다
destinationKeywords = [야탑동, 태전동, 초월읍, 곤지암읍, 부발읍, 가남읍, …]
                      ↑ 야탑→가남 경로가 지나는 동네 전부 (경유). 실측 99~105개
customCityFilters   = [성남시 분당구, 분당구, 분당, 광주시, 광주, 경기 광주, 이천시, 이천, 여주시, 여주]
progressKm          = { 야탑동:0, 태전동:9.5, 초월읍:16.5, 곤지암읍:21.4, 부발읍:44.9 }
                      ↑ 출발점에서 몇 km 지점인가 — 역주행 판정의 자 (카카오 폴리라인 실측)
allowedVehicleTypes = [오토바이, 승용차, 다마스, 라보]   ← 다마스 30 실어 남은 70박스
isSharedMode        = true                ← 🔴 상차 반경을 무시한다
pickupRadiusKm      = 10 (무시됨)
dropoffRadiusKm     = 3
```

🔴 **여기서 세 가지가 한꺼번에 바뀐다.**
- **목적지 도시가 사라지고 «경유 목록»이 그 자리를 대신한다** — 이제 «여주로 가는 콜»이 아니라
  «내 경로 위의 콜»을 찾는다
- **`isSharedMode = true` 라 상차 반경을 안 본다** — 합짐은 거리가 아니라 **경로**로 판단한다
- **`progressKm` 이 생겨 경로 순서 검사가 켜진다** — 뒤로 가는 콜은 이제 차단된다

**잡히는 콜**: 경로 위(야탑~가남)에서 실어 경로 위에 내리고, **상차 ≤ 하차**인 콜.
→ `(초월 → 부발, 다마스)` = 상차 16.5km → 하차 44.9km, 앞으로 감 **통과** ✅

### 2️⃣ 합짐을 잡고 출발 — **운행(`drive` · DELIVERING)**

`(초월 → 부발, 다마스 30)` KEEP 후 «출발» 을 누름. 누적 60박스.

```
callTarget          = DEST
dispatchPhase       = DELIVERING
destinationCity     = ""
destinationKeywords = [태전동, 초월읍, 곤지암읍, 부발읍, 가남읍, …]   ← 아직 안 지난 곳
customCityFilters   = (위와 같음)
progressKm          = { 태전동:9.5, 초월읍:16.5, 곤지암읍:21.4, 부발읍:44.9 }
allowedVehicleTypes = [오토바이, 승용차, 다마스, 라보]   ← 남은 40박스
isSharedMode        = true
detourAllowKm       = 0                   ← 🔴 운행 중엔 경유를 0 으로 (여기서 더 안 벌린다)
dropoffRadiusKm     = 3
```

**운행 국면의 특징** — `merge` 와 거의 같은데 **경유 허용이 5km → 0km** 로 좁아진다.
*"이제 모으지 말고 가자"* 는 뜻이다. 경로에서 벗어나는 콜은 안 받는다.

🔴 **GPS 가 움직이면 지나온 동네가 목록에서 빠진다.** 야탑을 떠나면 `야탑동` 이 키워드와
`progressKm` 에서 사라진다 — 뒤에 남겨 두면 되돌아가는 콜이 잡힌다.

실측(2026-08-25 모의 주행): 도착지 키워드가 **44 → 99 → 105 → 18 → 13개** 로 변했다.
첫짐(여주시 44) → 합짐(경유 99) → 확장(105) → **주행하며 지나온 곳 제거(18 → 13)**.

---

### 3️⃣ 곤지암 직전에서 또 잡았다 — **운행 유지**

`(곤지암 → 부발, 다마스 30)` KEEP. 누적 **90박스**.

```
dispatchPhase       = DELIVERING (그대로)
destinationKeywords = [곤지암읍, 부발읍, 대월면, 가남읍, …]   ← 서현·초월은 지나서 빠짐
progressKm          = { 곤지암읍:21, 부발읍:35, 가남읍:44 }   ← 지나온 구간 제거됨
allowedVehicleTypes = [오토바이, 승용차]     ← 🔴 남은 10박스뿐. 다마스(30)·라보(40) 탈락
isSharedMode        = true
```

🔴 **적재가 필터를 좁힌다.** 90박스를 실었으니 남은 10박스에 들어갈 차종만 남는다.
이제 다마스 콜은 **차종 축에서** 떨어진다 — 도착지가 맞아도 안 잡힌다.

**경로 순서도 여전히 본다**: 상차 곤지암(21km) → 하차 부발(35km), 앞으로 감 **통과** ✅

### 부발에서 두 건 하차 → **남은 짐 = 가남행 1건** → 🔔 **팝업**

```
하차 완료: (초월 → 부발) · (곤지암 → 부발)
남은 콜  : (서현 → 가남, 다마스 30)   ← 마지막 하차지 = 가남읍(여주시)
현위치   : 부발읍
```

```
┌────────────────────────────────────┐
│  부발 하차 완료 · 짐 1건 남음        │
│  다음: 가남 (여주시) · 8.9km        │
│                                    │
│  ① 여주에서 계속      ← 관내        │
│  ② 서현(집)으로 복귀                │
│  ③ 둘다                            │
│                            30초     │
└────────────────────────────────────┘
```

마지막 하차지가 **목적지(여주)** 라서 ①은 «노선행»이 아니라 **«관내»** 가 된다 (§4 B 시나리오).

                 경로 순서 차단 로그 **없음** — 역주행 판정에 닿지도 않았다

→ **목적지에 집을 넣어야 비로소 역주행 판정에 닿는다.** 순서가 그렇다.

```

역주행 면제         = ON (복귀 쪽만)  🔴
```

**잡히는 콜**: 가남읍 근처에서 실어 **여주 안** 또는 **서현·정자동**에 내리는 콜
→ `여주 → 여주` **또는** `여주 → 성남`

**상차 기점이 «가남읍» 하나라서 조합이 안 터진다** — 하차 후보만 둘로 늘고 상차는 한 곳이다.

## 5. «둘다» 로 콜이 폭발하지 않는가

기사님 우려: *"필터는 빠르고 정확한 게 생명인데."*

하차지 후보가 둘이 되어도 **상차 기점이 하나**라 조합이 안 터진다.

```
③ 둘다 · 상차 기점 = 가남읍(마지막 하차지)
   가남 → 여주    ✅ 원함 (관내)
   가남 → 서현    ✅ 원함 (복귀)
   서현 → 서현    ❌ 상차지가 가남 반경 밖 → 자동 탈락
   초월 → 서현    ❌ 상차지가 가남 반경 밖 → 자동 탈락
```

**하차지만 둘로 늘고 상차지는 한 곳으로 묶인다.**

## 6. 🔴 가장 큰 걸림돌 — «상차 기점»이라는 값이 없다

```kotlin
// InsungParser.kt:415
order.pickupDistance <= filter.pickupRadiusKm
```

`pickupDistance` 는 우리가 계산한 값이 **아니다.** **인성 화면에 이미 찍혀 있는 «거리» 숫자를
그대로 읽은 것**이다 (리스트 왼쪽 칸의 `11.4 / 13.8`).

**그 값은 배차망이 «기사님 현위치 기준»으로 계산해 뿌린 것이라, 우리가 기점을 바꿀 수 없다.**

→ 그래서 *"상차 기점을 마지막 하차지로 옮긴다"* 는 **앱의 1차 필터에서는 불가능하다.**

### 길은 둘

| | 방법 | 대가 |
|---|---|---|
| **가** | **서버가 좌표로 다시 잰다** — 앱은 느슨하게 올리고, 서버가 상차지 좌표와 마지막 하차지 사이 거리를 계산해 거른다 | 규칙 ⑤(*앱은 느슨하게, 서버는 정밀하게*)와 맞음. 콜이 더 많이 올라와 스캔이 바빠짐 |
| **나** | **앱이 반경을 넓게 받는다** — 복귀 국면에서 `pickupRadiusKm` 를 크게 (예: 30km) | 간단하지만 엉뚱한 방향 콜도 같이 올라옴 |

**«가»가 규칙에 맞다.** 앱은 *"놓치지 않는 것"*, 서버는 *"정확히 구분하는 것"* 이 이 제품의 분업이다.

## 7. 그 밖에 막는 것 둘

### ① 역주행 판정 — **두 번째** 걸림돌이다 (첫째는 도착지)

```kotlin
// RouteOrderFilter — 상차 > 하차면 차단 (여유 0km)
가남(43km) → 서현(0km)  =  43km 후진  →  ❌ 역주행
```

**복귀콜은 본질적으로 역주행이다.** 왔던 길을 되돌아오니까.

⚠️ **다만 실측에서는 여기까지 오지도 못했다** (§4-1 5️⃣) — 도착지 축에서 먼저 떨어졌다.
필터는 여섯 축을 **전부 계산한 뒤 AND** 하므로 «먼저»라는 순서는 없지만,
**도착지가 ❌면 역주행을 면제해도 통과하지 못한다.**

이 판정은 실사고로 태어난 안전장치다 — *"파주 도착 직전에 78km 뒤로 돌아가 실어야 하는
콜이 통과했다"* (2026-08-18). 그러니 **없애면 안 되고, 좁게 면제**해야 한다.

```
남은 하차가 1건  +  상차지가 그 마지막 하차지 근처  +  하차지가 집 방향
→ 이때만 역주행 허용
```

중간에서 뒤로 가는 콜은 여전히 막힌다.

### ② 목적지가 문자열 하나 — «둘다»를 담을 데가 없다

```ts
destinationCity     : string     ← 하나
destinationKeywords : string[]   ← 배열 (그릇은 둘을 담을 수 있다)
destinationGroups   : Record<시, string[]>
customCityFilters   : string[]
```

**앱에 내려가는 값은 이미 «여러 시»를 전제로 만들어져 있다.** `destinationGroups` 가
`{시: [동…]}` 인 것이 그 증거다. 만드는 함수만 도시 하나를 받는다.

```ts
getCityRegionsWithRadius('여주시', 반경)   →  flat·grouped·alias
getCityRegionsWithRadius('광주시', 반경)   →  flat·grouped·alias
                  ↓ 합치면 «둘다»
```

**함수를 두 번 부르고 합치면 된다. 앱은 고칠 필요가 없다.**

⚠️ 다만 `destinationCity`(문자열 하나)에 무엇을 넣을지 정해야 한다.
예전에 여기 `'🎯 투-트랙 탐색'` 이라는 **없는 도시 이름**을 넣었다가, 그 값을 읽는
모든 곳(지리 연산·화면)이 함께 속은 적이 있다. **가짜 이름을 넣지 않는다.**

## 7-1. 🔬 실측으로 새로 드러난 것 (2026-08-25 · `서현여주` 문제지)

집을 **다이소 분당서현점**으로 두고 문제지를 돌린 결과다.

### ① **관내 콜은 팝업 없이도 잡힌다**

```
⑥ 가남 → 여주 점동 :  도착지(95중 점동면)=✅  →  잡혔다
```

서현→가남 **경로 목록에 여주 동네가 이미 들어 있어서**, «관내 콜»이 «경로 위 콜»로
통과했다. 설계 §4 B 의 «여주 관내»는 **지금도 절반은 되고 있다.**

→ 팝업이 필요한 것은 **복귀(HOME)** 쪽이지 관내 쪽이 아니다.

### ② 🔴 **같은 콜인데 판마다 결과가 다르다 — 재현이 안 된다**

| 판 | ② 곤지암 → 이천 부발 | ③ 곤지암1 → 이천 대월 | 경유 목록 크기 |
|---|---|---|---|
| 22:15 | **잡힘** ✅ | **잡힘** ✅ | 99~100개 |
| 07:52 | **차단** — 경로 밖(초월읍) | **차단** — 경로 밖(곤지암읍) | 95~96개 |

**같은 문제지, 같은 콜, 같은 설정인데 결과가 갈렸다.** 경유 목록의 크기도 다르다
(100 → 95). 카카오 경로가 조금씩 달라져 지나는 동네가 바뀌는 것으로 보이지만
**원인은 아직 확인하지 않았다.**

### ✅ 원인 확정 (2026-08-25) — 서버가 아니라 **문제지가 틀렸다**

둘이었고 **둘 다 우리 쪽 결함**이었다. 서버의 경유 계산은 멀쩡했다.

**가. 상하차지를 경유 반경 «경계»에 세웠다**

```
초월읍행정복지센터  →  서현→가남 경로에서 8.53km    (경유 반경 merge 5km · first 1km)
푸디스트 이천       →  5.09km   ← 5km 에 0.09km 초과
```

카카오 경로가 조금만 달라져도 들어왔다 나갔다 한다. **자를 경계에 세운 것**이지
서버가 흔들린 게 아니었다. 게다가 서현 출발 경로는 **광주를 아예 안 지난다** —
남쪽으로 돌아 용인 포곡·양지로 간다. 「초월IC」와 「초월읍 시내」는 다른 곳이다.

**나. `region` 이 시 이름이었다 — 화면이 «광주시»라고 말했다**

```
주소:   경기 광주시 고불로 264 코카콜라 태전물류   ← 도로명주소에 읍·면·동이 없다
region: 광주시                                  ← 시 이름으로 때웠다
경유 목록: … 태전동 …                            ← 제대로 들어 있었다
```

`region` 이 곧 **시뮬 화면에 그려지는 글자**다. 경로에서 0.43km 인데 «광주시» 로
그려져 경유 목록의 «태전동» 과 못 맞았다. 사전에 같은 항목이 **12개** 있었다.

→ 좌표로 법정동을 물어 12개를 고치고, `주소생성` 스킬도 같은 방식으로 바꿨다
  (주소에서 동을 못 찾으면 **역지오코딩**한다. 시 이름으로 때우지 않는다).

**결과**: 야탑 출발 + 경로 1km 안 주소로 바꾸니 ①②③이 안정적으로 잡히고,
④(5t)는 **차종만**, ⑤(8천원)는 **요금만** 으로 떨어졌다 — 자가 자 노릇을 한다.

### ③ 🔴 **도착 목표가 콜을 잡는 순간 사라진다** (2026-08-25 오후 · 고침 완료)

①이 *"관내 콜은 팝업 없이도 잡힌다"* 고 적었는데, **판마다 갈린 진짜 이유**가 여기 있었다.

대비쌍을 만들어 재 봤다 — 상차지·차종·요금이 **완전히 같고 하차지만 다른** 두 콜.

```
⑧ 가남 → 세종대왕면   차종=✅ 요금=✅ 도착지(14중 세종대왕면)=✅  → 잡힘
⑨ 가남 → 점동면       차종=✅ 요금=✅ 도착지(14중 점동면)=❌      → 막힘
```

**둘 다 여주시인데 갈렸다.** 콜을 하나 잡으면 `destinationKeywords` 가 **경유 목록으로
통째로 덮어써져** 기사님이 고른 도착 목표(여주 전역 32개)가 판정에서 빠졌기 때문이다.
화면에는 «여주시»가 그대로 적혀 있었다 (규칙 ⑤-4 ④ — 화면이 조용히 거짓말한다).

→ **노선인 동안 첫짐의 도착 목표를 상속한다.** 저장하지 않고 파생한다 (규칙 ③).
  실측 확인: 주행중 하차 목록에 **점동면 · 교동 · 창동 · 홍문동**이 들어왔다.

⚠️ **상차지 축은 열지 않았다.** `progressKm` 에는 경유만 싣는다 — 도착 목표로 들어온
   동을 섞으면 «점동면에서 싣는 콜»이 통과해 2026-08-18 파주 사고(78km 후진)가 재발한다.
   실측으로 ⑦(점동면 상차 → 분당)은 그대로 막혔다.

| 상차를 전부 앞에 | 4km 앞 하차지를 두고 30km 동쪽으로 갔다 되돌아옴 | §6 을 고칠 때 같이 봐야 한다 |
| 모의 주행이 하차지에 못 닿음 | 물류센터가 도로에서 601m·525m — 도착 반경 500m | **문제지로 검증할 때의 전제**가 깨진다 |
| 승용차 카드 실종 | 차종 목록 세 벌 중 하나에 «승»이 빠짐 | 대비쌍을 승용차로 만들었더니 드러났다 |

### 🔴 그래서 §8 의 순서가 바뀐다

*"4(목적지 여러 개) 없으면 도착지 축에서 떨어진다"* 는 진단은 **절반만 맞았다.**

- **여주 안** 콜은 이제 잡힌다 (③으로 고침) — 목적지가 하나여도 된다
- **집(성남) 방향** 콜은 여전히 도착지 축에서 떨어진다 — 여기에만 4번이 필요하다

즉 4번은 «관내를 살리는 일»이 아니라 **«복귀를 살리는 일»** 이다. 관내는 이미 된다.


## 8. 그래서 무엇을 해야 하는가

| | 무엇 | 어디 | 크기 |
|---|---|---|---|
| ~~0~~ | ~~경유 목록이 판마다 달라지는 원인~~ | — | ✅ **해결** (2026-08-25) — 문제지 결함이었다 (§7-1) |
| **1** | 자동 복귀 전환을 **팝업으로** 바꾼다 | `dispatchEngine.ts` 의 타겟 자동 순환 | 작음 — 이미 자리가 있다 |
| **2** | 신호를 «콜 0건» → **«남은 하차 1건 + N km»** 로 | 같은 자리 | 작음 |
| **3** | **30초 토스트 세 갈래** 화면 | 관제웹 | 중간 |
| ~~3-5~~ | ~~도착 목표가 콜 잡는 순간 사라짐~~ | — | ✅ **해결** (2026-08-25) — 첫짐에서 상속 (§7-1 ③) |
| **4** | 목적지 **여러 개**를 받아 합치기 (**복귀용**) | `filterManager.ts` · `geoService.ts` | 중간 — 앱 무수정 |
| **5** | **상차 기점**을 서버가 좌표로 다시 재기 | 서버 판정 | **중간~큼** (§6) |
| **6** | 역주행 **좁은 면제** | `RouteOrderFilter.kt` + 서버 | 중간 — 안전장치라 조심 |

🔴 **순서는 4 → 5 → 6 이다** (2026-08-25 실측으로 확정).

```
4 없으면:  도착지 축에서 떨어진다      → 5·6 을 해도 소용없다
5 없으면:  상차 반경에서 떨어진다      → 6 을 해도 소용없다
6 없으면:  역주행에서 떨어진다
```

**4번(목적지에 집 넣기)이 가장 앞이다.** 설계 초안에서는 5번(상차 기점)을 첫째로 봤는데,
실측에서 복귀콜이 **도착지 축**에서 먼저 떨어져 그 앞에 4번이 있다는 것이 드러났다.

🔴 **다만 4번의 뜻이 좁아졌다** (2026-08-25 오후). «여주 안» 콜은 도착 목표 상속으로
이미 잡히므로(§7-1 ③), 4번이 필요한 것은 **집 방향 콜을 담을 자리**뿐이다.
관내는 4번 없이도 된다.

## 9. 아직 안 정한 것 (기사님 확인 필요)

- ❓ **«N km 안»의 N은 얼마인가** — 마지막 하차지까지 몇 km 남았을 때 물을 것인가
  · §4-1 예: 부발에서 가남까지 **8.9km** 남은 시점에 팝업이 떴다
  · 너무 이르면 마지막 하차가 멀어 복귀콜 상차 마감을 못 맞춘다
  · 너무 이르면 상차 마감(잡은 시각+60분)을 못 지키고, 너무 늦으면 빈차가 된다
- ❓ **30초 무입력이면 무엇을 하는가** — 지금은 자동 복귀. 노선 유지로 바꿀 것인가, 아무것도 안 할 것인가
- ❓ **복귀콜을 잡은 뒤 마지막 하차지에 닿으면** 그 콜이 새 첫짐이 되는가, 복귀 국면이 유지되는가
- ❓ **«광주 → 광주»(관내) 콜**을 노선행 중에도 잡을 것인가 (A 시나리오의 전제였는데 지금은 안 잡힌다)

## 참고 — 실측 거리 (2026-08-24)

**§4-1 시나리오 (집 = 다이소 분당서현점 · 첫짐 상차 = 성남 야탑)**

야탑 → 가남 카카오 폴리라인 기준, 각 지점의 **진행도**와 **경로 이탈**이다.

```
             진행도    이탈
코카콜라 태전   9.5km   0.43km
초월읍        16.5km   0.35km
쿠팡 곤지암2   21.4km   0.60km
쿠팡 이천4     44.9km   0.52km
```

🔴 **전부 1km 안이라 경유 반경이 1km(첫짐)든 5km(합짐)든 안정적으로 경로 위다.**
   처음엔 8.5km·5.27km 짜리를 골랐다가 **판마다 결과가 뒤집혔다** (§7-1 ②).
   경계에 세운 자로는 무엇을 재는지 알 수 없다.

**집이 광주(초월)일 때 — 갈등이 실제로 생기는 예**

```
이천시청 부근   집 17.0km · 여주 13.4km   ⚖️ 엇비슷 — 갈등
이천 마장면     집 13.4km · 여주 17.2km   ⚖️ 엇비슷 — 갈등
이천 부발읍     집 20.3km · 여주  7.6km   여주가 가깝다
```

기사님(2026-08-24): *"광주 - 이천에 마지막 하차를 하였다면 거기서는 위치상 딱 중간이라.
여주로 갈지, 광주로 돌아갈지 갈등이 생길 가능성이."* — **실측으로 확인됐다.**
그 갈등이 곧 **팝업이 필요한 이유**다.

⚠️ 집이 **분당(서현)**이면 여주까지 44km 라 갈등이 덜하다 — **집이 어디냐에 따라 달라진다.**
그래서 §9 의 «N km» 를 고정 상수로 정하면 위험하다.
