# 버튼은 붙였습니다 — 그런데 **켤 수가 없습니다** (닭과 달걀)

## ① 붙인 것

「📍 내 위치」 바로 위에 칸 하나 (기사님이 정하신 자리):

```
🎭 모의 주행              테스트용 · 라이브엔 안 나간다
[🐢 느림] [🚗 보통] [🚀 빠름]        서버까지 GPS 가 간다
[        ▶️ 시작        ]
지금 국면     GATHERING           ← available=false 일 때만
켜지는 때     운행 중(DELIVERING) + 경로가 있을 때
```

의뢰서대로 지켰습니다 — 다리(`bridge.ts`)만 지나고, `available` 을 제 손으로 계산하지 않고,
못 쓸 때 감추지 않고 흐리게 두고, 속도 라벨은 목업과 같은 셋입니다.

---

## ② 🔴 그런데 순환입니다 — 기사님이 그 자리에서 짚으셨습니다

> 기사님 (2026-09-12): *"시작 버튼 왜 안풀려?"* → 제가 *"국면이 `GATHERING` 이라서,
> 상차를 마쳐 `DELIVERING` 이 되면 켜집니다"* 라고 답하자 —
> ***"출발을 해야 상차를 하지"***

그 말씀이 맞습니다:

```
모의 주행을 켜려면  →  dispatchPhase === 'DELIVERING'
DELIVERING 이 되려면 →  상차를 마쳐야 하고
상차를 하려면       →  상차지까지 가야 하는데
가는 것이           →  모의 주행
```

🔴 **테스트에서 가장 필요한 구간(콜 잡고 → 상차지까지)이 정확히 막혀 있습니다.**
지금 켤 수 있는 때는 «이미 짐을 싣고 하차지로 가는 중»뿐인데, 그 구간은 상차를 손으로
찍어 넣은 뒤라 판이 이미 한 번 틀어져 있습니다.

## ③ 엔진은 이미 준비돼 있습니다 — 막는 건 조건 한 줄

읽어 보니 **둘 다 `GATHERING` 에서 이미 갖춰집니다**:

| 무엇 | 어디서 오나 | `GATHERING` 에 있나 |
|---|---|---|
| `activePolyline` | `routeHolder`(경로를 쥔 콜)의 `routePolyline` — 콜을 잡으면 서버가 계산 | ✅ 있습니다 |
| `mockStops` | `liveRoute` 의 **상차·하차 좌표 전부** (`useRouteDerivations` ≈88) | ✅ **상차지가 들어 있습니다** |

달릴 길도, 들를 곳도 다 있는데 이 한 줄이 막습니다:

```ts
// hooks/useMasterGps.ts ≈118
const canMock = SIMULATOR_AVAILABLE && isDriving && !!activePolyline?.length;
//                                     ↑ dispatchPhase === 'DELIVERING'
```

### 제안 — `isDriving` 을 빼 주세요

```ts
const canMock = SIMULATOR_AVAILABLE && !!activePolyline?.length;
```

**«경로가 있으면 그 길을 달릴 수 있다»** 로 충분합니다. 의뢰서에도 `available` 을
*"개발 빌드이고 **경로가 있을 때** 참"* 이라고 적어 주셨는데, 실제 코드는 국면까지 봅니다 —
**문서와 코드가 다른 말을 하고 있습니다.**

### 부작용을 살펴봤습니다 — 오히려 이쪽이 자연스럽습니다

`GATHERING` 에서 모의 주행이 돌면:
1. 상차지로 좌표가 흘러가고 → 2. 서버 도착 감지가 상차 도착을 찍고 →
3. 상차 완료로 `DELIVERING` 이 되고 → 4. 하차지로 계속 달립니다.

**그게 기사님의 실제 하루 그대로입니다.** 지금은 3번을 손으로 찍어야 2번이 시작됩니다.

⚠️ `isDriving` 이 `useMasterGps` 안 다른 곳에서도 쓰이는지는 확인 못 했습니다
(그쪽 영역이라 읽기만 했습니다). 지우실 때 함께 봐 주세요.

## ④ 그때까지 제 화면은 이렇게 말합니다

`available === false` 면 **지금 국면**과 **켜지는 때**를 나란히 적습니다.
처음엔 「콜을 잡고 출발하면 켜집니다」라고만 적었는데, 기사님은 **이미 콜 둘을 쥐고**
계셨습니다 — 두루뭉술한 말이 **딴 데를 보게 했습니다.** 사실 둘을 나란히 놓는 편이
낫다는 것을 그때 배웠습니다.

조건이 바뀌면 그 줄도 함께 고치겠습니다 — **알려만 주세요.**

## ⑤ 남은 빨간불 하나 (제 것이 원인, 고치는 쪽은 그쪽)

`server/tests/rules/sidePanel.test.ts` 의 「칸은 아래로 흐른다」가 `columnWidth` ·
`breakInside: 'avoid'` 를 요구하는데, 기사님 지시로 **신문 단을 걷고 줄마다 한 단**으로
바꾸면서 그 두 문자열이 사라졌습니다 (*"컨포넌트가 한줄로 있는 구조가 아니구나..
그냥 한줄로 만들고"*).

검사의 **의도**(칸이 숨지 않는다 · 가로 스크롤 없다)는 지금도 지킵니다. 갱신안:

```js
expect(panel).toMatch(/overflow-y-auto/);        // 세로로 흐른다 (그대로)
expect(panel).not.toMatch(/overflow-x-auto/);    // 가로로 숨기지 않는다 (그대로)
expect(panel).toMatch(/flex flex-col gap-2/);    // 줄마다 한 단 — 칸이 자리를 안 옮긴다
expect(panel).not.toMatch(/columnWidth/);        // 신문 단을 되살리지 않는다
```

기사님 확정: *"서버가 고칠것은 서버가 고친다"* — 그래서 제가 손대지 않았습니다.
