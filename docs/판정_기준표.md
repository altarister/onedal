# 판정 기준표 — 기사님 기입용

> **작성 2026-08-15** · 기사님: _"요소별로 **가중치**를 줄 수 있어야겠다. 컬럼과 로우를 네가
> 정의해 주고 **기존에 들어가 있는 값을 코드에서 추출**해 주고, 새로 생성된 가중치 값들은
> 내가 기입해서 다시 너에게 돌려줄게."_
>
> - `지금 값` 은 **코드에서 그대로 뽑은 것**이다. 제가 지어낸 값은 하나도 없다.
> - **`가중치` 와 `기사님 값` 칸이 비어 있다.** 여기를 채워 주시면 그대로 구현한다.
> - 채우실 때 근거가 있으면 `메모` 에 한 줄 적어 주시면 코드 주석에 그대로 넣는다.

# 표 0. 먼저 — 점수를 어떻게 쓸 것인가

지금은 **임계값**이다(넘으면 똥). 가중치를 쓰려면 **각 요소가 점수를 내고 합산**하는 구조가 된다.

```
요소마다 0~100 점  →  × 가중치  →  합산  →  총점  →  색
```

- **가중치 0** 은 _"이 요소는 색에 반영하지 않는다"_ 는 뜻이다 (표시는 계속 한다)
- 가중치는 **상대값**이다. 3 과 1 은 "3배 중요"라는 뜻이고, 합이 10 일 필요는 없다

**색 경계** — 총점이 얼마 이상이면 무슨 색인가

| 색      | 뜻          | 기사님 값     |
| ------- | ----------- | ------------- |
| 🔵 꿀   | 바로 잡는다 | `___` 점 이상 |
| 🟢 보통 | 바로 잡는다 | `___` 점 이상 |
| 🟡 똥   | 한 번 본다  | 그 미만       |

> 기사님: _"파란색, 녹색이면 코드를 믿고 바로 잡을 거야."_ → 🔵🟢 는 **둘 다 "잡는다"** 이고,
> 차이는 _"얼마나 좋은가"_ 뿐이다. 그래서 경계 두 개만 정하면 된다.

## 🔴 지금 이 표에서 벌어지는 일

- **1번(시간당 수익)을 아예 안 본다.** 합짐 판정에 `요율 판정` 이 한 번도 안 돈다 (2026-08-15 로그 전수 확인)
- **2번과 3번이 `OR`** 다 — 하나만 넘어도 🟡. `+31.1km` 콜이 시간과 무관하게 걸렸다
- **재탐색은 자기 숫자를 쓴다** — `dispatchEngine.ts:211` 의 `10km / 30분`.
  **같은 콜이 재탐색만 해도 색이 바뀐다**
