# 판정 — 콜을 집은 뒤 색을 내는 것

> **색이 곧 결정이다.** 기사님은 🔵🟢🟡🔴 를 보고 1~2초 안에 누른다. 설명 문구는 그다음이다.
> **그러므로 색을 틀리는 것이 이 시스템의 가장 큰 사고다.**
>
> 🔴 **판정은 «집은 뒤», 필터는 «집기 전»이다.** 둘은 완전히 격리되어 각각 따로 작동한다.
> 필터는 [필터 문서](필터.md)에 있다. 말의 원천은 [용어집](용어집.md).

---

## 1. 판정이 답하는 질문

앱이 `요금 ≥ 배송거리 × 단가` 로 **이미 걸러서** 올린 콜만 여기 온다.
그러므로 판정의 일은 *"이 콜이 돈이 되는가"* 가 **아니다.**

> **"지금 이 경로에 붙일 때 얼마나 좋은가"**

우회 비용으로 순위를 매기는 것이 판정이다.

🔴 **모르는 값은 가장 흔한 값으로 계산하고 «미확인»으로 표시한다.**
불리하게 잡으면 잡을 수 있었던 콜을 놓친다 — 잡은 뒤 통화로 확정하는 것이 이 제품의 순서다.
표시 없이 값만 쓰면 규칙 위반이다.

🔴 **물리적으로 불가능해 보여도 서버가 미리 버리지 않는다.** 시간은 통화로 조정된다.

## 2. 색 넷

| 색 | 이름 | 뜻 |
|---|---|---|
| 🔵 | **꿀** | 잡아라 |
| 🟢 | **보통** | — |
| 🟡 | **똥** | 별로다 |
| 🔴 | **사고** | **잡지 마라** |

```
총점 ≥ honeyMin(70)   → 꿀
총점 ≥ normalMin(40)  → 보통
그 아래              → 똥
문지기 하나라도 실패   → 사고 (점수와 무관)
```

🔴 **실패가 빨강인 이유** — 예전엔 회색(무해해 보임)이었다.
**나쁜 걸 아는 것보다 아무것도 모르는 게 더 위험하다.** 경로도 요율도 못 구한 콜은 판단 근거 자체가 없다.

## 3. 채점 — 문지기 · 축 · 딱지

```
문지기(gates)   통과/실패.  하나라도 실패하면 🔴 + 사유.  자동 탈락은 없다 (규칙 ①)
축(axes)        0~100 × 가중치 → 총점 → 색
딱지(tags)      판단 없이 사실만.  «정차 미확인» «배송주행 추정» «통화 필수»
```

### 문지기

| 열쇠 | 이름 | 실패하면 |
|---|---|---|
| `routePromiseGuard` | 기존 콜 약속 보존 | *"잡으면 복귀콜 상차 약속이 36분 깨집니다"* |
| `cargoTagCompat` | 짐 동승 | 같이 실을 수 없는 짐 |

### 축

| 열쇠 | 이름 | 가중치 |
|---|---|---|
| `revenuePerDetour` | 순증 대비 우회 | `weight_revenue_detour` = 1 |
| `bufferCost` | 버퍼 소비 | `weight_buffer_cost` = 1 |
| `loadCapacity` | 적재 | `weight_slots` = 1 |

**축은 «사실»을 함께 싣는다** — `raw` 에 `3.0만 ÷ 90분 = 2.0만/h` 처럼 계산 그대로 적는다.
판단하지 않고 보여 준다.

## 4. 기준값 — 원천은 DB 다

`user_judgment` 한 행이 사용자 한 명의 기준이다. **14칸.**

| 무리 | 칸 | 기본값 |
|---|---|---|
| **색 경계** | `color_honey_min` · `color_normal_min` | 70 · 40 |
| **가중치** | `weight_revenue_detour` · `weight_buffer_cost` · `weight_slots` | 1 · 1 · 1 |
| **목표** | `target_hourly_krw` | 30,000원/h |
| **데드라인** | `deadline_ratio_pct` | 150% |
| **모를 때 · 정차** | `unknown_pickup_dwell_minutes` · `unknown_dropoff_dwell_minutes` | 15분 · 10분 |
| **모를 때 · 상차 시계** | `unknown_pickup_offset_minutes` | 30분 |
| **모를 때 · 속도** | `speed_short_kmh` · `speed_mid_kmh` · `speed_long_kmh` | 25 · 46 · 56 |

### 🔴 값이 하나 늘면 표에 한 줄만 더한다

`shared/src/judgment.ts` 의 **`JUDGMENT_FIELDS`** 가 유일한 원천이다.
**DB 컬럼도, 관제웹 폼도, 기본값도 전부 이걸 읽는다** — 화면 코드와 서버 판정 코드는 안 고친다.

역할이 갈려 있다:

```
DB          지금 값이 얼마인가            ← 진실
JUDGMENT_FIELDS  라벨 · 단위 · 범위 · 근거   ← 폼의 칸 아래 그대로 뜬다
docs        왜 그렇게 정했나              ← 값은 안 적는다
```

**그래서 이 문서에는 값을 적지 않는다.** 위 표는 «어떤 칸이 있는가»를 보이려는 것이고,
지금 값은 관제웹 «판정 기준» 탭이나 DB 가 답한다.

## 5. 색이 화면까지 가는 길

```
OrderEvaluator          채점 → dry {color, score, axes, gates, tags}
   ├→ order_judgments   심사 1회 저장, 불변 (카드 접이·회귀 검사가 읽는다)
   ├→ pros / reasons    색이 «잡을 이유»와 «버릴 이유»를 가른다
   └→ kakaoTimeExt      ⚠️ 문자열
                            │
관제웹 PinnedRouteCard      └→ 그 문자열의 표식('꿀'·'사고'·'실패')을 찾아 색을 정한다
```

🔴 **화면은 색을 «값»이 아니라 «문자열 안의 표식»으로 받는다.**
그래서 카드는 표식을 낱말 단위로 지운 뒤 나머지를 사유로 보여 준다 — 통째로 지우면
`총 추가시간(+116분) 초과` 가 `총 가(+116분) 초과` 로 뭉개진 적이 있다.

⚠️ **이 이음새가 이 구조의 가장 약한 곳이다.** 문구를 바꾸면 색이 조용히 틀어진다.

## 7. 아직 없는 것

| 무엇 | 지금 | 남은 일 |
|---|---|---|
| **색 전달** | `kakaoTimeExt` 문자열의 표식 | 색을 값으로 내려보낸다. 문구를 바꿔도 색이 안 틀어지게 |
| **«사고»의 뜻** | 두 가지에 같은 색을 쓴다 — **연산 실패**와 **문지기 실패**(잡으면 약속이 깨지는 콜) | 이름을 가른다. 한 색이 두 뜻이면 「본콜」이 세 뜻으로 쓰이다 폐기된 길이다 |
| **첫짐의 «우회»** | 기존 경로가 없는 국면에서도 «우회 +N분» 딱지가 붙는다 | 무엇 대비 우회인지 확정. 접근 주행이라면 이름이 거짓말이다 |
| **`estimated` 표시** | 판정 딱지에만 뜬다 | 단계 예약·타임라인에도 «추정»을 표시 (규칙 ⑤-2 절반만 지켜짐) |
| **`target_hourly_krw`** | 3.0만/h — 문제지 캘리브레이션으로 정함 | 실주행 데이터로 재확인 |

### 🔴 확인이 필요한 관찰 (2026-08-28 주행)

같은 날 판정 13건 중:

```
꿀 100점  ← 우회 +85분 · +48.4km
보통 50점 ← 우회 +235분 · +121.8km
보통 46점 ← 우회 +217분 · +126.9km
보통 45점 ← 우회 +191분 · +112km
```

**우회 3~4시간짜리가 🟢 보통이다.** 색을 틀리는 것이 가장 큰 사고라는 규칙에 비추면
먼저 봐야 할 자리다. 원인은 아직 «관찰»이지 진단이 아니다 — 첫짐 국면의 «우회» 기점부터
확인해야 한다 (위 표 3행).
