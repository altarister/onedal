## 1. 지금 어떻게 도는가

콜을 잡으면 서버가 **기준마다 점수(0~100)를 매기고 평균**을 내서 색을 정한다.

```
돈    92점  ×1
약속  100점 ×1     →  평균 70점  →  🔵 꿀
공간  20점  ×1
```

**70점↑ 🔵 꿀 · 40~69점 🟢 보통 · 39점↓ 🟡 똥**

여기에 **점수와 상관없이 무조건 빨간불**이 되는 조건이 둘 있다 —
① 이미 잡은 콜의 약속이 깨질 때 ② 같이 못 싣는 짐일 때.

## 3. 기사님이 주신 답 (2026-08-29)

**① 만석일 때 무조건 빨간불로 할까?**
> *"나중에 가중치를 높일 거야. 그러면 빨간색으로 보일 거야."*

→ **무조건 빨간불은 「약속」·「성질」 둘만.** 만석은 가중치로 다룬다.

**② 모르는 값을 깎을까?**
> *"콜을 잡을 때 다마스를 불렀다면 기본적으로 박스 30개라고 묵시적으로 알 수 있다고 한 것 같은데..
> 모르는 게 있다는 것이 버그 아닐까?"*

→ **기사님이 맞다. 버그다.** 차종만 알면 짐이 나온다 (`defaultCargoByVehicle`):
```
다마스 → 라면박스 30개 → 수작업        1t → 파레트 2개 → 지게차
```
그런데 정차 시간을 계산하는 `getStopTiming`(`helpers.ts:88`)이 **신고 기록만 찾고 차종 기본값을 안 본다.**
콜을 막 잡았을 때는 신고가 없으니 **항상 「모른다」**가 된다.

→ **「근거」 기준은 만들지 않는다.** 이 버그를 고치면 「모른다」가 거의 사라진다.

**③ 역주행을 서버도 볼까?**
> *"앱이 역주행을 알고 있어? 서버에서 카카오를 통해서 판단하는 걸로 아는데?"*

→ **기사님이 맞다.** 서버가 카카오 경로에서 «이 동은 출발점에서 몇 km 지점인가»(`progressKm`)를
계산해 **앱에 내려보낸다** (`filterManager.ts:299`). 앱은 그 값으로 비교만 한다.

→ 서버가 판정하는 것은 **자기가 만든 값을 자기가 쓰는 것**이다. 새로 만들 값이 없다.

## 4. 바꿀 모습 — 기준 다섯, 한 곳에서

### 기준 다섯

| 기준 | 무엇을 보나 | 100점 | 0점 |
|---|---|---|---|
| **돈** | 이 시간 써서 얼마 버나 | 목표 시급(3만원/h) 넘음 | 0원/h |
| **약속** | 이미 잡은 콜에 늦지 않나 | 여유 30분 이상 | 늦는다 |
| **공간** | 실을 자리 있나 | 자리 넉넉 | 만석 |
| **성질** | 같이 실어도 되는 짐인가 | 문제 없음 | 같이 못 싣는 조합 |
| **지리** | 가는 길 위에 있나 | 순방향 | 역주행·경로 밖 |

- 기준마다 **가중치**가 있다. **0으로 두면 그 기준은 안 본다** (기사님 확정)
- 「약속」·「성질」은 0점이면 **무조건 빨간불**. 가중치가 0이면 기준 자체가 없으니 빨간불도 없다

### 한 곳에서

```
지금:  점수 내는 곳  ─┐
       사유 쌓는 곳  ─┴→ 문구로 합침 → 글자 → 화면이 글자를 찾아 색 결정

바꾼 뒤: 모든 조건 → 판정 함수 하나 → { 색, 점수, 기준5개 } 를 값 그대로 → 화면
```

- **콜 심사하는 쪽은 재료만 모은다** — 카카오·적재·시간. 점수는 안 낸다
- **판정 함수는 `shared/` 에 둔다** — 서버·관제웹이 같은 답을 내야 한다. 순수 계산이라 폰·DB 없이 검사된다

## 5. 무엇을 어떤 순서로 — 일곱 단계

각 단계가 **끝날 때마다 검사가 초록불**이어야 한다. 중간에 멈춰도 제품은 돈다.

### 1단계 — 죽은 값 조사 → **셋은 남기고 여섯만 지운다** 🟡

기사님(2026-08-29): *"코드상에 호출이 없지만 **존재 이유가 있었을 것 같은데** 그걸 함 찾아봐.
그리고 나중에 지우자"*

→ 하나씩 캐 봤다. **셋은 지우면 안 되는 것이었다.**

#### 🔴 남긴다 — 아직 할 일이 남은 값 셋

| 값 | 무엇이었나 | 왜 남기나 |
|---|---|---|
| `timeSensitive` · `isTimeSensitive()` | 태그마다 «늦으면 상품이 상하나» — 농산물·수산물·생물 = true | **판정에 들어가야 할 값이 아직 안 들어간 것**이다. 생물을 싣고 30분 우회하는 것과 철재를 싣고 30분 우회하는 것은 다르다. 지금 「약속」 기준이 **모든 짐을 똑같이** 본다. 지우면 이 생각이 사라진다 |
| `computeSlackMinutes` · `allowedDetourMinutes` · `describeSlack` | 마감까지 남는 시간 = 마감 − (지금 + 남은 주행). *"그 120분 안에서만 우회할 수 있다"* | 지금 「약속」 기준이 **약속 시각**만 보는데, 이건 **마감**을 본다. 둘은 다르다 — 약속은 통화로 정한 것, 마감은 업계 관행. `allowedDetourMinutes` 주석에 «음수를 0으로 깎으면 안 된다»는 2026-08-15 실측 사고가 적혀 있다 (99,000원 콜이 🟡 로 떴다). **그 교훈이 지금 코드에 반영돼 있는지 확인이 먼저다** |
| `bufferBeforeMin` | 붙이기 **전** 여유 — 화면에 «소비 25분 → 최소 +18분» 으로 보여 주려던 값 | 계산은 이미 있다(`dryRun.ts:101`). **넘겨주는 쪽만 안 이어져 있다.** 지울 게 아니라 **이어야 할 것**이다 — 기사님이 «이 콜이 여유를 얼마나 먹나» 를 볼 수 있게 된다 |

#### ✅ 지운다 — 진짜로 끝난 값 여섯

| 값 | 무엇이었나 | 왜 지워도 되나 |
|---|---|---|
| `DETOUR_HONEY_TIME_MAX` 30 · `DETOUR_HONEY_DIST_MAX` 15 · `DETOUR_SHIT_TIME_MIN` 60 · `DETOUR_SHIT_DIST_MIN` 30 | 옛 합짐 판정 — *"추가 시간 30분 이하 AND 거리 15km 이하면 꿀"* 같은 **절대 문턱** | **2026-08-21 판정색 v2 가 절대 문턱을 폐기**하고 «우회 시급»(운임 대비)으로 바꿨다. 기사님 확정: *"같은 40분이라도 3.5만이면 좋고 5천원이면 나쁘다"*. 같은 파일 주석도 «첫짐 기준은 이관됐다»고 적혀 있다 — 합짐 것만 남았다 |
| `targetHourlyKrw`(입력 인자) | 판정마다 다른 목표 시급을 넣으려던 자리 | 목표 시급은 **판정 기준 탭 하나**에서 온다 (규칙 ③). 호출마다 다른 값을 넣으면 두 벌이 된다 |
| `isRejected` | *"서버 종합 평가: 똥콜인가"* — 옛 시절 «서버가 콜을 버린다» 는 설계의 흔적 | 🔴 **규칙 ①(콜의 주인은 기사님)과 정면으로 어긋난다.** 서버는 콜을 자동으로 버리지 않는다. 쓰기만 하고 읽는 곳이 0인 것은 **그 설계가 폐기됐다는 증거**다 |

**어떻게**: 여섯만 지우고 `pnpm audit:dead` · `npx jest` · `pnpm drive`.
**되돌리기**: git revert.

**남긴 셋은 todo 로** — 지우는 게 아니라 **이어야 할 것**이라 별도 항목으로 올린다.

### 2단계 — 「모른다」 버그 고치기 🟢 판단 필요 없음 (기사님 지적)

**무엇이 문제인가**: `getStopTiming`(`helpers.ts:88`)이 신고 기록만 찾는다. 차종 기본값을 안 본다.
그래서 콜을 막 잡았을 때 **차종은 아는데도 「모른다」**가 뜬다.

**어떻게**:
1. **검사 먼저** — *"다마스 콜은 신고가 없어도 라면박스 30개·수작업으로 잰다"* → **빨간불 확인**
2. `getStopTiming` 이 신고가 없으면 `defaultCargoByVehicle(차종)` 을 쓰게 한다
3. 초록불 확인

**같은 값을 두 곳에서 만들던 것을 한 곳으로 모으는 일이다** — 단계 행을 만들 때(`stepSeeder`)는
이미 차종 기본값을 쓴다. 정차 시간 계산만 안 썼다.

**되돌리기**: 한 함수만 고치므로 git revert.

### 3단계 — 모르면 점수 오르는 것 막기 🟢 판단 필요 없음

**무엇이 문제인가**: 잴 값이 없으면 그 기준을 **아예 안 만든다**(`dryRun.ts:84,98,109`).
기준이 빠지면 평균의 분모가 줄어 **점수가 오른다.**

**어떻게**: 값이 없으면 기준을 빼지 말고 **「잴 수 없음」으로 남긴다.**
평균에는 안 들어가되, 화면에 «이 기준은 못 쟀다»고 보인다.

⚠️ 2단계를 먼저 해야 한다 — 2단계로 「모른다」가 대부분 사라지고 나서 남는 것만 다룬다.

**되돌리기**: git revert.

### 4단계 — 색을 글자 말고 값으로 🟡 화면이 바뀐다

**무엇이 문제인가**: 서버가 문구에 `'꿀'` 을 심고, 화면이 그 글자를 찾아 색을 정한다
(`PinnedRouteCard.tsx:341`). **문구를 바꾸면 색이 조용히 틀어진다.**

색이 곧 기사님의 결정인데(규칙 ⑤-3) 글자 찾기로 정해진다.

**어떻게**:
1. 서버가 색을 **값으로** 함께 내려보낸다 (판정 결과 객체는 **이미 화면까지 간다** — 색만 글자로 판별한다)
2. 화면이 **값과 글자 둘 다** 읽게 둔다. 값이 있으면 값을 쓰고, 없으면 옛 글자로
3. 며칠 돌려 값이 늘 오는 것을 확인한 뒤 글자 찾기를 지운다

**되돌리기**: 2단계에서 둘 다 읽으므로 언제든 되돌아간다.
