### 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 원달앱 · 스캔앱 | 폰에서 배차망 화면을 읽고 누르는 우리 앱 (`com.onedal.app`). 같은 것이다 |
| 시뮬레이터 앱 | 시뮬레이터 웹페이지를 띄우는 안드로이드 앱 (`com.onedal.simulator`). 인성·24시·픽커 화면을 **한 앱**으로 띄운다 |
| 앱 이름 | 폰 시스템이 화면마다 붙여 주는 «이 화면은 어느 앱 것인가» (예: 실제 픽커 `com.kakaomobility.flexer`). 시스템 로그에 찍히는 그 이름이다 |
| 망 표식 글자 | **한 망의 화면에만 있는 글자 묶음.** 묶음 안 글자가 화면에 전부 있어야 그 망으로 본다 (예: 인성 리스트 = `신규` + `빠른설정`) |
| 알아낸 망 | 스캔앱이 알아낸 «인성 / 24시 / 픽커». 어느 파서로 읽을지 정하고, 서버로 보내져 관제앱 폰 영역 배지로 보인다. 프리퍼런스 `targetApp` 에 이름표(«인성콜»·«24시»·«픽커»)로 저장된다 |
| 배차망 코드 | 서버·`shared` 가 쓰는 값 `insung` · `hwamul24` · `kakaopicker`. 원달앱에서는 `TargetApp.codeOf(이름표)` 한 곳이 이름표를 코드로 바꾼다 |
| 낱말 사전 | 서버가 망마다 내려 주는 화면 낱말 목록 (`server/config/keywords_*.json`) — 원달앱이 `GET /api/config/keywords` 로 받는다 |

## 1. 무엇을 고치나 — 셋

| | 무엇 | 왜 |
|---|---|---|
| ③ | **망을 앱 이름이 아니라 화면 글자로 가른다** · 설정 화면의 망 선택 칸을 지운다 | 시뮬레이터는 한 앱이라 앱 이름으로는 늘 «인성»이 된다. 실제 픽커도 «나 픽커입니다»라고 알려 주지 않으니 **화면 글자로 가르는 것이 실제·시뮬레이터 모두에 맞는 방법**이다 (기사님 확정 2026-09-14) |
| ① | 설정 화면 **«테스트 가상 콜 화면 열기»** 버튼이 우리 시뮬레이터가 아닌 곳을 연다 | 시뮬레이터로 시험하는 입구다 |
| ② | 낱말 사전을 **한글 이름표로** 요청하고, 받은 사전을 **망 구분 없이** 쓴다 | 서버가 «모르는 값이면 오류»로 바뀌면(기사님 확정 2026-09-14) 원달앱이 **틀린 사전을 조용히 쓰는 길**이 생긴다 |

③을 맨 앞에 둔 이유: ①·② 의 시험이 «시뮬레이터에서 망이 제대로 갈리는가»에 기댄다.

## 2. 지금 상태 — 확인한 사실

### ③ 망을 가르는 방법

```kotlin
// HijackService.kt — 화면 이벤트마다
val screenNetwork = TargetApp.codeOfPackage(rootNode.packageName?.toString())   // 앱 이름으로
NetworkSwitchGate.switchTargetFor(screenNetwork, currentTargetApp)?.let { switchNetworkTo(it) }

// TargetApp.kt
"com.kakaomobility.flexer" -> KAKAOPICKER
"com.onedal.simulator"     -> INSUNG        // 🔴 시뮬레이터는 무엇을 띄우든 인성
"com.insungdata.smartorder1" -> INSUNG      // 인성 실앱 (코드 주석: 미실측)
```

| 사실 | 어디 | 생기는 일 |
|---|---|---|
| 망을 **앱 이름**으로 가른다 | `HijackService.kt` 의 `codeOfPackage` 한 자리 | 실제 픽커 앱은 된다 · 시뮬레이터 화물24시·픽커 화면은 **인성으로 읽고 관제앱 배지도 «인성»** |
| 같은 앱 이름을 **픽커 운행 단계 로그의 조건**으로도 쓴다 | 같은 함수, `screenNetwork == KAKAOPICKER` | 2026-09-02 에 «잠금화면·런처가 모르는 픽커 화면으로 찍히던 것»을 막으려고 이렇게 걸었다 |
| 설정 화면에 망 선택 칸이 있다 (인성콜 · 24시 · 픽커) | `ui/SettingsScreen.kt` · `MainViewModel.saveTargetApp` | 저장값만 바꾼다. 서비스는 **붙을 때만** 저장값을 읽고, 바꾼 것을 알아채는 자리는 코드에서 못 찾았다. 그 뒤 자동 전환이 곧 덮어쓴다 |
| 망마다 화면을 알아보는 글자가 이미 있다 | `InsungKeywords.kt` · `Hwamul24Keywords.kt` · `KakaoPickerKeywords.kt` | 아래 표 — **이것이 망 표식 글자의 재료다** |

| 망 | 리스트 화면 | 상세 화면 | 그 밖 |
|---|---|---|---|
| 인성 | `신규` + `빠른설정` | `적요상세` + `요금` | |
| 화물24시 | `화물정보` + `자동새로고침` | `화물상세정보` + `운송료` | |
| 픽커 | `리스트 설정` | `넘기기` + `수락하기` | 홈 `시작하기` · 수락 뒤 단계 `밀어서 픽업 완료` · `밀어서 사진 촬영` · `배송 시간` … (`KakaoPickerKeywords.STAGE_WORDS`) |

⚠️ **픽커 리스트에도 «신규» 탭이 있다** (실물 02 · `신규 / 내 오더`) — 한 글자로 가르면 픽커를 인성으로 본다. 인성은 `빠른설정` 까지 둘 다 요구해서 지금은 안 겹친다.
⚠️ **실제 인성 앱 글자는 실물로 확인하지 못했다** (`TargetApp.kt` 주석). 지금 인성 글자는 시뮬레이터로 맞춰 온 것이다.
🔴 **시뮬레이터 화물24시 화면에 `자동새로고침`·`화물상세정보` 가 없다** (코드 검색 2026-09-14 · 리스트는 같은 날 고쳤다 — 한 글자가 빠진 `자동새로침` 오타였다 · 상세는 확인 대기) — 스캔앱이 지금 화물24시 시뮬레이터를 리스트·상세로 **못 알아보고 있을 수 있다.** ✅ 실물 캡처로 대조했다 (2026-09-14) — **스캔앱 글자가 맞고 시뮬레이터가 틀렸다** (실물 17·36 리스트에 `자동새로고침`, 18 상세 제목 `화물상세정보`). 시뮬레이터 계획 1단계에서 시뮬레이터 화면을 고친다.

## 3. 고치는 방향

### ③ 화면 글자로 망을 가른다

```
지금    폰 시스템이 붙여 준 앱 이름 ─→ 망 ─→ 파서 · 관제앱 배지
뒤      화면에 적힌 글자 ───────────→ 망 ─→ 파서 · 관제앱 배지
        (실제 앱이든 시뮬레이터든 같은 길)
```

**③-1. 망 표식 글자는 망 폴더에 둔다** — 공통 코드에 화면 글자를 박지 않는다 (배차망_통합 §9-4)

각 `InsungKeywords.kt` · `Hwamul24Keywords.kt` · `KakaoPickerKeywords.kt` 에 `NETWORK_MARKERS`(글자 묶음 목록)를 신설한다. **새로 적지 않고 이미 있는 글자에서 만든다** (두 곳에 적으면 갈라진다 — 규칙 ③):

| 망 | `NETWORK_MARKERS` (신설) 가 모으는 것 |
|---|---|
| 인성 | `INSUNG.listRequired` · `INSUNG.detailKeywords` |
| 화물24시 | `HWAMUL24.listRequired` · `HWAMUL24.detailKeywords` |
| 픽커 | `PICKER.listRequired` · `PICKER.detailKeywords` · `STAGE_WORDS` 의 단계마다 한 묶음(홈 `시작하기` 포함) |

⚠️ 픽커의 **한 글자짜리 묶음**(`리스트 설정` · `시작하기` · 단계 글자)은 **다른 망 화면에 절대 없어야** 한다 — 검사로 확인한다 (§5 ③).

**③-2. 판별 함수** — `core/NetworkByScreen.kt` 신설 (순수 함수 · JVM 검사로 돈다)

```kotlin
object NetworkByScreen {                                     // 신설
    /** 화면 글자로 망을 고른다. 모르면 null — 지어내지 않는다 */
    fun detect(texts: List<String>, markers: Map<String, List<List<String>>>): String? {
        val hits = markers.filter { (_, groups) ->
            groups.any { group -> group.all { w -> texts.any { it.contains(w) } } }
        }.keys
        return hits.singleOrNull()      // 둘 이상 맞으면 null — 화면이 넘어가는 중이다
    }
}
```

- 아무 망도 안 맞으면 `null` → **직전에 알아낸 망을 그대로 둔다** (폰 홈 화면 · 카톡 · 잠금화면). `NetworkSwitchGate.switchTargetFor` 가 이미 `null` 이면 안 바꾼다
- 둘 이상 맞으면 `null` + 로그 `🌐 [망 판별] 두 망 글자가 함께 보인다 — 바꾸지 않는다`
- `markers` 는 `TargetApp.kt` 가 망 목록을 돌며 각 망 폴더의 `NETWORK_MARKERS` 를 모아 넘긴다 — 망을 전부 아는 곳은 여전히 `TargetApp.kt` 한 곳이다

**③-3. 부르는 자리를 바꾼다** — `HijackService.kt`

```kotlin
// 지금
val screenNetwork = TargetApp.codeOfPackage(rootNode.packageName?.toString())
// 뒤
val screenNetwork = NetworkByScreen.detect(screenTexts, TargetApp.networkMarkers())
```

그 아래(`NetworkSwitchGate` → `switchNetworkTo` → 다시 읽기)는 **그대로 둔다** — 원천만 바뀐다.

**③-4. 앱 이름으로 가르는 것을 지운다** — `TargetApp.codeOfPackage` 와 그 검사. 망 결정에 두 원천을 두지 않는다. (③-5 ㉯ 의 로그 조건은 망을 정하지 않으므로 «이 앱 이름이 픽커인가» 한 가지만 묻는 작은 함수로 남긴다)

**③-5. 픽커 운행 단계 로그의 조건** — ✅ 기사님 확정 2026-09-14: ㉯

지금 이 로그는 «**앱 이름이 픽커**이고 리스트가 아닐 때» 남는다. 목적은 **처음 보는 픽커 화면의 글자를 모으는 것**이다(`❓ [모르는 화면]`).
화면 글자로 바꾸면 **표식 글자가 없는 픽커 화면은 픽커인지 모른다** — 바로 그 «처음 보는 화면»이다.

| | 방법 | 결과 |
|---|---|---|
| ㉮ | 표식 글자로 픽커라고 알아본 화면만 로그 | 단순하다 · **처음 보는 픽커 화면의 글자를 못 모은다** |
| ㉯ ✅ 확정 | **이 로그에 한해서만** 앱 이름을 참고한다 — 망 결정에는 안 쓴다 | 지금처럼 모은다 · 잠금화면이 찍히지 않는다(09-02 수리 유지) · 앱 이름이 «로그 조건» 한 자리에 남는다 |
| ㉰ | «직전에 알아낸 망이 픽커»면 로그 | 🔴 잠금화면·런처가 다시 «모르는 픽커 화면»으로 찍힌다 — 09-02 에 고친 것을 되돌린다 |

**③-6. 설정 화면의 망 선택 칸을 지운다** — `SettingsScreen.kt` 의 세 선택지 · `MainViewModel.saveTargetApp`

- 프리퍼런스 `targetApp` 은 남긴다 — «스캔앱이 **마지막으로** 알아낸 망». 부팅 직후 첫 화면을 읽기 전에 쓴다 (처음 설치면 인성)
- 스캔앱 화면에 따로 표시하지 않는다 — 알아낸 망은 **관제앱 폰 영역 배지**로 본다
- `saveTargetApp` 을 다른 곳에서 부르지 않는지 `pnpm audit:dead` 가 아니라(앱 코드는 거기 안 걸린다) **코드 검색으로** 확인하고 지운다

### ① 시뮬레이터 버튼 → 시뮬레이터 앱을 켠다

```kotlin

    if (intent != null) context.startActivity(intent)
    else Toast.makeText(context, "배차망 시뮬레이터 앱이 설치되어 있지 않습니다", Toast.LENGTH_LONG).show()
```

```xml

<queries>
```

- **브라우저로 되돌아가지 않는다** — 브라우저로 연 시뮬레이터는 스캔앱이 글자를 못 읽는다. 안 깔려 있으면 알리고 끝낸다
- 버튼 글자는 **바꾸지 않는다** — 여전히 맞는 말이다

### ② 낱말 사전 — 넷을 함께 고친다

순수 함수 셋을 `core/KeywordDictionary.kt` 로 신설한다 — JVM 검사로 돈다.

```kotlin
object KeywordDictionary {                                   // 신설
    /** a·b — 요청 주소는 배차망 코드로 (ASCII). 이름표→코드는 TargetApp 한 곳 */
    fun requestPath(label: String?): String =
        "/api/config/keywords?app=${TargetApp.codeOf(label)}"

    /** d — 저장된 사전이 지금 망 것일 때만 쓴다. 아니면 null (코드의 기본값) */
    fun usable(savedJson: String?, savedApp: String?, currentApp: String): String? =
        if (savedJson != null && savedApp == currentApp) savedJson else null

    /** e — 응답 코드에 따라 할 일. 200 이 아니면 저장된 사전을 지운다 */
    fun onResponse(code: Int): Action = if (code == 200) Action.SAVE else Action.CLEAR
    enum class Action { SAVE, CLEAR }
}
```

| # | 고칠 곳 | 무엇 |
|---|---|---|
| a·b | `ApiClient.fetchKeywords` | `KeywordDictionary.requestPath(이름표)` 로 요청 |
| d | `ApiClient.fetchKeywords` | 받은 사전과 함께 **받은 망 코드**를 프리퍼런스 `targetAppKeywordsApp` 에 저장 (칸 신설) |
| d | `InsungParser` 의 `uiNoiseWords` 읽는 자리 | `KeywordDictionary.usable(...)` 를 거친다 — 인성 사전이 아니면 코드의 기본값 |
| c | `HijackService.applyTargetApp` | 망이 바뀌면(`isSwitch`) **사전을 다시 받는다** — ③-6 으로 설정 화면에서 바꾸는 길이 없어지므로 **바뀌는 길은 화면 판별 하나**다 |
| e | `ApiClient.fetchKeywords` | 200 이 아니면 `targetAppKeywords`·`targetAppKeywordsApp` 을 **지우고** 로그 `🎯 [낱말 사전] 서버가 거절(코드) — 코드의 기본값으로 읽는다` |

⚠️ 사전을 받는 동안(비동기)은 d 의 대조 덕에 **다른 망 사전을 쓰지 않는다**.
⚠️ 옛 저장값(`targetAppKeywordsApp` 없이 사전만 있는 폰)은 `usable` 이 null 을 준다 → 기본값으로 읽다가 다음 요청에서 채워진다. 테스트 단계라 옛 값을 옮기는 처리는 만들지 않는다 (CLAUDE.md).

## 4. 순서 — 서버 계획과 맞물린다

```
1) 원달앱 ③ 화면 글자로 망 가르기 · ① 버튼      ← 서버와 무관. 먼저
2) 서버 [공통코드 계획 4단계 전반]  코드·이름표 둘 다 받기 · 모르는 값은 아직 지금처럼
3) 원달앱 ②  코드로 요청 · 망별 저장 · 바뀌면 다시 받기 · 거절이면 지우기
4) 폰 전부에 새 원달앱이 깔렸나 — 관제앱 폰 영역의 앱 버전으로 확인
5) 서버 [공통코드 계획 4단계 후반]  모르는 값이면 400
6) 서버가 한글 이름표를 받는 자리 지우기 — 지우기 전에 묻는다
```

🔴 **5) 를 3)·4) 보다 먼저 하지 않는다.** 옛 원달앱은 거절을 받아도 옛 사전을 그대로 쓴다 (§2 ② e).
🔴 서버는 `git push origin main` 이 곧 배포다 — **승인 없이, 기사님 운행 시간에 올리지 않는다** (CLAUDE.md «하지 말 것»).
🔴 ③ 은 **실제 픽커로 일하는 판단 경로**를 바꾼다. 폰에 올리기 전에 §5 ③ 의 «실물 픽커» 줄을 반드시 통과한다.
