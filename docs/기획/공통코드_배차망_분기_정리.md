## 1. 무엇이 문제인가

`onedal-web` 은 배차망별 차이를 **한 곳에서 답하도록** 짜여 있다:

```
배차망 코드 · 이름표      shared  TARGET_APPS · TARGET_APP_LABEL
화면 이름표               shared  screenLabels.ts (배차망별 표를 한 곳에서 고른다)
배차망마다 다른 처리      server  plugins/<배차망>/ + IAppPlugin + PluginFactory
```

그런데 공통 코드 여러 곳이 이 자리를 거치지 않고 **`=== 'kakaopicker'` 처럼 이름을 직접 묻는다.**
이미 드러난 증상이 둘이다:

- 관제웹 취소 한도 토스트가 **픽커를 «인성콜»로 적는다** — `'hwamul24' ? '화물24시' : '인성콜'` 이라 픽커가 «그 밖»으로 떨어진다
- 운행일지는 픽커 취소를 **`kakaopicker` 날것 그대로** 적는다

더 큰 위험은 **넷째 배차망**이다. 판정의 첫짐 하한가는 «픽커면 건너뛴다»로 적혀 있어서, 새 배차망은
아무 말 없이 **인성 하한(2만 원)에 걸려 전부 똥콜**이 된다 — 2026-09-02 픽커가 처음 붙었을 때 실제로 난 사고와 같은 모양이다
(`OrderEvaluator.ts` 주석: *"픽커 콜은 5,544원이 정상 범위인데 인성 하한 20,000원에 걸려 전부 «똥콜»로 나왔다"*).

## 3. 고치는 방향 — 종류별

### A. 이름표 → `shared` 의 `TARGET_APP_LABEL` 하나를 읽는다

```ts
// 지금
const name = budgetToast.app === 'hwamul24' ? '화물24시' : '인성콜';
// 뒤
const name = TARGET_APP_LABEL[budgetToast.app as TargetAppType] ?? budgetToast.app;
```

✅ **기사님 확정 (2026-09-14): 짧은 이름표 하나로 통일한다** — 토스트·일지·폰 영역 배지가 모두 `TARGET_APP_LABEL` 의 «인성 · 24시 · 픽커»를 쓴다.
⚠️ 화면 글자가 바뀐다 — 토스트가 «인성콜»에서 «인성», «화물24시»에서 «24시»가 된다 (규칙 ⑤-4 ④ 화면 · 확정됨). 이름표를 새로 만들지 않는다.

### B. 기본값 글자 → `DEFAULT_TARGET_APP`

```ts
static getPlugin(targetApp: string = DEFAULT_TARGET_APP)
db.prepare(`… COALESCE(targetApp, ?) = ?`).get(DEFAULT_TARGET_APP, …)
```

**동작은 바뀌지 않는다.** 기본값이 한 곳에 살게 될 뿐이다 (규칙 ③).
⚠️ 옛 행의 `targetApp` 이 비어 있는 것 자체는 고치지 않는다 — 지금은 테스트 단계라 옛 행을 채우는 작업을 설계하지 않는다 (CLAUDE.md «마이그레이션을 고려하지 않는다»).

### C. 배차망 성질 → `IAppPlugin` 에 칸을 신설하고 공통 코드는 플러그인에 묻는다

```ts
export interface IAppPlugin {
    …
    /** 첫짐 절대 하한가를 이 배차망에 적용하나 — 신설 (인성·24시 true · 픽커 false: 앱이 이미 걸렀다) */
    readonly appliesFirstFareFloor: boolean;
    /** 상세 화면 글자 원문을 intel 에 보관하나 — 신설 (픽커 true) */
    readonly keepsRawDetailText: boolean;
}
```

```ts
// OrderEvaluator — 지금
const skipFareFloor = this.targetApp === 'kakaopicker';
// 뒤
const skipFareFloor = !PluginFactory.getPlugin(this.targetApp).appliesFirstFareFloor;
```

🟢 **인터페이스 칸이라 새 배차망이 칸을 안 채우면 `tsc` 가 막는다** — 지금은 조용히 인성처럼 동작한다.
⚠️ `OrderEvaluator.ts:500~514` 주석의 이유(«돈은 앱이 이미 걸렀다» · 규칙 ⑤-1)는 **픽커 플러그인의 그 칸 옆으로** 옮긴다. 판정 쪽에는 «플러그인에 묻는다»만 남긴다.

### D. 한글 이름표 → 파일 대응을 한 곳으로

원달앱은 낱말 사전을 **한글 이름표로** 요청한다 (`ApiClient.kt:400` · `?app=인성콜`). 그래서 서버가 대응표를 따로 들고 있다.

- 서버는 `?app=` 에 **배차망 코드와 한글 이름표를 둘 다** 받는다 — 원달앱 배포 없이 지금 동작이 그대로 산다
- 대응은 플러그인에 칸 하나로 신설 후보: `keywordFile`(`keywords_inseong.json` …) · `appLabels`(원달앱이 보내는 이름표 «인성콜» …)
- 원달앱이 코드로 보내게 바꾸는 것은 [원달앱 계획서](원달앱_시뮬레이터_낱말사전_정리.md) ② 에서 함께 고친다
- ✅ **모르는 값이면 오류로 응답한다** (기사님 확정 2026-09-14) — `400` 과 쓸 수 있는 값 목록. `?app=` 이 **없을 때**도 같다. 픽커 폰이 인성 사전을 받아 화면을 잘못 알아보는 것보다 낫다
- 🔴 **지금 원달앱은 거절을 받으면 옛 사전을 그대로 쓴다** (`ApiClient.fetchKeywords` — 200 이 아니면 로그만 남긴다). 그 옛 사전이 다른 배차망 것일 수 있어, 서버만 먼저 바꾸면 **틀린 사전을 조용히 쓰는 길**이 된다 → 올리는 순서는 [원달앱 계획서](원달앱_시뮬레이터_낱말사전_정리.md) §4 를 따른다

### E. 취소 한도 — 먼저 확인한다

1. **확인:** 픽커 콜이 `orders.status = 'SAFE_CANCEL'` 로 끝나는 길이 있는가 — `SAFE_CANCEL` 을 쓰는 자리(`routes/detail.ts` · `routes/orders.ts` · `services/dispatchEngine.ts`)를 픽커 콜로 따라간다
2. **길이 없으면:** «픽커는 이 한도를 타지 않는다»를 검사로 잠그고 끝낸다
3. **길이 있으면:** 한도를 배차망 성질로 — 플러그인 칸 신설 후보 `cancelBudgetPerRound`. 🔴 **값을 정하기 전에 ⑤-4 다섯(스키마·값·시점·화면·읽는 곳)을 채운다** — 픽커 «하루 5번»은 노하우 자료에서 온 값이라 근거부터 확인한다

| 방법 | 기대 |

| 관제웹 검사 한 건 추가: 취소 한도 토스트에 `app: 'kakaopicker'` 를 주면 | «픽커»로 적힌다 — **고치기 전에는 «인성콜»로 빨간불** |
| 운행일지 필터 기록 한 줄에 `{ kakaopicker: 1 }` 을 주면 | «픽커 1» — 운행일지에 검사 틀이 없으면 `pnpm dev` 로 띄워 눈으로 확인하고 그렇게 적는다 |
| `pnpm test:web` | 초록 |

### 4단계 — D 낱말 사전 대응 (#5) — 기사님 확정: 모르는 값이면 오류

**만들 것:** 플러그인에 `keywordFile`·`appLabels` 신설 · `config.ts` 가 코드와 이름표를 둘 다 받게

🔴 **두 번에 나눠 올린다** — 전반(코드·이름표 둘 다 받기 · 모르는 값은 아직 지금처럼) → 원달앱 계획 ② 가 모든 폰에 깔린 뒤 → 후반(모르는 값이면 400). 순서는 [원달앱 계획서](원달앱_시뮬레이터_낱말사전_정리.md) §4

| 방법 | 기대 |
|---|---|
| 서버 검사 한 건 추가: `?app=` 에 `인성콜`·`24시`·`픽커`·`insung`·`hwamul24`·`kakaopicker` 를 하나씩 | 각자 맞는 사전 (`appName` 으로 대조) |
| 🔴 후반 · 빨간불 먼저: `?app=abc` · `?app=` 없음 | 지금은 인성 사전(200)이 와서 **실패**해야 한다 |
| 후반 · 고친 뒤: `?app=abc` · `?app=` 없음 | `400` · 응답에 쓸 수 있는 값 목록 |
| 원달앱을 **다시 깔지 않은 채** 폰에서 인성·픽커를 한 번씩 열어 로그의 낱말 사전 이름 확인 | 전과 같다 — 원달앱 배포 없이 산다 |
