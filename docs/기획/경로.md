## 2-2. 「고속도로우선」은 `TIME` 으로 근사한다

우리 길찾기 API 에 `rpOption 6`(고속도로 우선)에 딱 맞는 값이 **없다.**
그래서 09-03 여덟 구간을 전부 재서 골랐다 — **추천과 `TIME` 이 7/8 에서 같았고**,
갈린 하나(**방화동→집**)에서:

| | 거리 | 시간 | 통행료 |
|---|---|---|---|
| `RECOMMEND` | 57.7km | 148분 | 1,000원 |
| **`TIME`** | **71.3km** | **142분** | **2,000원** |

13.6km 더 멀고 통행료가 두 배인데 **6분 빠르다** — 정확히 「고속도로 우선」의 행동이다.
🟡 **어긋남이 0 은 아니다.** 그래서 §6 에 «무엇을 골랐나»를 남겨 나중에 잰다.

## 2-3. 대안경로도 온다 — 우리가 안 읽고 있었다

`alternatives=true` 를 넣으면 **경로가 여럿** 온다:
```
routes[0]  49.0km / 105분 / 3,800원
routes[1]  56.6km / 115분 / 1,000원   ← 10분 더 걸리고 2,800원 싸다
```
🔴 `kakaoService.ts` 는 **`data.routes[0]` 만 읽는다.**
⚠️ 켜면 **routes[0] 자체가 달라졌다**(47.5km/1,900원 → 49.0km/3,800원). 왜인지 모른다 —
   **켜기 전에 다시 재야 한다.**

## 2-4. 통행료는 이미 응답에 있다

```
summary.fare = { taxi: 65500, toll: 1900 }
```
그 1,900원이 **카카오내비 앱 화면의 1,900원과 같았다** (교차검증).
⚠️ `orders.tollFare` 는 **다른 값이다** — 배차망 화면에서 긁은 「탁송료/경유비」
(`parser.ts` 의 `extractField(lines, "탁송료")`). **한 칸에 섞으면 안 된다.**

## 2-5. 차종은 「갈 수 있는 길」을 바꾼다

| `car_type` | 거리 | 시간 | 통행료 |
|---|---|---|---|
| **1** (승용/1t) | 47.5km | 103분 | **1,900원** |
| **7** (이륜차) | **54.5km** | **132분** | **0원** ← 고속도로를 뺀다 |

🔴 **새 매핑을 만들지 않는다.** `mapVehicleToKakaoCarType('1t') = 1` 을 그대로 읽는다.
   이 레포는 이미 `car_type` 두 벌을 죽인 적이 있다 (`db.ts:146`, 전수조사 2026-08-21).
🟢 기사님이 실주행을 **승용차로** 하셔도 값이 같다 — 승용차도 1종이다.

## 2-6. 카카오내비 URL — SDK 를 안 깐다

```
kakaonavi-sdk://navigate?appkey=<JS키>&apiver=1.0&extras=<json>&param=<json>

param = {"destination":{"name":…,"x":경도,"y":위도},
         "option":{"coord_type":"wgs84"},
         "via_list":[{"name":…,"x":경도,"y":위도}]}
extras = {"KA":"sdk/… os/javascript lang/ko-KR origin/https://1dal.altari.com"}
```

🔴 **경유지 칸 이름은 `via_list` 다 — `viaPoints` 는 조용히 무시된다.**
문서 어디에도 없어서 **두 벌을 만들어 기사님 폰에서 눌러** 갈랐다:

| 보낸 이름 | 결과 |
|---|---|
| **`via_list`** | ✅ 「경유 1」 마커 · **45km / 1시간 42분** |
| `viaPoints` | ❌ 마커 없음 · 44km / 1시간 44분 — **경로가 그냥 사라졌다** |

👉 **틀린 이름을 보내도 에러가 안 난다.** 멀쩡해 보이는 경로가 나온다. **검사가 유일한 방어다.**

**`rpOption` 표** (공식 레퍼런스):

| 값 | 뜻 | 우리 대응 |
|---|---|---|
| **100** | 추천 *(기본)* | `RECOMMEND` |
| 1 | 가장 빠른 경로 | `TIME` |
| **2** | **무료 도로** | `avoid=toll` |
| 3 | 가장 짧은 경로 | `DISTANCE` |
| 4 | 자동차 전용 제외 | `avoid=motorway` |
| 5 | 큰길 우선 | ❌ 우리 쪽에 없음 |
| **6** | **고속도로 우선** | 🟡 `TIME` 로 근사 (§2-2) |
| 8 | 일반 도로 우선 | ❌ 우리 쪽에 없음 |

**그 밖에 실측으로 알아낸 것**
- 🔴 **`ViaPoint.name` 이 필수다** — `kakaomap://` 은 좌표만으로 되는데 이건 이름이 필요하다
- 🔴 **`coord_type` 기본이 `katec`** — 안 넣으면 조용히 엉뚱한 데로 간다
- 🔴 **도메인 등록이 필수다** — 콘솔이 *"등록하지 않으면 JavaScript 키를 사용할 수 없습니다"*
  라고 못박는다. 2026-09-04 에 `https://1dal.altari.com` 을 등록했다
- 🟢 **아이폰에서 열렸다** — 데브톡의 «iOS 사파리에서 안 열린다»는 2017년 이야기였다
- 🟢 출발지를 생략하면 **현위치**에서 시작한다

# 3. 경로를 고른다

> 기사님(2026-09-04): *"첫콜을 잡을 때 경로가 계산될 거야. 고속도로면 **가는 길에 콜이
> 떠도 한참을 돌아서** 가야 하고 통행료도 내지만 **시간은 단축**할 수 있어 — 콜을 찾는
> 대기시간이 늘어나 **비싼 콜을 잡을 수 있는 장점**이 있는 거지. 국도는 반대고.
> 첫콜을 잡고 나면 경로가 확정되니 **이후 필터 방향이 바뀌어야 할지도 몰라.**"*

## 3-1. 무엇이 맞바꿔지나

```
고속도로   주행 ↓  ·  경로 주변 합짐 ↓ (진출입이 드물다)  ·  통행료 ↑
국도       주행 ↑  ·  경로 주변 합짐 ↑                    ·  통행료 0
```

그리고 **줄어든 주행이 그냥 사라지지 않는다:**
```
상차버퍼 = 상차 약속 − (현위치→상차지 주행 + 상차 정차)
           ↑ 콜 잡은 시각 + 20분 (고정)      ↑ 경로 선택이 줄인다
```
상차 약속은 **주행에서 파생되지 않는 고정값**이라(규칙 ⑤-5), 주행이 줄면 **상차버퍼가
그만큼 커진다.** 그 자리에서 더 기다릴 수 있고, **급하게 아무거나 안 잡아도 된다.**

## 3-2. 🔴 선택은 **«어디서 콜을 모으나»** 를 정하는 일이다

> 기사님: *"기사는 **고속도로를 선택했다면 최대한 지금 자리에서 파주 가는 콜을 많이 잡고
> 출발**하려 할 거야. **무료도로를 선택했다면 여기서 조금만 대기하고 가는 길에 나오는 콜을
> 많이 잡겠다**는 생각을 할 거야."*

| | 고속도로를 골랐다 | 무료도로를 골랐다 |
|---|---|---|
| 속뜻 | *"길에서는 못 줍는다"* | *"길에서 줍겠다"* |
| **어디서 모으나** | **지금 이 자리** — 출발 전에 최대한 | **가는 길** |
| 상차버퍼를 | **다 쓴다** (여기서 기다린다) | **조금만 쓰고 출발** |

**그 두 축이 이미 있다** (`shared/src/index.ts`):

| 축 | 지금 뜻 |
|---|---|
| **`pickupRadiusKm`** | *"내 위치 반경 상차지 탐색(km)"* → **「여기서 잡는다」** |
| **`detourRadiusKm`** | *"경로 주변 이탈 허용 반경"* → **「가는 길에 잡는다」** |

```
고속도로우선 →  pickupRadiusKm ↑   ·  detourRadiusKm ↓
무료도로     →  pickupRadiusKm ↓   ·  detourRadiusKm ↑
추천         →  지금 값 그대로
```

🟢 **그 무게가 이미 국면마다 다르다** (`user_filter_phases` · 09-03 실제값):

| 국면 | 상차반경 | **경유허용** | 하차반경 |
|---|---|---|---|
| `first`(노선) | 10km | **5km** | 0 |
| `home`(복귀) | 10km | **110km** | 10km |

**복귀의 경유허용이 노선의 22배**다 — **복귀는 이미 「가는 길에 잡는다」로 설정되어 있다.**
새 개념이 아니라 **이미 쓰고 있는 축에 이름을 붙이는 일**이다.

⚠️ **노선과 복귀는 방향만 다르고 같다** (기사님 2026-09-04) — 상차는 둘 다 «내 주위»,
   하차만 «파주 주위 / 집 주위»로 갈린다. **타입마다 특별 규칙을 만들지 않는다.**

⚠️ **얼마나 옮길지는 숫자가 없다.** 표본이 쌓여야 안다 (§6).

## 3-3. ③ 시점 — 첫콜 결재 순간 하나뿐이다

```
STANDBY(첫짐 탐색)   경로가 아예 없다 — 고를 대상이 없다
      ↓  첫콜 KEEP   ◀── 🎯 여기. 경로가 여기서 태어난다
GATHERING(합짐 수집) 필터가 이미 그 경로로 돌기 시작했다 — 늦다
```
**그리고 이때 기사님은 서 있다.** 입력이 가능한, 하루에 몇 없는 순간이다.
⚠️ **합짐 콜에는 이 선택을 안 준다.** 경로는 첫콜이 정하고 합짐은 거기 붙는다 (규칙 ⑥).

## 3-4. ④ 화면 — 의도를 미리 고른다

> 기사님: *"만약 필터 설정창에 **「여기서 콜을 잡고 간다」와 「가는 길에 콜을 잡는다」**
> 이런 버튼이 있다면, 첫콜이 뜰 때 그걸 **미리 선택해서 보여줄 수 있고** 기사가 다 눌러볼
> 필요 없이 **그냥 킵을 누를 수 있을** 거야. 그럼 **우리 시스템이 쉬워지는** 거지."*

**말이 바뀌는 것이 핵심이다** — 「무료도로」는 *어떻게* 가느냐이고,
「가는 길에 잡는다」는 ***왜* 그렇게 가느냐**다. 기사님이 하는 생각은 뒤쪽이다.

**기사님이 정하신 것** (2026-09-04):

| | |
|---|---|
| **버튼** | **셋.** 하나는 **언제나 눌려 있다** (빈칸이 없다) |
| **어디서 바꾸나** | **필터에서.** 바꾸면 결재 화면에 **그게 눌린 채로** 나온다 |
| **오늘만 / 평소** | **필터 설정 맨 끝에서** 고른다 |
| **용어집** | **안 넣는다** — 풀어 쓴 말이라 설명이 필요 없다 |

🟢 **«맨 끝에서 고른다»가 중요하다.** 지금 ⚙️설정(평소)과 🔍필터(오늘만)가 **다른 화면**이라
2026-08-12 에 두 값이 갈라졌다(*"설정엔 파주인데 필터를 열면 용인"*). 한 화면에서 고르고
맨 끝에 «어디에 저장할까»를 묻는 방식이라 **갈라질 자리가 없다.**

**결재 화면 — 셋을 다 적는다:**
```
🔵 꿀콜   초월읍 상차 → 방화동 하차

   ▸ 🚚 여기서 잡고 간다   130km  113분  10,000원      ← 미리 눌려 있다
     🛣️ 가는 길에 잡는다    91km  200분       0원
     ⚖️ 추천               130km  113분  10,000원
```

🔴 **거리·시간·통행료 셋을 다 적는다** (기사님: *"걸리는 시간, 거리, 통행료를 감안하고
   생각하겠지"*). **거리는 기름값**이고 시간에서 파생되지 않는다 — 집→파주에서 무료도로는
   **더 짧으면서 더 느리다**(91km/200분 vs 130km/113분).

🔴 **그냥 KEEP 하면 지금과 똑같이 동작한다.** 고르는 건 선택이지 관문이 아니다.
🔴 **다만 기사님은 실제로 눌러 보신다** (*"30초 안에 3개를 눌러보고 하나를 선택하고 킵"*).
   누를 때 숫자·지도 선·«어디서 모을지»가 **그 자리에서 함께 움직여야** 한다.
⚠️ 셋을 **한 번에** 불러야 한다 (§2-8).
⚠️ 비교를 **심사 중인 모든 후보에** 부르지 않는다 — **결재 대상 하나만**이다.

🟢 **덤으로 죽은 설정 셋이 살아난다** — `avoid_toll`·`car_hipass`·`car_fuel` 이

> 그것이 안 된다면 … **경유지 도착하면 다음 경유지 위치까지만 내비로 가고, 도착하면
> 정차 중에 다시 다음 경로까지만 요청하고** 그런 식으로 해야 할지도 몰라."*

3콜 = 6정거장 = 경유 5개인데 카카오내비는 3개다. 그리고 **3콜이 상한도 아니다**(§2-7).
🟢 **카카오맵을 따로 부를 필요는 없다** — 우리는 **이미 전체 경로를 갖고 있다**
   (`orders.routePolyline`, 지금 지도가 그걸 그린다).

**그리고 한 구간씩 보내면 가정 셋이 통째로 사라진다:**

| | 3경유씩 보내기 | **한 구간씩** |
|---|---|---|
| ① 경유지로 안내하나 | 의존 | **경유지가 없다** |
| ② 지나면 넘어가나 | 의존 | **넘어갈 게 없다** |
| ③ 재탐색이 순서를 지키나 | 의존 | **순서가 없다** |
| 탭 (6정거장) | 2번 | 6번 — **매번 정차 중이다** |
| 우리 선 | 2번 갱신 | **6번 갱신** |

👉 **가정 위에 서 있던 판이 사실 위에 서게 된다.**

🟢 **전체 경로는 관제웹 지도가 보여준다.** 09-03: *"전체 경로가 같이 보이는 건 좋았는데
   **지금 가고 있는 곳만** 볼 수 있으면"* — 지도의 「현구간」이 이미 그 일을 한다.
🟢 **매번 새 선을 받는다** → §5 의 «값이 늙는다»가 크게 완화된다.

## 4-2. ⑤ 읽는 곳

### «자르는 개수» 문제가 없어졌다 — 각 버튼이 자기 숫자를 말한다

처음엔 *"`KAKAO_MAX_VIA`(=5) 하나가 세 가지를 답한다 → 4번째 정거장이 조용히 사라지는데
화면은 «6곳»이라 적는다"* 가 걱정이었다. **§4-1 이 없앴다** — 내비에는 **하나**만 보내므로
자를 목록이 없다.

| 버튼 | 보내는 것 | 말하는 것 |
|---|---|---|
| 🧭 **카카오내비** | **다음 정거장 하나** | 「다음 ① 초월읍 상차」 |
| 🗺️ 카카오맵 | 경유 5 + 도착 1 | 「경유 5곳 · 도착 방화동」 |

⚠️ 목록의 **흐리게 + «— 다음에»** 는 카카오맵의 사정이라 **함께 내려간다.**

### 🔴 좌표 차례가 둘이 반대다

| | 차례 | 우리 DB 와 |
|---|---|---|
| `kakaomap://` | **`위도,경도`** 문자열 | **뒤집는다** |
| `kakaonavi-sdk://` | JSON `x`=경도 `y`=위도 | **그대로** |

한 파일(`naviLink.ts`)에 **반대 규칙 둘**이 산다. 그 파일 주석이 *"이 변환을 여기 한 곳에만
둔다"* 고 적어 뒀는데 그 «한 곳»이 둘이 된다.
👉 뒤집기는 **`pair()` 안에만** 두고 카카오내비 쪽은 **아예 안 부른다.**

### 🔴 «다음 정거장»을 누가 정하나 — 서버 하나다

🟢 **이미 그렇다** — `/navi` 는 서버가 준 `routeStops` 를 그대로 쓰고 자기 순서를 안 만든다
   (`useNaviRoute` · 규칙 ③). **`routeStops[0]` 이 곧 «다음»이다.**

⚠️ 그래서 **서버가 틀리면 내비도 틀린다:**

| 언제 | 무슨 일 | 무엇을 해야 하나 |
|---|---|---|
| **도착 감지 실패** (터널·기지국 좌표) | `routeStops[0]` 이 **이미 다녀온 곳**을 가리킨다 | **손으로 넘길 길** — 「다음 정거장으로」 |
| **합짐으로 순서가 바뀜** | 내비는 옛 목적지로 안내 중인데 화면은 새 순서다 | **버튼이 눈에 띄게** — 「경로가 바뀌었습니다」 |

## 4-3. ④ 화면 — **관제폰에만 있다**

**관제폰 지도 좌하단** — 누르면 QR 이 뜬다
```
🧭  다음 ① 초월읍 상차
        ↓ 누르면
   ┌───────────┐
   │  ▪▪ ▪  ▪▪ │   개인폰 카메라로 찍는다
   │  ▪  ▪▪▪ ▪ │   → 카카오내비가 열린다
   │  ▪▪▪ ▪  ▪ │
   └───────────┘
   🗺️ 카카오맵 QR 로 바꾸기   ← 작게. 되돌아갈 길
```

🔴 **개인폰에는 아무것도 없다.** 카메라만 쓴다.
🟢 **되돌아갈 길도 QR 이다** — 카카오내비가 별로면 같은 자리에서 카카오맵 QR 로 바꾼다.

🔴 **왜 둘을 두나** — 주행 중 «별로다»가 나오면 **배포 없이 되돌아갈 길**이 있어야 한다.
   운전석에서 «안 되네» 하고 끝나면 그날 일을 망친다.
⚠️ 규칙 «큰 버튼 하나»와 어긋나 보이지만 아니다 — **둘은 크기가 다르다.**
🟢 실주행에서 좋으면 **카카오맵을 뗀다.** 그때 이 절을 지운다.

## 4-4. ① 스키마 — 새 DB 칸이 없다

| 무엇 | 어디 | 왜 |
|---|---|---|
| JavaScript 앱 키 | `client-app/.env` 의 `VITE_KAKAO_JS_KEY` | 자격증명이지 «기본값»이 아니다. `VITE_GOOGLE_CLIENT_ID` 와 같은 자리 |
| 출처(origin) | 저장 안 함 — `location.origin` | 파생된다 (규칙 ③) |
| 차종 | **있는 것을 읽는다** (`vehicle_type`) | §2-5 |

⚠️ **JS 키가 번들에 실린다.** 괜찮다 — 웹에 실리라고 만든 키이고 **도메인 등록이 유일한
   방어**다. 🔴 **REST 키는 절대 여기 오면 안 된다** — 그건 서버에만 산다.

# 5. 남은 분을 센다

> 기사님(2026-09-04): *"카카오가 값을 주었지만 표시하기 어렵겠군.. 구간별 위치값을
> 나누어서 계산하면 나올 수 있을까? 그건 너무 자주 계산되어 부하가 많을 수 있겠다."*

## 5-1. 무엇이 문제인가 — 값이 늙는다

`StopLead.driveMinutes` 는 **카카오 호출 시점부터의 누적**이다 (`timing.ts` 주석).
```
14:51  카카오에 묻는다   →  "가산동까지 8분"
15:20  29분을 달렸다     →  화면은 여전히  "~8분"
```
**틀린 게 아니라 낡은 것**이라 더 나쁘다 — 화면이 조용히 거짓말한다.

## 5-2. 🔴 값을 **둘로 가른다** — 이 절의 심장

지금 `driveMinutes` 를 읽는 곳이 여럿이다:

| 읽는 곳 | 무슨 질문의 답으로 |
|---|---|
| `etaMs` · `departByMs` · `promisedUntil` | *"몇 시에 도착한다고 약속하나"* |
| `segmentDriveMinutes` (통화 문장) | *"…에서 8분 상차하고 17:03 출발"* |
| 지도 이름표 · **시트 상태바** | *"지금 얼마나 남았나"* |

🔴 **살아 있는 값을 전부에 먹이면 약속이 GPS 마다 흔들린다.** 2026-08-18 에 이미 앓았다 —
상차 소요를 약속에 섞었더니 **신고할 때마다 약속이 흔들렸다.**

| 값 | 답하는 질문 | 언제 바뀌나 | 읽는 곳 |
|---|---|---|---|
| `driveMinutes` (지금 있는 것) | *"**계획대로면** 얼마"* | 카카오를 부를 때만 | 약속 · 출발마감 · 통화 문장 |
| **`remainingMinutes`** (새로) | *"**지금 여기서** 얼마"* | GPS 마다 | **시트 상태바 하나뿐** |

⚠️ **새 값을 약속 계산에 절대 넣지 않는다.** 검사로 잠근다 (§8).

## 5-3. 어떻게 계산하나 — 모드가 없는 한 식

```
남은 = (현위치 → 남은 선의 가장 가까운 «앞» 점)  +  (그 점 → 목적지, 도로 기준)
                        ↑
          선 위면 46m ≈ 0    ·    벗어나면 800m
```
숫자가 **끊기지 않고 서서히 나빠진다.** 모드 전환도 이름표도 빈칸도 없다.

- 누적 거리표는 **선이 바뀔 때 한 번** 만든다 (939점이면 939칸)
- GPS 마다 **가장 가까운 점 찾기 + 빼기** — 939점 실측 **1.2μs** (5초마다 재도 1시간에 0.9ms).
  `nearestIndex()` 가 `hooks/useMockGpsSimulator.ts` 에 이미 있다
- 분 = `남은 km × (카카오 구간 distance ÷ duration)` — **도로 기준** (규칙 ④)

🔴 **«앞» 점이어야 한다.** 그냥 «가장 가까운 점»을 쓰면 되돌아가는 길에서 뒤쪽 점이 잡혀
   **남은 거리가 갑자기 줄어든다.** 다녀온 정거장 뒤로 잘라서 찾는다.
🔴 **분을 못 만들면 그 조각을 통째로 뺀다** — `sheetStatus` 가 이미 그렇게 되어 있다.

## 5-4. 🔴 뒤집힌 전제 — 이탈은 «지울 이유»가 아니다

처음 내 안은 *"선에서 멀어지면 분을 지우고 «경로 이탈»이라 적는다"* 였다. **셋 다 틀렸다.**

| 무엇 | 왜 틀렸나 |
|---|---|
| «경로 이탈»이라 적기 | 기사님이 **이미 아는 말**이다 |
| 숫자 지우기 | 벗어난 **그때가 숫자가 가장 필요한 순간**이다 |
| 애초에 «이탈»이라 부른 것 | 내비가 다른 길로 안내했으면 기사님은 **멀쩡한 길** 위에 있다. 틀린 건 **우리 선**이다 |

> **화면에 «이탈»이라는 상태가 아예 없다.** «이탈»은 **지도가 이미 말한다** —
> 계획선과 궤적이 눈에 띄게 벌어진다.

## 5-5. ⏳ Q8 — 벗어나면 다시 물을 것인가 (**기사님 판단 대기**)

**없으면 무엇이 낡나:**

| | 얼마나 나쁜가 |
|---|---|
| 상태바의 남은 분 | 09-03 최대 800m ≈ **+1~2분.** 작다 |
| 지도의 계획선 | 옛 길이 남는다 — **오히려 좋다.** 벌어지는 것이 곧 「이탈」 표시다 |
| 필터의 경유 지역 | 옛 경로 기준. **이것 하나가 실질적이다** |

🔴 **§4-1 이 전제를 바꿨다** — 정거장마다 선을 새로 받으니 낡을 시간이 **한 구간**뿐이다.
그리고 자동 재호출에는 **달리는 중에 지도 선이 갑자기 바뀌는** 비용이 있다.

# 7. 깨지는 경우의 수

**판정** ✅ 답한다 · ⚠️ 반쯤 · 🔴 구멍

## A. ⚠️ 무료도로를 골랐더니 도심에 갇혔다 (기사님 시나리오)

> *"9시 파주 방향으로 설정하고 콜을 잡는다. **서울을 무료도로로 잡으니 서울을 관통하는
> 길이 나오고** 합짐을 시작한다. 강남에서 강북 가는 콜이 필터를 통과해 올라와 잡았다.
> **출발하니 갑자기 거기가 엄청 막힌다.** 중간에 합짐 경로가 있으니 **경로를 다시 설정해도
> 서울을 지나갈 수밖에 없다.**"*

**실제로 일어난다** (§2-1 집→파주). 세 단계로 잠긴다:
```
① 무료도로를 고른다        →  경로가 도심을 관통한다
② 필터가 도심 읍면동을 연다  →  강남→강북 콜이 올라온다
③ 그 콜을 KEEP 한다        →  🔒 경로가 도심에 고정된다
```

🟢 **기사님이 답하셨다 — 갇히는 것이 «설계»다.**
> *"그래서 내가 타입을 **노선·관내·복귀** 이렇게 부르는 거야. … 30초 안에 3개를 눌러보고
> 하나를 선택하고 킵을 누르는 거야. **그럼 노선이 결정 나는** 거지."*

**타입 이름 자체가 «한 번 정하면 그 길로 간다»는 뜻이었다.** ①②③ 은 버그가 아니라
**의도대로 동작한 것**이다. **되돌리기는 만들지 않는다** — 되돌리려면 이미 잡은 콜의
약속을 다시 짜야 하고, 그건 화주와 한 통화가 무너지는 일이다.

🔴 **남은 위험은 «막히는 걸 모르는 것» 하나다.** 카카오 응답에 도로별 교통 상태가
   실려 오지만 **우리는 아직 안 읽는다.** **별도 판이다.**

## B. 경로 선택이 낳는 함정

| | 무슨 일 | 어떻게 |
|---|---|---|
| **B-1** ⚠️ | 고속도로우선을 골랐더니 **합짐이 하나도 안 붙는다** | §3-2 대로 `pickupRadiusKm` 가 대신 열린다. 「고속도로우선 = 합짐을 포기한다」를 화면이 말해야 하나? |
| **B-2** ⚠️ | 비교표를 본 시점과 KEEP 시점이 다르다 | 30초면 작지만 0 은 아니다 (§2-8). 부른 시각을 적을 것인가? |
| **B-3** 🔴 | **무료도로를 골랐는데 통행료가 0 이 아니다** | `avoid=toll` 이 완전 회피를 **보장하지 않는다.** 저장은 실제값으로, 표시는? |
| **B-4** ⚠️ | 첫콜을 취소했다 | 고른 기준이 다음 첫콜에 이어지나, 기본으로 돌아가나 |

## C. 내비를 한 구간씩 보낼 때

|---|---|---|
| **C-1** 🟢 | 버튼을 안 누르고 그냥 출발하셨다 | **문제가 아니다** — 남은 분은 우리가 GPS 로 센다. 다만 **«눌러야 한다»고 재촉하면 안 된다** |

| **C-3** 🔴 | 합짐으로 순서가 바뀜 — 이미 켠 뒤다 | **버튼이 눈에 띄게** (§4-2) |
| **C-4** ⚠️ | 내비가 우리와 다른 길로 간다 | 한계로 적어 둔다 (§9). 남은 분은 GPS 로 세므로 **버틴다** |

## G. ✅ 노선→복귀 전환 — **내 전제가 틀려서 무너진 시나리오**

내가 *"복귀에는 약속이 없으니 시간을 돈으로 사는 셈이 성립하지 않는다"* 고 썼는데
**틀렸다** — 복귀도 **짐을 싣고** 간다. 기사님: *"**노선과 복귀는 방향만 다르고 같은 거야.**
어차피 방향만 다른 거라 **기사가 선택하는 거야.**"*

**남긴다** — 틀린 전제가 어떻게 그럴듯한 설계를 낳는지가 이 절의 값어치다.

# 10. 남는 한계 — 푸는 게 아니라 적어 두는 것

🔴 **기사님 내비가 어느 길로 갔는지 우리는 끝내 알 수 없다.** 카카오내비는 되돌려 주지
않는다. 링크를 넘기는 순간 우리 손을 떠난다 — 카카오맵이든 카카오내비든 같다.
그래서 §5 가 **위치에서 되짚는** 방식인 것이고, 숫자는 **언제나 `~`(추정)** 이다.

🟡 **「고속도로우선」은 `TIME` 근사다** (§2-2). 어긋남이 0 은 아니다 — §6 으로 잰다.

⚠️ **터널** — GPS 가 얼면 좌표가 굳어 «선 위»로 보인다. 남은 분도 안 변한다.
   **화면이 굳는 것은 사실이지만 거짓말은 아니다.** 09-03 에 터널이 길었으므로 실주행에서 본다.

⚠️ **미설치일 때** — 설치 페이지로 간다는 것이 문서의 말이다. 기사님 폰엔 깔려 있어 확인할
   일이 없었다. **한 번쯤 지우고 눌러 볼 값어치가 있다.**
