# 필터 파이프라인 설계 — 스캔앱에서 거꾸로 올라간다

> 🔴 **이것은 계획이다.** 「지금」이라 적은 것은 코드에서 읽은 사실이고, 「바꾼다」는 아직 없다.
> 다 만들면 이 문서를 `docs/지금/필터.md` 와 합치고 여기는 지운다.
>
> 범위: **관제앱 필터값 + 현위치 + 지금 콜 상태** → **스캔앱으로 내려가는 필터 값**.
> 조사 기준 커밋 `3732fe6e`.

## 왜 역순인가

필터는 앞에서 뒤로 만들어졌다. 그래서 «무엇을 위해 있는 값인가»를 잃은 칸이 생겼다.
목적지 반경은 매 하트비트에 스캔앱으로 내려가는데 **스캔앱이 아무 데서도 안 읽는다.**
끝에서 거꾸로 올라오면 그런 칸이 첫 장에서 드러난다.

## 지금 무엇이 잘못됐나 — 한 문장

**상위에 있는 것이 일을 나눠 주고 있다.**

```
사실 ──▶ state 하나로 뭉친다 ──▶ 표를 보고 재료를 켠다 ──▶ 영역
      (콜 수 + 출발 여부)      (상태 × 목적지 개수 칸)
```

부품이 자기에게 필요한 사실을 직접 안 보고 **뭉친 이름**을 거친다. 그래서 경우가
상태 개수 × 목적지 개수로 늘고, 그 칸을 표로 채우게 된다. 표를 정확히 채워도 사실이 하나 늘거나
목적지가 하나 늘면 칸이 새로 생기고, 새 칸은 아무도 안 채운다.

실제로 났다. 복귀를 켜서 목적지가 둘이 되자 상차 영역의 라인이 통째로 꺼졌다.

```ts
line: zones.every(z => z.state === 'driving')   // 광주가 «콜 없음»이라 거짓
```

## 본보기는 이미 레포 안에 있다 — 시트 · 아코디언 · 스텝

관제웹의 시트·아코디언·스텝은 **각자 구독하지 않는다.** 그 반대다.

```
소켓 하나  ──▶  저장소가 «사실»만 담는다  ──▶  순수 함수가 판단  ──▶  부품은 받아서 그린다
                (계산 없음)                   (화면·소켓·타이머를 모른다)
```

시트(`StageSheet`)는 저장소도 소켓도 안 본다. 받는 것은 속성뿐이다. 스텝 트랙(`StepSwipeTrack`)도 같다.
판단은 `stageRules.stageStep` · `sheetTransition` · `barFocusOf` 같은 순수 함수가 한다. 폰 없이 검사된다.

그렇게 만든 까닭이 주석에 남아 있다. 예전에 도착 사건을 세 곳이 각자 듣고 각자 판단해서
「덱이 가리킨 콜」과 「시트가 연 콜」이 갈라졌다. 기사님 말씀이 그대로 인용되어 있다.
*"gps 관리하는 거 하나 만들고 경로 관리하는 거 만들고 gps 가 이동하면 경로 관리하는 것이 이벤트 발생.
지금 그걸 각자 하고 있어서 문제 같은데."*

**필터만 그 구조 밖에 있다.** 화면규칙 문서에 필터 이벤트가 이름까지 정의되어 있는데 듣는 부품이 없다.

| 이벤트 | 규칙 | 상태 |
|---|---|---|
| `FILTER_CORRIDOR_CHANGED` (E21) | F5 경로가 바뀌면 경유 지역도 바뀌어야 한다 | ⬜ **듣는 곳이 없다** |
| — | F2 두 그릇이다 (메모리 · 서버 저장) | ⬜ 잠그는 검사가 없다 |

## 0. 새 뼈대 — 층 다섯

각 층은 **아래층이 내놓은 것만** 받는다. 위층을 되돌아보지 않는다.

```
⑦ 사실     내 위치 · 잡은 콜 · 얼린 경로 · 출발했나 · 기사님이 정한 값
              │   각 조각이 자기에게 필요한 사실만 골라 본다
⑥ 조각     현위치 원 · 라인 띠 · 목적지 원 · 마름모        ← 켜짐/꺼짐과 모양
              │   상차는 겹치고(∩) 하차는 더한다(∪)
⑤ 영역     { 조각 목록, 합치는 법, 빼는 것 }              ← 값이다. 서버와 화면이 같은 것을 받는다
              ├──▶ ④ 목록   영역 안의 읍·면·동          (서버)
              └──▶    그림   영역을 칠한다                (관제웹)
③ 지역 목록  상차 목록 · 하차 목록 · 별칭 · 덫 · 진행도
              │
② 조립     스캔앱 봉투에 담는다
              │
① 스캔앱    필터 값 열아홉 칸
```

🔴 **⑤ 영역이 값으로 오가는 것이 이 설계의 전부다.** 지금은 서버와 관제웹이 ⑥⑤를 **각자 다시 만든다.**

## ① 스캔앱이 받는 값

### 나가는 자리는 하나
`POST /api/scrap` 응답의 `dispatchEngineArgs`. 만드는 곳 `routes/scrap.ts`.
스캔앱은 그 **원문 문자열**을 그대로 저장한다 (`ApiClient`). 다시 직렬화하지 않는다 — 값이 사라진 적이 있다.

`GET /api/config/keywords` 는 필터가 아니라 화면 낱말 사전이다. `routes/filters.ts` 는 묘비다(마운트 없음).

### 칸의 원천은 표 하나
`shared/src/index.ts` 의 `APP_FILTER_KEYS`. `server/tests/rules/appFilterKeys.test.ts` 가 잠근다 —
스캔앱 Kotlin 에서 `filter.X` 로 읽는 이름이 표에 다 있는지, 관제웹 전용 값이 표에 섞이지 않았는지,
서버가 소수로 보낼 수 있는 칸을 스캔앱이 정수로 받지 않는지.

세는 명령: `grep -c "'" onedal-web/shared/src/index.ts` 대신 `npx jest tests/rules/appFilterKeys` 를 돌린다.

| 갈래 | 칸 |
|---|---|
| 켜짐 | `isActive` · `isSharedMode` |
| 지역 목록 | `pickupKeywords` · `destinationKeywords` · `customCityFilters` · `keywordTraps` · `excludedKeywords` |
| 반경 | `pickupRadiusKm` · `destinationRadiusKm` |
| 목적지 | `destinationCity` |
| 순서 | `orderKm` |
| 돈 | `minFare` · `maxFare` · `ratePerKm` · `pickerAlarmMinFare` |
| 차종 | `allowedVehicleTypes` |
| 대기 시간 | `safeCancelSecInsung` · `safeCancelSecHwamul24` · `pickerAlarmDetailSec` |

### 🔴 빈 목록은 «전부 통과»가 아니라 «고장»이다
- `pickupKeywords` — **`null` 은 옛 서버**(스캔앱이 옛 판정으로 물러선다) · **빈 목록은 차단**
- `destinationKeywords` — 비면 차단
- `orderKm` — 빈 맵은 첫짐(순서 안 봄) · 키 없음은 경로 밖 차단 · 값이 없으면 통과

이 셋의 뜻이 서로 다르다. **하나로 합치지 않는다.**

### 지금 어긋난 것

| # | 무엇 | 사실 |
|---|---|---|
| 1-a | `destinationRadiusKm` | 매번 실려 가는데 스캔앱이 **아무 데서도 안 읽는다.** 자동 반경이면 소수까지 실린다 |
| 1-b | `destinationCity` | 판정에서 읽는 곳이 없다. 디버그 화면 문구에만 쓴다 |
| 1-c | `ScrapResponse` 타입 | 「필터 전체가 간다」고 말하는데 실제는 골라 담기다. 그리고 **아무도 import 하지 않는다** |
| 1-d | 표 위 주석 | 「이 열다섯만」이라 적혀 있는데 실제 칸 수가 다르다. 숫자를 적지 말고 세는 명령을 적는다 |
| 1-e | 스캔앱 안의 갈래 셋 | 수동 파싱 갈래가 대기 시간 셋과 픽커 알람 하한을 **안 읽는다.** 그 경로로 만든 값은 늘 기본값 |

### 바꾼다
- **①-1** 죽은 칸 둘(`destinationRadiusKm` · `destinationCity`)을 표에서 뺀다. 디버그 화면은 다른 길로 받는다
- **①-2** 쓰이지 않는 `ScrapResponse` 타입을 지운다. 규격은 표 하나다
- **①-3** 표 위 주석에서 숫자를 뺀다
- **①-4** 스캔앱이 필터를 읽는 갈래를 **하나로** 모은다. 갈래가 셋이라 어느 칸이 어디서 안 읽히는지 사람이 기억해야 한다

## ② 조립 — 봉투에 담는 마지막 함수

### 지금
`routes/scrap.ts` 가 순서대로 한다. 표로 고르고, 반경 둘을 덮어쓰고, 복귀행이면 목적지 시를 갈아 끼우고,
순서 값을 얹고, 픽커 알람 하한과 대기 시간 셋을 얹고, 네 경우에 `isActive` 를 끄고, 버전이 같으면 본문을 뺀다.

`isActive` 를 끄는 네 경우: 부트스트랩 중 · 적재 만석 · 관제탑 미접속 · 콜 필터 차단기.

### 🔴 이 층은 계산하지 않는다
지금 반경을 여기서 `effectiveRadii` 로 **덮어쓴다.** 그것은 계산이다. 계산은 ⑥⑤에서 끝나야 한다.
조립은 «있는 값을 봉투에 담기»만 한다.

### 바꾼다
- **②-1** `effectiveRadii` 호출을 조립에서 뺀다. ⑦ 사실 층이 «실제 반경»을 이미 들고 있게 한다
- **②-2** `isActive` 를 끄는 네 판단을 **이름 있는 함수 하나**로 모은다 — `dispatchBlockedBecause(session)` 이
  막는 까닭을 돌려주고, 조립은 그것이 있으면 끈다. 지금은 네 곳에 흩어져 있어 다섯째가 붙어도 아무도 모른다
- **②-3** 복귀행 목적지 갈아 끼우기를 뺀다. ①-1 에서 그 칸이 없어진다

## ③ 지역 목록

### 지금 — 만드는 함수

| 목록 | 만드는 함수 | 자리 |
|---|---|---|
| 상차 목록 · 묶음 | `pickupListFor` | `server/src/services/geoService.ts` |
| 하차 목록 · 묶음 | `netOfGoals` → 목적지마다 `netKeywordsOf` → `mergeDropoffGroups` | `filterManager.ts` · `shared/src/filterArea.ts` |
| 시 별칭 | `cityAliases` | `geoService.ts` |
| 덫 | `trapsForKeywords` ← `refreshKeywordTraps` | `geoService.ts` · `filterManager.ts` |
| 진행도 | `progressAlongKm` · turf `nearestPointOnLine` | `callNet.ts` · `geoService.ts` |
| 지나온 동 빼기 | `applyTraveledTrim` | `filterManager.ts` |
| 제외 지역 빼기 | `pruneExcludedRegions` | `callNet.ts` |

### 🔴 이 층에서 지켜야 할 약속 (주석에서 옮김 — 깨면 사고가 난 자리들)
- **그물을 못 그려도 목록을 비우지 않는다** — 도시 둘레로 물러선다. 빈 목록은 고장이다
- **상차 목록이 먼저** 만들어져 있어야 한다
- **진행도를 키워드보다 먼저** 기억한다 — 끝의 트림이 그 진행도로 뺀다
- **트림은 파생 계산의 맨 끝**에 둔다. 어느 길로 다시 그려도 지나온 동이 되살아나지 않게
- **트림을 `updateActiveFilter({})` 로 트리거하지 않는다** — 0.5km 마다 경유가 통째로 지워진다
- **별칭은 목록에 든 시 전부**에서 만든다. 목적지 시 하나만 실으면 스캔앱 2단계가 다른 시를 막는다
- **덫은 상차 ∪ 하차 한 벌** — 두 벌이면 한쪽 목록을 빠뜨린다
- **`me`(현위치 원)로 든 동에 진행도를 붙이지 않는다** — 진행도 0 이 붙어 몇 m 움직이자마자 «지나온 곳»이 된다
- **마름모 · 목적지 원으로 든 동에도 진행도를 붙이지 않는다** — 아직 안 간 곳이다

### 지금 어긋난 것

| # | 무엇 | 사실 |
|---|---|---|
| 3-a | 하차 목록에서 상차 목록 동 빼기 | **코드는 안 뺀다** (`mergeDropoffGroups` 가 인자를 `void` 로 버린다). 그런데 여섯 자리 주석이 아직 «뺀다»고 적고 있다 |
| 3-b | 진행도 셈법이 둘 | 평면 근사 `progressAlongKm` 과 turf `nearestPointOnLine`. 서버가 둘 다 쓴다 |
| 3-c | 지나온 동 빼기 구현이 둘 | `applyTraveledTrim`(서버 실물)과 `mergeGoalNets`(목업·비교 도구). 같은 일이다 |

### 바꾼다
- **③-1** 낡은 주석 여섯 자리를 코드에 맞춘다. **한 곳에만 적는다** — `mergeDropoffGroups` 머리
- **③-2** `mergeDropoffGroups` 의 안 쓰는 인자를 **지운다.** 지금은 검사가 호출 모양을 보느라 남아 있다.
  검사를 「인자를 쓰나」가 아니라 「목록이 무엇을 담나」로 바꾸면 인자를 지울 수 있다
- **③-3** 진행도 셈법 둘 중 하나를 고른다. 「지금 몇 km 지점인가」와 「이 동이 경로 몇 km 에 있나」는
  다른 질문이니 **칸을 둘로 가르든가 셈법을 하나로 하든가** 한 쪽으로 정한다 (규칙 ⑤-4 ⑤)

## ④ 영역에서 동 뽑기

### 지금 — 뽑는 방법이 여럿

| 방법 | 함수 | 어떤 도형에서 |
|---|---|---|
| 중심점 그물 | `collectDongs` | 동 **중심점**이 판정 안인가 |
| 영역에 걸친 동 | `regionsTouchingAreaGrouped` | 격자 점이 동 안 **또는** 동 꼭짓점이 영역 안 |
| 원에 걸친 동 | `regionsTouchingCircleGrouped` | 위 + 원 재료 |
| 하차 조각에 걸친 동 | `regionsTouchingNetGrouped` | 위 + 그물 판정기 |
| turf 버퍼 경유 | `getDetourRegions` | 경로 버퍼 ∪ 하차 원 |
| 도시 둘레 | `getCityRegionsWithRadius` | 물러섬 경로 |

### 🔴 성능이 설계를 정한 자리 (주석의 실측)
- `turf.buffer` 는 꼭짓점 수에 비례해 비싸고 **반경이 작을수록 더 비싸다.**
  원본으로 버퍼링하면 한 도시가 1초를 넘고, 간소화 사본(200m)이면 100배 빠르다
- 이동할 때마다 경유를 다시 그리던 함수를 걷고 **숫자 비교**로 바꿨다. 세 자릿수 밀리초에서 소수점으로 내려왔다
- 그래서 **영역을 폴리곤으로 합치지 않는다.** 합치면 느리다

### 🔴 그래서 ⑤ 영역은 «도형 하나»가 아니다
영역을 turf 로 합쳐 폴리곤 하나로 만들면 느려서 못 쓴다. 대신 이렇게 표현한다.

```
영역 = { 조각 목록, 합치는 법 }
```

- **서버**는 조각 목록에서 «이 점이 안에 드나» 판정기를 만들어 동을 뽑는다
- **관제웹**은 같은 조각 목록을 받아 캔버스에 칠한다. 겹치기(∩)는 clip, 더하기(∪)는 한 틀에 모아 칠하기

둘이 **같은 조각 목록**을 본다. 이것이 갈라지지 않는 유일한 방법이다.

### 바꾼다
- **④-1** 동을 뽑는 입구를 **하나**로 한다 — `regionsInArea(area)`. 안에서 조각 종류에 따라
  지금 쓰는 방법을 고른다. 부르는 쪽은 방법을 모른다
- **④-2** 목업·비교 도구만 쓰는 `mergeGoalNets` 와 제품 호출부가 없는 `quadTesterOf` 를 정리한다.
  지우기 전에 기사님께 여쭙는다

## ⑤ 영역 — 조각과 합치는 법

### 새 모양

```ts
type AreaPiece =
    | { kind: 'circle'; at: Point; km: number }
    | { kind: 'band';   line: Point[]; km: number; cutAt: Point | null }   // cutAt 부터 앞으로만
    | { kind: 'quad';   from: Point; to: Point; params: QuadParams };

type Area = {
    pieces: AreaPiece[];
    join: 'all' | 'any';        // 상차는 all(∩) · 하차는 any(∪)
    minus: AreaPiece[];         // 하차가 현위치 원을 뺀다
};
```

🔴 **`join` 을 조각 안에 두지 않는다.** 조각은 «어디»만 말하고, 합치는 법은 영역이 정한다.
조각에 두면 조각마다 다른 합치는 법을 고를 수 있게 되어 또 표가 생긴다.

### 상차는 겹치고(∩) 하차는 더한다(∪) — 뜻이 반대다

| | 뜻 | 합치는 법 |
|---|---|---|
| 상차 | **갈 수 있고**, 가는 길이고, 목적지 권역이어야 | `all` (∩) |
| 하차 | 가는 길**이거나**, 그 방향이거나, 목적지 권역이면 | `any` (∪) |

이 차이가 이 층에 있어야 한다. 아래층(조각)이나 위층(목록)에 흩어지면 또 갈라진다.

### 🔴 하차는 현위치 원을 **뺀다**
현위치 원은 사방으로 퍼져 뒤쪽까지 하차 후보가 된다. 그래서 `minus` 에 넣는다.
다만 **«상차 영역을 뺀다»가 아니라 «현위치 원을 뺀다»** 이다. 지금 관제웹은 상차 **모양**을 지워서
서버와 다르게 지운다 (지금 어긋난 것 5-c).

### 지금 어긋난 것 — 서버와 관제웹이 같은 것을 각자 만든다

| # | 같은 질문 | 다른 점 |
|---|---|---|
| 5-a | 상차 영역 도형 | **라인 원천이 다르다.** 서버는 KEEP 때 얼린 경로, 관제웹은 지금 그리는 경로. **원 중심도 다르다** — 서버는 5분 지나거나 빈차 모의면 집 주소로 대신하는데 관제웹은 실시간 위치 |
| 5-b | 가까이 온 목적지의 원 고르기 | 서버는 좌표를 아는 **첫 시**를 찾아 돌고, 관제웹은 **첫 목적지 하나만** 보고 실패하면 원을 안 씌운다. 첫 목적지가 지도에 없으면 서버는 좁히고 화면은 안 좁힌다 |
| 5-c | 하차에서 빼는 것 | 서버는 **현위치 원 통째**를 뺀다. 관제웹은 **상차 모양**을 지운다. 상차가 원∩라인이면 관제웹이 **덜 지운다** |
| 5-d | 하차 라인 자르는 순서 | 서버는 «현위치부터 → 마지막 하차지까지», 관제웹은 «마지막 하차지까지 → 현위치부터». 같은 자리를 두 번 지나는 경로와, 마지막 하차지가 이미 뒤에 있는 경우에 **다른 구간**이 나온다 |
| 5-e | 라인 띠 기본 반경 | 하차는 하나, 상차와 지도는 다른 하나. **같은 서버 안에서 상차 띠와 하차 띠가 다른 폭**이 될 수 있다 |
| 5-f | 목적지 원 반경 | 하차 목록은 설정값 그대로, 「가까이 옴」 판정과 지도는 자동 반경을 먹인 값. 설정이 비면 하차 원은 0 이고 지도 원은 기본값이다 |

🔴 **여섯 중 다섯이 «서버와 관제웹»이다.** ⑤ 영역을 값으로 내려보내면 다섯이 한 번에 없어진다.

### 바꾼다
- **⑤-1** 서버가 `Area` 를 만들어 **관제웹에 실어 보낸다.** 관제웹은 조각을 받아 칠하기만 한다
- **⑤-2** 관제웹의 영역 조립 코드를 지운다. 남기면 다시 갈라진다
- **⑤-3** 라인 자르는 순서를 **한 함수**로 못박는다 — `bandLineFor(line, from, until)`
- **⑤-4** 기본 반경을 한 곳으로 모은다. 지금 두 벌인 것은 **어느 쪽이 참인지 코드로 단정할 수 없다** — 기사님께 여쭌다
- **⑤-5** 하차가 빼는 것은 **현위치 원**이라고 이름으로 못박는다. 「상차 영역을 뺀다」는 말을 문서와 주석에서 없앤다

## ⑥ 조각 — 각자 자기 사실만 본다

### 🔴 여기가 이 설계의 핵심이다

지금은 조각이 목적지 **상태**를 보고, 상태는 「콜 수」와 「출발했나」를 한 칸에 담고 있다.

```ts
const stateOf = (calls) => calls === 0 ? 'idle' : departed ? 'driving' : 'routed';
```

`calls` 는 목적지마다 다르고 `departed` 는 **전체가 하나**다. 둘을 한 칸에 담았으니
「내가 달리나」를 물으려면 목적지 목록을 뒤져야 하고, 목적지가 하나 늘면 답이 뒤집힌다.

**떼어 놓는다.** 조각마다 자기에게 필요한 사실만 받는다.

| 조각 | 보는 사실 | 주인 |
|---|---|---|
| 현위치 원 | 내 위치를 아는가 · 현위 반경 | 나 |
| 라인 띠 | 확정된 경로가 있는가 · 출발했는가 · 라인 반경 | 나 |
| 목적지 원 | 그 목적지에 가까이 왔는가 · 목적 반경 | 목적지마다 |
| 마름모 | 두 기준점을 아는가 · 각도 둘 · 마름모 반경 | 목적지마다 (하차만) |

주인이 「나」인 조각은 **목적지 목록을 아예 안 본다.** 그래서 목적지가 몇 개든 답이 안 바뀐다.

### 상차와 하차가 각각 무엇을 켜나

**상차** — 주어가 나다. 「내가 20분 안에 가서 실을 수 있고, 내가 지금 달리는 길에 있는 곳」

```
현위치 원                                    늘
∩ 라인 띠        출발했고 경로가 있으면
∩ (가까이 온 목적지 원들의 합집합)   하나라도 가까이 왔으면
```

🔴 가까이 온 목적지가 둘이면 두 원을 **더한다**(∪). 겹치면(∩) 두 원이 안 만날 때 영역이 비고,
빈 영역은 고장이다 (규칙 ④).

🔴 마름모는 상차에 안 쓴다. 기사님: *"아무리 빨리 가도 마름모 영역까지 상차를 20분 안에 할 수 없잖아."*

**하차** — 주어가 목적지다. 목적지마다 만들어 더한다.

```
목적지마다:  라인 띠(그 목적지 마지막 하차지까지)  ∪  마름모  ∪  목적지 원
전부 더한 뒤  −  현위치 원
```

### 🔴 「목적지에 가까이 옴」은 더하기만 한다
상차에 목적지 원을 **더하고**, 하차에서는 상차 목록 동을 **안 뺀다**(지금은 어차피 안 뺀다 — 3-a).
**라인도 마름모도 끄지 않는다.** 목적지에 닿아 콜을 다 내리면 그 목적지에 콜이 0건이 되어
라인이 저절로 없어진다. 조건이 재료를 끄면 거리를 넓히는 일과 방향을 버리는 일을 한 손이 하게 된다.

### 「가까이 옴」을 재는 식
**현위치가 그 목적지 영역 안인가.** 목적지 반경 하나로만 잰다. 현위치 반경을 더하지 않는다.
기사님이 목적지 반경을 정하신 것이 곧 「이만큼이 내 목적지 근처다」라는 말씀이다.

지금 식은 마름모가 두 원의 합집합 안에 통째로 드는가인데, 두 반경을 합쳐 보기 때문에
설정에 따라 목적지에서 한참 떨어진 곳에서도 참이 된다.

### `state` 는 어떻게 되나
**표시용으로만 남긴다.** 로그와 화면이 읽는다. 뭉친 이름은 읽기에 좋고 계산에 나쁘다.
계산하는 함수는 `state` 를 **인자로 받지 않는다.** 받을 수 없으면 볼 수도 없다.

### 지금 `state` 를 계산에 쓰는 자리 — 전부 바꾼다

| 자리 | 지금 묻는 것 | 바꿔 물을 것 |
|---|---|---|
| 상차 라인 | 모든 목적지가 「운행 뒤」인가 | 출발했고 경로가 있는가 |
| 하차 마름모 시작점 | 「콜 없음」인가 | 그 목적지의 마지막 하차지를 아는가 |
| 하차 라인 자르기 | 「운행 뒤」인가 | 출발했는가 |
| 하차 조각 고르기 | 상태가 무엇인가 | 그 목적지까지 자른 라인이 있는가 |

🔴 하차는 이미 「콜을 잡았다」와 「출발했다」의 답이 **같다.** 그러니 하차는 출발 여부를 안 본다.
`state` 의 세 값 중 뒤의 둘을 가르는 것은 **상차 하나뿐**이었다.

### 바꾼다
- **⑥-1** `pickupPartsOf(zones)` → 사실을 받는다. 목적지 목록이 아니라 `{ departed, hasLine, nearGoalCities }`
- **⑥-2** `dropoffPartsOf` 는 인자가 「그 목적지까지 자른 라인이 있는가」 하나로 줄어든다.
  지금 네 갈래가 그 하나로 그대로 나온다
- **⑥-3** `GoalZone` 에서 `state` 를 뺀다. 남는 것은 `city` · `isHome` · `hasCalls` · `nearGoal`.
  표시가 필요한 곳에서 `goalStateLabel(hasCalls, departed)` 로 만든다
- **⑥-4** 「가까이 옴」을 재는 식을 목적지 반경 하나로 바꾼다
- **⑥-5** 조각을 쪼개 놓고 **문자열 하나로 다시 뭉치지 않는다.** 지금 `pickupListFor` 가
  조각 셋을 `'meLineGoal'` 같은 이름으로 합쳐 내보내고, 읽는 쪽이 그걸 풀어야 한다.
  조합이 하나 늘자 로그가 「없음」이라 적기 시작했다

- **⑧-4** F2 를 잠그는 검사를 만든다 — 「화면이 두 그릇을 같이 바꾸지 않는다」

## 9. 옮기는 순서

🔴 **한 걸음마다 게이트가 초록이고 기사님이 보신 뒤에 다음으로 간다.**

| 걸음 | 무엇 | 끝의 기준 |
|---|---|---|
| ✅ 1 | ⑥ 조각이 사실을 직접 본다 (⑥-1~⑥-5) | 복귀를 켜도 상차 라인이 안 꺼진다. **검사는 초록 · 실주행 확인 남음** |
| 2 | ⑤ `Area` 를 값으로 만든다 | 서버 한 곳이 조각을 만들고, 목록과 그림이 그것을 쓴다 |
| 3 | ⑤-1 관제웹에 실어 보낸다 | 관제웹의 영역 조립 코드가 **없다**. 5-a~5-f 여섯이 사라진다 |
| 4 | ⑦-1 사건을 낸다 | 경로가 바뀌면 경유가 바뀐다. F5 가 ✅ 가 된다 |
| 5 | ①②③ 정리 (죽은 칸 · 낡은 주석 · 중복 구현) | 세는 명령이 줄어든 것을 보인다 |

🔴 **1과 2 사이에서 멈출 수 있게 짠다.** 1만 해도 지금 버그는 없어진다.

## 10. 검사로 잠글 것

표의 칸을 하나씩 무는 검사를 **만들지 않는다.** 표가 생기는 것 자체를 막는다.

| 검사 | 무엇을 막나 |
|---|---|
| `filterPartsFacts` | 조각 계산 함수가 `state` 를 **인자로 받지 않는다** · 목적지 목록에 `every`·`some` 을 쓰지 않는다 |
| `filterAreaOneWay` | 관제웹이 영역 조각을 **만들지 않는다** — 서버가 보낸 것만 그린다 |
| `filterAreaJoin` | 상차는 `all`, 하차는 `any` · 조각에 합치는 법이 없다 |
| `filterTriggers` | 방아쇠 표에 없는 자리에서 다시 재지 않는다 |
| `filterTwoBowls` | F2 — 화면이 두 그릇을 같이 바꾸지 않는다 |
| 기존 `appFilterKeys` | 그대로 둔다 — ① 층을 이미 잘 잠그고 있다 |

그리고 이미 있는 짝 검사를 쓴다. 소켓 계약 감사가 「한 사건을 여러 곳이 듣는가」를 세고 기준선보다 늘면 빨간불이다.
`FILTER_CORRIDOR_CHANGED` 도 그 목록에 올린다.

## 11. 기사님께 여쭐 것 — 셋

코드로 단정할 수 없어 남겨 둔다. 나머지는 물어보지 않고 진행한다.

| | 무엇 | 왜 못 정하나 |
|---|---|---|
| ㉠ | 라인 반경 기본값 | 두 벌인데 DB 기본값이 없어 어느 쪽이 참인지 코드에 근거가 없다 |
| ㉡ | 죽은 칸을 지울까 | 지우는 것은 여쭙고 한다 (`destinationRadiusKm`·`destinationCity`·`driver_action`·`filters.ts`·`quadTesterOf`) |
| ㉢ | 가까이 온 목적지가 둘일 때 | 두 원을 더하기로 했는데(∪), 상차가 그만큼 넓어진다. 맞는지 |

## 12. 1걸음에서 실제로 한 것 (✅)

- `GoalZone` 에서 `state` 를 뺐다 — 남은 것은 `city` · `isHome` · `hasCalls` · `nearGoal`.
  `GoalState` 타입이 없어졌고, 화면·로그는 `goalStateLabel(hasCalls, departed)` 로 그때 만든다
- `goalZonesOf` 가 «출발했나»를 **안 받는다** — 목적지가 사는 조건과 무관하다
- 상차는 `pickupPartsOf({ departed, hasLine, nearGoalCities })` — 목적지 목록을 안 본다.
  `every`·`some` 이 사라졌다
- 하차는 `dropoffPartsOf(hasLine)` — 인자가 셋에서 하나로. 네 갈래가 그 하나로 그대로 나온다
- 「가까이 옴」은 `isNearGoal({ me, goal, destinationRadiusKm })` — 목적지 반경 하나로 잰다
- 가까이 온 목적지가 **여럿이면 그 원들을 더한다**(∪). 서버도 지도도 그렇게 겹친다
- 지도가 목적지 원이 있을 때 **라인을 무시하던 것**을 고쳤다 — 이제 셋을 다 겹친다
- 목적지가 0건이면 빈 목록을 내는 길을 `rebuildPickupList` 로 옮겼다 (규칙 ④)
- 상차 로그가 조합 이름 대신 **켜진 조각을 그대로** 적는다

**끝의 기준** — 조각 계산 함수 어디에도 목적지 상태가 인자로 없고, 관제웹에 영역을 만드는 코드가 없고,
경로가 바뀌면 경유가 바뀌는 것을 실주행에서 본다. 지금은 첫째만 참이다.
