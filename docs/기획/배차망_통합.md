# 배차망 통합 — **새 배차망을 붙이는 법**

> 2026-09-02 신설 · 같은 날 전면 개정. 기사님 지시:
> *"다음에 또 어떤 앱을 추가하더라도 이것만 읽으면 추가할 수 있을 거니까."*
>
> **이 문서 하나가 원천이다.** 층 가르기·계약·폴더를 여기서만 정한다.
> ⚠️ §7 이 차야 코드를 시작한다 (규칙 ⑤-4).

---

## 1. 🔴 진리 — 배송은 하나다

기사님(2026-09-02):
> *"배송하는 건 모두 똑같아. 콜 받아서 지금 위치에서 상차지 가서 물건 받아서
> 하차지로 이동해서 받는 사람에게 전달한다. 이건 진리야."*

```
콜 받음 → 상차지 도착 → 물건 받음 → 하차지 도착 → 전달
```

이 넷이 **마일스톤**이고, `shared` 에 이미 있다:

```ts
MILESTONES = ['ARRIVED_PICKUP', 'PICKED_UP', 'ARRIVED_DROPOFF', 'DELIVERED']
```

🔴 **마일스톤은 절대 늘어나지 않는다.** 기사님 지적이 이 문서의 뼈대다:
> *"모든 페이지를 마일스톤에 넣으면 앱이 추가될 때마다 마일스톤이 생겨날 것 같아."*

배차망이 「픽업지로 이동하세요」 같은 화면을 갖고 온다고 마일스톤을 늘리면, 다음
배차망이 자기 화면을 갖고 올 때 또 늘어난다. **화면은 페이지지 마일스톤이 아니다.**

## 2. 층 셋 — 페이지 · 치환 · 진리

```
[배차망별]  페이지        이름도 개수도 그 앱 마음대로. 밖에서 알 필요 없다
               ↓ 치환 (배차망별)
[계약]      마일스톤 넷   나가는 문은 이것 하나
               ↓ 같은 문
[공통]      reportMilestone → 장부 · 판정 · 관제
```

**서로 다른 것은 «답하는 방법»이지 «질문»이 아니다.** 세 배차망 모두 같은 질문을 받는다 —
*"이 화면은 진리의 어디인가?"* 답하는 재료만 다르다:

| 배차망 | 진행을 무엇으로 아나 |
|---|---|
| 인성 · 24시 | **GPS** — 정거장 500m 안에 들면 마일스톤 (`socketHandlers` 가 이미 한다) |
| 픽커 | **화면** — 「픽업 완료해주세요」가 곧 «상차지 도착» |

그래서 인성의 `milestoneOf()` 는 **언제나 `null`** 이다 — *"화면으로는 모른다"*.
지금 동작과 완전히 같다. **인성은 한 줄도 안 흔들린다.**

## 3. 계약 — `IScrapParser` 에 한 줄

배차망마다 다르게 답하는 것은 이미 `core/IScrapParser.kt` 에 모여 있다. 치환도 같은 성질이다.

```kotlin
interface IScrapParser {
    fun parse(texts): SimplifiedOfficeOrder      // 이 화면의 콜은 무엇인가
    fun shouldClick(order, tally): Boolean       // 잡을 만한가
    fun parsePickupDistance(rawText): Double?
    fun groupListNodes(allNodes): …
    fun alarmBandHalfPx(): Int

    fun milestoneOf(screenText: String): String? // 🆕 이 화면은 진리의 어디인가
}
```

공통 코드가 아는 것은 **한 줄뿐**이다:

```kotlin
scrapParser.milestoneOf(rawScreenStr)?.let { reportMilestone(orderId, it, 'AUTO_SCRAPE') }
```

공통 코드는 **페이지가 몇 개인지, 이름이 뭔지 영영 모른다.** 그것이 마일스톤이
안 늘어나는 이유다.

🟢 **서버는 손댈 것이 하나도 없다 — 자리까지 이미 있다.**
`reportMilestone(userId, orderId, milestone, source, io)` 가 공통 문이고,
「출처」에 **`AUTO_SCRAPE`(앱의 화면 자동 감지)** 가 **이미 준비돼 있다.**

```ts
MILESTONE_SOURCES = ['AUTO_SCRAPE', 'APP_BUTTON', 'MANUAL_WEB', 'GPS', 'SKIPPED']
//                    ↑ 아직 아무도 안 쓴다 — 픽커가 첫 사용자다
```

`socketHandlers.ts:507` 에 *"앱의 화면 자동 감지(AUTO_SCRAPE)가 붙어도 이 핸들러는…"*
라고 적혀 있다 — **이 일을 미리 내다보고 만들어 둔 자리다.** 새로 만들지 않는다.

⚠️ 출처는 «믿는 정도»를 답한다 (`index.ts:166~171`): 직접 누른 것은 실측,
`GPS` 는 참고값. `AUTO_SCRAPE` 가 **어느 쪽인지는 아직 안 정했다** — §7 ④의 숙제다.

### 3-1. 🟢 중복과 역행은 **서버가 이미 막는다** — 앱은 신경 쓰지 않아도 된다

화면은 1초마다 스캔된다. 「픽업 완료해주세요」가 30초 떠 있으면 앱은 같은 마일스톤을
**30번 보낸다.** 처음엔 이걸 앱이 막아야 하는 줄 알았는데, 서버가 이미 둘 다 막는다:

```ts
// dispatchEngine.reportMilestone
if (!canReportMilestone(order.status, milestone))   // ② 역행 방지
    return { duplicated: true, reason: already ? "ALREADY_REPORTED" : "OUT_OF_ORDER" };
if (milestoneAlreadyRecorded(orderId, milestone))   // ③ 중복 방지 — 장부를 본다
    return { duplicated: true };
```

- **중복** — `milestoneAlreadyRecorded` 가 **장부(step 표)** 를 조회한다. 메모리가 아니라
  장부라 앱을 껐다 켜도 안 뚫린다
- **역행** — `canReportMilestone` 이 콜 상태로 막는다. 하차한 콜에 상차 보고가 늦게
  도착하는 일이 **실제로 생겨서** 만든 방어다 (주석에 그렇게 적혀 있다)

🔴 **그러니 앱에서 «바뀔 때만 보내기» 같은 것을 새로 만들지 않는다** — 두 벌이 된다 (규칙 ③).
앱은 매 스캔 보내도 되고, 로그가 시끄러우면 **로그만** 줄인다.

### 3-2. 🔴 아직 안 정한 것 — **어느 콜의 픽업인가**

화면이 「픽업 완료해주세요」라고 말해도 **어느 콜인지는 화면에 없을 수 있다.**
지금은 `session.currentOrderId` 로 아는데, 이건 **앱 메모리**라:

- 앱을 껐다 켜면 사라진다
- 콜을 둘 이상 들고 있으면 어느 것인지 흐려진다
- 기사님이 픽커 앱을 직접 열어 진행하면 우리 세션과 어긋난다

**후보 셋** (저녁 캡처로 정한다):

| | 방법 | 조건 |
|---|---|---|
| ⓐ | 화면의 **오더번호**로 대조 | 수락 후 화면에 `F2609011638JDU17` 이 보였다 — 그게 매 화면에 있는지 확인 필요 |
| ⓑ | 주소로 대조 | 수락 후 화면에 상·하차 주소가 다 있다. 다만 콜이 둘이면 흔들린다 |
| ⓒ | 세션만 믿는다 | 지금 방식. 껐다 켜면 끊긴다 |

🔴 **정해지기 전에는 마일스톤을 보고하지 않는다.** 엉뚱한 콜에 «하차 완료»가 찍히면
장부가 더럽혀지고, 서버의 중복·역행 방어는 **콜이 맞다는 전제** 위에서만 돈다.

`core/engine/ScreenDetector.kt`(66줄)와 `core/ScreenKeywords.kt`(43줄)는

grep 하면 안 걸린다 — 조사할 때 **낱말도 함께** 훑어야 한다.

## 6. 폴더 — `plugins/` 가 맞나

지금 `plugins/` 밑에 **배차망이 아닌 것이 둘** 있다:

```
plugins/
├── insung/ · hwamul24/ · kakaopicker/   ← 배차망별 ✅
├── RegionMatch.kt                        ← 🔴 배차망 무관
└── RouteOrderFilter.kt                   ← 🔴 배차망 무관
```

**이름이 이미 거짓말을 하고 있다.** 지향점:

```
core/          배차망을 몰라도 되는 것 (+ 위 둘을 여기로)
network/       🆕 «배차망» — 정직한 이름
  TargetApp · ScrapParser · IScrapParser        경계
  insung/      Keywords · Parser · Sequence     ← 636줄이 여기로
  hwamul24/    Keywords · Parser
  kakaopicker/ Keywords · Parser · Pages        ← 페이지·치환표가 여기서만 산다
```

⚠️ **폴더 이름 바꾸기는 마지막에 한다.** import 가 33개 파일에서 흔들린다 —
내용을 먼저 옮기고 이름은 그다음 판에.

🔴 **«옮긴다»보다 «빼낸다»가 정확하다.** 파일 통째로 옮길 것은 `DetailCollectMachine.kt`
하나뿐(166줄)이고, 나머지는 전부 `HijackService`(1,554줄) **안에서 빼내는** 일이다.

```
배차망별로 나가는 것   693줄  = 인성 636 + 픽커 57
  그중 별도 파일        166줄  (DetailCollectMachine — 통째로 옮김)
  HijackService 에서    527줄
남는 HijackService     1,027줄  ← 진짜 공통 뼈대
```

| | 상태 | 내용 |
|---|---|---|
| ① 스키마 | 🔶 | 계약은 정했다(`milestoneOf`). **페이지 enum 을 어디 둘지**는 폴더 결정과 함께 |
| ② 값 | ⬜ | **픽커 페이지 낱말이 미확정** — 2023 자료 추정. 실물 캡처 대기 |
| ③ 시점 | 🟢 | **서버가 이미 막는다** (§3-1). 앱은 매 스캔 보내도 된다 — 첫 번만 기록된다 |
| ④ 화면 | ⬜ | 관제웹이 «화면이 알려준 마일스톤»을 GPS 것과 구분해 보여줄지 |
| ⑤ 읽는 곳 | 🔶 | 마일스톤 소비자는 이미 안다(장부·판정·관제). **출처(`AUTO_SCRAPE`)를 «실측»으로 볼지 «참고값»으로 볼지**가 미정 |

🔴 **②(픽커 낱말)와 ⑥(어느 콜인가)이 비어 있어 아직 코드를 시작하지 않는다.**

## 8. 새 배차망을 붙이는 법 — 체크리스트

> 이 순서대로 하면 공통 코드를 한 줄도 안 고치고 배차망이 붙는다.

1. **화면을 뜬다** — 실물 덤프(`uiautomator dump`)를 화면마다. **지어내지 않는다.**
   최소: 홈 · 리스트 · 상세 · 수락 후 각 단계
2. **낱말을 «골라낸다»** — 덤프 전수를 훑어 *「이 화면에만 있고 다른 화면엔 없는」* 낱말.
   🔴 **낱말은 둘 이상 요구한다** (인성 방식). 하나면 잔상 한 줄에 걸린다
   (2026-09-02 실사고: 픽커 상세 낱말이 「픽업」 하나여서 리스트를 상세로 오인)
3. **«배차망»Keywords 파일** — 화면 판별 사전. 없는 화면은 `NEVER` 로 끈다
4. **«배차망»Parser 파일** — `IScrapParser` 를 구현. 리스트에서 콜을 읽는다
5. **«배차망»Pages 파일** — 페이지 enum + 낱말 표 + **치환표**(페이지→마일스톤).
   잡지 않는 배차망이면 여기까지가 전부다
6. **`TargetApp.kt` 에 한 줄씩** — 코드·라벨·패키지·`supportsCatching`
7. **`ScrapParser.kt` 에 한 줄** — 파서 고르기
8. **`server/config/` 의 `keywords_…json`** — 서버가 낱말을 배포한다 (앱 재설치 없이 고침)
9. **검사** — 덤프를 문제지로. *"리스트를 상세로 오인하지 않는다"* 를 반드시 넣는다

### 잡기(계약)까지 하려면 더

10. **`supportsCatching = true` 로 바꾸기 전에** — 그 배차망의 **되돌리기 성질**을 먼저 적는다
    (인성: 앱에서 30초·10회 / 픽커: **버튼 취소 없음·전화만·하루 5번**).
    되돌릴 창이 없으면 **판정이 계약보다 앞**이어야 한다 — 수순의 방향이 반대가 된다
11. 잡는 수순(`Sequence`)을 그 폴더에 — 인성 것을 **복사하지 않는다**

## 9. 🔴 하지 말 것

1. **마일스톤을 늘리지 않는다** — 페이지가 아무리 늘어도 진리는 넷이다
2. **페이지를 공통 자리에 두지 않는다** — `ScreenContext` 에 배차망 화면을 더하면
   그 목록이 앱마다 부푼다
3. **인성 수순을 복사해 고치지 않는다** — 되돌리기 성질이 다르면 방향이 반대다
4. **공통 코드에 화면 글자를 박지 않는다** (`"적요상세"` 같은 것) — §5 의 덤이 그 사고다
5. **«없음»을 «있음»의 근거로 쓰지 않는다** — 2026-09-02 실사고:
   「수락하기가 안 보인다」를 「수락했다」로 읽어 안 누른 콜이 잡은 콜이 됐다.
   **화면 표식은 적극적으로 확인한다**

## 10. 인성이 흔들리지 않게 (기사님 못박음)

> *"이 일을 하고도 인성은 아주 잘 작동해야 해. 지금도 잘 작동하고 있으니까."*

### 🔴 먼저 — 「옮기기만 한다」는 **거짓이다** (2026-09-02 검토에서 잡음)

처음엔 *"636줄을 옮기기만 하고 한 줄도 안 고친다"* 고 적었다. **실측해 보니 틀렸다.**

`handlePreConfirmScreen`(214줄) 하나가 `HijackService` 내부 것 **열 개**에 기댄다:
`session` · `telemetryManager` · `scrapParser` · `touchManager` · `keywords` ·
`recentListOrders` · `collectMachine` · `mainHandler` · `cautionVerifier` · `currentTargetApp`

빼내려면 **함수 서명이 바뀌고 넘겨줄 것을 묶는 구조가 필요하다.** 그건 «이동»이 아니라
**리팩터**다 — 인성이 흔들릴 수 있는 진짜 자리다.

⚠️ 이 문서가 «안전하다»고 말했으면, 읽는 사람이 **없는 방어를 믿고** 바로 옮겼을 것이다.
이 레포가 네 번 당한 그 사고다 (CLAUDE.md 「문서 신뢰도」).

**그래서 순서를 이렇게 잡는다:**

1. **먼저 «넘겨줄 것»을 하나로 묶는다** — 열 개를 낱개로 넘기지 않는다.
   그 묶음(가칭 «스캔 맥락»)을 만드는 것이 **첫 공사**이고, 이때는 함수를 안 옮긴다
2. 묶음이 서고 검사가 통과하면 **그다음에** 함수를 옮긴다
3. 두 단계를 **다른 커밋**으로 — 문제가 나면 어느 쪽인지 바로 안다

| 지킴 | 어떻게 |
|---|---|
| **행동 불변** | 함수 본문은 **한 줄도 안 고친다** — 바뀌는 것은 «무엇을 넘겨받는가»뿐이다 |
| **증거** | `pnpm scenario`(53) · `pnpm drive`(15) · 앱 단위검사가 **옮기기 전후로 똑같이** 통과 |
| **되돌리기** | 커밋을 «옮기기»와 «고치기»로 나눈다 — 문제가 나면 옮기기만 되돌린다 |
| **실물** | 옮긴 뒤 **인성 시뮬로 한 바퀴** (`pnpm e2e:app`) |
| **인성의 치환** | `milestoneOf() = null` 한 줄 — 지금 동작과 완전히 같다 |

## 11. ✅ 어떻게 검증하나 — **«인성이 그대로인가»를 기계가 답하게 한다**

기사님 못박음: *"이 일을 하고도 인성은 아주 잘 작동해야 해."*
사람 눈으로 «잘 도는 것 같다»는 증거가 못 된다. **숫자로 남긴다.**

### ① 기준선을 먼저 뜬다 (공사 전)

공사를 시작하기 **전에** 아래를 돌려 숫자를 적어 둔다. 뒤에 이 숫자와 **똑같아야** 한다.

```bash
cd onedal-web && pnpm scenario        # 콜 생애 53건
cd onedal-web && pnpm drive           # 모의 주행 15건
cd onedal-web/server && npx jest      # 129 스위트 / 1,279건
cd onedal-app && ./gradlew :app:testDebugUnitTest    # 93건
```

🔴 **`Test Suites:` 줄까지 본다** — 컴파일이 안 되는 검사는 «실패»가 아니라 «없는 것»이
되어 조용히 사라진다 (onedal-web/CLAUDE.md). 건수가 줄면 통과해도 후퇴다.

### ② 행동이 안 바뀌었음을 **로그로** 대조한다

검사는 «깨지지 않았다»만 말한다. «**같게** 돈다»는 로그가 답한다.

```bash
# 공사 전/후 각각 인성 시뮬로 한 바퀴 돌리고, 그 구간 로그를 떠서 대조
cd onedal-web && pnpm e2e:app                      # 앱 구간 7단계
diff <(공사전 로그 | grep ROADMAP) <(공사후 로그 | grep ROADMAP)
```

`ROADMAP` 줄은 **콜이 지나간 길**이다. 그 순서가 한 줄이라도 달라지면 행동이 바뀐 것이다.

### ③ 픽커 쪽은 «장부가 더럽혀지지 않았나»를 본다

```bash
cd onedal-web && pnpm ledger          # 콜별 6단계와 출처(직접·자동·건너뜀)를 눈으로
```

🔴 **보아야 할 것 셋:**
- 마일스톤이 **한 콜에 한 번씩만** 찍혔나 (중복 방어가 실제로 도는가 · §3-1)
- 순서가 **앞으로만** 갔나 (`ARRIVED_PICKUP → PICKED_UP → ARRIVED_DROPOFF → DELIVERED`)
- 출처가 `AUTO_SCRAPE` 로 남았나 — GPS 것과 구분되는가

### ④ 새 검사로 잠근다 — 다음 사람이 되풀이하지 않게

| 무엇을 잠그나 | 왜 |
|---|---|
| **인성의 `milestoneOf()` 는 늘 `null`** | 인성이 화면으로 마일스톤을 만들기 시작하면 GPS와 두 벌이 된다 |
| **마일스톤은 넷뿐** | `MILESTONES.length === 4` — 배차망이 늘어도 안 늘어난다 (§1) |
| **페이지 enum 은 공통에서 안 보인다** | `plugins/` 밖에서 `Stage`·`Page` 를 import 하면 실패 |
| **리스트를 상세로 오인하지 않는다** | 실물 덤프를 문제지로 (2026-09-02 실사고) |

### ⑤ 되돌릴 수 있게 자른다

커밋을 **셋**으로 나눈다 — 문제가 나면 어느 것만 되돌릴지 바로 안다.

```
1. «넘겨줄 것을 묶는다»   (함수 안 옮김 · 검사 그대로 통과해야 함)
2. «함수를 옮긴다»        (본문 한 줄도 안 고침)
3. «치환을 붙인다»        (milestoneOf 구현 — 픽커만)
```

🔴 **1이 통과 못 하면 2로 안 간다.** 1은 인성 경로를 안 건드리므로, 여기서 깨지면
묶는 방식이 틀린 것이다.
