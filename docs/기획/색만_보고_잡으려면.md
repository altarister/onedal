# 색만 보고 잡으려면 — 판정이 아직 못 막는 것

> 기사님: *"첫짐도 정차중합짐도 주행중합짐도 판단만 보고 잡으면 되려면 뭘 더해야 해?"*
>
> 🔴 **이 문서는 «할 일»이다.** 여기 적힌 것은 **아직 코드에 없다** — 있는 것은
> 「지금 재는 것」 표뿐이고 그것도 **코드와 대조해 적었다**. 끝난 것은 이 문서에서 지우고
> [판정 개편 이력](../기록/판정_개편_이력.md) 에 옮긴다.
>
> 판정식 자체의 이력은 [판정 개편 이력](../기록/판정_개편_이력.md) ·
> 기준의 원천은 [docs/지금/판정.md](../지금/판정.md).

---

## 0. 왜 아직 «참고»인가

색은 나온다. 눈금도 고수의 하루와 맞는다 —
볼트 실측(`docs/자료/노하우/일하는_법/노하우_추출.md`)과 대조하면
**하루 시급 5.05만/h ↔ 우리 꿀 5.0만/h**, **첫짐 5만원÷120분 = 2.5만/h ↔ 첫짐 기준 2.5만/h** 로
거의 그대로 겹친다.

🔴 **그런데 «잡으면 안 되는 콜»을 막는 그물이 비어 있다.** 색이 좋게 나오는 것과
나쁜 콜을 막는 것은 다른 일이다. 아래 A 가 그 그물이다.

---

## 1. 지금 각 국면에서 실제로 재는 것

| 축 | 첫짐 | 정차 중 합짐 | 주행 중 합짐 |
|---|---|---|---|
| 💰 돈 | ✅ 첫짐 눈금(`solo_hourly_krw`) | ✅ 한계 우회 시급 | ✅ 같음 |
| 🧭 지리 | ✅ 목적지 전진 배수(`dest_bonus_*`) | — 안 본다 (우회 시급이 대신) | — 같음 |
| ⏰ 약속 | — 잴 게 없다 (빈 차) | ⚠️ 깨짐만 · **몇 분인지 모른다** | ⚠️ 같음 |
| 📦 공간 | — 잴 게 없다 (빈 차) | ⚠️ **추정이면 점수에서 빠진다** | ⚠️ 같음 |
| 🧪 성질 | 🔴 **안 본다** | 🔴 **안 본다** | 🔴 **안 본다** |

🔴 **정차 중과 주행 중이 완전히 같다.** 판정이 국면을 가르는 곳은 최저 요금 하나뿐이다
(`OrderEvaluator` 의 `dispatchPhase === 'STANDBY'`). 콜 필터는 둘을 다르게 보는데
(모을 땐 상차 반경 · 뛸 땐 라인) 판정은 같은 잣대를 쓴다.

대조하는 법: `onedal-web/server/src/core/engine/judgeFacts.ts` 의 `firstLoadFacts` · `mergeFacts`
두 함수가 **판정에 무엇을 넘기는지**를 그대로 말한다. 표가 의심되면 거기를 먼저 읽는다.

---

## 2. 🔴 A — 막는 그물 (여기까지 되면 색을 믿고 누를 수 있다)

### A1. 제외 키워드를 서버 판정이 본다

| | |
|---|---|
| **지금** | `judgeFacts` 가 `excludedHits: []` 를 **하드코딩**한다 — 재료를 한 번도 안 채운다 |
| **판정식** | `shared/src/criteria.ts` 의 `NATURE` 에 **이미 있다** (제외어가 걸리면 🔴). 고칠 필요 없다 |
| **왜 위험** | 인성·화물24시는 앱 파서(`InsungParser`·`Hwamul24Parser` 의 `blacklistClear`)가 거르지만 **픽커는 아무도 안 거른다**. 손으로 잡은 콜(`MANUAL`)도 앱 필터를 안 지난다 |
| **막힌 곳** | `mergeFacts`/`firstLoadFacts` 의 입력에 **적요·원문 칸이 없다** — 찾을 대상이 판정까지 안 온다 |
| **먼저 할 것** | 적요가 서버 어디까지 와 있나 (`orders` 칸 · `intel.rawText`). 있으면 잇기만 하면 되고, 없으면 앱이 올려 주는 길부터 내야 한다 |

### A2. 역주행을 판정이 본다

| | |
|---|---|
| **지금** | 콜 필터만 본다 (`orderKm` · 경로 순서). 판정은 안 본다 |
| **왜 위험** | 필터를 안 지나는 길이 둘 — **픽커**와 **손으로 잡은 콜**. 그때는 그물이 없다 |
| **실측 근거** | 볼트 7번 콜이 «상차지가 등 뒤 15km» 라 되돌아가다 취소됐다 (노하우 표의 「남은 거리」 칸이 그 식을 검산한 자리) |
| **어디** | 식은 이미 있다 — 상차·하차·현위치의 «목적지까지 남은 거리» 셋을 견준다. 판정에 그 셋을 넘긴다 |

### A3. 약속이 «몇 분» 늦는지 숫자로 넘긴다

| | |
|---|---|
| **지금** | `mergeFacts` 가 `lateMinutes: null` 을 넣는다 — 분(分)이 **문장 안에만** 있어 숫자로 못 꺼낸다 |
| **결과** | **1분과 60분이 똑같이 🔴.** 통화 한 통으로 풀리는 콜까지 통째로 막힌다 |
| **왜 아직 안 했나** | 숫자가 없어 비례 감점을 못 켠다. 한 번 시도했다가 되돌렸다 (이력 참조) |
| **어디** | 옛 조건(`routePromiseGuard`)이 문장을 만들 때 **분을 함께 들고 오게** 한다 |
| **그다음** | 숫자가 오면 비례 감점을 켠다 — `bufferAfterMin < 0`(임시 약속) 구간이 먼저다. 통화로 굳힌 약속은 🔴 그대로 |

## 3. ⚠️ B — 재료가 없어 죽은 축

### B1. 적재량을 확정값으로 받는 길

추정(차종 글자)으로 «자리 부족»이 나오면 **점수에서 빠진다** (규칙 ⑤-2 · 오독이 꿀콜을 깎지 않게).
그래서 **통화로 짐 양을 신고하기 전에는 공간 축이 색에 없다.**
→ 통화 시트에서 신고한 값이 판정까지 닿는지 확인하고, 안 닿으면 잇는다.

### B2. 픽커 콜의 판정 재료가 얼마나 차는지 센다

픽커는 화면을 OCR 로 읽어 칸이 덜 찬다. **무엇이 비는지 아직 안 셌다.**
→ 픽커를 한 바퀴 돌려 `pnpm db parse kakaopicker` 로 빈 칸을 센다.

## 4. 🟡 C — 국면을 안 가른다 (정확도)

| | 무엇 | 근거 |
|---|---|---|
| **C1** | **정차 중 ↔ 주행 중을 판정이 가른다** — 모을 땐 «상차 반경 안», 뛸 땐 «라인 위» | 콜 필터는 이미 가른다. 판정만 같은 잣대 |
| **C2** | **첫짐 거리 하한** — 먼 첫짐은 비싸도 나쁘다 (합짐 예산이 안 남는다) | 노하우 「첫짐 고르는 세 기준」 |
| **C3** | **판의 시계** — «오늘 몇 시까지 모을까» | 볼트: *"한 시간 반 모아서 3~4개, 그리고 장거리"* |
| **C4** | **후속 콜 빈도** — «여기서 뒤에 더 뜰까» | 볼트 첫짐 세 기준 중 셋째 |

## 5. 📊 D — 검증 (병행)

**D1. 실콜 검증 0건.** 지금까지 전부 시뮬레이터다.
색과 기사님 판단이 **어긋난 콜**을 모으는 것이 가장 값진 데이터다 —
🔵 인데 «이건 아닌데» 는 놓친 축이 있다는 뜻이고, 🟡 인데 «잡고 싶은데» 는 눈금이 박하다는 뜻이다.

쌓인 판정을 보는 법: `cd onedal-web && pnpm db judge`

## 6. 순서와 까닭

```
A1 제외 키워드   ─┐
A3 약속 분 숫자   ├─ 여기까지가 «막는 그물». 되면 색을 믿고 누를 수 있다
A2 역주행        ─┘
        ↓
B1 적재 확정값 · B2 픽커 재료 센다      재료를 채운다
        ↓
C1 국면 가르기 → C2 첫짐 거리 → C3 판의 시계 → C4 후속 콜 빈도
```

**A 를 먼저 하는 까닭** — B·C 는 *더 좋은 색*을 만드는 일이고, A 는 *틀린 색을 막는* 일이다.
좋은 콜을 놓치는 것은 다음 콜로 만회되지만, 나쁜 콜을 잡으면 그 시간이 통째로 날아간다.

**A 안에서 A1 이 먼저인 까닭** — 판정식이 이미 완성돼 있어 **재료만 이으면 된다**.
A2·A3 은 계산을 새로 얹어야 한다.

**C1 이 C2~C4 보다 먼저인 까닭** — 국면을 가르고 나야 «모을 때의 기준»과 «뛸 때의 기준»을
따로 놓을 수 있다. C2~C4 는 전부 그 둘 중 한쪽에 붙는 규칙이다.

🔴 **새 설정값이 생기는 항목은 규칙 ⑤-4 의 다섯을 먼저 정한다** — C2(거리 하한)·C3(판의 시계)가
그렇다. 값이 없으면 코드를 시작하지 않고 묻는다.
