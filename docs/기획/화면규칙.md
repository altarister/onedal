# 화면 규칙 — 부품마다 무엇을 지키나 (2026-09-05)

> 기사님: *"각각의 요소에 규칙이 어느정도 잘 마련되어 있는 것 같아. … 이걸 컴포넌트별로
> 정리해서 표로 만들어줘. 그걸 보면 너도 작동 함수나 테스트 코드 짤 때 도움이 될 거 같아."*

**이 문서는 «무엇이 참인가»를 부품별로 모은 것이다.** 뒤쪽의 **이벤트 표**가 «무엇이
일어나나»를 정하고, 부품 표의 「이벤트」 칸이 그 번호(E1~E12)를 가리킨다 — 그러니
**«이 이벤트가 오면 무엇이 움직이나»는 E번호로 훑으면 나온다.**
(칸이 `E-` 인 줄은 이벤트와 무관하게 늘 참인 규칙이다.) 코드를 고치기 전에 여기를 보고,
새 규칙을 정하면 여기에 줄을 더한다. 규칙마다 **어느 검사가 잠그는지**를 함께 적는다 —
검사가 없는 줄은 «아직 말뿐인 규칙»이라 그 자리에서 깨질 수 있다.

⚠️ **여기 적힌 것은 시트 목업(`/mockup/sheet`)에서 확정된 것**이다. 실물에 아직 안 들어간
것이 섞여 있고, 그런 줄은 «실물»칸에 ⬜ 로 적었다.

# 🎬 이벤트 — 무엇이 일어나면 무엇이 움직이나

> 기사님: *"이벤트가 발생하면 이벤트에 따라 각 컴포넌트가 작동한다 — **각 컴포넌트가
> 이벤트를 트래킹하고 있다.**"*

**이벤트가 «사실»이고, 부품은 그 사실을 읽어 자기 몫을 한다.** 부품이 서로를 부르지
않는다 — 그러면 «누가 누구를 부르나»가 얽혀 오늘 겪은 엉킴이 다시 난다.
아래 표의 **E번호**를 부품 표의 「이벤트」 칸이 가리킨다.

| | 이벤트 | 무엇이 참이 되나 | 어디서 오나 |
|---|---|---|---|
| **E1** | **대기** | 잡은 콜 0 · 심사 없음 | 사이클 시작 · 하차 완료 뒤 |
| **E2** | **심사 시작** | 심사석에 콜 하나 (아직 안 잡음) | 앱이 콜을 집어 서버가 판정 |
| **E3** | **심사 끝 — KEEP** | 그 콜이 목록 **맨 아래**에 붙는다 | 기사님 손 · 30초 자동 |

## 🔴 오늘 되풀이된 병 하나

넷 다 같은 모양이었다 — **한 사실을 여러 곳이 각자 정하거나, 각자 짐작하는 것.**

| | 어디 | 무엇이 갈라졌나 |
|---|---|---|
| ① | 화면 조각 넷 | «없다»의 뜻 (대기? 심사 중? 끝?) |
| ② | 드래그 · 조작판 | 시트 높이 |
| ③ | 시나리오 · 조작판 | 판 · 국면 · 다녀온 곳 |
| ④ | 목록 · 지도 | 콜의 색 (자리로? 번호로?) |

**새 값을 만들 때 «누가 이 값을 읽고, 각자 무슨 질문의 답으로 쓰는가»를 먼저 본다**
