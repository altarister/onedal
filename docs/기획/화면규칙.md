# 화면 규칙 — 부품마다 무엇을 지키나 (2026-09-05)

> 기사님: *"각각의 요소에 규칙이 어느정도 잘 마련되어 있는 것 같아. … 이걸 컴포넌트별로
> 정리해서 표로 만들어줘. 그걸 보면 너도 작동 함수나 테스트 코드 짤 때 도움이 될 거 같아."*

**이 문서는 «무엇이 참인가»를 부품별로 모은 것이다.** 코드를 고치기 전에 여기를 보고,
새 규칙을 정하면 여기에 줄을 더한다. 규칙마다 **어느 검사가 잠그는지**를 함께 적는다 —
검사가 없는 줄은 «아직 말뿐인 규칙»이라 그 자리에서 깨질 수 있다.

⚠️ **여기 적힌 것은 시트 목업(`/mockup/sheet`)에서 확정된 것**이다. 실물에 아직 안 들어간
것이 섞여 있고, 그런 줄은 «실물»칸에 ⬜ 로 적었다.

## 🔴 오늘 되풀이된 병 하나

넷 다 같은 모양이었다 — **한 사실을 여러 곳이 각자 정하거나, 각자 짐작하는 것.**

| | 어디 | 무엇이 갈라졌나 |
|---|---|---|
| ① | 화면 조각 넷 | «없다»의 뜻 (대기? 심사 중? 끝?) |
| ② | 드래그 · 조작판 | 시트 높이 |
| ③ | 시나리오 · 조작판 | 판 · 국면 · 다녀온 곳 |
| ④ | 목록 · 지도 | 콜의 색 (자리로? 번호로?) |

**새 값을 만들 때 «누가 이 값을 읽고, 각자 무슨 질문의 답으로 쓰는가»를 먼저 본다**
(CLAUDE.md ⑤-4 ⑤). 읽는 곳이 둘이면 그 자리에서 의심한다.

⚠️ 그리고 하나 더 — **검사가 있다고 규칙이 옳은 것은 아니다.**
L1(잡은 순서)은 내가 «찾기 편하려고» 뒤집어 놓고 **검사로 굳혀** 뒀던 자리다.
초록불이라 안심하고 있었다. **무엇을 잠갔는지**를 본다.
