## 1. 무엇을 바꾸나 — 한 줄이다

```
지금:  kakaomap://route?sp=…&vp=…&ep=…&by=car
바꾼 뒤: kakaonavi-sdk://navigate?appkey=…&apiver=1.0&extras=…&param=…
```

**SDK 를 안 깐다.** 카카오 SDK 도 속을 보면 URL 하나를 만들어 여는 것뿐이다
(iOS 문서의 `navigateUrl()` 이 그렇게 말한다). 우리가 그 URL 을 직접 만든다.

⚠️ 2026-09-03 밤에 *"JS SDK 를 써야 한다"* 고 적었던 것은 **틀렸다.**

## 2. ② 값 — 폰 실측으로 정했다 (2026-09-04)

### 🔴 경유지 칸 이름은 `via_list` 다

문서 어디에도 없어서 **두 벌을 만들어 기사님 폰에서 눌러** 갈랐다:

| 보낸 이름 | 결과 |
|---|---|
| **`via_list`** | ✅ 「경유 1」 마커가 찍힌다 · **45km / 1시간 42분** |
| `viaPoints` | ❌ 마커 없음 · 44km / 1시간 44분 — **경로가 그냥 사라졌다** |

`coord_type` 도 밑줄이니 앞뒤가 맞는다 — `viaPoints` 는 **JS SDK 가 자바스크립트 쪽에서만
쓰는 이름**이고, SDK 가 안에서 `via_list` 로 바꿔 보내는 것이었다.

🔴 **틀린 이름을 보내도 에러가 안 난다.** 경유지만 조용히 사라지고 **멀쩡해 보이는 경로**가
나온다. 기사님이 두 벌을 다 눌러 보지 않으셨으면 **도로 위에서** 알게 됐을 것이다.
→ **검사가 유일한 방어다** (§7).

### 보내는 값

| 칸 | 값 | 근거 |
|---|---|---|
| `param.destination` | `{name, x:경도, y:위도}` | 🔴 **`name` 이 필수다** — 지금 kakaomap 링크는 좌표만으로 되는데 여기는 이름을 줘야 한다 |
| `param.via_list` | 같은 모양 **최대 3개** | 🔴 **우리는 안 쓴다** — §5-1 (한 구간씩 보낸다). 값과 이름은 실측으로 확정해 뒀으니 필요해지면 그때 쓴다 |
| `param.option.coord_type` | `"wgs84"` | 🔴 **기본이 `katec`** 이라 안 넣으면 조용히 엉뚱한 데로 간다 |
| `param.option.vehicleType` | **`1`** | §2-1 — **틀리면 위험하다**: 이륜차(7)로 물었더니 카카오가 고속도로를 빼고 7km 더 도는 경로를 줬다 (실측 2026-09-04). 차종은 «정확도»가 아니라 «갈 수 있는 길»의 문제다 |
| `appkey` | JavaScript 앱 키 | 앱 ID 1419838 · REST 키와 **같은 앱** |
| `extras.KA` | `… origin/https://1dal.altari.com` | 등록한 도메인과 같아야 한다 |
| 출발지 | **안 넣는다** | 생략하면 현위치에서 시작한다 (실측 확인). 지금 `sp` 로 넣던 것을 뺀다 |
| **`rpOption`** | **넣는다** | ⚠️ **2026-09-04 에 뒤집혔다.** 「모른다」고 적어 뒀는데 표를 찾았다 — 추천 `100` · 무료도로 `2` · 고속도로우선 `6`. [경로를 고른다](경로를_고른다.md) §7-① |
| `car_fuel` · `car_hipass` | **안 넣는다** | 이 URL 이 받는지 **모른다.** 모르면 안 보낸다 (규칙 ④) |

### 2-1. 차종은 **`1`** 이고, 새로 만들지 않는다

DB `user_settings.vehicle_type = '1t'`, 그리고 `vehicles.ts` 의
`mapVehicleToKakaoCarType('1t') = 1` (1종 = 승용차/소형승합/소형화물).

🟢 **기사님이 실주행을 승용차로 하셔도 값이 같다** — 승용차도 1종이다.
   그래서 09-03 자료의 경로·거리는 트럭 기준으로 읽어도 된다
   (다만 **적재·톨비는 아니다** — 승용차 5박스 vs 트럭 100박스).

🔴 **새 매핑을 만들지 않는다.** `mapVehicleToKakaoCarType` 를 그대로 읽는다.
   이 레포는 이미 **`car_type` 이라는 두 벌을 죽인 적**이 있다
   (`db.ts:146` 의 «차종 두 벌의 죽은 쪽 — 원천은 vehicle_type», 전수조사 2026-08-21).
   같은 실수를 반복하지 않는다 (규칙 ③).

## 3. ① 스키마 — **새 DB 칸이 없다**

| 무엇 | 어디 | 왜 거기인가 |
|---|---|---|
| JavaScript 앱 키 | `client-app/.env` 의 `VITE_KAKAO_JS_KEY` | **자격증명이지 «기본값»이 아니다.** `VITE_GOOGLE_CLIENT_ID` 와 같은 자리 |
| 출처(origin) | 저장 안 함 — 실행 시 `location.origin` | 우리 도메인에서 열리므로 파생된다 (규칙 ③) |
| 차종 | **있는 것을 읽는다** (`vehicle_type`) | §2-1 |
| 경유 한도 | `naviLink.ts` 상수 `KAKAO_NAVI_MAX_VIA = 3` | `KAKAO_MAX_VIA = 5` 바로 옆 |

⚠️ **JS 키가 번들에 실린다.** 그래도 괜찮다 — 웹 페이지에 실리라고 만든 키이고,
**도메인 등록이 유일한 방어**다. 그래서 등록을 비워 두면 안 된다
(콘솔이 *"등록하지 않으면 JavaScript 키를 사용할 수 없습니다"* 라고 못박는다).
🔴 **REST 키는 절대 여기 오면 안 된다** — 그건 서버에만 산다.

## 5. ④ 화면 — **카카오맵을 지우지 않는다**

| | |
|---|---|
| 큰 버튼 | 🧭 **카카오내비로 열기** |
| 그 아래 작게 | 🗺️ 카카오맵으로 열기 |

🔴 **왜 둘을 두나** — §0 때문이다. ①②③ 을 **가정**으로 진행하는 중이라, 주행에서
카카오내비가 나쁘면 **배포 없이 되돌아갈 길**이 있어야 한다. 운전석에서 «안 되네»
하고 끝나면 그날 일을 망친다.

⚠️ 규칙 «운전 중엔 큰 버튼 하나» 와 어긋나 보이지만 아니다 —
**둘은 크기가 다르다.** 먼발치에서 잡히는 것은 여전히 하나다.

🟢 **③이 주행으로 확인되면 카카오맵을 뗀다.** 그때 이 절을 지운다.

### 5-1. 🔴 **한 구간씩 보낸다** — 경유지를 아예 안 쓴다 (기사님 안 2026-09-04)

기사님: *"우리는 최소 5개가 있어야 해. 그래야 3콜을 한 번에 합짐할 수 있으니까.
그것이 안 된다면 … **경유지 도착하면 다음 경유지 위치까지만 내비로 가고, 도착하면
정차 중에 다시 다음 경로까지만 요청하고** 그런 식으로 해야 할지도 몰라."*

**계산이 맞다.** 3콜 = 상차 3 + 하차 3 = 6정거장 = **경유 5개.** 카카오내비는 3개다.

| | 경유지 | 3콜(6정거장) |
|---|---|---|
| 카카오내비 링크 | **3개** | ❌ 2콜까지 |
| 카카오맵 링크 | 5개 | 딱 맞음 |
| **우리 길찾기 API** | **30개** | ✅ 여유 (실측: 경유 5개 = 67.4km/172분, 그날 기록 68km 와 맞음) |

🟢 **카카오맵을 따로 부를 필요는 없다** — 우리는 **이미 전체 경로를 갖고 있다**
   (`orders.routePolyline`, 지금 지도가 그걸 그린다). 기사님 안의 앞부분은 이미 되어 있다.

#### 🔴 그리고 한 구간씩 보내면 §0 의 가정 셋이 **통째로 사라진다**

| | 3경유씩 보내기 | **한 구간씩** |
|---|---|---|
| ① 경유지로 안내하나 | 의존 | **경유지가 없다** |
| ② 지나면 넘어가나 | 의존 | **넘어갈 게 없다** |
| ③ 재탐색이 순서를 지키나 | 의존 | **순서가 없다** |
| 탭 (6정거장) | 2번 | 6번 — **매번 정차 중이다** |
| 우리 선 | 2번 갱신 | **6번 갱신** |

👉 **가정 위에 서 있던 판이 사실 위에 서게 된다.** 이게 결정적이다.

🟢 **전체 경로는 관제웹 지도가 보여준다.** 09-03 에 *"네비와 전체 경로가 같이 보이는 건
좋았는데 **지금 가고 있는 곳만** 볼 수 있으면"* 하신 것이 정확히 이 분담이다 —
**관제웹은 전체, 내비는 지금 구간.** (지도의 「현구간」 모드가 이미 그 일을 한다)

🟢 **그리고 매번 새 선을 받는다** — [남은 주행 분](남은_주행_분.md) 의 «값이 늙는다»가
   크게 완화된다. 실측으로 **30분 만에 거리·통행료까지 바뀌는 것**을 확인했다.

## 6. ⑤ 읽는 곳

### 6-1. 🟢 **«자르는 개수» 문제가 없어졌다** — 각 버튼이 자기 숫자를 말한다

처음엔 이렇게 적었다: *"`KAKAO_MAX_VIA`(=5) 하나가 세 가지를 답한다 — ①링크에 몇 개를
넣나 ②목록에서 몇 번째부터 흐리게 그리나 ③«몇 곳 보냅니다» 문구. 카카오내비를 더하면
셋이 앱마다 달라지는데, 퉁치면 **4번째 정거장이 조용히 사라지면서 화면은 «6곳
보냅니다»라고 적는다**."*

**§5-1 이 이걸 없앴다.** 카카오내비에는 **다음 정거장 하나**만 보내므로 **자를 목록이 없다.**

| 버튼 | 자기가 보내는 것 | 자기가 말하는 것 |
|---|---|---|
| 🧭 **카카오내비** | **다음 정거장 하나** | 「다음 ① 초월읍 상차」 |
| 🗺️ 카카오맵 | 경유 5 + 도착 1 = 6곳 | 「경유 5곳 · 도착 방화동」 |

👉 **공유하는 숫자가 없다.** 화면이 자기 숫자를 갖지 않고, **각 버튼이 자기 안에서 센다.**

⚠️ **딸려 오는 것 하나** — 지금 목록은 `i > KAKAO_MAX_VIA` 인 정거장을 **흐리게** 그리고
   «— 다음에» 를 붙인다. 그건 **카카오맵의 사정**이다. 카카오맵이 보조 버튼으로 내려가면
   그 흐리게도 **함께 내려간다** — 주 버튼(내비)은 어차피 하나만 보내므로
   목록 전체가 또렷해야 «남은 정거장이 이만큼»이 읽힌다.

### 6-2. 🔴 좌표 차례가 **둘이 반대다** (이건 남는다)

| | 차례 | 우리 DB 와 |
|---|---|---|
| `kakaomap://` | **`위도,경도`** 문자열 | **뒤집는다** |
| `kakaonavi-sdk://` | JSON `x`=경도 `y`=위도 | **그대로** |

한 파일(`naviLink.ts`) 안에 **반대 규칙 둘**이 살게 된다. 그 파일의 주석은
*"섞으면 엉뚱한 나라를 안내한다 — 그래서 이 변환을 여기 한 곳에만 둔다"* 라고 적혀 있는데,
그 «한 곳»이 **둘**이 된다.

👉 뒤집는 일은 **`pair()` 안에만** 두고, 카카오내비 쪽은 **아예 안 부른다.**
   검사로 «내비 URL 에 위도경도 뒤바뀐 값이 안 들어간다»를 잠근다.

### 6-3. 🔴 «다음 정거장»을 누가 정하나 — **서버 하나다**

한 구간씩 보내려면 **«다음이 어디냐»** 가 늘 하나여야 한다.

🟢 **이미 그렇다** — `/navi` 는 서버가 준 `routeStops` 를 **그대로** 쓰고 자기 순서를 안 만든다
   (`useNaviRoute` · 규칙 ③). 다녀온 정거장은 서버가 빼 준다.
👉 **`routeStops[0]` 이 곧 «다음»이다.** 새로 만들 것이 없다.

⚠️ 그래서 **서버가 틀리면 내비도 틀린다.** 아래 두 가지가 그 자리다 (§7 검사).

| 언제 | 무슨 일 | 무엇을 해야 하나 |
|---|---|---|
| **도착 감지가 실패** (터널·기지국 좌표) | `routeStops[0]` 이 **이미 다녀온 곳**을 가리킨다. 09-03 에 실제로 흔들렸다 | **손으로 넘길 길**이 있어야 한다 — 「다음 정거장으로」 |
| **합짐이 붙어 순서가 바뀜** | 내비는 옛 목적지로 안내 중인데 화면은 새 순서다 | **버튼이 눈에 띄게 바뀌어야** 한다 — 「경로가 바뀌었습니다」 |

## 7. 먼저 만들 검사 (버그 순서: 진단 → 빨간불 → 수정 → 초록불)

| 검사 | 무엇을 잡나 |
|---|---|
| 🔴 **경유지가 `via_list` 라는 이름으로 나간다** | §2 — **틀린 이름은 에러를 안 낸다.** 실측으로만 알아낸 것이라 코드가 되돌아가면 아무도 모른다 |
| 🔴 **`coord_type` 이 반드시 실린다** | 빠지면 katec 으로 읽혀 엉뚱한 데로 간다 |
| 🔴 **내비 URL 은 좌표를 안 뒤집는다** | §6-2 — 한 파일 안의 반대 규칙 둘 |
| **내비 링크에는 정거장이 «하나»만 들어간다** | §6-1 — 경유지가 섞여 들어가면 3개 한도에 걸려 조용히 잘린다 |
| **버튼 문구의 숫자가 그 버튼이 실제로 보내는 수와 같다** | §6-1 — 화면이 자기 숫자를 갖지 않는다 |
| **«다음»은 `routeStops[0]` 하나에서 온다** | §6-3 — 관제웹이 자기 순서를 만들면 서버와 갈라진다 |
| **`name` 이 빈 정거장은 안 보낸다** | 이름이 필수인데 빈 채로 보내면 어떻게 되는지 모른다 |
| **차종은 `mapVehicleToKakaoCarType` 한 곳에서 온다** | §2-1 — 두 벌을 또 만드는 것 |
| **키가 없으면 링크를 안 만든다** (`null`) | 규칙 ④ — 못 만들면 «없다»가 낫다 |
