## 0. 🔴 이 판은 **가정 위에 서 있다**

기사님(2026-09-04): *"① 여수동 쪽으로 안내하나 ② 지나면 넘어가나 ③ 재탐색 뒤에도
순서를 지키나 — **암묵적으로 다 그렇다고 생각하고** 다음을 진행하자."*

**셋 다 아직 주행으로 확인하지 않았다.** 확인한 것은 *"경로가 만들어진다"* 까지다
(2026-09-04 · 기사님 폰 · 「경유 1」 마커).

> 이 레포에서 **계획을 완료로 적어 네 번 사고**가 났다. 그러니 여기 분명히 적는다 —
> **①②③ 은 «확인함»이 아니라 «그렇다고 보고 진행함»이다.**
> 주행에서 아니라고 나오면 이 문서 전체가 무효다. 그래서 §5 가 **카카오맵을 남긴다.**

## 1. 무엇을 바꾸나 — 한 줄이다

```
지금:  kakaomap://route?sp=…&vp=…&ep=…&by=car
바꾼 뒤: kakaonavi-sdk://navigate?appkey=…&apiver=1.0&extras=…&param=…
```

**SDK 를 안 깐다.** 카카오 SDK 도 속을 보면 URL 하나를 만들어 여는 것뿐이다
(iOS 문서의 `navigateUrl()` 이 그렇게 말한다). 우리가 그 URL 을 직접 만든다.

⚠️ 2026-09-03 밤에 *"JS SDK 를 써야 한다"* 고 적었던 것은 **틀렸다.**

## 2. ② 값 — 폰 실측으로 정했다 (2026-09-04)

### 🔴 경유지 칸 이름은 `via_list` 다

문서 어디에도 없어서 **두 벌을 만들어 기사님 폰에서 눌러** 갈랐다:

| 보낸 이름 | 결과 |
|---|---|
| **`via_list`** | ✅ 「경유 1」 마커가 찍힌다 · **45km / 1시간 42분** |
| `viaPoints` | ❌ 마커 없음 · 44km / 1시간 44분 — **경로가 그냥 사라졌다** |

`coord_type` 도 밑줄이니 앞뒤가 맞는다 — `viaPoints` 는 **JS SDK 가 자바스크립트 쪽에서만
쓰는 이름**이고, SDK 가 안에서 `via_list` 로 바꿔 보내는 것이었다.

🔴 **틀린 이름을 보내도 에러가 안 난다.** 경유지만 조용히 사라지고 **멀쩡해 보이는 경로**가
나온다. 기사님이 두 벌을 다 눌러 보지 않으셨으면 **도로 위에서** 알게 됐을 것이다.
→ **검사가 유일한 방어다** (§7).

### 보내는 값

| 칸 | 값 | 근거 |
|---|---|---|
| `param.destination` | `{name, x:경도, y:위도}` | 🔴 **`name` 이 필수다** — 지금 kakaomap 링크는 좌표만으로 되는데 여기는 이름을 줘야 한다 |
| `param.via_list` | 같은 모양 **최대 3개** | 앱의 «+ 경유»도 3개다 — 앞뒤가 맞는다 |
| `param.option.coord_type` | `"wgs84"` | 🔴 **기본이 `katec`** 이라 안 넣으면 조용히 엉뚱한 데로 간다 |
| `param.option.vehicleType` | **`1`** | §2-1 — **틀리면 위험하다**: 이륜차(7)로 물었더니 카카오가 고속도로를 빼고 7km 더 도는 경로를 줬다 (실측 2026-09-04). 차종은 «정확도»가 아니라 «갈 수 있는 길»의 문제다 |
| `appkey` | JavaScript 앱 키 | 앱 ID 1419838 · REST 키와 **같은 앱** |
| `extras.KA` | `… origin/https://1dal.altari.com` | 등록한 도메인과 같아야 한다 |
| 출발지 | **안 넣는다** | 생략하면 현위치에서 시작한다 (실측 확인). 지금 `sp` 로 넣던 것을 뺀다 |
| `rpOption` · `car_fuel` · `car_hipass` | **안 넣는다** | 이 URL 이 받는지 **모른다.** 모르면 안 보낸다 (규칙 ④) |

### 2-1. 차종은 **`1`** 이고, 새로 만들지 않는다

DB `user_settings.vehicle_type = '1t'`, 그리고 `vehicles.ts` 의
`mapVehicleToKakaoCarType('1t') = 1` (1종 = 승용차/소형승합/소형화물).

🟢 **기사님이 실주행을 승용차로 하셔도 값이 같다** — 승용차도 1종이다.
   그래서 09-03 자료의 경로·거리는 트럭 기준으로 읽어도 된다
   (다만 **적재·톨비는 아니다** — 승용차 5박스 vs 트럭 100박스).

🔴 **새 매핑을 만들지 않는다.** `mapVehicleToKakaoCarType` 를 그대로 읽는다.
   이 레포는 이미 **`car_type` 이라는 두 벌을 죽인 적**이 있다
   (`db.ts:146` 의 «차종 두 벌의 죽은 쪽 — 원천은 vehicle_type», 전수조사 2026-08-21).
   같은 실수를 반복하지 않는다 (규칙 ③).

## 3. ① 스키마 — **새 DB 칸이 없다**

| 무엇 | 어디 | 왜 거기인가 |
|---|---|---|
| JavaScript 앱 키 | `client-app/.env` 의 `VITE_KAKAO_JS_KEY` | **자격증명이지 «기본값»이 아니다.** `VITE_GOOGLE_CLIENT_ID` 와 같은 자리 |
| 출처(origin) | 저장 안 함 — 실행 시 `location.origin` | 우리 도메인에서 열리므로 파생된다 (규칙 ③) |
| 차종 | **있는 것을 읽는다** (`vehicle_type`) | §2-1 |
| 경유 한도 | `naviLink.ts` 상수 `KAKAO_NAVI_MAX_VIA = 3` | `KAKAO_MAX_VIA = 5` 바로 옆 |

⚠️ **JS 키가 번들에 실린다.** 그래도 괜찮다 — 웹 페이지에 실리라고 만든 키이고,
**도메인 등록이 유일한 방어**다. 그래서 등록을 비워 두면 안 된다
(콘솔이 *"등록하지 않으면 JavaScript 키를 사용할 수 없습니다"* 라고 못박는다).
🔴 **REST 키는 절대 여기 오면 안 된다** — 그건 서버에만 산다.

## 4. ③ 시점 — 지금과 똑같다

```
서버 → 소켓 sync-active-orders → useNaviRoute → /navi 가 링크를 만든다
                                                 기사님이 누르면 앱이 열린다
```

바뀌는 것은 **만들어지는 문자열뿐**이다. 순서를 정하는 곳도, 받는 곳도 그대로다
(순서는 서버가 정한 것을 그대로 쓴다 — 규칙 ③).

## 5. ④ 화면 — **카카오맵을 지우지 않는다**

| | |
|---|---|
| 큰 버튼 | 🧭 **카카오내비로 열기** |
| 그 아래 작게 | 🗺️ 카카오맵으로 열기 |

🔴 **왜 둘을 두나** — §0 때문이다. ①②③ 을 **가정**으로 진행하는 중이라, 주행에서
카카오내비가 나쁘면 **배포 없이 되돌아갈 길**이 있어야 한다. 운전석에서 «안 되네»
하고 끝나면 그날 일을 망친다.

⚠️ 규칙 «운전 중엔 큰 버튼 하나» 와 어긋나 보이지만 아니다 —
**둘은 크기가 다르다.** 먼발치에서 잡히는 것은 여전히 하나다.

🟢 **③이 주행으로 확인되면 카카오맵을 뗀다.** 그때 이 절을 지운다.

### 경유가 5 → 3 으로 준다

09-03 경로는 6정거장이었다.

| | 한 번에 | 09-03 이면 |
|---|---|---|
| 카카오맵 | 경유5 + 도착1 = 6곳 | 한 번에 |
| **카카오내비** | 경유3 + 도착1 = **4곳** | **두 번 나눠서** |

화면의 «남은 곳은 도착 후 다시» 안내가 **더 자주** 뜬다. 치명적이진 않다 —
도착할 때마다 `/navi` 가 남은 경로를 다시 준다.

🟢 **오히려 좋은 면이 있다** — 이어 보내는 횟수가 늘면 그때마다 **우리 선도 새로 받는다.**
[남은 주행 분](남은_주행_분.md) 의 «값이 늙는다» 문제가 그만큼 줄어든다.

## 6. ⑤ 읽는 곳 — 🔴 **여기가 이 판에서 제일 위험하다**

### 6-1. 두 링크가 **같은 목록을 다르게 자른다**

지금 `Navi.tsx` 는 `KAKAO_MAX_VIA`(=5) **하나**로 세 가지를 답한다 —
① 링크에 몇 개를 넣나 ② 목록에서 몇 번째부터 흐리게 그리나 ③ «몇 곳 보냅니다» 문구.

카카오내비를 더하면 **그 셋이 앱마다 달라진다.** 한 값으로 퉁치면
**카카오내비에서 4번째 정거장이 조용히 사라지는데 화면은 «6곳 보냅니다»라고 적는다.**

👉 **자르는 개수는 «어느 앱으로 보내느냐»에서 파생시킨다.** 화면이 자기 숫자를 갖지 않는다.

### 6-2. 🔴 좌표 차례가 **둘이 반대다**

| | 차례 | 우리 DB 와 |
|---|---|---|
| `kakaomap://` | **`위도,경도`** 문자열 | **뒤집는다** |
| `kakaonavi-sdk://` | JSON `x`=경도 `y`=위도 | **그대로** |

한 파일(`naviLink.ts`) 안에 **반대 규칙 둘**이 살게 된다. 지금 그 파일의 주석은
*"차례가 «위도,경도»다 … 섞으면 엉뚱한 나라를 안내한다 — 그래서 이 변환을 여기 한 곳에만 둔다"*
라고 적혀 있는데, 그 «한 곳»이 **둘**이 된다.

👉 뒤집는 일은 **`pair()` 안에만** 두고, 카카오내비 쪽은 **아예 안 부른다.**
   검사로 «내비 URL 에 위도경도 뒤바뀐 값이 안 들어간다»를 잠근다.
