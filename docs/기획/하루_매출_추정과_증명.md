# 하루에 얼마나 벌 수 있나 — 지금 말할 수 있는 것과 없는 것

> 🔴 **이 문서는 계획이다.** 여기 적힌 추정은 **잡은 콜이 아니라 화면에 뜬 콜**로 낸 것이다.
> 실제로 수행한 콜은 아직 없다. 숫자를 실적으로 읽지 않는다.

---

## 1. 한 줄 답

**픽커 단독이면 하루 8만원 안팎이다. 그 위는 지금 말할 수 없다.**

말할 수 있는 이유는 픽커가 실물 앱이라 화면에 뜬 콜이 진짜 시장 값이기 때문이고,
말할 수 없는 이유는 **인성 요금을 모르고, 잡기 성공률을 모르고, 합짐이 몇 배가 되는지 모르기** 때문이다.

중앙값 11,165원짜리 콜을 **혼자** 수행하면 65분쯤 걸린다

## 4. 왜 하루 매출을 못 내는가 — 끊긴 고리 셋

하루 매출은 이 사슬로 나온다.

```
① 뜬 콜  →  ② 필터 통과  →  ③ 판정 색  →  ④ 잡기 성공  →  ⑤ 수행 시간  →  ⑥ 받은 요금
```

지금 무엇이 쌓이는지 표로 본다.

| 고리 | 어디에 | 지금 |
|---|---|---|
| ① 뜬 콜 | `intel` | ✅ 쌓인다 (픽커는 실물) |
| — 관측 시간 | 없다 | ❌ 로그에 「리스트 못 봄 N초」만 찍히고 표에 안 남는다 |
| ② 필터 통과·거름 | `user_devices` 의 집계 칸 | ⚠️ 지금 화면 값만. 하루치가 누적되지 않는다 |
| ③ 판정 색 | `order_judgments` | ✅ 쌓인다 (53건) |
| ④ 잡기 시도·성공 | 없다 | ❌ **놓친 콜이 기록되지 않는다** |
| ⑤ 수행 시간 | `step_*` 표 여섯 | ✅ 틀은 있다. 실콜이 없어 표본 0 |
| ⑥ 받은 요금 | `orders` | ⚠️ 4행뿐이고 전부 시뮬 |

**끊긴 곳이 셋이다.** 관측 시간, 잡기 성공률, 합짐 배수(한 번 나갈 때 몇 콜을 겹치나).
이 셋이 없으면 「하루 몇 콜」을 계산할 수 없고, 그러면 하루 매출도 못 낸다.

🟢 **그중 합짐 배수는 사업자 없이도 잴 수 있다** — 체험 모드로 미리 돌리면 된다 (§6).

## 5. 확률적으로 증명하려면 무엇이 필요한가

### ① 무엇을 증명하는 것인가부터 정한다

「하루 얼마 번다」는 증명할 수 없다. 날씨·요일·시간대가 매일 다르고 같은 날을 두 번 살 수 없다.
증명할 수 있는 것은 **예측과 실적의 대조**다.

> **판정이 «꿀»이라 한 콜은 실제로 꿀이었는가.**

이건 증명할 수 있다. 예측(판정 색·점수)은 이미 남고, **실적(그 콜을 하고 실제로 번 시급)만
남기면** 된다. 그 둘을 붙이면 판정이 맞는지 틀리는지 숫자로 나온다.

### ② 그래서 남겨야 할 것 넷

| 무엇 | 왜 | 어디에 |
|---|---|---|
| **리스트를 본 시간** | ①을 시간당 몇 건으로 바꾸려면 분모가 필요하다 | 기기 세션에 하루 누적으로 |
| **잡으려다 놓친 것** | ④ 성공률. 지금은 성공만 남고 실패가 안 남는다 | 콜 기록에 시도·결과 |
| **콜별 실적** | 수행이 끝난 뒤 실제 걸린 시간과 받은 요금 | 마일스톤에 이미 틀이 있다 |
| **한 번 나갈 때 겹친 콜 수** | 합짐 배수. 픽커가 값을 가지려면 이게 1보다 커야 한다 | 콜 묶음 단위로 |

### ③ 표본이 얼마나 필요한가

픽커 요금의 표준편차가 6,673원이고 평균이 11,684원이다. 변동이 크다(변동계수 0.57).
평균 요금을 얼마나 좁게 알고 싶은지에 따라 필요한 콜 수가 이렇게 나온다 (95% 신뢰).

| 알고 싶은 정밀도 | 필요한 콜 | 하루 7콜이면 |
|---|---:|---:|
| ±2,000원 | 43건 | 6일 |
| ±1,500원 | 77건 | 11일 |
| ±1,000원 | 172건 | 25일 |
| ±500원 | 685건 | 98일 |

**±2,000원이면 일주일, ±1,000원이면 한 달이다.** 요금만 그렇고, 잡기 성공률과
합짐 배수는 표본이 더 필요하다. 성공률은 비율이라 분모가 커야 한다.

### ④ 판정이 맞았는지 재는 법

콜마다 **예측 시급**(판정이 쓴 값)과 **실제 시급**(수행 뒤 요금 ÷ 실제 걸린 시간)을
함께 남기면, 색깔별로 실제 시급의 분포를 그릴 수 있다.

```
🔵 꿀이라 한 콜들의 실제 시급 분포
🟢 보통이라 한 콜들의 실제 시급 분포
🟡 똥이라 한 콜들의 실제 시급 분포
```

세 분포가 순서대로 갈리면 판정이 맞는 것이고, 겹치면 틀린 것이다.
**색깔 하나에 30건씩만 모여도 방향은 보인다.** 하루 7콜이면 2~3주다.

## 6. 체험 모드로 사업자 전에 미리 재기 (기사님 제안)

체험 모드는 실물 배차망 콜을 **잡지 않고** 관제 흐름만 태워 보는 기기 모드다.
사업자 등록 전에 쓸 수 있는 유일한 실물 측정 수단이다.

### ① 이미 부분적으로 돌고 있다

판정 53건 중 **18건이 네 축을 다 썼다.** 약속과 공간이 점수를 냈다는 것은 그때 세션에
콜이 실려 있었다는 뜻이다. **체험으로 합짐 판정이 실제로 돈 기록**이다.

### ② 체험이 채우는 것과 못 채우는 것

| 고리 | 체험으로 | 왜 |
|---|:---:|---|
| 합짐 배수 | ✅ | 실물 콜로 실제 카카오 경로를 계산한다. 값이 진짜다 |
| 하루에 결재 기회가 몇 번 오나 | ✅ | 앱을 켜 두면 세어진다 |
| 판정 색 분포 | ✅ | 이미 쌓인다 |
| 잡기 성공률 | ❌ | 안 잡으니 경쟁에서 이겼을지 모른다 |
| 실제 수행 시간 | ❌ | 안 움직이니 카카오 추정만 남는다 |
| 실제 받는 요금 | ❌ | 픽커는 수행 뒤에 확정된다 |

🔴 **그래서 체험으로 나오는 하루 매출은 예측이 아니라 상한선이다.**
「경쟁이 없었다면 최대 이만큼」이다. 그렇게 적고 쓴다.

### ③ 지금 막고 있는 것 셋

| 무엇 | 지금 | 크기 |
|---|---|---|
| **체험 콜이 남지 않는다** | 규칙 ⑦ 대로 메모리에만 산다. 하루가 끝나면 사라진다. 판정만 `order_judgments` 에 남고 「무엇을 잡았다고 쳤나」가 안 남는다 | 전용 표 하나 |
| **좌표가 저장되지 않는다** | 픽커 `intel` 432행 전부 상차·하차 좌표가 비어 있다. 서버가 지오코딩은 하는데 장부에 안 넣는다. 칸은 이미 있다 | 작다 |
| **관측 시간이 짧다** | 이틀 합쳐 34분이다. 콜이 그 안에 몰려 있어 시간당 유입률을 못 낸다 | 켜 두는 시간을 늘린다 |

🔴 **체험 기록을 `orders` 에 넣지 않는다.** 규칙 ⑦ 의 격리를 지킨다 —
장부에 들어가면 정산과 적재가 틀어진다. 전용 표에 따로 쌓는다.

### ④ 하면 나오는 것

앱을 켜 두고 하루를 체험으로 돌면 하루 끝에 이런 줄이 나온다.

```
오늘 판정을 따랐다면 N콜 · 합짐 배수 M배 · 추정 매출 얼마 (경쟁 제외 상한선)
```

처음으로 숫자가 생긴다. 그리고 그 숫자는 사업자 등록 뒤 실적과 나란히 놓고
**얼마나 빗나갔는지**를 재는 기준선이 된다.

## 7. 지금 당장 할 수 있는 것

실콜을 수행하려면 사업자 등록이 먼저다. 그 전에 **측정 틀만 미리 세워 둘 수 있다.**
틀이 없으면 일을 시작한 첫 주 데이터가 그냥 사라진다.

| 순서 | 무엇 | 크기 |
|---|---|---|
| 1 | `intel` 에 상차·하차 좌표를 저장한다 (칸은 이미 있다) | 작다 |
| 2 | 체험 주행 기록을 전용 표에 남긴다 (`orders` 는 건드리지 않는다) | 중간 |
| 3 | 리스트를 본 시간을 하루 누적으로 기기 세션에 쌓는다 | 작다. 로그에 이미 찍히는 값이다 |
| 4 | 판정 예측값을 실적과 같은 행에 둔다 | 작다 |
| 5 | 잡기 시도와 결과를 남긴다 (성공·실패·사유) | 중간. 실콜부터 값이 있다 |
| 6 | 콜별 실적(실제 시간·요금)을 마일스톤에 붙인다 | 중간. 틀은 있다 |

**1·2·3 은 사업자 없이도 값이 나온다.** 체험으로 합짐 배수와 유입률을 재기 시작한다.
4·5·6 은 일을 시작하는 날부터 값이 쌓인다.

## 8. 지금 숫자를 쓸 때의 규칙

🔴 **픽커 요금 분포는 인용해도 된다.** 실물 앱에서 온 값이다. 다만 위 §2 의 조심할 것 다섯을 함께 적는다.

🔴 **인성·화물24 의 요금·콜 수는 인용하지 않는다.** 우리가 만든 배차망 시뮬레이터가 지어낸 값이다.

🔴 **「하루 N원 번다」를 실적으로 적지 않는다.** 아직 수행한 콜이 없다.
추정이라고 쓰고, 무엇을 전제했는지 함께 적는다.

🔴 **체험으로 낸 숫자에는 「경쟁 제외 상한선」을 함께 적는다.** 잡기 성공률이 빠져 있다 (§6-②).
