# [계획] 상세의 필수 요소는 전체 주소 — 채우기·사진·탈락이 전부 «요소에 값이 있는가»에서 나온다

기사님 확정 (원문 요지):
- *"상세페이지에 진입하고서는 모든 주소(상차지·하차지)를 다 가지고 있어야 한다. 필수 요소다 — 배차망에 따라 달라질 수 없다."*
- *"판정할 콜로 서버에 올라갈 상세화면 데이터에 짧은 주소가 아니고 전체 주소가 들어가도록 룰을 바꾸자."*
- *"모든 정보를 각 배차망이 정한 플러그인으로 해결한 후 값이 모두 채워지지 않았다면 그 콜을 버린다."* · *"'누른 그 콜인가' 확인은 공통으로."*
- 전체 주소 판정 = 명부 대조. **명부 원천 = 서버 지도 산출물(shared DONG_CENTROIDS)** — 전국 확대는 지도 확장과 함께. 도로명 주소는 전체로 인정.
- 서버는 앱이 올린 상차·하차를 그대로 믿는다 — *"복잡하게 하지 말고 그냥 삭제해서 에러가 나는 것이 수정하기 쉽다"* → 옛 앱 폴백 없음.
- 도보 콜도 상세 뒤에는 하차 전체 주소 필수 — 없으면 탈락.
- 인성 적요 팝업은 늘 연다(적요 제외 단어·주의 동네 검사의 재료) · 상차지거리 읽기는 공통, 배송거리는 인성 플러그인만.

## 바꾸는 모습 — 상세 화면의 공통 순서

```
① 글자 읽기 → 요소별 파싱 (플러그인 parseDetailElements — 목록 줄 값과 병합)
② 필수 요소 대조 — 전체 주소(상차·하차) · 요금. 판정은 AddressForm(아래)
③ 모자라면 채운다 — 그 배차망의 수단. 인성은 목록에 전체 주소가 없어 ③이 늘 켜진다(팝업 3장 — 부분 실행은 만들지 않는다). 적요는 늘: 제외 단어·주의 동네 재료
④ 그래도 모자라면 사진 — 사진 파서가 있는 배차망만(지금 픽커). 없으면 탈락
⑤ 필수 요소 최종 대조 — 모자라면 탈락(보내지 않고 목록으로 · 이상 징후 보고). 도보도 하차 필수
⑥ «누른 그 콜인가» 공통 검증 — 얻은 전체 주소 ↔ 찍은 목록 줄(동 토막, 픽커 matchDong 공통화). 불일치 = 탈락 + DETAIL_MISMATCH 보고. 손으로 연 상세(찍은 줄 없음)는 건너뜀. ⚠️ 인성 쪽 대조는 시뮬 글자 기준 — 실물 인성 후 재검산
⑦ 조건 재검 (passesFilterAfterFill)
⑧ 보고 — 서버에 올라가는 상차·하차는 항상 전체 주소. 픽커는 admin 뒤에 place(건물명 — 사진 파서가 이미 읽음)를 붙여 지오코딩 정밀도를 지금과 같게 한다
```

- ⑥ 주의: 옛 결정 «찍은 카드는 상세에서 되찾지 않는다»는 **식별**(어느 콜인가)이고 ⑥은 **검증**(그 상세가 맞나) — 주석으로 갈라 적는다
- 승격/«미확인» 층은 없다 — 전체 주소는 필수다

**전체 주소 판정 (AddressForm — 공통 한 벌)**
- 시·군·구 대조 + (그 시군구의 읍·면·동·리·가 — 뒤 숫자·N동 접미는 접어 대조 — **또는** 도로명 꼴 «…로/…길 + 번지»)
- ⚠️ 명부의 시군구 키는 두 토막이다 — 서울은 «서울 영등포구», 경기는 광역 없이 «성남시 수정구» 꼴. 대조는 «시+구» 연속 토큰으로, 광역 접두(픽커 admin «경기 성남시 수정구 …») 유무 양쪽 사례를 검사에 넣는다
- 구가 있는 시는 **구 없이 «시 + 동»도 전체로 인정**(그 동이 그 시의 어느 구엔가 있으면 — 부천처럼 실제 주소에 구가 빠지는 시 실측). 광역시는 인정하지 않는다 — 같은 동 이름이 여러 구에 있다 (구현 중 실측으로 더한 완화 · ab 승인)
- 🔴 명부 밖 지역(대구·부산 등) 상·하차 콜은 상세에서 탈락 — 기사님이 수용하신 한계. 전국 확대는 지도 확장과 함께
- **명부는 앱에 굳혀 넣는다 (ab 판단 «가»)** — 이름만 30~40KB 를 생성 Kotlin 상수로. 다운로드·버전 게이트·«명부 없음 = 탈락» 창이 통째로 없어진다.
  짝 관리: dongCentroids 생성기가 TS·Kotlin 두 파일을 함께 뽑고, 두 내용이 같은지 무는 검사 하나. 지도를 늘리면 앱도 새로 깐다(폰 설치는 일상).
  dongCentroids.ts 머리 주석(«실물 필터는 이 파일을 쓰지 않는다»·«시군구(광역 포함)» — 경기엔 광역이 없다)도 같은 커밋에서 고친다

**목록 완독 칸** — 상차·하차(예외 인자)·요금(지금 그대로) + **상차지거리 공통 추가**(listComplete — 상세 요건과 분리).
- 이것은 거르는 게 아니라 **미루는 것**이다 — 덜 읽힌 줄은 그 스캔만 빼고 다음 스캔에 다시 본다(⑤-2 «모르는 값으로 떨어뜨리지 않는다»와 부딪히지 않는 까닭)
- «모름=통과» 삭제의 실제 변화는 **픽커(:476) 하나**다. 인성 :385·24시 :350 은 옛 서버 폴백의 죽은 길이라 걷어도 동작 불변 — 갈라 적는다
- ⚠️ 인성·24시 목록 줄에 거리 칸이 «늘» 있는지는 시뮬로만 확인됐다(실물 확인 전) — 실물에서 거리 없는 줄 종류가 발견되면 완독 칸에서 뺀다
- 배송거리는 인성 플러그인의 조건 재료로만(못 읽으면 단가 조건만 생략). **24시의 죽은 단가 가지는 걷지 않고 둔다** — «아직 안 읽는다» 주석이 실물 후 붙일 자리의 표시다. 주석에 기사님 확정(«24시 목록엔 상차지거리만») 한 줄만 보강

**인성 팝업 파싱의 이동과 서버 추출 삭제 (폴백 없이)**
- parseLocationDetails 의 «위치» 추출을 인성 플러그인으로(InsungPopupAddress — DONE 직후 order 에 넣음). 나머지 팝업 파싱(연락처·적요)은 서버에 남는다
- 서버 삭제 목록: promoteDetailAddresses(parser.ts:277) · **OrderEvaluator.ts:90 의 호출** · 픽커 분기(detail.ts:74-80 + pickerDetailText.ts). ⚠️ detail.ts 의 parseLocationDetails 호출은 **남긴다** — 주소 승격은 사라졌지만 전화번호·고객명 추출을 dispatchEngine(전화·장소)과 관제웹 경로 카드가 읽는다(«연락처·적요는 서버에 남는다» 문장이 이긴 것 · «위치» 값은 앱이 넣는 pickup 과 같은 문자열이라 중복 계산이 아니다). dispatchEngine.ts:629·645 는 폴백이 이미 있어 그대로 맞다
- 🔴 **배포 순서**: 앱(전체 주소 탑재) 설치가 서버 삭제 push 보다 먼저 — push 는 기사님 지시·운행 확인 규칙 그대로

**이번에 하지 않는 것** — 인성 팝업 부분 실행(위 ③) · 24시 사진 파서·상세 판별·단가 가지(실물 후) · 전국 명부(지도 확장과 함께).

## ⑤ 이 수정이 기사님 하루에 무엇을 하나

- **좋은 콜**: 관제웹 콜 주소가 전부 전체 주소(픽커는 건물명까지)가 되어 판정 좌표·색을 믿을 수 있다. 엉뚱한 상세가 걸러진다
