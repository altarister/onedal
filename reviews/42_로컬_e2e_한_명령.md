# 42. 로컬 e2e 한 명령 — 모의 주행(`pnpm drive`)에 «e2e» 모드를 붙여 통신 고리 · 주행 · 화면을 한 번에

기사님 말씀:
- *"로그인은 잘 되는지 서로 통신은 잘 되는지 배포하지 않아도 로컬에서 다 확인하고 올리고 싶어 근데 지금은 그럴 수가 없어 뭐 수정만 하면 거기에 따라 다른 것들이 문제가 발생하거든."*
- *"통신뿐만 아니고 모의 주행까지 자동으로 해 볼 수 있으면 좋겠어."*
- *"그냥 테스트하고 싶을 때를 이야기하는 건데 난."* — push · 배포와 잇지 않는다. 원할 때 한 명령.

(관제 onedal-69 리뷰 반영판 — 새 스크립트를 만들지 않고 drive 에 붙인다)

## 끝의 모습

> `cd onedal-web && pnpm drive e2e` 한 번이면, 폰 · 실서버 없이 내 PC 에서
> ① 통신 고리(로그인 · 폰 연결 토큰 · 계정 막힘 · 관제웹 세션 충돌 · 원달앱 보고 답의 결재 전달 · 운영센터)
> ② 모의 주행(지금 drive 그대로 + 목적지 필터)
> ③ 관제웹 · 운영센터 실제 화면 사진(하얀 화면 없음 · 소켓 붙음)
> 이 차례로 돌고, 끝에 «✅/❌ 한 줄씩 + 사진 경로»가 나온다. 떠 있는 `pnpm dev`(4000) 와 local.db 는 건드리지 않는다.
> 평소는 카카오를 끄고 돈다(돈 · 인터넷 없음). «판정 색까지» 보고 싶을 때만 카카오를 켜고 호출 수를 센다.

## 지금은 이렇게 돈다 [관제 리뷰 · 코드로 본 것]

| 검사 | 덮는 것 | 빠진 것 |
|---|---|---|
| `pnpm drive` | 빈 DB · 전용 포트(4014) · 기기를 DB 에 직접 넣음(drive.mjs:177-182) · 관제웹 소켓 → 판정(order-evaluated) 기다림 → KEEP(decision ORDER_CONFIRMED · :204-216) · GPS 재생으로 경로 순서 · 도착 감지 · 궤적 | 원달앱 화면 보고 `/api/scrap` 과 그 답의 결재 · «받았음» · 폰 연결 번호/토큰 · 계정 막힘 · 관제웹 세션 충돌 · 운영센터 · 실제 화면 · 목적지(지리 판정) |
| `pnpm scenario` | 우회 로그인 · 선점/상세 보고(`/api/orders/*` · MANUAL 이라 결재 없이 KEEP) · 콜 생애 6단계 · 장부 | `/api/scrap`(scripts 전체 grep 0) · 씨앗이 local.db · 카카오가 필수(scenario.mjs:715 «실제 카카오 경로를 계산했다») |
| `pnpm shot` | 다른 웹 · API 포트를 받아 화면을 찍고 화면 값을 물을 수 있음(shot.mjs:42-43 · :151-160) | 판정이 없다(사진만) |

- **카카오**: 시험 서버는 기동 때 `server/.env` 를 스스로 읽는다(index.ts:60 dotenv). 그래서 drive 도 키가 있으면 실제 카카오를 부른다(OrderEvaluator.ts:221). 끄려면 서버 env 에 `KAKAO_REST_API_KEY: ''`(빈 값 — dotenv 는 이미 있는 값을 안 덮는다). 키가 없으면 판정은 죽지 않고 «API KEY 부재 · 판정 불가»로 넘어가고(OrderEvaluator.ts:842-890), 방문 순서는 카카오 없이 짜진다. drive.mjs 머리말의 «카카오 키 불필요»는 «없어도 돈다»이지 «안 부른다»가 아니다 — 같이 바로잡는다.
- **화면**: 시험 서버는 같은 포트에서 관제웹 빌드 결과(`client-app/dist` · index.ts:186-195)를, 주소가 `ops.` 로 시작하면 운영센터 빌드 결과(hostStatic.ts)를 내준다. 관제웹 vite 미리보기는 4000 으로 붙고(프록시 고정) 두 앱이 4173 으로 부딪혀 쓰지 않는다.
- **운영센터 허락**: 우회 로그인 계정에는 승인만 붙고 운영센터 허락은 없다(auth.ts:264 · :293). 켜는 문은 허락 있는 사람만 열려 닭과 달걀 — 시험 DB 에 직접 한 줄 쓴다(ops/CLAUDE.md 와 같다).

## 바꾸는 것 — drive 에 «e2e» 모드 (새 스크립트 없음)

`onedal-web/CLAUDE.md` «새로 만들기 전에 표에서 찾는다» — 서버 띄우기 · 우회 로그인 · 판정 기다림 · KEEP 이 이미 drive 에 있어 인자로 붙인다(새 스크립트면 서버 띄우기가 세 벌).

**1. 통신 고리 — `pnpm drive e2e` 의 앞부분**
각 줄 ✅/❌ · 끊긴 줄에서 멈추고 까닭.
1. 로그인 — 우회 로그인 → 토큰 · `/api/join/me`
2. **폰 연결 토큰** — 연결 번호 발급(`/pin`) → 붙이기(`/pair`) → 받은 토큰을 실어 보고 → 서버가 «토큰 확인됨» 길을 탐. 지금 drive · scenario 는 토큰 없이 보고해(deviceAuth.ts:64-67 «이번 단계는 통과») «토큰 필수»로 바뀌는 날 다 깨진다 — 그 길을 미리 덮는다.
3. **계정 막힘** — 시험 DB 에 승인 전 · 정지 계정을 하나 써 두고: 폰 보고 · 연결 번호 · 붙이기 · 관제웹 소켓 네 곳이 같이 막히는지(accountGateOf · webAccountGate). «진행 중 콜 끝난 뒤 정지»는 진행 콜 있음/없음 두 갈래.
4. **원달앱 보고 답의 결재 전달** — 원달앱인 척 `/api/scrap`(목록) → 답에 모드 · 필터 판 · 필터 본문 → 선점 보고 콜이 관제웹에 «심사 중» → (카카오 꺼짐이면 «판정 불가»로 와도 다음으로) → KEEP → 다음 `/api/scrap` 답에 결재가 실림 → «받았음»(ackDecisionId)을 실은 다음 답에서 사라짐(scrap.ts:182-200).
5. **운영센터** — 관리자(시험 DB 에 운영센터 허락)로 `/api/ops/calls` 에 그 콜 · `/ops` 소켓이 «콜 바뀜»을 받음.
6. **관제웹 세션 충돌** — 같은 계정 소켓 둘째가 «다른 기기에서 접속» 대기에 걸리는 길(socketHandlers.ts:137-209)이 지금 동작대로 가는지. 이 길을 덮는 검사는 지금 없다.

**2. 모의 주행 — 지금 drive 그대로 + 목적지 필터**
- e2e 모드에서는 목적지가 든 필터를 시험 DB 에 심고 돈다 — «지리» 판정 줄이 로그에 찍히는지까지. 인자 없는 `pnpm drive` 는 지금과 같다.

**3. 화면 — 시험 서버가 내주고 shot 이 찍는다**
- 관제웹 · 운영센터를 먼저 빌드한다. **빌드가 exit 0 일 때만** 다음으로 — 낡은 dist 를 찍는 함정(오늘 `tsc -b` 실패를 못 보고 옛 dist 로 관제앱을 깐 일과 같은 꼴)을 막는다.
- `pnpm shot` 을 시험 서버 포트로 불러 `http://localhost:<포트>` · `http://ops.localhost:<포트>` 를 폰 폭으로 찍고, 화면 값(하얀 화면 아님 · 오류 경계 빨간 상자 없음 · 소켓 연결됨)을 묻는다.
- 🔴 화면은 통신 고리 6 이 끝난 뒤, **검사 소켓을 닫고** 연다(같은 우회 계정이면 둘째 연결이 세션 충돌 대기에 걸려 «연결됨»이 안 뜬다). 또는 화면 전용 계정으로 연다.

**4. 카카오 두 갈래**
- 기본 `pnpm drive e2e` — 서버 env `KAKAO_REST_API_KEY: ''`. 통신 · 순서 · 화면만 본다(판정 색은 «판정 불가»).
- `pnpm drive e2e kakao` — 키를 켜고, 끝에 시험 DB 의 카카오 사용량 표(`kakao_usage_days`) 합을 적는다.

**5. 끝 장 · 표**
- «✅/❌ 한 줄씩 · 걸린 시간 · 사진 경로 · (켰으면) 카카오 호출 수». 실패면 그 단계의 서버 로그 끝 몇 줄.
- `onedal-web/CLAUDE.md` 스크립트 표의 drive 줄에 «e2e 모드»를 더한다(잡는 것 · 못 잡는 것 · 검수). drive.mjs 머리말의 카카오 문장도 바로잡는다.

## 하지 않는 것

- push · 배포 훅(기사님 «테스트하고 싶을 때») — reviews/41 은 미룸.
- 새 스크립트 · 카카오 가짜 응답 장치(키 끄기로 충분) · vite 미리보기.
- 원달앱 실물 · 폰(`e2e:app`) · 구글 로그인(우회 로그인만) · 시뮬레이터 개별콜 길(개발 빌드 전용 · 덜 급함) · 소켓 재연결(깊이 안 봄).
- scenario 고치기(local.db 씨앗 · 카카오 필수는 그대로).

## 확인 못 한 것

- shot 이 `ops.localhost:<포트>` 로 운영센터를 여는지(크롬은 `*.localhost` 를 내 PC 로 돌린다고 알고 있음) — 1단계 3번을 만들 때 첫 실행에서 본다.
- 원달앱인 척 `/api/scrap` 을 보낼 때 서버가 그 기기를 «결재를 기다리는 콜이 있는 기기»로 잇는 조건(선점 보고의 deviceId 가 같아야 하는지) — 1-4 를 만들 때 코드에서 읽어 맞춘다.
- 운영센터 빌드 시간(관제웹과 비슷할 것으로 봄).
