# 39. 관제웹이 없으면 확정만 안 누른다 — 38 을 작게

38 의 방향(«되돌릴 수 없는 누름은 확정 하나 · 이미 있는 통신으로 막는다»)은 그대로 두고, 막는 것 대비 큰 부분을 덜어낸 판이다.

기사님 말씀 (38 에서):
- *"관제앱이 준비되지 않았는데 사용성(접근성)이 켜져서 그냥 콜을 잡아 버리면 사고 날 가능성이 아주 큰 것 같아."*
- *"중간에 관제앱이 꺼질 수도 · 통화한다고 다른 화면으로 넘어가 있을 수 있는 것까지 고려해야 할 것 같아."*
- *"그럼 경쟁력이 없어진다 · 다른 기사가 다 가져가 버린다."*
- *"발열이나 기타 등등 때문에 이 방법(HTTP 폴링)을 쓴 거야 · 기사의 룰과 습관으로 해도 그리 치명적이지 않은 거 아닌가?"*

## 끝의 모습

> 원달앱은 지금처럼 목록을 읽고, 알람을 내고, 상세를 연다 — 누를 때마다 서버에 묻지 않는다.
> 확정(계약)을 누르기 직전에만, 이미 받아 둔 서버 답의 «관제웹이 지금 붙어 있나»를 본다. 안 붙었으면 확정하지 않고 상세에서 나온다.
> 관제웹이 뒤에 있어도(통화 중) 소켓이 붙어 있으면 잡는다.
> 미뤄 찍기는 발사하는 순간 화면이 예약 때와 다르면 쏘지 않는다.

## 바꾸는 것 — 셋

**1. 서버 — 화면 보고 답 맨 위에 `webAttached` 한 칸**
- 그 기사의 `activeWebSession` 이 있으면 `true`. 저장하지 않고 그때그때 읽는다(규칙 ③).
- `evaluatingNow` 와 같은 자리 · 같은 꼴. 필터 판 글자에는 넣지 않는다(순간 상태라 판이 흔들린다).
- 끝: 서버 검사 — 관제웹 소켓이 있으면 `true` · 없으면 `false` · 필터 본문이 생략된 답에도 칸이 있다.

**2. 원달앱 — 확정 직전 확인 하나 (🔴 운행 바뀜)**
- 답이 올 때마다 마지막 `webAttached` 를 메모리에 적는다(폰 저장소에 안 씀 — 새로 뜨면 비어 있고, 그때는 모드가 «직접»이라 어차피 안 누른다).
- `PreConfirmSequence` 의 «앱이 계약하는 콜»을 정하는 자리, **선점 보고 앞**에서 본다.
  - `true` → 지금처럼 선점 보고 → 확정.
  - `false` → 확정도 선점 보고도 하지 않고, 지금 «2차 필터 탈락»과 같은 길로 상세에서 나온다. 선점 보고를 먼저 보내면 서버에 심사 줄이 남기 때문에 앞에 둔다.
  - 칸이 없다(옛 서버) → 지금처럼 누른다.
- 기다리지 않는다 — 상세 진입 뒤 답이 아직 안 왔으면 그 앞의 마지막 답을 쓴다.
- 로그 한 줄: «🔐 [확정 안 누름] 관제웹 없음 — 상세에서 나온다»(#결재).
- 같이: «첫 답 전 모드 = 직접» · «직접이면 목록 안 누름»을 원달앱 단위 검사로 잠근다(코드 동작 무변화 · 지금 지키는 검사가 없다).
- 끝: 원달앱 단위 검사 — 붙음 → 누름 · 안 붙음 → 안 누름 · 칸 없음 → 누름 · 확인이 선점 보고 앞 · 첫 답 전 모드 «직접». 폰 시험: 시뮬레이터 인성 자동에서 관제웹을 닫고 콜을 띄우면 «🔐 [확정 안 누름]»으로 나오고 서버에 선점 보고가 안 간다 · 관제웹을 열면 지금처럼 확정.

**3. 원달앱 — 미뤄 찍기 화면 확인 + 마지막 우회 누름 하나 (🔴 운행 바뀜 · 드묾)**
- 미뤄 찍기를 예약할 때의 화면(`screenNow`)을 적어 두고, 발사 때 화면이 다르면 쏘지 않는다 — «🛑 [찍기 취소] 미룬 사이 화면이 바뀌었다» 한 줄. 지금의 «늦게 깸 · 자리 바뀜» 취소와 같은 꼴이다.
- `HijackService.kt:1992` 의 뒤로 가기를 터치 관리자의 `performBack` 으로 옮긴다 — 자국 · 같은 누름 잠금 · «안 먹힘» 판정을 같이 탄다.
- 끝: 단위 검사 — 예약 때 목록 · 발사 때 다른 화면 → 안 쏨 · 같은 화면 → 쏨 / 원달앱 소스에서 `performGlobalAction` · `dispatchGesture` 가 `AutoTouchManager` 밖에 0.

## 기사님이 정하실 것 — 두 말씀이 부딪힌다

- 38: *"관제앱이 준비되지 않았는데 사용성이 켜져서 그냥 콜을 잡아 버리면 사고 날 가능성이 아주 큰 것 같아. 스캔앱과 싱크되기 전까지는 어떤 것도 클릭하면 안 될 것 같은데."*
- shared `resetToBaseFilter` 주석의 말씀: *"아침에 출근 시 필터 설정 없으면 그냥 디폴트 값으로 콜을 잡는 거고."*

지금 코드는 뒤의 말씀대로 돈다. 그래서 서버가 밤새 켜져 있던 보통 아침에는, 관제웹이 붙기 전에도 원달앱이 기본 설정으로 목록을 누르고 상세를 연다. 위 2 가 확정은 막지만 목록 누르기 · 알람 · 상세 열기는 돈다.

- 가: 지금처럼 기본 설정으로 잡는다 — 확정만 2 로 막고, 목록 누르기는 습관(«관제앱을 켠 뒤 배차망을 연다»)에 맡긴다. 코드 무변화.
- 나: **«오늘(영업일) 관제웹이 한 번도 안 붙었으면»** 서버가 콜 잡기를 잠근다(`appFilter` 잠금 넷에 하나 더). 한 번 붙은 뒤의 순간 끊김에는 안 걸리므로 위 «하지 않는 것» 넷째 줄의 걱정(새로고침에 콜을 놓침)은 생기지 않는다. 대신 아침에 관제웹을 켜야 콜 잡기가 시작된다 — 뒤의 말씀(«디폴트로 잡는다»)을 «관제웹을 켜면 디폴트로 잡는다»로 바꾸는 것이다.

추천: **가**. 2 로 되돌릴 수 없는 일(확정)은 이미 막히고, 남는 것은 상세를 한 번 열었다 닫는 것뿐이라 습관으로 충분하다. «나»는 관제웹을 잊고 출근한 날 아침 콜을 통째로 놓친다.
