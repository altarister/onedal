# 43 · 운영센터 회원 화면 — 오늘 «안 잡은 콜» 보기

기사님 말씀: «운영센터에서 회원에서 알타리를 선택하면 내가 오늘 잡지 않은 콜(알림이든, 체험이든, 자동이든)들을 볼 수 있으면 좋겠어» · «그 콜이 어떤 필터로 올라왔고 무슨 색에 몇 점을 받았는지도 알 수 있으면 좋겠는데».

## 1. 지금은 이렇게 돈다 (센 것 · 실서버 알타리)

| 경우 | 장부에 남나 | 콜 내용(상차 · 하차 · 요금) | 색 · 점수 | 그때의 필터 | 최근 건수 |
|---|---|---|---|---|---|
| 알림 · 손으로 연 미리보기(판정은 받고 안 잡음) | 판정 표(`order_judgments`)에만 | **없음** — 픽커면 `intel` PICKER_DETAIL 에 따로 있으나 **잇는 id 칸이 없음**(시각 ±60초로 9/9 짝지어짐 · 어림) | 있음(색 · 점수 · 축별 까닭) | **없음** | 09-30 5 · 10-01 1 · 10-03 3 (9월 중순엔 하루 18~43) |
| 체험 콜 | 판정 표에만 | **없음** — 세션 메모리뿐 · 서버 재시작이면 사라짐 | 있음 | 없음 | 최근 0 |
| 자동 — 잡았다가 무름(안전취소 · 시간 초과 · 방출) | `orders` + 판정 표 | 있음 | 있음 | 없음 | 7일 0 (지금까지 안전취소 175 · 방출 47) |
| 목록에서만 본 콜(판정 전) | `intel` INTEL_BULK | 있음 + 앱 필터가 거른 까닭(`verdict`: 요금 · 상차 · 예약 · 지역) | 판정 전이라 없음 | 걸린 까닭만 | 09-30 511 · 10-03 665 |

- 운영센터 회원 화면의 «오늘 콜» 칸은 `orders` 만 읽는다(`ops.ts` `todayCallsOf`) → 미리보기 · 체험은 안 보임. «🗑️ 버린 콜» 상자(목록에서만 본 콜)는 이미 있으나 최근 N건 · 날짜 거르기 없음.
- 판정 표 detail 에는 축(돈 · 노동강도 · 운전 · 콜 대기 · 지리 …)별 점수와 까닭 글이 있다 — «무슨 색에 몇 점 · 왜»는 지금 장부로 된다.
- **그때의 필터**는 어디에도 콜마다 남지 않는다. 하루 결과 표(`filter_day_results.settings`)에 하루 한 벌뿐이라, 하루 중 필터를 바꾸면 어느 콜이 어느 필터였는지 못 가린다.

## 2. 무엇을 만드나 (안)
- **가 — 기존 장부만으로**(새 저장 칸 없음): 운영센터 회원 화면에 «오늘 판정 받은 콜» 목록 = 판정 표 오늘 줄 전부 · 줄마다 색 · 점수 · 축 까닭 · 잡았나(orders 상태: 확정 / 무름 / 방출 / 없음=안 잡음). 콜 내용은 orders 에 있으면 그것, 없으면 픽커 `intel` 을 시각으로 어림 짝(어림 표시) · 체험 콜은 «내용 없음». 필터는 «그날 설정»만.
- **나 — 판정 때 한 줄 더 남김**(🔴 새 저장 칸 · 기사님 합의): 판정 표에 콜 내용(상차 · 하차 · 요금 · 배차망 · 미리보기/체험 표시)과 **그때의 필터 요약**(목적지 · 상차 반경 · 하차 목록 이름 · 필터 판 번호)을 같이 쓴다. 그러면 미리보기 · 체험까지 내용 · 필터가 정확히 남는다.
- 추천: **나**. 기사님이 물으신 «어떤 필터로 올라왔나»는 가로는 답할 수 없고, 콜 내용도 어림 짝에 기댄다. 새 칸은 판정 표 한 곳이고 쓰는 곳도 판정 저장 한 곳(`OrderRepository` 판정 저장)이다.

## 3. 새 설정값 · 새 저장 칸의 다섯 (나 를 고르시면)
| | |
|---|---|
| ① 스키마 | `order_judgments` 에 칸 더함(`ensureColumns`): `call_summary`(상차 · 하차 · 요금 · 배차망 · 미리보기 · 체험 — JSON 글) · `filter_summary`(목적지 · 상차 반경 · 하차 목록 이름 · 필터 판 번호 — JSON 글) |
| ② 값 | 판정 순간의 값 그대로 — 기본값 없음(없으면 빈칸 = 옛 줄) |
| ③ 시점 | 판정 저장 때 한 번 쓰고 안 바꿈(판정과 같이 «심사 1회 · 불변») |
| ④ 화면 | 운영센터 회원 상세 «오늘 판정 받은 콜» — 관제웹 화면 무변화 |
| ⑤ 읽는 곳 | 운영센터 회원 상세 하나(«이 콜이 왜 이 색이었나 · 그때 필터는») |

## 4. 순위 검산
- 가는 새 칸 없이 오늘부터 잡았다 무른 콜 · 판정 색은 보이나, 미리보기 · 체험 콜 내용과 필터가 비거나 어림이다.
- 나는 새 칸 둘이 생기지만 기사님 질문 셋(안 잡은 콜 · 어떤 필터 · 무슨 색 몇 점)에 모두 정확히 답한다. 옛 줄(오늘 이전)은 가처럼 보인다.

## 5. 기사님 하루에 무엇을 하나
- 좋은 콜 · 노이즈: 바뀌지 않음(보는 화면이 느는 것뿐 · 판정 · 필터 무변화).
- 기사님 손: 운행이 끝난 뒤 운영센터에서 «오늘 놓친 콜이 왜 그 색이었나 · 필터가 맞았나»를 한 화면에서 — 필터를 고칠 재료.
- 관제웹 화면 무변화 · 운영센터 화면만 늚.

## 6. 단계마다 끝 (나 기준)
1. 판정 저장에 두 칸 쓰기 — 끝: 서버 검사 «미리보기 · 체험 판정에도 콜 내용 · 필터 요약이 남는다» 빨간불 → 초록 · 못 잡는 것: 원달앱이 콜 내용을 덜 읽어 올린 경우
2. 운영센터 API «회원 · 날짜의 판정 목록»(판정 표 + orders 상태 + 옛 줄은 intel 어림) — 끝: 서버 검사 · 못 잡는 것: 어림 짝의 틀림
3. 운영센터 회원 상세 칸 — 끝: `pnpm shot` 으로 운영센터 화면을 찍어 눈으로 · `pnpm drive e2e` 운영센터 고리 초록
- 전체: 커밋 직전 게이트 한 번(관제웹 `tsc -b` · 운영센터 빌드 포함)

## 7. 찾음 (하던 일과 따로)
- 운영센터 «오늘 본 콜» 숫자는 실제로 «오늘 `orders` 행 수»(잡은 콜 + 무른 콜) — 이름과 다름.
- 하루 결과 표의 색 수는 미리보기 · 체험 판정까지 세고, 같은 함수의 취소 수는 `orders` 로 세어 셈 기준이 다름(`filterManager.ts:1443-1455`).
- 픽커 상세 `intel` 줄에 «수락했나» 칸이 없음.

## 8. c6 리뷰 반영
- 근거 확인: 판정 저장은 `OrderRepository` 한 곳 · detail = axes · gates · tags · stops(합짐 때 기존 콜 정거장 — 후보 콜 내용 아님) · unknownWhy · extraMin. 필터는 판정 시작 때 `snap.filter = { ...session.activeFilter }` 를 뜨므로 그 자리에서 쓸 수 있음.
- **다 (추천으로 바꿈)**: 새 DB 칸 대신 기존 detail JSON 안에 `call`(상차 · 하차 · 요금 · 배차망 · 미리보기/체험) · `filter`(목적지 · 상차 반경 · 최소 요금 · 차종 · 오늘만 여부 · 필터 판 · 하차 목록 개수)를 더해 쓴다. 스키마 무변화 · 쓰는 곳 한 곳. 저장 값이 느는 것이라 기사님 합의는 그대로 필요.
- 필터는 **서버가 판정할 때의 필터** — 원달앱이 걸러 올린 필터와 다음 보고까지(목록 15초 · 그 밖 60초) 한 판 어긋날 수 있음 → 화면에 «서버 필터 기준»이라 적고, 원달앱 필터 판이 실려 오면 «같음/다름» 한 칸.
- 여쭐 것 하나 더: 목록에서만 본 콜(판정 전 · 하루 500~600줄)도 넣을지.
