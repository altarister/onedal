# 41. 배포 전 자동 검사 — push 하면 GitHub 가 게이트를 돌리고, 초록일 때만 실서버에 배포한다

기사님 말씀: *"우리 프로젝트에 자동으로 돌아가는 e2e 테스트가 있으면 좋겠어 어떻게 뭘 만들 수 있는데 리서치 해봐"* → 조사 · 관제 리뷰 뒤 «A 먼저» → «배포를 검사가 초록일 때만» 에 *"가"*.

## 끝의 모습

> main 에 push 하면 GitHub 가 커밋 전 게이트(타입 검사 · jest · vitest · 감사 · lint · 시뮬레이터 검사 · 원달앱 단위 검사)를 돌린다.
> 모두 초록이면 지금과 같은 배포 스크립트로 실서버에 올린다. 하나라도 빨간불이면 **실서버에 손대지 않는다** — 실서버 코드는 옛 판 그대로 돈다.
> 손으로 배포를 다시 돌리는 길이 있고, 그때도 검사는 건너뛰지 않는다.

## 지금은 이렇게 돈다

| 무엇 | 지금 | 자리 |
|---|---|---|
| 자동으로 도는 것 | 배포 하나 — main 에 `onedal-web/**` · `onedal-sim/**` push 면 checkout → ssh 로 EC2 | `.github/workflows/deploy.yml` |
| 검사 | GitHub 에서는 없음. 게이트는 에이전트가 커밋 전에 지키는 규칙뿐(README «커밋 전 필수») | — |
| 실서버 안의 막힘 | 배포 스크립트가 실서버에서 `git reset --hard origin/main` 으로 코드를 먼저 바꾸고, 그다음 관제웹 빌드(`tsc -b && vite build`)가 실패하면 멈춘다(pm2 reload 안 함) | deploy.yml `[1/5]` · `[3/5]` |
| 그 막힘의 빈 곳 | 멈췄을 때 실서버 작업 트리는 이미 새 코드다 — 서버가 저절로 다시 뜨면(pm2 자동 재시작 · 실서버 재부팅) «새 서버 코드 + 옛 화면»으로 뜰 수 있다. 서버 검사(jest) · 시뮬레이터 · 원달앱 검사는 실서버에서도 안 돈다 | 관제 리뷰 |
| 손 배포 길 | 없음(workflow_dispatch 없음) | deploy.yml `on:` |

## 지금 값 대조 (10-06)

- 오늘 관제가 관제웹 타입 검사를 `tsc --noEmit -p .`(관제웹 tsconfig 는 `files: []` + references 라 아무 파일도 안 봄)로 돌려 «초록»이라 넣은 커밋이 push 뒤 실서버 빌드에서 멈췄다(검사 파일 타입 오류 넷 · 59c24e93 로 고침). 이 계획이면 push 직후 GitHub 에서 빨간불 · 실서버는 안 건드림.
- 오늘 GitHub 실행기 장애로 배포 #235 · #236 이 15분 대기 끝에 «The job was not acquired by Runner» 로 실패 — 검사를 앞에 붙이면 GitHub 의존이 커지므로 손 배포 길이 함께 필요하다.
- 검사가 기대는 파일: jest 는 일꾼마다 빈 DB(`tests/jestWorkerDb.js` — local.db 안 씀)라 GitHub 에서도 돈다. 원달앱 빌드에는 서명 설정이 없다(`app/build.gradle.kts`). 노드 24 · pnpm 10.29 · gradle 8.9 · JDK 11 대상.
- 확인 못 함: git 이 무시하는 파일(`ex_images/카카오픽커/실물_2026/` · `reviews/` · `local.properties`)에 기대는 검사가 있는지 — 검사 주석에는 그 경로가 여럿 나온다. **1단계 첫 실행이 이것을 드러낸다**(그래서 1단계는 배포와 잇지 않는다).

## 바꾸는 것 — 두 단계

**1단계 — 검사 워크플로를 따로 돌린다 (배포는 그대로)**
- 새 파일 `.github/workflows/check.yml`(있는 폴더 · 새 폴더 아님). 도는 때: main push · PR · 손으로(workflow_dispatch).
- 실행기 판 고정 `ubuntu-24.04`(10월 19일부터 `ubuntu-latest` 가 바뀐다는 공지 — 판이 바뀌어 빨간불이 나는 날을 우리가 고르게).
- 작업 셋(나란히 돎 · **비밀값을 안 읽음**):
  - 웹: 노드 24 · pnpm 10 · `onedal-web` 에서 `pnpm install --frozen-lockfile` → 서버 `tsc --noEmit` · 관제웹 `tsc -b` · 운영센터 `tsc -b` · `npx jest`(Test Suites 의 passed = total 을 스크립트로 확인) · `pnpm test:web` · `pnpm audit:dead` · `pnpm lint:gate` · `pnpm audit:docs` · `pnpm audit:socket`. `audit:docs` 가 HEAD 와 견주므로 checkout 은 전체 이력(fetch-depth 0).
  - 시뮬레이터: `onedal-sim` 에서 install → `tsc -b --noEmit` · `vitest run`.
  - 원달앱: JDK 17(gradle 8.9 실행용) · `./gradlew :app:compileDebugKotlin :app:testDebugUnitTest`. **`onedal-app/**` 또는 `onedal-web/shared/**` 가 바뀐 커밋에서만**(원달앱 검사가 shared 표를 읽는다 — `NetworkPagesPairTest` 등). 실행 시간을 아낀다.
- GitHub 에서만 나는 빨간불(무시되는 파일 · 환경 차이)은 고치거나, 그 검사 이름과 까닭을 이 문서에 적고 건너뛴다 — 조용히 빼지 않는다.
- 끝: main 에서 check 가 초록 · 원달앱 작업은 해당 파일이 바뀐 커밋에서만 돎 · 비밀값 없는 작업 · 배포는 지금과 똑같이 따로 돎.

**2단계 — 배포를 검사 뒤로 잇는다 (🔴 배포 동작 바뀜)**
- `deploy.yml` 의 내용(ssh 스크립트)은 그대로 두고, 검사 작업 뒤에 `needs` 로 잇는다 — 검사와 배포를 한 워크플로로 합쳐 같은 커밋을 두 번 돌지 않는다.
- 배포 작업이 도는 조건: main · push(또는 손으로) · 검사 작업 모두 성공 · **이번 push 에 `onedal-web/**` 또는 `onedal-sim/**` 가 바뀜**(지금 조건 그대로 — 원달앱만 바뀐 커밋은 배포 안 함). 바뀐 파일은 셸 한 줄(`git diff --name-only`)로 본다 — 바깥 액션을 더하지 않는다.
- EC2 비밀 키는 배포 작업에서만 읽는다.
- 손 배포(workflow_dispatch): 검사부터 다시 돌고 초록이면 배포. **«검사 건너뛰기» 입력은 두지 않는다** — 남이 고치는 파일 때문에 빨간불이면 고쳐서 올리는 것이 답이다. GitHub 자체가 멈춘 날은 실서버에서 손으로 배포한다(아래 습관).
- 끝: 일부러 빨간불을 낸 커밋을 **main 이 아닌 가지**에서 돌려 «검사 실패 → 배포 작업 건너뜀»을 본다(배포는 main 에서만이라 가지에서는 «조건 미충족»으로 건너뛰는 것까지 본다) · main 첫 push 에서 검사 → 배포 순서를 Actions 화면으로 본다.

## 순위 검산 — 지금과 나란히

| 경우 | 지금 | 바꾼 뒤 |
|---|---|---|
| 관제웹 타입 오류 커밋을 push(오늘 일) | 실서버가 코드를 바꾼 뒤 빌드에서 멈춤 — 실서버 작업 트리는 새 코드 · 서버는 옛 판으로 돎 | GitHub 에서 빨간불 · 실서버 손 안 댐 |
| 서버 jest 가 깨진 커밋 | 실서버는 jest 를 안 돌려 그대로 배포 · 운행 중 서버가 새 코드로 뜸 | 빨간불 · 배포 안 됨 |

| 원달앱만 고친 커밋 | 배포 안 됨(조건 밖) · 검사도 없음 | 원달앱 검사만 돎 · 배포 안 됨 |
| 문서만 고친 커밋(reviews 밖 · 웹 폴더 밖) | 아무 일 없음 | 검사(웹 · 시뮬레이터)가 돎 · 배포 안 됨 |

## 새 설정값 · 새 저장 칸 · 새 폴더

- 없다. 새 파일은 `.github/workflows/check.yml` 하나(1단계)이고, 2단계에서 그 안으로 배포 작업을 옮긴 뒤 `deploy.yml` 을 지운다(또는 deploy.yml 을 검사+배포 한 워크플로로 바꾸고 check.yml 을 지운다 — 2단계 때 하나로 정한다). 파일 지우기라 그때 여쭙는다.
- README 「짝이 있는 것」 · 「커밋 전 필수」에 «게이트 목록 ↔ check.yml» 짝을 한 줄 더한다(게이트를 더하면 두 곳). 검사로 물리게 하려면 «README 게이트 명령이 check.yml 에 다 있다»는 규칙 검사를 하나 둔다.

## 이 수정이 기사님 하루에 무엇을 하나

| | 기사님 |
|---|---|
| 좋은 콜 | 지킨다 — 운행 중에 깨진 서버가 배포돼 콜 잡기 · 판정이 멈추는 일을 구조로 막는다 |
| 노이즈 | 준다 — «배포가 빌드에서 멈춤» 같은 반쯤 된 배포가 사라진다 |
| 손 | 그대로 — push 는 지금처럼 기사님 말씀 뒤 · 직전 «운행 중이신가». 빨간불이면 에이전트가 고쳐 다시 올린다. GitHub 이 멈춘 날만 실서버 손 배포(아래) |

## 손 배포 — GitHub 이 멈춘 날

- `ssh onedal-live` → `deploy.yml` 의 스크립트를 그대로 한 줄씩(백업 → 코드 → 설치 → 빌드 → pm2 reload → health). 2단계 때 이 절차를 스크립트 한 장으로 레포에 둘지 정한다.

## 확인 못 한 것

- GitHub 무료 실행 시간 한도(비공개 레포면 한도가 있다) — 한 번에 몇 분 걸리는지는 1단계 첫 실행에서 잰다.
- git 이 무시하는 파일에 기대는 검사가 있는지 — 1단계 첫 실행에서 드러난다.
- 원달앱 단위 검사가 GitHub 의 안드로이드 SDK 로 그대로 도는지(compileSdk 35).
