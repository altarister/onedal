# [기획] 1DAL 운영센터 — 회원 · 앱 배포 · 유튜브 멤버십 (주소 하나로 다른 기사님이 1DAL 을 쓰게)

(파일 이름의 «어드민»은 첫 판의 이름이다 — 화면 · 폴더 · 서버 문은 **운영센터**로 부른다. 파일을 바꾸려면 옛 파일을 지워야 하니 기사님 말씀 뒤에.)

기사님 말씀 (원문):
- *"어드민 페이지를 만들꺼야."* → 쓰는 사람: **서비스 운영자**
- *"어드민 프로젝트 폴더 구조서부터 시작해야 할꺼 같은데? 다른 프로젝트와의 관계도 필요할꺼 같고.. 어떤걸 가지고 있을껀지 사용자에게 어떤 영향과 범위를 가질껀지. 일반적인 배차망이 가지는 그런 기능들이 필요해."*
- *"내가 다른 기사에게 url을 주고 거기에 구글 아이디 등록 하면 내 서비스를 쓸수 있어 이렇게 해야해 앱도 다운 받을수 있어야 하고 말이지. 그래 가입 기능도 있어야 해"*
- *"운전자가 보는 범위축소가 필요한 이유를 모르겠다. 인성이나 그런곳에서도 위치를 모두 알고 있고 기사 관리하고 있을꺼야. 그래야 정산을 해줄꺼고 … 나중에 월결제 같은 기능도 필요할꺼야.. 유료회원인지 무료 회원인지 등. 탈퇴, 가입등 기능도 필요할꺼고 이름이 어드민이면 안될꺼 같기도 하고.."*
- *"주선사 별점이나 상하차지 (상호명)(전화번호) 식별만 할수 있으면 되는거니 한글짜만 별표로 바꿔서 저장하면 문제 없을듯 한데."*
- *"유튜브 채널 하나 만들고 거기에 유료회원 하면 우리 서비스 쓰게 해준다. 이러면 될듯 한데.. 그 유튜브에 사용법 알려주고 하면.."*
- 콜을 회원끼리 넘기는 기능은 **없다** (기사님 «의미 없다»).

**전제** — 1DAL 은 «배차망 위에서 기사 한 명을 돕는 도구»가 아니라 **인성처럼 회원 기사를 관리하고, 위치 · 콜을 보는 플랫폼**이다. 배차망 계정은 각 기사의 것이고, 콜은 각자 원 배차망 안에서 잡고 끝낸다. **회원 = 유튜브 채널 멤버(모두 유료)**.

**끝의 모습 (이 계획서 전체의 «무엇이 참이면 끝인가»)**
> 기사님이 처음 보는 기사에게 주소 하나를 보낸다 → 그 기사가 유튜브 채널 멤버가 되고, 구글로 가입하고 동의하고 → 운영자(기사님)가 운영센터에서 멤버를 확인해 승인하고 →
> 그 기사가 같은 주소에서 앱 두 개를 받아 설치하고 → 유튜브 사용법 영상과 화면 안내만 따라 연결을 마치고 → 자기 필터로 첫 콜을 받고 →
> 운영자는 회원의 위치 · 콜 · 폰 상태를 본다.
> **그 사이에 개발자 PC · adb · DB 손질이 한 번도 없다.** 두 기사는 운영자가 아니면 서로의 콜 · 위치 · 거래처를 못 본다.

## 🔴 만드는 것과 여는 것은 다른 문이다 — 인성이 하는 일에는 자격이 있다

인성이 기사 위치를 보고 정산하고 배차하는 것은 **사업자 + 주선 허가 + 위치 신고**를 가진 구조이기 때문이다(인성 프로그램을 쓰는 주선사가 주선 허가를 가진다). 1DAL 이 같은 일을 하려면 같은 자격이 필요하다. **코드는 지금부터 다 만들 수 있고, 다른 기사를 받는 날은 자격 뒤다** (onedal-ab · 1f · 04 — 법률가 아님, 방향만. 확정은 법률 검토).

| 자격 · 조건 | 언제 필요한가 | 없어도 만드나 | 없으면 여나 |
|---|---|---|---|
| 사업자등록 · 소득 신고 | 아래 전부의 전제. 유튜브 멤버십 수익도 기사님 소득이다 | 만든다 | 다른 기사에게 못 연다 |
| 개인정보 처리방침 · 동의 | 남의 정보를 받는 첫날 | 만든다 | 못 연다 |
| 위치기반서비스사업 신고 | 회원 위치를 받아 운영자가 볼 때 | 만든다 | 위치 기능은 못 연다 |
| 위치정보사업 허가 | 위치를 모아 **남에게 제공**할 때 — 이 설계에는 그런 모양이 없다(운영자 열람뿐). 해당 없음 쪽 · 검토 한 줄 | — | — |
| 화물자동차운송주선사업 허가 | 1DAL 이 콜을 배정 · 중개하거나, 운임을 받아 정산하거나, 수수료를 받을 때 — **이 설계에는 그런 기능이 없다** | — | — |
| **유튜브 채널 멤버십 문턱** | 파트너 프로그램 자격(구독자 수 등 · 만 18세 · 경고 없음) | 만든다 | 결제(=회원)를 못 연다 |
| **유튜브 멤버십 혜택 정책 검토** | 멤버 혜택으로 «외부 앱 이용권»을 주는 것 — «우회 판매»로 볼 여지가 있어 **확실히 된다고 말할 수 없다.** 어긋나면 채널이 멤버십을 잃는다 | 만든다 | 검토 전 못 연다 |
| 통신판매업 신고 · PG · 청약철회 · 환불 | 판매자가 유튜브라 **사실상 없어진다** — «외부 앱 이용권 판매»라는 실질이 모호해 법률 검토 한 줄 | — | — |
| 전자금융(정산 대행) | 기사 간 운임을 1DAL 이 받아 나눠 줄 때 | — | **하지 않는다 — 설계에서 뺀다** |

여는 순서: **사업자 → 개인정보 · 위치 신고와 동의 → 유튜브 채널 멤버십(문턱 · 정책).** 이 표 위의 문이 열리기 전에는 기사님 계정과 시험 계정으로만 돈다.
⚠️ 유튜브 채널이 정지되면 **모든 회원의 이용권이 한 번에 멈추는 단일 실패점**이다 — 약관에 «결제 · 환불은 유튜브 규정, 서비스 중단 · 장애 때의 처리는 1DAL 약관»으로 나눠 적는다 (ab).

## 2. 층 넷과 폴더 구조

| 층 | 누가 · 어디서 | 하는 일 | 폴더 |
|---|---|---|---|
| ① 현장 | 기사 폰 | 원달앱(배차망 읽기 · 알림 · 잡기) · 관제앱(결재 · 위치) | `onedal-app` · `client-app`(Capacitor) |
| ② 기사 개인 | 기사 폰 · 브라우저 | 관제웹(판정 · 결재 · 필터) · 운행일지(**개인 정산**) | `client-app` · `logbook` |
| ③ **운영** | 운영자 PC | 회원(가입 · 멤버 확인 · 승인 · 허락 · 정지 · 탈퇴) · 위치 · 콜 · 공지 · 앱 배포 · 이상 기록 · 통계 · 열람 기록 | ✚ `onedal-web/ops` — **새 폴더는 이 하나** |
| ④ 공통 | 서버 | 판정 · 세션 · 회원 자료의 한 출처 · 규격 | `server` · `shared` |

정산은 둘이다 — 기사 개인 정산(운행일지, 이미 있음)과 회원비(유튜브가 받는다 · 운영센터는 기한 대조만). 정산 폴더는 따로 만들지 않는다. 운행일지는 손대지 않는다.

### 어디에 두나 — 순위 검산 (Q3)

| 자리 | 로그인 | 실서버에 올라가나 | 관제웹 폰 앱이 무거워지나 | 규격(shared) 공유 | 순위 |
|---|---|---|---|---|---|
| **`onedal-web/ops/`** (작업 공간에 한 칸 더) | 같은 구글 로그인 · 같은 서버 | 예 — `deploy.yml` 에 빌드 단계 하나 | 아니요 — 따로 빌드 | 예 | **1** |
| 관제웹 안 `/ops` | 같다 | 예 | 한 앱에 두 사용자층이 섞인다 | 예 | 2 |
| 최상위 `onedal-ops/` | 새로 | 배포 새로 | 아니요 | 작업 공간 밖 — shared 가 바뀔 때 함께 깨지는 것을 검사가 못 잡는다 (`deploy.yml` 이 `onedal-sim` 을 따로 빌드하다 폴더를 못 찾은 적이 있다) | 3 |


- 새 폴더는 `onedal-web/ops/` 하나다. 만들면 같은 커밋에서 README 「구성」 에 한 줄(`layoutListed`) · 「포트」 에 3002 한 줄(`portsListed`) · `pnpm-workspace.yaml` 에 한 줄.
- `deploy.yml` 은 `client-app` 만 빌드한다(99줄). **운영센터 빌드 단계를 따로 넣고, 실패하면 `onedal-sim` 처럼 건너뛰고 기사용 서버는 올린다** (04).
- 🔴 `deploy.yml` 의 올리기 조건(`onedal-web/**`)이 이 폴더도 덮는다 — **운영센터만 고쳐 push 해도 실서버가 다시 뜬다.** «운행 중 배포 금지»가 여기에도 걸린다.
- 서버 밖에서 할 일: `ops.altari.com` DNS · 그 주소의 HTTPS 인증서(8장 ⑧ 과 같은 곳) · 구글 콘솔 «승인된 자바스크립트 원본»에 그 주소.
- 운영자와 기사 사이 경계는 **서버가 지킨다** — 폴더를 떼어 내도 경계는 늘지 않는다.

## 5. 사용자에게 주는 영향과 범위

| 누가 | 할 수 있는 것 | 볼 수 있는 것 | 못 하는 것 |
|---|---|---|---|
| **운영자** (기사님) | 멤버 대조 · 승인 · 정지 · 탈퇴 처리 · 허락 · 공지 · 앱 올리기 | 모든 회원의 위치 · 콜(구간 · 요금 · 시각 · KEEP/취소 · 상호 · 유선 번호) · 폰 · 이상 기록 · 통계 — **위치 신고 · 동의 뒤** · 열람은 기록에 남는다 | 회원의 필터 · 판정 기준 · 결재 대신 하기 · 콜 배정 · **개인 이름 · 010 휴대폰 · 상세 번지**(가림) |
| **회원** (승인됨) | 지금과 같다 + 탈퇴 | 자기 것 + 공지 | 남의 콜 · 폰 · 거래처 · 위치 |
| **회원** (승인 전) | 가입 정보 고치기 · 확인 번호 적기 · 앱 받기 · 탈퇴 | «승인 기다리는 중» | 콜 필터 · 폰 연결 |
| **회원** (유예 · 정지) | 확인 번호 적기(유예) · 탈퇴 | «멤버십을 확인해 주세요» / «이용이 멈췄습니다» | 서버가 폰 보고를 거절한다 — 콜이 안 들어온다 |

🔴 **정지는 그 회원의 운행을 멈춘다.** 운행 중에 정지하면 KEEP 해 둔 콜의 안전취소도 멈춘다. 거는 방식은 Q5. 즉시 정지 때는 «안전취소가 멈춥니다» 경고를 운영자에게 띄운다. 어느 쪽이든 결재 대기 · 진행 중 콜이 있으면 «진행 중 콜 N건, 끝나면 멈춥니다»를 보인다. 기한 만료 자동 정지(Q9)도 같은 «끝난 뒤» 규칙을 탄다.

경쟁 문제(운영자 = 기사님 = 회원과 같은 배차망 기사)는 법보다 신뢰 문제다 — 약관에 «운영자가 무엇을 보는가»를 적고 동의받고, 열람 기록을 남긴다 (ab).

## 6. 회원 — 가입 · 멤버 확인 · 허락 · 정지 · 탈퇴

### 회원 자료는 «상태 이름»이 아니라 «사실 + 기한» 칸이다 (1f · 04)

🔴 «승인 대기 · 사용 중 · 정지 · 유예»를 한 칸에 담지 않는다 — `if (status === …)` 가 생긴다(CLAUDE.md). 부품마다 제게 필요한 사실만 본다. 이름은 화면 글에서만 만든다.

| 칸 | 뜻 | 누가 읽나 — 무슨 질문의 답으로 |
|---|---|---|
| `users.approved_at` | 비면 승인 전 | 폰 보고 · 로그인 문 — «받아도 되나» |
| `users.paid_until` | 유료 기한(멤버 대조 때 한 달씩) | 폰 보고 문 — «기한 안인가» · 화면 배지 «유예 D-n» |
| `users.suspended_at` · `users.suspend_after_active` | 비면 사용 중 · 끝난 뒤 멈춤 걸림 | 폰 보고 문 — «거절하나» · 안전취소 · 6단계 — «끝났으니 이제 멈추나» |
| `users.withdrawn_at` | 탈퇴 시각 · 파기 예정 | 파기 작업 — «지울 때가 됐나» |
| `users.auto_until` · `stats_until` | 자동 잡기 · 통계 허락 기한 | 서버가 폰에 모드를 내려보내는 곳 — «AUTO 를 ALARM 으로 낮추나»(앱 코드는 안 바뀐다) · 통계 문 |
| `users.phone` · `dispatch_networks` · `home_region` · `youtube_channel` | 가입 정보 · 주 활동 지역(스스로 적음) · 유튜브 채널명 | 승인 판단 · 멤버 대조 |
| `member_checks` 표 (회원 · 달 · 적은 확인 번호 · 대조 시각 · 결과) | 매달 멤버 대조 이력 | `/members/check` |
| `agreements` 표 (회원 · 약관 판 · 항목 · 필수/선택 · 동의 시각) | 동의 이력 — 약관이 바뀌면 다시 받는다 | 가입 · 위치 기능 켜기 |

기한이 지나면(`paid_until` < 오늘) 서버가 **자동 정지**(Q5 «끝난 뒤» 규칙) → **14일 유예**(회원은 확인 번호를 적어 되살릴 수 있다 · 운영자가 대조해 기한을 늘림) → 유예가 끝나면 탈퇴 처리는 **운영자 손**(되돌릴 수 없는 일).

### 탈퇴 · 파기
탈퇴하면 무엇을 지우고 무엇을 몇 달 남기나를 개인정보 처리방침과 짝으로 정한다. DB 백업 파일 보존 기간도 (8장 ⑬).

### APK (04)
- 두는 곳: **EC2 레포 밖 폴더**(예: `~/onedal-releases/`) + 운영센터 업로드 + `app_releases` 줄(버전 · versionCode · sha256 · 최신/최소). GitHub Releases 는 비공개 레포라 못 받는다.
- 🔴 릴리스 서명 키는 git 밖 두 곳(개발 PC + 오프라인 백업). 잃으면 모든 회원이 지우고 다시 깐다. CI 가 아니라 개발 PC 에서 서명한다.
- 🔴 서명이 바뀌면 덮어 설치가 안 된다 — 기사님 폰 둘은 한 번 지우고 다시 깔아야 하고 폰 저장값이 날아간다. 기기 토큰 재연결과 **같은 날** 한 번.

| **0. 결정** | 이 계획서 1장. 남은 것: **새 폴더 `onedal-web/ops` 허락** | 기사님 «만들어» |

| **3. 운영센터 뼈대 + 회원** | `ops/` 앱 · 주소 · DNS · 인증서 · 구글 원본 · `/members` · `/members/check` · `/phones` · `/anomalies` · `/audit`(열람 포함) · 기한 만료 자동 정지 · 유예 14일 | 운영자만 들어온다. 대조 · 승인 · 정지 · 탈퇴가 되고 `/audit` 에 남는다. 기한이 지난 시험 계정이 «끝난 뒤» 규칙으로 멈춘다. 검사: **관제웹이 `ops/` 를 가져다 쓰지 않는다** |

### 1단계 검사 (ab)
- 🔴 계정 A 로 로그인해, 라우터에서 뽑은 **운영자 API 밖의 모든 문(GET)과 소켓 이벤트**를 부르면 응답에 계정 B 의 user_id · device_id · 주소 · 전화가 한 줄도 없다 — B 에 알아볼 표시 값을 심어 찾는다. 문을 하나 더하면 검사가 저절로 그 문도 부른다.
- 🔴 회원 계정으로 `/api/ops/*` 를 부르면 403.

### 1단계 올리는 순서 — 기사님 운행이 안 끊기게 (04)
㉠ 실서버 DB 백업(기사님 손) → ㉡ 서버 먼저: 토큰 발급 · 오면 검사 · 안 오면 지금처럼(더하기만) → ㉢ 원달앱: 토큰 저장 · 헤더로 → ㉣ 기사님 폰 다시 깔기(서명) + 재연결 — 운행 아닐 때 · 같은 날 한 번 → ㉤ 서버 강제: hash 있는 기기는 토큰 필수 · 없는 기기 거절 — 기사님 폰 둘이 hash 를 가진 것을 DB 로 확인한 뒤. 앱을 먼저 강제하는 순서는 없다.
