# 50. 49 ① — 필터 · 모드 · 판정을 블루투스로 이사 · 줄별 안

reviews/49 «① 필터 · 모드 · 판정을 블루투스로 이사»의 어느 파일 어느 줄을 무엇으로. 될지 시험(49 0 · 0-2 · 0-3) 통과 뒤. 기사님 «① 줄별 안 만들어».

## 끝의 모습

> 관제웹(관제앱)에서 필터 · 모드를 바꾸거나 결재를 누르면, 서버가 저장 · 계산한 값이 소켓으로 관제앱에 오고, 관제앱이 블루투스로 스캔폰에 곧바로 넘긴다.
> 스캔폰은 그 값으로만 돈다 — 지금 HTTP 보고 응답에 실려 오던 필터 · 모드 · 결재 · «받았음» 길은 지운다(한 값 한 길).
> 블루투스가 끊기면 스캔폰은 마지막 값으로 목록 판정 · 알람만 하고 자동 확정은 하지 않는다.

## 메시지 한 벌 — shared `bleProtocol.ts` (원달앱 · 관제앱 · 서버 짝)

| 종류 | 방향 | 주소 | 실은 것 |
|---|---|---|---|
| `HELLO` | 스캔폰 → 관제앱 | — | 폰 번호(deviceId) · 짝 서명(같은 기사님인지) |
| `SUPPLY` | 관제앱 → 스캔폰 전부 | 기사님 | 필터(압축 · 통째로) · 필터 판 · 서버 살아 있음 |
| `MODE` | 관제앱 → 스캔폰 | **폰마다** | 그 폰에 갈 모드(`modeForPhone` 결과) |
| `DECISION` | 관제앱 → 스캔폰 | **폰마다** | 콜 번호 · KEEP/CANCEL(체험 포함) · 빨리 접기 남은 ms |
| `ACK` | 스캔폰 → 관제앱 | — | 받은 결재의 콜 번호 |
| `BREATH` | 서로 | — | 살아 있음(감시 5초 · 48 시험) |

- 틀: [종류 1바이트][길이 4바이트][본문] · 쓰기 한 번 512 바이트 이하로 쪼갬(0-3 에서 514 로 앱이 죽음) · 쓰기는 한 번에 하나.
- 짝 서명: **폰마다 다르게** — 서버 비밀값으로 «기사님 번호|폰 번호»를 서명(HMAC) · 스캔폰은 보고 응답, 관제앱은 소켓으로 받음(저장 안 함) → 연결 하나 ↔ 폰 번호 하나가 증명되고, `MODE` · `DECISION` 은 그 연결에만 보낸다 · 광고에는 날짜를 섞은 짧은 해시만.

## 먼저 시험 0-2b — 관제앱의 서버 소켓이 화면 뒤 · 화면 끔에서 버티나 (onedal-69 리뷰 · 🔴 빠졌던 것)

공급의 첫 고리(서버 → 관제앱)는 **웹 화면(JS) 안의 socket.io** 다. 0-2 는 블루투스 서비스만 시험했다 — 화면 뒤에서 웹 화면이 멈추면 소켓 숨이 끊겨 서버가 «관제웹 없음»으로 보고 공급이 멈춘다.
- 시험: S23 관제앱(로컬 서버) 화면 끔 30분 — 서버 로그에 관제웹 소켓 해제 0 · 서버가 10초마다 보내는 시험 신호를 관제앱이 받은 간격.
- 통과 → 50 그대로(웹 소켓) · 떨어짐 → **서버 연결도 블루투스 서비스(네이티브)가 직접**(네이티브 socket.io 클라이언트 · 공급 · 결재 · 받았음이 JS 를 거치지 않음) — 그때 50 ①-2 를 고쳐 다시 올림.

**사이드이펙트**
1. 🔴 twin 넘겨주기(`socketHandlers.ts:776`): 웹 화면 소켓이 끊길 때 «같은 창 번호의 살아 있는 소켓»을 찾는데, 여기서 공급 소켓이 걸리면 `activeWebSession` 을 넘겨받는다. 그러면 화면이 꺼져도 «관제웹 있음»이 되어 ④ 를 «나»로 골라도 조용히 «가»가 된다. → twin 찾기에서 `role === 'supply'` 를 뺀다. 검사: «웹 화면 끊김 + 공급 소켓만 남음 → `activeWebSession` null».
