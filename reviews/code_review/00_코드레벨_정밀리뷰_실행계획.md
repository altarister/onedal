## 📱 [Part 1] 안드로이드 앱 코틀린 코드 (`onedal-app`)
> **"배차앱 화면을 긁고 터치하는 첫 관문의 코드 무결성"**

### 1. 중점 분석 대상 파일
- `onedal-app/app/src/main/java/.../AccessibilityService.kt` (접근성 서비스 수명주기 및 노드 트리 순회부)
- `onedal-app/app/src/main/java/.../parser/InsungParser.kt` (배차앱 텍스트 파싱 및 정규식)
- `onedal-app/app/src/main/java/.../filter/PickupListFilter.kt` & `RegionMatch.kt` (동 단위 매칭 로직)
- `onedal-app/app/src/main/java/.../timer/SafeCancelTimer.kt` (30초 안전취소 타이머 및 스레드)

### 2. 현미경 체크리스트 (코드 단위 점검 항목)
- [ ] **메모리 할당 & GC 멈춤**: `AccessibilityNodeInfo` 사용 후 `.recycle()`이 누락된 곳이 없는가? 루프 내에서 불필요한 String/List 객체를 대량 생성하는가?
- [ ] **NPE(NullPointerException) 방어**: 배차앱 화면 텍스트나 뷰 트리가 일시적으로 깨졌을 때 `null` 안전 연산자(`?.`, `?:`)가 철저히 적용되어 있는가?
- [ ] **정규식(Regex) 성능**: 정규식 패턴이 매번 컴파일되고 있는가, `val regex = Regex(...)` 형태로 재사용(Pre-compiled)되고 있는가?
- [ ] **스레드 안전성**: 백그라운드 스레드에서 UI 노드를 건드리거나, 메인 스레드에서 블로킹 I/O를 수행하는 코드가 있는가?

## 🧠 [Part 2] 서버 판정 엔진 & 상태 머신 (`onedal-web/server`)
> **"수익성 판정의 수학적 정확성과 주문 생명주기 상태 전이"**

### 1. 중점 분석 대상 파일
- `onedal-web/server/src/core/engine/OrderEvaluator.ts` (5대 판정 지표 및 시급 계산)
- `onedal-web/server/src/services/dispatchEngine.ts` (KEEP/CANCEL 결재 및 콜 수명주기)
- `onedal-web/server/src/state/filterManager.ts` & `userSessionStore.ts` (필터/세션 메모리 관리)
- `onedal-web/server/src/db.ts` (SQLite 쿼리 동기성, 트랜잭션 무결성)

### 2. 현미경 체크리스트 (코드 단위 점검 항목)
- [ ] **0으로 나누기(Division by Zero) & NaN**: 추가 시간(`extraMinutes`)이나 거리가 0일 때 `hourly = (fare / extraMinutes) * 60`에서 `Infinity`나 `NaN`이 발생하지 않는가?
- [ ] **동시성 레이스 컨디션 (Race Condition)**: 1초 간격으로 연속 스크랩이 들어올 때 동일한 콜에 대해 중복 판정이 실행되거나 세션 데이터가 덮어써지지 않는가?
- [ ] **SQLite I/O 블로킹**: `db.prepare().run()` 쿼리가 실행되는 동안 Node.js 메인 이벤트 루프가 몇 ms 동안 블로킹되는가?
- [ ] **타입 안전성**: `@onedal/shared` 규격과 서버 내부 타입 간에 `any` 캐스팅으로 인해 런타임 타입 불일치 버그가 숨어있지 않은가?

## 🛣️ [Part 3] 합짐 동선 & 기하학 알고리즘 (`routeComposer.ts` & `shared`)
> **"복도(Corridor) 기하학, TSP 경유지 정렬, 카카오 캐싱 로직"**

### 1. 중점 분석 대상 파일
- `onedal-web/server/src/services/routeComposer.ts` (`planMergedStops`, `orderByNearest`, 베이스 캐시)
- `onedal-web/shared/src/filterArea.ts` & `callNet.ts` (마름모/폴리곤 Turf.js 기하학 연산)
- `onedal-web/shared/src/timing.ts` (150% 약속 시간 타임라인 사다리)

### 2. 현미경 체크리스트 (코드 단위 점검 항목)
- [ ] **배열 인덱스 초과(IndexOutOfBounds)**: 하차 정거장 목록이 비어 있거나 상차지가 없을 때 배열 접근(`[0]`, `.pop()`)에서 크래시 위험은 없는가?
- [ ] **캐시 키(Cache Key) 충돌 및 무결성**: `baseCacheKey`가 좌표, 우선순위, 차종을 완벽히 구분하고 있는가? 잘못된 캐시 히트로 엉뚱한 경로가 반환될 가능성은 없는가?
- [ ] **지오메트리 부동소수점 오차**: 위경도 연산(`haversineKm`, Turf 교집합) 시 부동소수점 정밀도 오차로 경계선에 걸린 동이 누락되지 않는가?
- [ ] **경로 순서 플리커링(Hysteresis)**: `STOP_ORDER_HYSTERESIS`와 `STOP_ORDER_TIE_KM` 계산식에 논리적 허점이 없는가?

## 🖥️ [Part 4] 관제탑 클라이언트 UI & 실시간 훅 (`client-app`)
> **"운전 중 60fps 렌더링 유지, 제스처 락, 소켓 메모리 누수"**

### 1. 중점 분석 대상 파일
- `onedal-web/client-app/src/components/dashboard/JudgmentSeat.tsx` (35:65 버튼 & CSS 트랜스폼 게이지)
- `onedal-web/client-app/src/components/stage/StageSheet.tsx` & `stageRules.ts` (3단 스냅 및 손 유예)
- `onedal-web/client-app/src/components/stage/sheetStatus.ts` (38px 상태바 문장 조립)
- `onedal-web/client-app/src/stores/` (Zustand 스토어 및 Socket.IO 리스너)

### 2. 현미경 체크리스트 (코드 단위 점검 항목)
- [ ] **불필요한 리렌더링(Re-render) 루프**: 소켓 틱마다 가상 DOM 트리가 전체 재렌더링되며 프레임 드랍(Jank)을 유발하는 컴포넌트가 있는가?
- [ ] **메모리 누수(Memory Leak)**: 컴포넌트 언마운트 시 `socket.off()`나 `clearTimeout()`이 누락되어 메모리에 이벤트 리스너가 누적되는가?
- [ ] **GPU 가속 무결성**: 30초 카운트다운 게이지가 CPU 연산 없이 순수 GPU 컴포지팅(`transform: scaleX`)으로만 부드럽게 돌아가고 있는가?
- [ ] **터치 제스처 충돌**: 3단 시트를 스와이프할 때 지도 패닝(이동) 제스처와 충돌하여 스크롤이 버벅거리지 않는가?

### 1. 중점 분석 대상 파일

- `onedal-web/client-app/src/App.tsx` (하단 네비게이션바 및 safe-area-inset)
- `onedal-web/client-app/src/pages/Dashboard.tsx` (모바일 뷰포트 높이 100dvh)

### 2. 현미경 체크리스트 (코드 단위 점검 항목)
- [ ] **시스템 제스처 영역 침범**: `safe-area-inset-bottom`이 누락되어 하단 버튼이 폰 홈바와 충돌하지 않는가?
- [ ] **GPU 가속 무결성**: 30초 카운트다운 게이지가 `width` 대신 `transform: scaleX()`로 GPU 가속되고 있는가?
- [ ] **트럭 진동 오터치 방어**: `user-select: none`과 `touch-action: manipulation`으로 더블탭 줌과 텍스트 선택이 차단되었는가?
- [ ] **주간 햇빛 시인성**: 라이트 모드에서 심사석 버튼이 어두운 다크 색상으로 하드코딩되어 있지 않은가?
- [ ] **모바일 뷰포트 출렁임**: `100vh` 대신 `100dvh`를 사용하여 모바일 주소창 개폐에 반응하는가?

## 📋 진행 방식 및 산출물 규칙

1. **파트별 순차 진행**: 한 파트씩 실제 소스코드 전체를 열어서 정밀 분석.
2. **리뷰 보고서 작성**: 각 파트 완료 시 `reviews/code_review/01~05_코드리뷰_..._결과.md` 형식으로 구체적인 라인 번호와 문제점, 해결 코드까지 상세 기록.
3. **즉각적 핫픽스 도출**: 치명적인 잠재 버그 발견 시 바로 수정할 수 있는 실제 교체 코드 제시.
