## 🔴 기사님께 여쭐 것 — 셋

**A. 원달앱이 스스로 다른 페이지로 찾아가 «취소»를 누르나 (운행 동작)**
- 지금: 원달앱은 **지금 화면**에서만 «취소»를 찾는다. 목록에서 안전취소 시간이 끝나거나 관제웹 «놓기»(CANCEL) 결재가 오면, 버튼이 없어 «취소 못 누름 — 계약이 남아 있다» 알림만 보낸다(D1 ①⑥). 운전 중이면 알림을 바로 못 보셔서 원치 않는 계약이 남는다.
- 가: 지금 화면에 놓기 버튼이 없으면 원달앱이 **잡은 콜 다시 열기 목록**(인성 «완료» · 화물24시 «배차내역» · 픽커 «내 오더»)으로 가서 **그 콜**을 찾아 열고 → 잡은 뒤 페이지의 놓기 버튼을 누르고 → 다음 화면을 읽어 «놓였나»를 보고한다. 그 콜을 못 찾거나 버튼이 없으면 지금처럼 알림만.
- 나: 지금처럼 알림만.
- 추천: 가 — «무입력에도 일이 되게». 다만 배차망 화면을 원달앱이 여러 번 눌러 옮겨 다닌다(그동안 목록을 못 읽음 · 몇 초).
- 좋은 콜: 그대로(놓기 중에는 새 콜을 안 누름 — D1 ①과 같음). 노이즈: 그대로. 손: 원치 않는 계약을 손으로 취소하실 일이 준다. 취소 횟수: **실제로 놓였을 때만** +1(C 와 ③단계) — 지금 «알림만»으로 남던 콜이 놓이면 그만큼 +1(인성 10번마다 페널티 · 그 콜은 어차피 놓기로 정한 콜).

**B. «놓을 수 있나 = 모름»인 콜은 어떻게 하나 (운행 동작)**
- 지금: 자동 모드면 인성 · 화물24시는 **배차망 이름으로** «잡은 뒤 놓을 수 있다»고 보고 먼저 확정을 누른 뒤 30초 안에 결재를 기다린다(안전취소). 픽커는 배차망 이름으로 «놓을 수 없다»라 자동 확정이 없다(`KakaoPickerPlugin` 자동 모드 · 수락 칸 없음).
- 원칙 ③대로 «놓을 수 있나»를 그 콜 화면의 사실(예 · 아니오 · 모름)로 읽으면, 지금 근거가 있는 것은: 인성 — 확정 뒤 페이지에 «취소» 버튼이 있고 30초 안 취소가 된다(취소 셈 +1) → **예** · 픽커 — 잡은 뒤 페이지에 «배정 취소»는 있지만 «배정 취소 불가» 팝업이 뜨는 콜이 많다(실물 캡처 19) → **아니오(그 콜에서 불가 표시를 읽기 전엔 모름)** · 화물24시 — 배차내역 상세에 취소 버튼을 본 적이 없다(시뮬 · 실물 캡처 모두 없음) → **모름**.
- 가: 모름이면 아니오처럼 — **확정 전에 판정을 기다린다**(원칙 ② · 원달앱은 확정을 누르지 않고 미리보기로 올려 기사님이 확정).
- 나: 모름이면 예처럼 — 지금처럼 먼저 확정 · 30초.
- 추천: 가 — 놓을 수 있는지 모르는 콜을 먼저 잡으면 «되돌릴 수 없는 계약»이 될 수 있다.
- 좋은 콜: **화물24시 자동이 사실상 «미리보기 + 기사님 확정»이 된다**(화물24시 놓기 화면을 확인하기 전까지) — 화물24시 좋은 콜을 손이 늦어 놓칠 수 있다. 인성은 그대로(예). 노이즈 · 취소 횟수: 화물24시 자동 확정 → 안전취소가 없어져 줄어든다.

**C. 픽커에서 이것이 무엇을 바꾸나 (지금 픽커는 원달앱이 잡지 않는다 — 수락은 기사님 손)**

## 단계 — 각 줄 «무엇이 참이면 끝인가» · 검증(동작으로만)

순서는 정의 → 시뮬 → 원달앱 판단(순수) → 원달앱 집행 → 서버. 배차망만의 흐름은 만들지 않는다 — 다른 것은 정의 표 인자뿐.

1. **정의 표에 놓기 인자 (원칙 ③)** — shared `networkPages.ts` 의 «잡은 뒤 페이지»에 칸 셋: `releaseButton`(놓기 버튼 글자 — 인성 «취소» · 픽커 «배정 취소» · 화물24시 없음) · `releasedWhen`(놓인 뒤 무엇이 보이나 — 다시 열기 목록에서 그 콜이 빠짐 / 확인 팝업) · `releaseRefused`(불가 표시 — 인성 «취소할 수 없» · 픽커 «배정 취소 불가»). 결재 «닫기»(KEEP) 도 같은 칸(`keepButton`). `pnpm gen:pages` 로 원달앱 생성 파일에. 화물24시는 «모름» — 캡처가 생기면 채운다(사업자 뒤 · «모을 것»에 적음).
   - 끝 · 검증: 원달앱 `NetworkPagesPairTest`(표 = 코틀린)가 새 칸까지 견준다 · 화물24시는 빈 칸(모름).
2. **시뮬에 놓기 화면 (모든 페이지 · 팝업)** — 인성 잡은 뒤 페이지 «취소» 뒤 «취소 확인 팝업» · 30초가 지나면 «취소할 수 없습니다» 팝업(실물 캡처 `인성/상세-확정(다른사람 못잡음, 취소+1).png` 기준 · 없는 부분은 «시뮬만» 표시) · 픽커 «배정 취소» 뒤 **콜마다** 불가 / 됨(지금은 늘 불가 — 시험에 «됨» 길이 없다) · 화물24시는 그대로(모름).
   - 끝 · 검증: 시뮬 검사(onedal-sim vitest)로 «30초 안 취소 → 잡은 콜에서 빠짐 · 넘으면 불가 팝업» · «픽커 됨 콜 → 내 오더에서 빠짐 · 불가 콜 → 팝업».
3. **원달앱 «놓을 수 있나» 사실 (B)** — 상세 화면을 읽을 때 `releasable: 예 / 아니오 / 모름` 을 정한다: 그 배차망 잡은 뒤 페이지에 `releaseButton` 이 정의돼 있고(1단계) 상세에 불가 표시가 없으면 예 · 불가 표시가 있으면 아니오 · 정의가 없으면 모름. 자동 확정 여부(`appContractsOnOpen`)는 «모드가 확정을 하나 **그리고** releasable == 예»로 — 배차망 이름(`getSafeCancelMs` 있나)으로 가르지 않는다.
   - 끝 · 검증(단위): 순수 함수 `Releasable.of(정의, 상세 글자)` — 인성 예 · 픽커 불가 글자 있음 → 아니오 · 화물24시 → 모름 / `appContractsOnOpen` 이 모름 · 아니오면 거짓. 변이(배차망 이름으로 되돌림) 🔴.
4. **원달앱 놓기 루틴 판단 (A · 순수)** — `ReleasePlan.next(지금 화면, 그 콜 번호, 정의)` 가 한 걸음씩 답한다: 지금 화면이 그 콜의 잡은 뒤 페이지면 «releaseButton 누름» · 다시 열기 목록이면 «그 콜 줄 누름(못 찾으면 포기)» · 목록 · 그 밖이면 «다시 열기 탭으로»(탭 글자도 정의 인자) · 걸음 상한(예: 5)을 넘거나 화면을 모르면 «포기 → 알림만». 누른 뒤 다음 화면을 읽어 `released: 예 / 아니오(불가 표시) / 모름`.
   - 끝 · 검증(단위): 화면 순서를 넣은 표 검사 — 인성 «목록 → 완료 탭 → 그 콜 → 잡은 뒤 페이지 → 취소 → 완료에서 빠짐 = 놓임» · 픽커 «… → 배정 취소 → 불가 팝업 = 안 놓임» · «그 콜이 목록에 없음 → 포기». 변이 🔴.
