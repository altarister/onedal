## 4. 단계 — 단계마다 «무엇이 참이면 끝인가» (①)

**S1-1 서버: 이 폰 몫 한 벌을 주는 주소 · «받았음» 주소**
- `GET /api/devices/:deviceId/supply` — 폰 토큰으로(`/api/scrap` 과 같은 인증). 답: `{ filter, filterVersion, phone: { mode, evaluatingNow }, decisions: PhoneDecision[], folds: PhoneFold[] }`. 몸통은 값만 받는 `phoneSupplyFor(deviceId, session, …)` 하나 — 안은 `phoneSupplyOf` · `phoneDecisionsOf` · `foldRemainMsOf` 를 부르기만(새 셈 없음 · 공급 소켓과 같은 원천).
- `POST /api/devices/:deviceId/decision-ack {orderId}` → `ackDecision(…, via: '인터넷')`. 두 길로 두 번 와도 둘째는 «늦은 받았음» 또는 할 일 없음(지금 함수 그대로).
- 끝: ① `phoneSupplyFor` 단위 검사 — 공급 소켓에 가는 것과 같은 값(필터 판 · 모드 · 심사 중) · 결재 큐의 이 폰 몫만 · 다른 폰 · 다른 기사님 몫 없음 · 짝 서명(pairSig) 안 실림 ② 라우트 동작 검사 — 토큰 없음 401 · 남의 폰 403 · «받았음» 두 번에 큐 한 번만 지움 ③ 변이(이 폰 몫 거르기 · via 이름 · 인증) 🔴.

**S1-2 원달앱: 끊김 신호 · 안전취소가 걸린 때부터 1초마다 묻기**
- 새 `core/InternetSupply.kt`(가칭): **켜는 사실 셋** — ① 블루투스 끊김(`onLinked(false)`) ② 관제앱 서버 끊김(`onServerAlive(false)`) ③ 안전취소가 걸림(`safeCancelTimer.armedOrderId != null` · 기사님 답 4). 셋 다 거짓이면 끈다. 시간 짐작 없음. 1초 간격은 코드 상수(기사님 «고정값»). 켜는 판단은 값만 받는 `InternetSupply.wanted(linked, serverAlive, armed)` 하나.
- ③ 은 블루투스가 멀쩡해도 30초 동안 인터넷 묻기가 함께 돈다 — 원달앱 폰 데이터 · 전지는 30초 × 1초 = 묻기 30번 남짓(안전취소 한 번에).
- 답을 받으면 **`bleListener` 와 같은 처리 함수**를 부른다 — onSupply · onPhone · onDecision · onFold. 결재는 `DecisionReplay.stepOf` 를 그대로 거쳐 두 길로 와도 한 번만 집행. 인터넷으로 받은 결재의 «받았음»은 인터넷으로, 블루투스로 받은 것은 블루투스로(그 길이 살아 있으면 둘 다).
- 받는 처리 함수를 `bleListener` 안에서 꺼내 한 곳에 둔다(두 길 · 한 처리) — 이 꺼내기는 옮기기만(별도 커밋 · 디프 견줌).
- 끝: ① `InternetSupply` 단위 검사 — 켜는 사실 셋(하나씩) · 끄는 조건(셋 다 거짓) · 같은 결재가 두 길로 와도 집행 한 번 · «받았음»은 온 길로 ② 변이(켜는 사실 셋을 하나씩 빼기 · 끄는 조건 · 같은 결재 거르기 · «받았음» 길) 🔴 ③ 원달앱 단위 검사 전체 · 원달앱을 읽는 서버 검사 초록.

**S2-1 서버: KEEP 한 콜의 원달앱 자동 취소를 가린다**
- `emergency.ts`: 결재 큐 줄을 지우기 **전에** `keepLost = row?.action === 'KEEP'` 을 읽는다(사실 하나).
- `reason === 'AUTO_CANCEL' && cancelPressed === true` 면 콜을 `SAFE_CANCEL` 로(메모리 · DB · `order-canceled` 의 status) — 그 밖의 까닭은 지금처럼 `ORDER_RELEASED_BY_OFFICE`. 취소 셈(`countCancel`)은 지금 그대로.
- 경보에 `keepLost: true` 를 싣는다(`EmergencyAlert` 칸 하나 — 저장 칸 아님 · 소켓 메시지 칸).
- 끝: ① 동작 검사 — KEEP 줄 + 자동 취소 · 눌렀음 → SAFE_CANCEL · keepLost true / KEEP 줄 없음(받았음 끝) → keepLost false / 다른 까닭 → 방출(사무실) 그대로 / 눌렀음 false → 지금처럼 끝내지 않음(dd65ce9d) ② 변이(지우기 앞뒤 차례 · 까닭 조건 · 상태 이름) 🔴.

**S2-3 원달앱: 못 보낸 비상 보고를 들고 있다가 인터넷이 붙으면 보낸다**
- 지금은 두 번 실패하면 버린다(G8). 메모리 줄에 들고 있다가 다음 보고(1초 · 60초)가 성공한 때 다시 보낸다 — 사실(«보고가 닿았다»)로 다시 보내기 · 시간 짐작 없음.

- 끝: ① 단위 검사 — 실패한 보고가 다음 성공 뒤 한 번 나간다 · 같은 콜 같은 보고는 한 번만 · 저장 칸에서 되살아난 보고도 한 번 · 닿은 뒤 저장 칸이 빈다 ② 변이 🔴.

## 6. 남은 질문

**Q-반쯤 죽은 상태 — «블루투스는 붙어 있다는데 아무것도 안 온다»를 사실로 가를 길 (코드로 본 것)**
- 이미 막혀 있는 몫: 관제앱의 숨(BREATH)은 결재 · 필터와 **같은 쓰기 줄**(`smallQ`)로 1초마다 간다. 쓰기가 막히면 숨도 막혀 원달앱이 «5초 쓰기 없음 → 공급 연결 끊김»(`BleLink.kt:316`)을 낸다 → S1 이 켜진다. 관제앱이 서버와 끊기면 숨의 «서버 살아 있음» 칸이 0 → `onServerAlive(false)` → S1 이 켜진다.
- 남는 몫: 숨은 잘 오고 «서버 살아 있음»도 1인데, 서버가 결재를 그 관제앱에 안 보낸 경우(공급 소켓 방 · 기기 번호 어긋남 등).
- **사실로 가르는 제안 (추천 순)**
  1. **[기사님 답 4 — 넣음 · S1-2 ③]** **원달앱이 «결재를 기다리는 동안»에도 인터넷으로 묻는다** — 안전취소 타이머가 걸린 것은 시간 짐작이 아니라 사실이고(`safeCancelTimer.armedOrderId`), KEEP 을 놓치면 좋은 콜을 잃는 창은 정확히 이 30초다. 이러면 반쯤 죽은 상태든 아니든 결재는 늦어도 1초 안에 닿는다. 켜는 사실이 하나 늘어나는 것이라 **기사님 몫**(Q1 은 «끊김 신호부터»로 정하셨음).
  2. **서버가 이미 아는 어긋남을 쓴다** — 원달앱 보고에는 «들고 있는 필터 판»(`filterVersion`) · «적용 중인 모드»(`appliedMode`) · «지금 하는 일 = 안전취소 · 남은 초»(`workStage` · `workStageSeconds`)가 실린다. 서버는 «보낸 판»을 기억한다(`core/phoneCheck` 의 `rememberSentFilterVersion`). «폰은 X 안전취소 중이라는데 서버엔 X 의 KEEP 줄이 있고 «받았음»이 없다»가 **두 보고 연속**이면 반쯤 죽은 것 — 서버 로그 · 관제웹 폰 칸에 보인다(필터 판 어긋남은 이미 «필터 옛 판»으로 보임).
  3. 숨에 관제앱이 든 필터 판을 실어 원달앱이 제 판과 견준다 — 블루투스 틀 칸 하나가 늘고 관제앱 · 원달앱을 같이 고쳐야 해 마지막.
- 시간 짐작(«N초 동안 결재가 없으면»)은 쓰지 않는다 — 1이 같은 일을 사실로 한다.

**Q4 (G2) — 정함(기사님 답 2 · 가)**: 인터넷이 받쳐 줘도 원달앱은 지금처럼 알람으로 내려간다. 이미 계약한 콜의 KEEP 만 인터넷으로 닿는다.
