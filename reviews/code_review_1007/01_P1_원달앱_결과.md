### 오류가 기사님에게 닿나 · 로그로 콜을 따라갈 수 있나

- 닿는 것: 버튼 못 찾음(비상 보고) · 확정 버튼 못 찾음 · 요건 미달 · 누른 콜 아님 · 누르기 안 먹힘 · 먼저 가져감 · 모르는 화면(이상 기록 + 사진) — 모두 운영센터 «이상 기록»으로 간다.
- 안 닿는 것: 보고가 멈춤(P1-01) · 화면을 못 얻어 결재를 못 누름(P1-13) · 낱말 사전 깨짐(P1-27) · 안전취소가 리셋으로 꺼짐(P1-02).
- 콜 따라가기: 목록 단계는 «상차→하차 요금 · 지문», 상세 이후는 세션 id(`AUTO-…` · `MANUAL-…`), 결재는 `orderId` 로 찍혀 **한 열쇠로 이어지지 않는다**. 목록 → 상세 진입 줄(`🚪 [상세 진입]`)에 지문과 세션 id 를 함께 찍으면 한 줄로 이어진다(고침 계획 P1-19 묶음에 넣음).

## 7. 못 잡는 것 · 추정

- **P1-01 빈도**: 어느 앱이 `AccessibilityManager.interrupt()` 를 부르는지(내비 · 메신저 · 음성 안내)는 폰 로그로만 안다 — 원달앱 로그에 `⚠️ 1DAL Service Interrupted!` 줄이 있었는지 폰 로그 3일치를 찾아보면 바로 확인된다(이번엔 폰 로그를 안 열었다). 코드 결과(보고가 멈추고 다시 안 켜짐)는 확인했다.
- **P1-02 · P1-09 · P1-13 · P1-16**: 앱이 계약하는 길은 인성 · 화물24시 자동뿐이고 지금 둘 다 시뮬레이터다 — 실물 인성에서 확정 뒤 화면이 «확정 뒤 상세»에 머무는지 목록으로 가는지(`SharedModels.kt:31` 주석은 «인성은 확정하면 리스트로 돌아간다»고 적는다)는 사업자 뒤에 본다. 목록으로 간다면 P1-02 는 «가끔»이 아니라 «매번»이 된다.
- **P1-11 · P1-21 비용**: 재지 않았다. `⏱️ [목록 화면 읽기]` 요약의 처리 ms 를 고치기 전후로 재야 «중간»이 맞는지 안다.
- **P1-15**: 구글 백업 복원으로 기기 id 가 실제로 복제됐는지는 운영센터 폰 목록(P7)에서 같은 id 두 폰을 찾아야 확인된다.
- **P1-22**: 서버가 응답 없이 시간을 끄는 경우가 실주행에 있는지 — 연결 자체가 안 되면 곧바로 실패한다(코드 주석의 실측).
- **같은 orderId 에 다른 결재**: `DecisionReplay` 는 같은 콜 번호의 두 번째 결재를 글자와 상관없이 «다시 옴»으로 버린다. 서버가 한 콜에 KEEP 뒤 CANCEL 을 보내는 길이 있는지는 P2(`decisions.ts`)가 답한다 — 없으면 문제없음.
- **블루투스 큰 칸 조립**(`BleFrames.BigAssembler`): 길이 머리에 위 한도가 없고 조각을 잃으면 다음 공급과 섞일 수 있다(증명된 관제앱만 쓴다). P4 «큰 칸 조립이 깨진 조각에서 굳지 않는가» 몫으로 넘긴다.
- 실물 인성 · 화물24시 화면(사업자 전) · 폰 기종별 접근성 차이 · 원달앱이 실물 화면에서 도는 것(`e2e:app` 보류)은 이 리뷰가 못 본다.
- `AndroidManifest.xml` · `res/xml/accessibility_service_config.xml` 은 범위(소스 폴더) 밖이라 Q7 백업 칸만 봤다 — 두 파일 주석에도 날짜 · «예전엔» 경위가 있다(P1-24 와 같은 꼴).
