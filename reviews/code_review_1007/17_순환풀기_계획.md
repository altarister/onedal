# 17 서버 순환 묶음 풀기 — 줄별 계획

재료: onedal-24 의 D13 끝 보고 · [12](12_D13_계획.md) «남은 것» · 원칙(onedal-71 전달): 동작은 그대로, «누가 누구를 부르나»로 층을 정하고 한 방향으로. 함수 안 `require` · 늦은 가져오기(`await import`) · 다시 내보내기로 **숨기지 않는다**(감춘 것이지 푼 것이 아니다). 타입만 오가는 고리는 `import type` 이면 족하다. 검사는 동작으로만 · 옮기기 전 HEAD 복사본(레포 밖 scratchpad)에서 초록 · 변이 🔴 · 옛 줄 잃음 0 · 커밋은 `git commit -- <내 파일>`.

## 단계 — 각 줄 «무엇이 참이면 끝인가»

1. **필터 값 읽기를 아래로** — `filterManager.ts:43 loadFilterValues`(DB `user_filters` 한 줄 → 값 다섯)를 새 `state/filterValues.ts` 로 글자 그대로 옮기고, `userSessionStore` 의 함수 안 `require('./filterManager')` 를 맨 위 정적 가져오기 `from './filterValues'` 로 · `filterManager` 와 그 이름을 부르는 곳은 새 경로에서 가져온다(다시 내보내기 없음).
   - 끝: 셈에서 `userSessionStore → filterManager` 0 · 런타임 묶음이 줄어든다(셈으로 수를 적는다).
2. **기기 표 읽기를 아래로** — 위 «아래층» 함수들을 새 `state/deviceRegistry.ts` 로 글자 그대로 옮긴다. `deviceSessions` 는 위층(보고 처리)만 남기고 `deviceRegistry` 를 가져다 쓴다. `phoneSupply` · `phoneStatus` · `cancelCount` 와 그 밖에 옮긴 이름을 부르는 곳(routes · ops · telemetry 등 — 단계 시작 때 grep 으로 표를 만든다)은 새 경로에서 가져온다(다시 내보내기 없음).
   - 끝: 셈에서 `phoneSupply / phoneStatus / cancelCount → deviceSessions` 0 · **런타임 묶음 0** (남으면 그 줄을 셈이 짚는다 — 계획에 없던 고리면 멈추고 올림).
   - 계획과 다른 둘(onedal-71 승인): ① `getActiveDevicesSnapshot` 은 위층에 남긴다 — 끊긴 폰을 넘기는 순간 `cleanPreviewOfDevice` → `forceCancelEvaluatingOrder`(배차 엔진 · 4층)를 불러, 옮기면 고리가 남는다. 그 짝 `heardSinceBoot` · `DEVICE_FORGET_MS` · `LIST_EXIT_GRACE_MS` 도 남긴다. ② 값만 받는 셈 `blindSignalFrom` · `leftDetailFrom` · `isDetailish` · `leftDetail` 은 위층만 써서 옮기지 않는다(고리 수 같음 · 디프를 줄임).
   - 알고 둠: `networkAxis` 의 «capturedVia 로 보호를 가르지 않는다» 검사는 `deviceRegistry` 를 읽지 않는다 — 옮긴 함수에 `capturedVia` 가 없어 지금은 거짓 초록이 아니고, 넓히면 글자 검사를 늘리는 것이라 넓히지 않는다(기사님 «글자 가»).
3. **타입만 오가는 고리** — 타입까지 넣은 셈에서 남는 것(`StateMachine` · `orderMemory` 쪽 · `userSessionStore` 의 `import('../services/routeComposer').RouteSnapshot` 타입)은 `import type` 으로(이미 그렇다면 그대로 — 런타임에 안 남는다).
   - 끝: 타입까지 넣은 셈의 묶음이 타입 가져오기로만 이뤄졌는지 적는다(0 이 아니어도 `import type` 이면 족함 · onedal-71 원칙).

## 검증 — 커밋마다 (D13 과 같은 방식)

- 가. **옮기기만 했다**: 담긴 디프에서 지운 줄이 모두 더한 줄에 같은 횟수로 있고(`export ` 만 정규화), 새 줄은 `import` · `export` · 새 파일 머리 주석 · 빈 줄뿐 — 임시 스크립트(scratchpad · 레포에 안 남김).
- 나. **그 파일 이름을 글자로 읽는 기존 검사 전부를 먼저 센다**(`grep -rl "state/deviceSessions\|filterManager"` — 서버 tests · 관제웹 · shared). 동작으로 바꿀 수 있는 것은 먼저 동작 검사로(옮기기 전 HEAD 복사본에서 초록 · 변이 🔴) · 구조 규칙만 읽는 경로를 같은 범위로 고친다 · «경로만 고친 것» 다섯 넘으면 멈추고 올림. «없어야 한다»(`not.toMatch`) 검사는 옮긴 뒤 거짓 초록이 될 수 있어 따로 목록 · 하나는 변이로 확인.
- 다. **동작**: 게이트 전부(서버 tsc · jest «Test Suites» 줄까지 · test:web · 관제웹 tsc -b · lint · audit:dead · socket · docs) · `pnpm scenario` · **기존 DB 사본 부팅**(순환을 풀다 «초기화 전 접근»이 새로 생기면 여기서 멈춘다) · jest 는 «전부 초록일 때만 커밋»(`&&`).
- 라. **«됐다»의 셈**: 단계 끝마다 `cycles.mjs` 를 다시 돌려 «런타임 묶음 수 · 파일 수»를 커밋 메시지에 적는다. 새 도구(madge 등) · 새 글자 감사는 들이지 않는다 — 한 번 쓰고 버리는 셈 + tsc + 사본 부팅.
