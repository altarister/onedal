# 12 D13 큰 파일 나누기 → 순수화 — 계획 (2판)

기사님 말씀: «이걸로 함수들이 퓨어해지고 종속관계가 최소화된 모듈화된 구조가 되었으면 좋겠어. 코드 품질 · 상태 관리 · 성능 · 렌더링 최적화 · 주석까지 전반적으로 우리 앱의 핵심이기 때문». «2개의 서브 에이전트 — 1번 서버 쪽 단계 · 2번 관제웹 쪽 단계 · 너가 중간에서 컨트롤».
재료: [09](09_덩어리.md) D13 줄 · P2-10 · P3-03 · P5-03 · P1-14 · [06](06_P6_관제웹_결과.md) «6. Q1 큰 파일».

원칙
- **나누기는 동작이 같다**(onedal-71) — 커밋마다 «옮기기만 했다»를 디프로 확인한다(아래 5).
- **새 규칙은 동작 검사와 타입으로만 지킨다**(기사님) — 소스 글자를 세는 검사 · 감사는 새로 만들거나 넓히지 않는다. 층 방향 · 순수함도 글자 검사로 지키지 않는다.
- **층은 «누가 누구를 부르나»로 가른다**(onedal-71 · 2단계에서 배움) — 주제로 가르면 순환이 생긴다. 아래 층은 위 층을 모른다.

## 0. 이 덩어리가 기사님 하루에 하는 일 (⑤)

| | 늘어남 · 줄어듦 |
|---|---|
| 좋은 콜 | 0 — 판정 · 잡기 동작이 같다 |
| 노이즈 | 0 — 알림 · 소리 · 화면이 같다 |
| 기사님 손 | 0 — 누르는 곳 · 화면 글자가 같다 |

- 얻는 것은 구조다: 한 파일에 한 일 · 한 방향 종속 · 값을 받아 값을 돌려주는 셈 함수. 다음에 판정 · 필터를 고칠 때 볼 범위가 줄고, 셈 함수는 세션 · DB 없이 값만 넣어 시험된다.
- 성능 · 렌더링은 이 덩어리에서 바꾸지 않는다(동작 변화다). 관제웹 부품을 작게 나눠 두어 D9(재고 고침)가 다시 그리는 범위를 줄이기 쉽게 만드는 데까지만 한다.
- 위험: ① 옮기다 동작이 바뀜 ② 순수화하며 결과가 바뀜 ③ 소스 글자 검사가 옮긴 글자를 따라가 거짓 초록. ①②는 동작 검사(옮기기 · 바꾸기 전 · 뒤 모두 초록)가, ③은 «그 파일을 적은 검사 전부»를 먼저 세어 동작 검사로 바꾸는 일(5-다)이 막는다.

## 1. 두 층 — 나누기 → 순수화

| 층 | 무엇 | 커밋 꼴 | «같다»의 증거 |
|---|---|---|---|
| ① 나누기 | 큰 파일을 «누가 누구를 부르나» 방향의 층으로 글자 그대로 옮긴다 | `test:` 동작 검사로(묶음별) → `refactor:` 나눔 | 옮기기 전 HEAD 에서 동작 검사 초록 + 변이 🔴 · 옮긴 뒤 같은 검사 초록 · 디프 «잃은 줄 0» |
| ② 순수화 | 층마다 바깥 일(세션 `getUserSession` · DB · 지금 시각 `Date.now` · 소켓 알림 · 카카오 부름)을 가장자리 함수로 밀고, 가운데 셈 함수는 **값을 받아 값을 돌려준다** | `refactor(순수화):` 파일 하나씩 | 바꾸기 전 · 뒤 동작 검사 초록 + 순수 셈 함수에 «값만 넣는» 단위 검사(안 일어나야 함 + 일어나야 함 · 변이 🔴) |

- 순수화의 꼴: `xxxOf(userId)`(안에서 세션 · 설정을 읽음) → `xxxFrom(값들)`(순수 셈) + `xxxOf(userId) = xxxFrom(읽은 값들)`(얇은 겉). 부르는 곳은 그대로 `xxxOf` 를 부른다 — 함수 이름 · 부르는 길이 늘지 않게 겉은 하나만.
- 관제웹의 순수화 꼴: 셈은 훅 밖 순수 함수(`areasOf(입력)`)로, 훅은 그것을 부르는 얇은 겉으로 · 부품은 props 만 받는다(안에서 저장소 · 소켓을 직접 안 읽음).
- 각 새 파일 머리에 두 줄: «이 파일은 위(…)를 가져오지 않는다 — 방향: …» · «바깥 일을 하는 함수: … (나머지는 값만 받는다)».

## 4. 제가(onedal-24) 하는 일 — 가져오기 · 확인 · 멈춤 올리기

1. **시작 전**: 단계마다 «그 파일 이름을 적은 검사 전부» 목록과 «관제웹 ↔ 서버 서로 읽는 검사» 목록을 갈라 에이전트에게 준다 · onedal-33 과 파일 겹침을 묻는다.
2. **가져오기 전(커밋마다)**: 옮긴 줄 잃음 0(디프 견줌) · 동작 검사가 옮기기 · 바꾸기 전 HEAD 에서 초록이고 변이 🔴 를 본 기록 · «경로만 고친 검사» 수(다섯 넘으면 멈춤) · 새 파일 머리 두 줄 · 담긴 파일이 그 단계 파일뿐인가.
3. **가져오기**: 에이전트 복사본의 커밋을 본 트리로 하나씩 옮긴다(커밋 경계 그대로 · 파일을 이름으로 지정). 본 트리에서 게이트 전부 · 서버는 `pnpm scenario` + 기존 DB 사본 부팅 · 관제웹은 화면 사진 앞뒤 견주기. 두 에이전트 커밋을 한꺼번에 가져오지 않는다.
4. **덩어리 끝**: `pnpm drive e2e` 는 onedal-71 에게 부탁(포트 4014 를 onedal-33 과 나눠 씀).
5. **멈춤 올리기**: 에이전트가 «경계가 계획과 달라짐 · 경로만 고칠 검사 다섯 넘음 · 결과가 바뀜(순수화에서 동작 검사 빨강)»을 만나면 저에게 멈추고 알린다 → 저는 onedal-71 에게 가/나 로 · 운행 동작이 걸리면 기사님께.
6. **push 는 하지 않는다**(기사님이 먼저 말씀하실 때만).

## 5. 확인 방법 — 커밋마다 (1판 그대로 · 순수화 한 줄 더함)

- 가. 파일 사이 옮기기 — 지운 줄이 모두 더한 줄에 같은 횟수로 있고(앞 `export ` 만 정규화), 새 줄은 `import` · `export` · 새 파일 머리 주석 · 빈 줄뿐. 임시 스크립트 · 레포에 안 남김.
- 나. 한 파일 안 함수 떼기 — 몸통 줄 글자 그대로 · 새 줄(함수 머리 · 부르는 줄 · 인자 · `return`)을 모두 찍어 하나씩 읽음.
- 다. 그 파일을 «파일 이름 · 글자 위치»로 읽는 기존 검사 — **깨진 것만이 아니라 그 파일 이름을 적은 검사 전부**를 먼저 센다(1단계에서 배움: 옮긴 뒤에도 초록인 거짓 초록 · 지키는 자리가 소리 없이 바뀐 것이 깨진 것보다 많았다). 먼저 동작 검사로 바꾸고, 구조 규칙만 경로를 고친다(같은 범위로). «경로만 고친 것» 다섯 넘으면 멈춤.
- 라. 화면 사진 앞뒤 견주기(관제웹) · 지도 캔버스는 사진이 곧 확인.
- 마. 동작 — 게이트 전부(서버 tsc · 관제웹 tsc -b · jest «Test Suites» 줄까지 · test:web · lint:gate · audit:dead · audit:docs · audit:socket) · 서버는 scenario + 사본 부팅 · 경로 · 도착을 만지면 `pnpm drive`.
- 바. 순환 가져오기 — 단계마다 새 파일들의 `import` 를 그어 한 방향인지 본다(임시 스크립트) · 사본 부팅이 런타임 순환을 드러낸다.
- **사. 순수화** — 바꾸기 전 · 뒤 동작 검사 초록 · 새 순수 셈 함수에 값만 넣는 단위 검사(세션 · DB 를 안 만든다) · 변이 🔴 한 번 · 바깥 일을 하는 함수 목록이 파일 머리와 맞는다(읽어서 확인 · 검사로 안 만듦).

## 7. 못 잡는 것

- 사진 견주기는 문제지가 띄우는 화면만 본다 — 합짐 세 콜 지도 같은 층 순서는 실주행 화면에서만.
- «옮기기만» 스크립트는 글자를 본다 — 모듈 상태(`let` · 캐시)를 옮기면 두 벌이 될 수 있어 단계마다 최상위 상태를 먼저 찾아 «한 파일에만 남는다»를 적고 시작한다.
- 순수화는 «같은 입력 → 같은 결과»를 동작 검사가 보는 길에서만 보장한다 — 검사가 안 지나는 갈래는 단위 검사를 더해 덮는다.
- 성능 · 렌더링 나아짐은 이 덩어리에서 재지 않는다(D9).
