## 차례를 이렇게 둔 까닭

0. **D0 배포 안전이 맨 앞.** D1~D4 를 고칠 때마다 실서버에 올리고, 그 배포가 지금의 배포 길을 지난다 — vite 가 죽으면 관제웹 하얀 화면(P8-01) · health 실패면 실서버가 꺼진 채(P8-08) · 운행 중 배포를 막는 것은 사람 손 하나(P8-09)(c6).
1. **D1 · D2 는 잡은 콜 · 좋은 콜에 바로 닿는다.** D1 의 «목록 복귀가 안전취소를 끔»(P1-02)은 실물에서도 나는 길(뒤로 가기 · 목록 오탐)이 있다(c6). D2 는 첫 걸음(끼어들기 사유 `INTERRUPT` 분리)이 운행 무변화라 **D1 첫 배포에 함께 실어** D2 차례가 올 때 며칠치 빈도가 쌓여 있게 한다(c6).
2. **D3 · D4 는 기사님 귀 · 눈.** 필터를 연 동안 관제웹이 비상 사이렌 · 안전취소 경고를 못 듣는다(P6-01 — 픽커 «삑»은 원달앱 폰에서도 난다). D4 는 결정 둘을 한 번에 먼저 여쭌다. D3 는 D0 뒤면 D5b · D6 앞이어도 된다.
3. **D5b · D6 은 서버 재시작 · 보안.** 로컬 · 실서버 비밀값이 같을 수 있다(P7-01 — 지문 확인은 지금도 할 수 있음).
4. **D7 은 D3 · D8 의 바닥.** 원천이 하나가 돼야 화면 글자 · 검사가 한 번에 맞는다.
5. **D9 는 재고 나서.** 코드 추적은 «매초 · GPS 마다 통째 그림»을 가리키지만, React DevTools 로 사건 셋(콜 들어옴 · 결재 · 1초 기기 목록)을 먼저 재서 고칠 순서를 정한다(P6 재 볼 자리 일곱).
6. **D10~D13 은 운행 무변화 정리.** 큰 파일 나누기(D13)는 손 목록 · 주석이 정리된 뒤가 범위가 작다(c6).
