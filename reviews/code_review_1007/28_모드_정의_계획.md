## 1. 지금은 이렇게 돈다 (27 요약)

- 모드는 두 걸음: 명령(관제웹 단추 · DB) → 실제로 도는 모드(허락 · 관제웹 · 다른 자동 폰 · 픽커 · 서버와 끊김 · 새 폰에 따라 자동을 알람으로 · 새 폰은 직접). 이 걸음은 `MODE_TABLE.situations` 한 표 + 서버 · 원달앱 각자 계산 + 검사 둘.
- 도는 모드 → 하는 일은 원달앱 손 동작 넷(`tapsList` · `sound` · `contracts` · `blocksAccept`)과 테두리 색 · 단추 글자만 표(`MODE_TABLE.acts`)에 있다. 원달앱 `ModeActs.kt` · `ModeFrame.kt` 는 표를 읽지 않는 사본이고 `ModeTablePairTest` 가 같은지 문다. TS 실행 코드가 `acts` 를 읽는 곳은 0.
- 그 밖의 행동 — 서버(필터 · 삑 · 체험 표시 · 자동은 한 폰 · 운영센터 표시)와 화면(색 · 배지 · 운영센터 이름 · 셈 · 고르기) — 은 자리마다 모드 이름을 직접 견준다.
- 관제앱(자바)은 모드로 가르지 않는다 — 범위 밖.

## 4. 원달앱 쪽 — 셋을 견줌

원달앱(코틀린)은 shared(TS)를 직접 못 읽는다.

| | 가. 사본 + 짝 검사 (지금 길) | 나. 서버가 공급에 표를 실어 보냄 | 다. 표에서 코틀린 파일을 뽑음(`pnpm gen:pages` 와 같은 길) |

| 하는 것 | `ModeActs` 에 원달앱이 읽는 칸(`capturedViaWhenOpenedByHand`)을 더하고 `ModeTablePairTest` 가 표와 견준다 | 블루투스 공급 틀(`bleProtocol.ts` · 관제앱 `SupplyService`)에 표를 싣는다 | 표 → 원달앱 생성 파일(`ModeActs` 를 생성 파일로) · 짝 검사는 «생성 파일 = 표» |
