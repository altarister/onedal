# 15b 원달앱 62판 폰 시험 — 줄별 시나리오

[15 시험표](15_원달앱61_폰시험.md)의 남은 줄을 «무엇을 하면 · 누가 무엇을 하고 · 무엇이 보이면 통과»로 다시 썼다. 원달앱 · 서버 · 시뮬레이터 · 관제웹 코드를 읽고 썼다. 아래 «관제웹»은 S23 관제앱 안의 관제 화면이다(근거 줄은 끝에).

## 0. 모든 줄에 공통 — 시작 전 확인 · 무효 기준

**시작 조건 (셋 다 참이어야 «자동» 시험이다)**
1. 관제는 **S23 관제앱 하나만** 연다 — 관제웹과 관제앱은 함께 열 수 없다(기사님). 관제앱이 관제(결재 화면)와 블루투스 공급을 함께 한다. 관제앱이 닫히거나 블루투스가 5초 안 닿으면 자동이 알람으로 내려간다(서버 «🛑 [관제웹 없음]» · 원달앱 «📶 공급 연결 끊김»)
2. 자동 폰은 A24 하나뿐이다(«🔁 [자동은 한 폰]»)
3. 관제앱에서 A24 모드 = 자동

**무효 기준:** 시험 중 서버 로그에 «🎛️ [모드] A24 명령 AUTO → … ALARM 로 돈다»가 찍히면, «🎛️ [모드 복귀]»까지 잡힌 콜은 그 시험에서 뺀다(10-08 00:06:52 ~ 00:08:56 이 그랬다).

**시뮬레이터가 스스로 하는 일 — 이것을 «손»이나 «원달앱»으로 읽지 않는다**
- 인성 **확정 전 상세**는 열리면 10초 카운트다운(«확정(10)»의 숫자)을 돌리고 0 이면 **스스로 목록으로 닫는다**. 원달앱은 이 화면 변화를 «기사님 손(상세 → 목록)»으로 잘못 적는다 → [찾은 것 F6]
- 확정 뒤 상세 «취소»: 팝업 없이 바로 목록 · 그 콜은 다시 안 나온다. «닫기»: 상세만 닫음 · 콜은 확정 목록에 남음
- 시나리오(현황판)는 콜을 **한 번에 하나만** 낸다. 두 콜을 동시에 띄우려면 시뮬레이터 **개별콜** 모드 + 현황판 «🚚 개별콜» 두 번

**시간 셋 (같은 30초가 아니다)**
- 원달앱 안전취소 30초: 원달앱이 «확정»을 누른 때부터
- 서버 안전취소 30초: 서버가 `/confirm` 을 받은 때부터 — 원달앱보다 수십 ms 먼저 끝난다. 로그는 «관제탑으로 부터 수동 취소/방출»이라고 찍히지만 **서버 자신의 타이머다** → [찾은 것 F7]
- 관제웹 심사 막대: 판정이 관제웹에 **도착한 때**부터 — 늦게 시작해, 막대가 남아 있어도 콜이 먼저 사라질 수 있다 → [찾은 것 F8]
