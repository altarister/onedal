# 39 X12 남은 것 — 시를 뺀 주소(«경기 광주 초월읍»)를 온전한 주소로 (계획 · 코드 없음 · 24)

## 무엇이 문제인가
- 화물24시는 실물(캡처 18 «경기 군포 부곡동»)도 시뮬(«경기 광주 초월읍»)도 시 · 군 이름에서 «시»를 빼고 적는다.
- 원달앱 요건 검사(`OrderRequirement.missingDetail` → `AddressForm.isFull`)가 이것을 «상차 주소 짧음»으로 보고 서버에 안 보낸다.
- 그래서 기사님 손이나 알람으로 연 화물24시 상세에서는 판정 · 삑이 안 선다(70판 시험 장면 1-2 · 10-09 06:48:13).
- 원달앱이 목록에서 눌러 연 상세는 목록 값을 써서 지금도 이 검사를 안 거친다.

## ② 지금은 이렇게 돈다 (코드로 봄)
- `AddressForm.isFull`(onedal-app core/engine/AddressForm.kt:55)
  - 주소를 띄어쓰기로 토막 낸다(시도 긴 이름은 `SIDO_SHORT` 로 «서울» 등으로).
  - 명부(`RegionRegister.withAdmin` · 서버 지도와 같은 법정동 ∪ 행정동)의 시군구 키 토막이 주소에 연달아 있는지 본다.
  - 그 뒤에 그 시군구의 읍면동이나 «…동/읍/면/가» 토막, 또는 «…로/길 + 번지»가 있으면 온전한 주소다.
- 명부 키는 두 꼴이다.
  - 광역: «서울 강남구» · «인천 …» · «대전 …»
  - 도 아래: «광주시» · «군포시» · «성남시 분당구» · «가평군»
  - 도 이름(«경기»)은 키에 없다. 있어도 없어도 된다.
- «경기 광주 초월읍»의 토막은 [경기, 광주, 초월읍]이다. 키 «광주시»와 맞는 토막이 없어 거짓이다.
  - «초월읍»은 명부의 광주시 읍면동에 있다.
  - «시»만 빠져서 떨어지는 것이다.
- 배차망별로 오는 꼴(장부 원문)
  - 인성: «경기 광주시 초월읍 경충대로 907 모다아울렛 곤지암점» — 시 붙음
  - 픽커: «경기 광주시 곤지암읍 곤지암성당» — 시 붙음
  - 화물24시: 장부에 줄이 0 이다(사업자 없음). 상세 화면은 «경기 광주 초월읍» · «경기 군포 부곡동» — 시 뺌
- 서버는 콜 주소를 카카오 주소 검색(`kakaoService.geocodeCallAddress`)으로 좌표로 바꾼다. 못 찾으면 읍면동 중심으로 물러선다(«📍 좌표 대략»).
  - «경기 광주 초월읍»을 카카오가 찾는지는 확인 안 했다(단계 1).

## ③ 지금 값 대조
- 새 설정값 · 새 저장 칸은 없다.
- 명부는 원달앱 상수(119 키: 광역 3 · 도 아래 시군 59 키 + 구)이고, 서버 지도 산출물(`pnpm gen:regions`)에서 뽑는다.

## ④ 순위 검산 — 시 · 군을 떼면 이름이 겹치나
- 도 아래 시군 59 개에서 끝 «시 · 군»을 뗀 이름: 서로 겹침 0 · 광역 이름(서울 · 인천 · 대전)과 겹침 0 · 한 글자 이름 0(10-09 명부로 셈).
- 그래서 지금 명부로는 «광주» → «광주시», «군포» → «군포시»가 하나로만 풀린다.
- 🔴 명부가 전국으로 넓어지면 겹친다: «광주»(경기 광주시 ↔ 광주광역시) · «고성»(강원 ↔ 경남) 등.
  - 그때는 앞의 도 이름(«경기»)으로 가려야 한다. 그런데 명부 키에 도 이름이 없다.
  - 그래서 «뗀 이름이 겹치면 빨간불»인 동작 검사를 함께 둔다. 명부를 넓히는 날 그 검사가 막는다.

## 여쭐 것 (하나)
- 원문(71 · X12): «화물24시 상세는 시를 뺀 주소라 «상차 주소 짧음»으로 버린다 — 온전한 주소로 볼 규칙».
- 부딪히는 문장(AddressForm 머리): «전체 주소 = 명부의 시군구가 주소에 있고 …» — 지금은 키 글자 그대로만 맞춘다.
- 가: **판정만 넓힌다** — `isFull`(과 같은 명부를 쓰는 `knownDong`)이 도 아래 시군 키를 «시 · 군을 뗀 이름»으로도 맞춘다.
  - 주소 글자는 그대로(«경기 광주 초월읍») 서버로 간다.
  - 세 배차망이 같은 한 판정이다. 시를 붙여 오는 인성 · 픽커는 지금과 같다.
- 나: **글자를 채운 뒤 판정한다** — 원달앱이 상세 주소의 시 뺀 토막을 명부로 채워(«광주» → «광주시») 그 글자로 판정하고, 서버에도 채운 글자를 보낸다.
  - 관제웹 표시 · 서버 좌표 찾기 · 목록 줄 대조 열쇠가 모두 «경기 광주시 초월읍»으로 같아진다.
  - 원달앱이 보내는 글자가 화면 글자와 달라진다(원문 rawText 는 그대로 둔다).
- 추천 가.
  - 바꾸는 자리가 판정 함수 한 곳이다.
  - 서버 좌표는 카카오가 시 뺀 주소도 찾는지 단계 1 에서 한 번 확인한다. 못 찾아도 읍면동 중심으로 물러서니 판정은 선다.
  - 확인에서 «좌표 대략»만 나오면 나로 바꾼다.

## ① 단계 — 무엇이 참이면 끝인가
1. 확인(코드 없음): 로컬 서버로 카카오에 «경기 광주 초월읍» · «경기 군포 부곡동»을 한 번씩 묻는다(`geocodeCallAddress` · 카카오 2회).
   - 끝: 두 주소가 «좌표 대략» 없이 좌표로 나오는지 적었다. 대략이면 «나»로 다시 여쭌다.
2. 검사 먼저(빨간불): 원달앱 `AddressFormTest` 에 동작 검사를 더한다.
   - 실물 캡처 18 «경기 군포 부곡동» · 시뮬 «경기 광주 초월읍» → 온전
   - 대조: «경기 광주 없는동» → 짧음 · «광주 초월읍»(도 없음)도 온전 · «경기 광주시 초월읍»(지금) → 그대로 온전
   - 명부 검사: 도 아래 시군의 뗀 이름이 서로 · 광역 이름과 겹치지 않는다
   - 끝: 새 검사가 지금 코드에서 빨강이다(겹침 검사는 초록).
3. 고침: `AddressForm` 의 «구 없는 시» 합치기(`citiesWithoutGu`) 옆에 «시 · 군 뗀 이름» 키를 한 벌 더한다. 같은 명부 · 같은 함수 · 세 배차망 같은 순서이고, 화물24시만의 흐름은 없다.
   - 끝: 2 의 검사가 초록이다. 원달앱 testDebugUnitTest · audit:dead 가 초록이다. `Hwamul24DetailReadTest` 의 «시뮬 꼴 요건 통과» 견본을 실물 꼴(시 뺌)로 바꿔도 초록이다.
4. 폰(다음 판): 시뮬 화물24시 손 진입 상세 → «🔔 [삑]» · 결재석 판정 · «요건 미달» 없음(38 장면 1-2).
   - 끝: 그 장면이 통과다.
