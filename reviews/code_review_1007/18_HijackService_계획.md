읽는 사람: onedal-71(관제 리뷰) · 기사님(승인). 쓴 사람: onedal-24.
목표(기사님 말씀 그대로): «함수들이 퓨어해지고 종속관계가 최소화된 모듈화된 구조 — 코드 품질 · 상태 관리 · 성능 · 렌더링 최적화 · 주석까지». D13 이 서버 · 관제웹에 한 일을 원달앱의 가장 큰 파일에 한다.

## 4. 단계 — 단계마다 «무엇이 참이면 끝인가» (①)

**0단계 — 바닥 셈(고치지 않음).** 글자 검사 41 + 16 을 «어느 토막을 읽나»로 표에 나눈다. 1·2단계 판단 줄에 변이 10개 안팎을 넣어 지금 검사가 몇 개를 잡는지 센다(D13 의 «첫 증거»와 같은 셈 · gradle 단위 검사 + jest).

**1단계 — 누를까 결정 → `core/ListTapPick.kt`(가칭).** 1663–1870 의 판단을 `pick(통과 콜들 · 막은 기억 · 손 먼저 · 모드 사실 …) → 누를 콜 · 안 연 까닭` 으로. 본문 줄은 글자 그대로 옮기고 바뀐 줄은 머리 · 넘기는 값뿐. 서비스는 사실을 모아 부르고 결과대로 누른다.
→ 끝: 단위 검사(일어나야 함 + 안 일어나야 함) 초록 · 0단계 변이 중 이 토막 것 전부 🔴 · 이 토막을 읽던 글자 검사는 동작으로 바뀜 · 디프 견줌 «옛 줄 잃음 0» · gradle 컴파일 · 단위 검사 977+ 초록 · jest 초록.

**1단계 줄 단위(onedal-71 승인 · HEAD 126297da 줄 번호).**

## 8-1. 남은 것 (이 덩어리 안 · 65판 견줌 뒤)

- **scanRow 안의 판단과 기록 가르기** — 2단계는 루프 몸통을 글자 그대로 `ListRowScan.scanRow` 로 옮긴다(판단과 기록이 줄마다 섞여 «판단만 값으로» 떼면 차례가 바뀐다). 판단(요금 0 · 덜 읽힘 · 이미 본 콜 · 막힌 계정 · 이미 연 콜)과 기록(기억 넣기 · 보고 · 성적표)을 가르는 «셈은 값을 받아 값을 돌려줌»은 65판 견줌 뒤에 한다 — 2단계의 ListRowScanTest 가 그 가름의 안전망이다. **2단계는 «순수화 끝»이 아니다** (onedal-71).
