# 49. 필터 · 모드 · 판정은 블루투스 한 길로 — 관제앱이 공급하고, 확정은 관제앱이 한 번에 한 폰에게만 허락한다 (모든 폰 자동)

reviews/48 «다». 방향은 기사님이 onedal-69 창에서 «가 보내»로 승인하신 판(10-06).

## 목표 (기사님)

- **모든 폰이 자동으로 잡는다.**
- 필터를 폰이 수동으로 받아 오는 HTTP 방식은 싱크가 안 맞는다 — 믿을 수 없는 정보가 쌓이면 안 쓰게 된다.
- 한 사람의 폰들은 늘 같이 다니고(10m 안), 일하는 동안 켜져 있고, 끊겨도 스스로 다시 붙는다.

## 원칙 셋

1. **필터 변경 · 폰 모드 변경 · 판정은 아주 빠르게** — 기사님이 관제앱에서 누르시면 저장은 서버가 하지만, 화면이 바뀌는 것은 스캔앱이다. 그러니 이 셋은 블루투스로 간다.
2. **한 값은 한 길로만** — 지금 HTTP 응답으로 오는 필터 · 모드 · 판정은 블루투스로 이사하고 HTTP 쪽 길은 지운다(기사님 *"한 벌이 2개는 문제가 있다"*).
3. **일이 생긴 쪽이 서버와 동료 폰에 함께 알린다 · 받은 쪽은 자기 일을 한다** — 서버는 저장 · 계산 · 판정, 앱은 화면과 동작.

## 블루투스가 끊겼을 때 — 기사님 «가»

- HTTP 예비 길을 두지 않는다. 스캔앱은 **마지막에 받은 값으로 목록 판정과 알람만** 계속하고, **확정은 하지 않는다.**
- **확정 허락은 끊긴 그 순간 멈춘다**(«된다»가 안 오니 기다림 없이) — 아래 5초는 관제웹 표시 기준일 뿐이다.
- 🔴 **관제웹 화면 바뀜 (둘)**:
  1. «블루투스 끊김 · 끊긴 시각» — 숨이 5초 없으면(잠깐 끊김에 깜빡이지 않게). 마지막 값으로 도는 알람이 «믿을 수 없는 정보»가 되지 않게 몇 분째 옛 값인지 보이게.
  2. «관제앱 폰 없음 — 알람만 · 확정 안 함» — 관제웹을 PC 로만 보실 때(고를 것 ② 가).

## 0-3 결과 — 필터 본문을 블루투스로 몇 초에 넘기나 (10-06 · S23 관제앱 흉내(포그라운드 서비스) → A24 스캔폰)

A24 원달앱이 실제로 들고 있던 `activeFilter`(33,234 바이트)를 보냄 · MTU 517 · 조각 512 바이트 · 조각마다 «써짐» 답을 기다리는 쓰기(가장 느리고 안전한 방식) · A24 가 다 모아 sha256 지문을 답으로.

| 보낸 것 | 크기 | 걸린 시간(3번) | 지문 |
|---|---|---|---|
| 원문 | 33,234 바이트 · 65조각 | 4.02 · 4.18 · 4.18초 | 3번 다 맞음 |
| **압축(gzip)** | **7,116 바이트 · 14조각** | **0.93 · 0.92 · 0.88초** | 3번 다 맞음 |

- 결론: 고를 것 ① 가(압축해서 통째로)면 **필터 전체가 1초 안**. 답을 안 기다리는 쓰기로 바꾸면 더 줄 여지가 있다(실측 전).
- 🔴 실제로 겪은 것(0-5 근거): 블루투스 한 번 쓰기의 최대 길이는 **512 바이트** — 514 로 보내자 `IllegalArgumentException` 으로 앱 프로세스가 죽었다. 조각은 512 이하로 · 블루투스 콜백 · 쓰기를 모두 감싸 원달앱 접근성 서비스 · 관제앱이 죽지 않게.
- 쓰기는 한 번에 하나 — 필터를 보내는 동안 숨 쓰기를 멈춰야 한다(처음 판은 둘이 부딪혀 감시가 연결을 끊었다).

## 나중에 할 일 (기사님 10-06)
- **스캔폰 → 관제앱 폰 칸 값도 블루투스로** — 기사님: *"스캔앱에서 바꾸어 관제앱에 보이는 것들이 있어 폰 영역에 들어가는 값들이야. 이것도 나중에는 블루투스로 연결 가능할 것 같아. 지금은 서버 값으로 바꾸고 있는데."*
  - 지금은 이렇게 돈다: 원달앱이 HTTP 보고(`/api/scrap` · 화면 · 받은 모드 · 필터 통과 수 · 화면 켬 · 위치 …) → 서버가 기기 세션에 적음(`touchDeviceSession`) → 1초마다 관제웹에 `telemetry-devices` → 관제웹 폰 칸.
  - 할 일: 블루투스 알림 칸(폰 → 관제앱)으로도 그 값을 보내 관제앱 폰 칸이 서버를 거치지 않고 바로 바뀌게 — 「한 값 한 길」로 어느 값을 옮기고 어느 값을 서버에 남길지(운영센터 · 기록 · 데드맨은 서버가 봐야 한다)를 그때 표로 가른다.
  - 언제: ①(필터 · 모드 · 결재 이사)을 다 마친 뒤.
- **시뮬레이터가 확정된 콜을 목록에서 뺀다** (10-07 · 관제 판단 · 기사님 «나 — 나중에»)
  - 까닭: 실물 인성 · 화물24시는 잡은 콜을 목록에서 뺀다. 시뮬레이터는 확정된 콜을 다시 띄워, 시험할 때 «이미 잡은 콜을 또 확정 → 서버가 재열람으로 판정 안 함 → 30초 뒤 안전취소(취소 +1)»가 생긴다(폰 시험 10-07 01:16 · 서버 규칙 ① 은 지켜짐 — 확정 콜은 안 건드림).
  - 고칠 곳: `onedal-sim`(서버가 아님 — 실물에서 안 나는 일을 서버 표의 한 칸으로 두지 않는다). 시험 도구만의 일 · 운행 무변화.
  - 그동안: 시험할 때 아직 안 잡은 다른 콜로 한다.
- **원달앱 «결재 대기 1초 보고» 빼기** — 결재는 블루투스로 오지만 그 1초 보고가 관제웹 심사 막대의 진행 핑(`telemetry-ping`)을 싣는다. 막대를 공급 쪽 사실로 옮길 때 같이(reviews/50 ①-5 «미룸»).
