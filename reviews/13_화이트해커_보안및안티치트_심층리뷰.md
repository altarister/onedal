## 📌 총평 및 보안 위협 진단

배차망(인성콜, 화물24시 등) 앱은 주기적으로 **안랩 V3 Mobile, 앱실링(AppSealing), 락인컴퍼니(LIAPP), Xigncode** 같은 모바일 보안 솔루션을 업데이트하여 자동화 프로그램을 사냥합니다.

현재 1DAL의 안드로이드 앱 코드는 순수하고 정직하게 작성되어 있어, **배차망 보안 모듈이 마음만 먹으면 0.1초 만에 원달의 존재를 감지하고 기사 계정을 정지시킬 수 있는 상태**입니다. 또한 원달 자체의 APK와 통신 패킷도 전혀 암호화/난독화되지 않아 경쟁사나 크래커에게 기술이 통째로 털릴 위험이 큽니다.

해커의 시각에서 배차망 보안 솔루션이 원달을 사냥하는 방식과 이를 우회하는 스텔스(Stealth) 방어 전략을 제시합니다.

## 1. 배차망 보안 솔루션의 매크로 탐지 원리 & 1DAL의 취약점

### ⚠️ 배차망이 원달을 적발하는 3대 기법
1. **설치된 접근성 서비스 패키지명 블랙리스트 검사**:
   - 보안 솔루션은 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 시스템 설정을 조회하여 활성화된 접근성 서비스 목록을 수집합니다.
   - 현재 원달의 패키지명(`com.onedal...`)이 그대로 노출되어 있어, 배차망이 이 패키지명을 블랙리스트에 올리는 순간 모든 사용자가 일괄 정지됩니다.
2. **`MotionEvent`의 가상 터치 플래그 검사 (`FLAG_IS_ACCESSIBILITY_EVENT`)**:
   - 사람이 손가락으로 화면을 누르면 정전용량 센서의 접촉 면적(`size`), 압력(`pressure`), 미세한 흔들림이 생성됩니다.
   - 접근성 서비스의 `performAction(ACTION_CLICK)`은 하드웨어 터치 신호가 아닌 OS 소프트웨어 이벤트 플래그(`FLAG_IS_ACCESSIBILITY_EVENT` 또는 `TOOL_TYPE_UNKNOWN`)를 달고 전달되므로, 배차앱은 **"이 클릭이 사람 손가락이 아닌 접근성 서비스가 쏜 가짜 클릭임"**을 100% 식별할 수 있습니다.
3. **터치 간격 엔트로피(Entropy) 통계 분석**:
   - 사람이 아무리 빨라도 화면이 바뀐 뒤 클릭하기까지의 반응 시간은 정규분포(150~300ms)를 따르며, 터치 좌표도 매번 몇 픽셀씩 흔들립니다.
   - 0.01초 만에 버튼 정중앙 좌표를 누르는 패턴이 반복되면 서버 로그 분석에서 기계로 확정 판정됩니다.

### 💡 스텔스(Stealth) 우회 엔지니어링
- **패키지명 랜덤화 빌드 파이프라인 (Polymorphic Package)**:
  - 기사마다 배포되는 APK의 패키지명과 서비스 클래스명을 난수(예: `com.samsung.accessory.util.service...`)로 빌드하여 배차망의 패키지명 블랙리스트 기반 차단을 원천 무력화합니다.
- **제스처 기반 아날로그 터치 시뮬레이션 (`dispatchGesture`)**:
  - 단순 `ACTION_CLICK`을 폐기하고, 안드로이드 `dispatchGesture` API를 사용하여 20~40ms 동안 손가락이 화면을 누르고 떼는 실제 아날로그 터치 곡선(Path)과 미세한 압력/면적 값을 생성하여 전달합니다.
- **가우스 분포 기반 인간형 타이밍 지터 (Gaussian Jitter)**:
  - 반응 시간과 터치 좌표에 정규분포 가우시안 노이즈(평균 130ms, 표준편차 ±25ms, 좌표 오차 ±8px)를 주입하여 보안 분석 엔진의 통계적 매크로 탐지를 통과합니다.

## 2. 원달 앱 자체의 보안 & 지적재산권(IP) 보호

### ⚠️ 현재 상태의 위험성
- `onedal-app` APK를 `jadx-gui`나 `apktool` 같은 무료 역어셈블러에 넣고 돌리면, **자바/코틀린 소스코드가 1초 만에 원본 그대로 복원**됩니다.
- 서버 API 엔드포인트 주소, 시크릿 키, 판정 로직이 그대로 노출되어 경쟁사가 원달의 핵심 로직을 100% 복제하거나, 악의적 유저가 크랙 버전을 만들어 무단 배포할 수 있습니다.

### 💡 보안 강화 가이드라인
- **R8 / ProGuard 다중 난독화 및 문자열 암호화**:
  - 클래스명, 메서드명, 변수명을 의미 없는 영문자(`a`, `b`, `c`)로 치환하고, 소스코드 내 하드코딩된 서버 주소와 키값을 AES-256으로 런타임 복호화 처리.
- **APK 무결성 검증 & 서명 해시 체크**:
  - 앱 기동 시 자신의 서명 키(Keystore SHA-256)를 검사하여 앱이 변조(Modding)되었거나 Frida 등의 후킹 도구가 붙어 있으면 즉각 프로세스를 자폭(Exit)시키는 셀프 프로텍션(Self-Protection) 구축.

## 3. 네트워크 통신 보안 & API 탈취 방어

### ⚠️ 현재 상태의 위험성
- `HttpURLConnection` 및 일반 Socket.IO 통신이 사용되고 있어, 유저가 Charles Proxy나 Fiddler 같은 패킷 캡처 툴을 사용하면 서버와 앱 간에 오가는 배차 정보와 토큰을 중간에서 엿보거나 변조(Man-in-the-Middle Attack)할 수 있습니다.

### 💡 보안 강화 가이드라인
- **SSL/TLS 핀닝(Certificate Pinning)**:
  - 원달 앱이 오직 원달 서버의 고유 SSL 인증서와만 통신하도록 강제하여, 중간자 프록시 패킷 감청을 원천 차단.
- **동적 리퀘스트 서명 (HMAC Request Signing)**:
  - 앱에서 서버로 스크랩 데이터를 보낼 때, 타임스탬프와 기기 고유 ID를 결합한 HMAC 해시 토큰을 헤더에 실어 보내 서버 외부에서의 무단 API 호출을 완벽히 차단.
