# [기획] 1DAL 운영센터 — 가족 1차판 (기사님 · 딸 · 와이프)

참고: [27_어드민_계획.md](27_어드민_계획.md)(전체 구상 · 코드 조사).
이 문서가 **하나로 모은 판**이다. 단계마다 구조 · 설계 · 연동 · 검사 · 기사님 손을 적었다. 04 · ab · e7 검토를 반영했다.

기사님 말씀 (원문):
- *"일단 시작은 기사1(나), 기사2(딸), 관리자(와이프) 이렇게 3명이 쓸 꺼야. 법적인 것은 서비스가 만들어지면 그때 어떤 자격이 필요한지 따진다. 12월 화물운송 시작할꺼야. 그때 개인 사업도 만들꺼고."*
- *"회원 가입 관리, 탈퇴 등등은 형식적으로 모든 페이지는 있어야 한다. 내용은 내가 만들어 볼께. 스텝은 있어야 한다."*
- *"내가 기사로 현장에 나가고 와이프가 집에서 상차지 하차지에 전화해 주면 협업이 가능할 것 같다. 1차 가족 버전이니까 그렇게 해도 좋을 것 같은데."*
- *"방향은 e7 판으로 하고 너가 취합해. 그리고 단계별 개발 방향도 넣어 주고 — 구조, 설계, 연동 등등."*
- *"어드민이면서 유저면 안되는거야?"* (ab 창) → 된다 — 기사님 = 기사 + 관리자.

## 기준 (가족 1차판 — 이 문서의 모든 설계가 따른다)

1. **모든 자료에는 주인(기사)이 붙는다** — 서버는 읽을 때도 쓸 때도 주인을 확인하고, 확인 못 하면 거절한다.
2. **기사는 모두 같은 기능을 쓴다** — 딸도 기사님과 같다. 자동 잡기는 관리자가 기사마다 켜고 끈다(첫 값: 둘 다 켬).
3. **관리자는 모든 기사의 자료를 원문으로 본다** — 쓰는 것은 통화 결과(신고)뿐, 결재(KEEP/CANCEL)는 기사만 누른다.
4. **기사님 계정은 기사이면서 관리자다.** 와이프는 관리자.
5. **남을 받을 때(12월 뒤)** 가림 · 자격 · 기능 차이를 다시 본다.

## 끝의 모습 — 무엇이 참이면 끝인가
> 딸이 가입 주소를 열어 → 동의(형식) → 가입 정보 → 승인 대기 → 와이프가 운영센터에서 승인 → 딸이 같은 주소에서 앱 두 개를 받아 설치 → 화면 안내만 따라 폰 연결 → 자기 필터로 첫 콜(알람).
> 기사님이 콜을 KEEP 하면 와이프 화면에 «전화할 콜»이 뜨고, 와이프가 상차지 · 하차지에 전화해 결과를 적으면 **기사님 판정 단계에 그대로 들어간다**(누가 적었는지 남는다).
> 딸 폰에 개발자 PC · adb · DB 손질이 닿지 않는다. **두 기사는 서로의 콜 · 위치 · 거래처를 한 줄도 못 본다**(1단계 검사의 기준 문장).

## 6. 단계 — 구조 · 설계 · 연동 · 검사 · 기사님 손

### 0. 결정
- 끝의 기준: 기사님 «가» — 새 폴더 `onedal-web/ops/` · 4장 칸(⑤-4 다섯) · 아래 «기사님이 정하실 것».

### 1. 기준 1 지키기 (주인 확인이 빠진 곳 · 겹칠 수 있는 폰 이름 · 함께 쓰는 거래처 표를 고친다)
- **구조**: 서버 `routes/devices.ts` · `state/pairingStore.ts` · `routes/auth.ts` · 로그인만 하면 전부 주는 문 5개(폰 상태 · 폰 초기화 · 앱 이상 기록 · 거래처 · 화면 새 글자 — 경로 · 파일 이름은 1단계 줄별 안에 적는다) · DB 에 쓰는 소켓 이벤트 전부(`save-cargo-report` · `report-milestone` …) · `places`/`user_places` · `services/mask.ts`(자리만) · `index.ts` CORS. 원달앱 `ApiClient` · 연결 화면.
- **설계**:
  - 기기 비밀 토큰 — 연결할 때 발급(`user_devices.token_hash` · 원문은 앱에만) · 앱 요청마다 헤더로. 폰은 식별 id(난수)와 표시 이름(기종) 두 칸.
  - 연결 번호 시도 한도 · 잠금(DB 기본값 · 근거 한 줄).
  - 문 5개는 «자기 것만 / 관리자만».
  - 🔴 **콜 주인 확인** 한 함수 — «이 orderId 는 이 기사의 콜» — DB 에 쓰는 모든 소켓 이벤트 앞에 둔다.
  - `user_places` 로 거래처 개인 칸을 기사별로(지금 줄은 기사님 것으로 복사).
  - 연결 안 된 폰은 거절(`ADMIN_USER` 가짜 기사 없앰).
  - 사실 칸을 요청마다 DB 에서 — HTTP 는 요청마다, 소켓은 붙을 때 보고 정지하면 `io.in(userId).disconnectSockets()` 로 끊는다.
  - CORS 를 알려진 주소(1dal · ops · rehearsal · 개발 포트)로 좁힌다.
  - HTTPS 확인 · 배포판 앱은 HTTPS 만.
  - 가림 자리(`mask.ts` · 켜기 값 · 지금은 꺼 둠) · 로그 줄에 회원 구분.
  - 원달앱: 거절(401/403)을 받으면 «폰 연결이 풀렸습니다 — 다시 연결» 띠 · 보고 간격을 늦춘다.
- **연동**: 짝 순서 — DB 백업(기사님 손) → 서버 먼저(토큰 받되 없어도 통과) → 원달앱(토큰 발급 · 싣기) → 기사님 폰 다시 깔기 + 재연결(운행 아닐 때 · 4단계 서명 교체와 같은 날이면 한 번에) → 기사님 폰 둘의 `token_hash` 를 DB 로 확인 → 서버 강제(토큰 없으면 거절).
- **검사**: 계정 A 로 **모든 문을 불러도** B 의 것이 한 줄도 없다 — 문 목록은 손으로 적지 않고 라우터 · 소켓 이벤트에서 뽑는다(문을 하나 더하면 검사가 저절로 그 문도 부른다) · 기사 계정으로 `/api/ops/*` → 403 · 남의 orderId 로 소켓 쓰기 → 거절 · 토큰 없는 폰 거절(강제 뒤) · 시도 한도.
- **끝**: 로컬에 계정 둘 · 폰 둘로 위 검사 초록 · 기사님 폰이 재연결 뒤 지금과 같이 돈다.
- **기사님 손**: 실서버 DB 백업 · 앱 다시 깔기 · 재연결.

### 3. 운영센터 뼈대
- **구조**: `onedal-web/ops/`(Vite · React · Tailwind — 관제웹과 같은 틀) · `pnpm-workspace.yaml` 한 줄 · 서버 `routes/ops.ts` · `index.ts` 에 `OPS_HOST = 'ops.'` → `ops/dist`(REHEARSAL_HOST 와 같은 자리 · `/api` 는 모든 주소에서 산다). README 「구성」 · 「포트」(3002) 한 줄씩.
- **설계**: 관리자 검사는 두 자리 — HTTP 붙일 때 `app.use('/api/ops', requireAuth, requireOps, …)` 한 번 · 소켓 관리자 방에 들 때 `ops_allowed_at` 확인. 화면 `/members` · `/phones` · `/anomalies` · `/contents` · `/notices` · `/audit`. 모든 쓰기는 `ops_audit` 한 줄. 정지 규칙(끝난 뒤 · 영업일 · 즉시 · 소켓 끊기).
- **연동**: `deploy.yml` 에 ops 빌드 단계(실패해도 기사용 서버는 올린다 · 시뮬 단계와 같은 모양). ⚠️ `onedal-web/**` 조건이 `ops/` 도 덮는다 — **운영센터만 고쳐 push 해도 실서버가 다시 뜬다 · 운행 중 배포 금지가 여기에도.** DNS `ops.altari.com` · 인증서 · 구글 로그인 허용 원본에 새 주소. 로그인 토큰이 주소별 저장이라 운영센터는 따로 로그인한다(기사님은 관제웹 · 운영센터 두 번). 기사님 · 와이프 `ops_allowed_at` 켬.
- **검사**: `ops_allowed_at` 있는 계정만 들어온다(HTTP · 소켓 둘 다) · 승인 · 정지 · 탈퇴가 되고 `/audit` 에 남는다 · `/contents` 글이 관제웹에 뜬다 · 관제웹이 `ops/` 를 가져다 쓰지 않는다(기사 폰 파일에 운영센터 코드 없음).
- **기사님 손**: 새 폴더 허락 · DNS · 구글 콘솔 원본 추가 · 와이프 첫 로그인.

### 4. 앱 배포 (딸이 스스로 설치)
- **구조**: 서버 `routes/downloads.ts`(APK 는 EC2 의 레포 밖 폴더) · 운영센터 `/releases` · 원달앱 · 관제앱 `build.gradle.kts` · `AndroidManifest` · `network_security_config`.
- **설계**:
  - 릴리스 서명 키(레포 밖 두 곳 보관). 🔴 **debug 빌드도 같은 릴리스 키로 서명**(signingConfig · 키는 개발 PC 에만) — 아니면 기사님 폰을 릴리스로 깐 뒤 개발 중 바로 까는 길(`installDebug`)이 서명이 달라 막힌다. `applicationIdSuffix` 로 둘을 따로 두지 않는다(접근성 · 연결이 두 벌).
  - 서버 주소: 배포판은 `BuildConfig` 로 `isLiveMode` 기본값을 실서버로 · PC 주소 칸 · 로컬 시험 도구는 debug 에서만 · release 는 `network_security_config` 로 암호 없는 통신을 막는다.
  - `versionCode` 는 릴리스마다 올린다(규칙) · 비교는 versionName 이 아니라 versionCode · `app_releases` 에 최신/최소 · 앱이 `/api/scrap` 응답의 버전을 보고 «업데이트 있음 / 해야 씀».

  - 첫 실행 점검 화면(서버 · 연결 · 접근성 · 배터리 · 안드로이드 버전 — 빨간 칸 옆에 안내 글/영상).
- **연동**: 구글 콘솔에 릴리스 키 SHA-1 · 테스트 사용자에 딸 · 와이프. 기사님 폰 둘을 릴리스 서명으로 다시 깔기(1단계 재연결과 같은 날).
- **검사**: 공장 초기화 폰(또는 딸 폰)에서 adb 없이 주소만으로 설치 → 연결 → 첫 알람 · 개발 PC 에서 `installDebug` 가 릴리스로 깐 폰에 덮어 설치된다.

### 5. 운영 화면 + 통화 도우미
- **구조**: 운영센터 `/calls` · `/map` · `/stats` · 카카오 사용량. 서버 `routes/ops.ts` 읽기 문 · 관리자 소켓 방.
- **설계 — 통화 도우미**:
  - 대상: 기사가 **KEEP 한 콜**만(미리보기 콜은 10~30초 안에 사라져 전화가 따라가지 못한다). 판정이 🟡(통화 필요)인 KEEP 콜을 맨 위로.
  - 와이프가 전화 → 결과(짐 크기 · 상차 가능 시각 · 상대가 취소했다는 **정보**)를 적는다. 🔴 «취소됨»은 정보다 — CANCEL 결재는 기사님이 누른다.
  - 적는 길: 소켓 `save-cargo-report` 몸통을 `saveCargoReport(driverId, orderId, report, by)` 한 함수로 빼서 기사 소켓과 `/api/ops` 가 같이 부른다 → `bridgeCargoReport` 를 **기사 userId 로** 불러 단계 행 · 판정이 지금처럼 읽는다. 관리자는 DECLARED(통화 신고)만 적는다 — ACTUAL(현장 실측)은 현장 기사만.
  - 단계 행 `by` 칸으로 출처를 남긴다 — 실측 통계(`pnpm db ledger` ✍️)가 관리자 신고를 기사 실측처럼 세지 않는다. 두 사람이 같은 정거장을 적으면 나중 것이 이기고, 관제웹 · 운영센터 둘 다 «마지막으로 누가 적었나»를 보인다.
- **연동**:
  - 관리자 방에는 **콜 사건(KEEP · 판정 · 취소)만** — 이벤트 수십 곳에 하나씩 더하지 않고, 1초 동기(`buildOrderSync` · `sync-active-orders`)를 가족 기사마다 관리자 방에도 보내는 **한 곳**으로. 위치는 읽기 문으로(새 1초 방송 없음).
  - 적은 뒤 `steps-synced` 를 적은 소켓이 아니라 `io.to(driverId)` 와 관리자 방 둘에.
  - 기사 관제웹은 새 줄을 띄우지 않고 단계 행에 «(와이프)» 출처 표시만 붙인다(같은 사실을 두 번 말하지 않는다).
  - 🔴 관리자가 결재를 대신 누르지 않는다 — **서버가 막는다**: 관리자 소켓의 `decision` · `report-milestone` 은 거절.
- **검사**: 관리자가 기사 콜에 통화 결과를 적으면 기사 판정 단계가 닫히고 관제웹에 «(와이프)»로 뜬다 · `by` 가 관리자로 남는다 · 기사 계정은 남의 콜에 못 적는다 · 관리자 소켓의 결재 → 거절 · 미리보기 콜은 `/calls` 에 없다.
- **기사님 손**: 없음 — 와이프 첫 사용.

### 6. 허락 칸 (허락 + 기한 — 기능 차이는 이 칸으로만)
- **설계**: 자동 잡기 `auto_allowed_at` + `auto_until` · 통계 `stats_allowed_at` + `stats_until` · 유료 `paid_until`. 기한 칸이 비면 기한 없음. 부품은 «지금 이 허락이 살아 있나» 하나만 본다(허락 시각이 있고, 기한이 비었거나 오늘 이후). 자동 잡기를 뺄 기사는 허락만 끈다. `paid_until` 이 지나면 서버가 자동 정지(«끝난 뒤 멈춤»과 같은 길) · 유예 14일 뒤 탈퇴는 관리자 손. 운영센터 `/members` 에서 켜기 · 끄기 · 기한.
- **연동**: 자동 잡기 허락이 살아 있지 않은 회원 폰에는 서버가 ALARM 을 내려보낸다(앱 코드 변경 없음 — 지금 모드 내려보내기 그대로). 통계 허락이 없으면 통계 문이 거절.
- **검사**: 허락 끔 → ALARM · 켬 → AUTO · 기한 지남 → ALARM · `paid_until` 지남 → 정지(진행 중 콜은 끝난 뒤) · 비면 기한 없음 — 기사님 · 딸 둘 다 같은 길.
