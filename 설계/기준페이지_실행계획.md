## 2. 지금은 이렇게 돈다

- 기준 페이지 여섯(홈 · 목록 · 상세 · 확정 · 내 오더 · 내 오더 콜)의 이름이 인성 단추(«확정») · 픽커 탭(«내 오더»)에서 왔다.

- 정의 표는 `networkPages.<배차망>.ts` 의 `/*JSON*/` 표시 사이 글자다. TS 는 불러 쓰고, **생성 스크립트(`gen-pages.mjs:23-27`)와 원달앱 짝 검사(`NetworkPagesPairTest.kt:23-27`)는 그 글자를 직접 읽는다** — TS 함수를 부르지 못한다(같은 꼴의 앞례: `TARGET_APPS` 를 생성 스크립트가, `STANDARD_SCREENS` 를 원달앱 검사가 정규식으로 뽑는다).
- 원달앱은 생성 파일의 `bases` 를 읽는다 — 결재 단추는 «확정» 줄(`DecisionWord.kt:11`), 수락 · 물러남 단추는 «상세» 줄(`PreConfirmSequence.kt:198` · `InsungPlugin.kt:60` · `Hwamul24Plugin.kt:44`), 낱말 모으기는 첫 기준 칸(`ScreenWords.kt:13`), 인성 손 확정 요금 받침은 «확정» 칸(`InsungSequence.kt:96`). 서버도 «상세» 이름으로 칸을 읽는다(`routes/detail.ts:111 · 128 · 133`).
- 인성 출발지 · 도착지 · 적요 팝업이 «확정 전 상세» · «확정 뒤 상세» 두 줄 덧칸 **맨 앞**에 글자까지 똑같이 두 번 적혀 있다.
- 인성플렉스 «확정»은 화면을 못 본 빈 줄이고, «수락 뒤 가는 곳» 표시는 «진행중(한 건)»에만 있다.

## 4. 구현 방법을 견준 것 (순위 검산)

**4-1. 부속 팝업의 공통 이름(«콜 상차지 팝업» 등)을 정의 표에 싣는 모양**

| | ⓐ 팝업 이름 칸(`name`)을 공통 이름으로 바꾼다 | ⓑ 이름 칸은 배차망 말 그대로 두고, 부속 자리 낱말 `slot`(pickup · dropoff · memo)을 더한다 — 공통 이름은 shared 표 하나(`CALL_OVERLAY_LABEL`)에서 꺼낸다 **(이걸로 한다)** (만들 것) |
|---|---|---|
| «정의 표 이름 = 배차망 글자 그대로» 약속 | 팝업에서 깨진다 | 지킨다 |
| 공통 이름을 손으로 적나 | 배차망마다 적는다 | shared 표 한 곳 |
| 이번 커밋 A 에서 | 관제웹 폰 줄 배지 글자가 곧바로 바뀐다(이름 칸이 `screenLabels.ts:232` 로 배지에 감 — 2-2가는 «5단계에 그림 먼저») | `slot` 칸만 더한다 · 배지 무변화 · 원달앱 생성 파일에는 `slot` 을 안 뽑는다(원달앱 `OverlaySpec` 에 칸이 없다) |
| 5단계에서 할 일 | 없음 | 배지 이름표가 `slot` 이 있으면 공통 이름을 쓰게 한 줄 — 그림을 먼저 보여 드린 뒤 |

**4-2. «화면 종류 → 기준 페이지» 표를 두는 모양과 원달앱이 그 값을 얻는 자리** — 이 표는 «기준 페이지 사전»(A-1)의 `baseOf` 칸이다

| | ① 원달앱이 `StandardScreen` 으로 직접 계산 | ② **글자 표 하나**(`BASE_PAGE_OF` — `/*JSON*/` 표시 사이)를 shared 에 두고, TS · 생성 스크립트 · 원달앱 짝 검사 **세 곳이 같은 글자를 읽는다**. 생성 스크립트가 줄마다 `base = "newCall"` 를 생성 파일에 적는다 **(이걸로 한다)** (만들 것) |
|---|---|---|
| 표 | 두 벌(shared · 코틀린) | 한 벌(글자 표) · 읽는 곳 셋 |
| 덧칸 «맨 앞에 붙이기» 규칙 | — | 같은 규칙을 TS 불러오기 · 생성 스크립트 · 짝 검사 세 곳이 구현한다 — 셋이 같은지는 짝 검사(생성 파일 ↔ 자기 구현)와 shared 검사 하나(불러온 결과 ↔ 글자 표를 같은 법으로 읽은 결과)로 묶는다 |
| 새 파일 · 새 폴더 | 없음 | 없음 |
| 원달앱 칸 모양 | — | `bases: List<String>` → `base: String?` — 한 화면 줄은 기준 페이지 하나 |
