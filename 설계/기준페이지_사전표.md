# 기준 페이지 사전표

> 🔴 **생성 파일이다 — 손으로 고치지 않는다** · `cd onedal-web && pnpm gen:pages doc`
> 원천: shared `pageFields.ts` 의 기준 페이지 사전 + 배차망 정의 표 `networkPages.<배차망>.ts`. 뽑은 글이 이 파일과 같은지는 shared `pagesDoc.test.ts` 가 묻는다.

## 1. 기준 페이지 — 이름의 원천

이름은 콜의 두 사실(주인이 없음/나 × 목록/한 건)로만 짓는다. 배차망이 부르는 이름은 정의 표 화면 줄 이름에만 둔다.

| 기준 페이지 | 코드 값 | 원달앱 상수 | 콜의 주인 | 모양 | 하는 일 |
|---|---|---|---|---|---|
| 홈 | `home` | — (칸을 안 적음) | — | — | 배차망 앱을 켜는 첫 화면 · 원달앱은 아무것도 안 한다 |
| 새 콜 목록 | `newList` | `NEW_LIST` | 없음 | 목록(여러 건) | 주인 없는 콜들 · 원달앱이 줄을 읽어 거르고 맞는 줄을 누른다 |
| 새 콜 화면 | `newCall` | `NEW_CALL` | 없음 | 한 건 | 주인 없는 콜 한 건 · 칸을 읽어 판정 · 자동이면 계약 단추 |
| 내 콜 목록 | `myList` | `MY_LIST` | 나 | 목록(여러 건) | 내 콜들 · 여러 콜 · 여러 상태 |
| 내 콜 화면 | `myCall` | `MY_CALL` | 나 | 한 건 | 내 콜 한 건 · 결재 단추 · 운행 단계 |

내 콜 화면 안의 운행 단계 — 화면 종류 이름은 그대로 두고, 어느 기준 페이지인지는 사전 `baseOf` 가 정한다.

| 화면 종류 | 운행 단계 |
|---|---|
| `RUN_TO_PICKUP` | 상차지로 가는 중 |
| `RUN_AT_PICKUP` | 상차지에서 |
| `RUN_TO_DROPOFF` | 하차지로 가는 중 |
| `RUN_AT_DROPOFF` | 하차지에서 |
| `RUN_DONE` | 완료 |

콜 한 건 화면 위의 부속 팝업 — 정의 표에서는 부속 자리 `slot` 으로 가른다.

| 부속 자리 | 공통 이름 |
|---|---|
| `pickup` | 콜 상차지 팝업 |
| `dropoff` | 콜 하차지 팝업 |
| `memo` | 콜 적요 팝업 |

## 2. 배차망이 부르는 이름 — 자리 × 배차망

칸은 셋 중 하나다. **이름** = 정의 표 화면 줄 이름 글자 그대로 · **② 없음** = 이 배차망엔 그 자리가 없다 + 근거 · **?** = 아직 모름 + 무엇을 모을 것인가. 한 칸에 화면 줄이 여럿이면 ` / ` 로 잇는다. 이름 뒤의 `?` 는 화면 줄은 있으나 모을 것이 남았다는 뜻이다.
못 본 화면에 지어낸 이름을 붙여 정의 표 줄을 미리 만들지 않는다 — 이 표의 `?` 칸에만 둔다.

| 자리 | 인성 | 화물24시 | 카카오 픽커 | 인성플렉스 |
|---|---|---|---|---|
| 홈 | 홈 «인성퀵화면분할» | 홈 «전국24시콜화물» | 홈(출근 전) | 홈 |
| 새 콜 목록 | 신규 콜 목록 | 화물정보(실시간 목록) | 신규 리스트 | 목록(신규) |
