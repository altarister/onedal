# 기준 페이지 개념 바꾸기 — 새 에이전트 인계

이 일을 처음 맡는 에이전트가 **이 문서 한 장부터** 읽는다. 아래 차례대로 읽고, «첫 걸음»부터 시작한다.

## 무엇을 하나

배차망 화면을 우리 쪽 «기준 페이지»로 부르는 이름이 인성 단추(«확정») · 픽커 탭(«내 오더»)에서 빌려 와, 새 배차망이 붙을 때마다 이름이 늘었다. 이를 **콜의 두 사실(주인이 없음/나 × 목록/한 건)** 로만 짓는 다섯 이름(홈 · 새 콜 목록 · 새 콜 화면 · 내 콜 목록 · 내 콜 화면)으로 바꾸고, 그 정의를 **«기준 페이지 사전»(JSON 원천 하나)** 으로 두어 원달앱 · 서버 · 운영센터 · 생성 파일 · 문서가 같은 원천을 읽게 한다.
커밋 차례: **A 개념 바꾸기(코드 한 커밋) → A′ 문서(디프 탭 먼저) → B 인성플렉스 손 수락 → C 사전에서 문서 뽑기 · 빈칸 검사**.

## 읽을 차례

| 차례 | 문서 | 무엇으로 읽나 |
|---|---|---|
| 1 | 루트 `CLAUDE.md` 전부 | 일하는 규칙 — «계획:» 줄 · 계획 승인 ≠ 구현 승인 · 문서 고침은 디프 탭 · 묻는 일 넷 · 하나씩 · 말하는 법 |
| 2 | 루트 `README.md` 의 «수정» 줄 장들: 「구성」 · 「이건 버그가 아니라 규칙이다」 · 「짝이 있는 것」 · 「지금은 테스트 단계다」 · 「이 문서 · 코드 주석에 무엇을 적나」 · 「로그를 넣을 때」 · 「커밋 전 필수」 · 「여럿이 한 작업 트리에서 일한다」 | 게이트 · 짝 · 내 줄만 커밋 |
| 3 | `onedal-web/shared/CLAUDE.md` · `onedal-app/CLAUDE.md` · `onedal-web/CLAUDE.md`(검증 스크립트 표 — `gen:pages` 줄) · `onedal-web/server/CLAUDE.md` | 고치는 곳들의 규칙 · 서버 검사가 shared · 관제웹 소스를 읽는다 |
| 4 | **`설계/기준페이지_실행계획.md`** | **할 일 그 자체** — 커밋마다 «어느 파일 어느 줄 → 무엇으로» · 끝 조건 · 게이트 · 폰 시험 |
| 5 | **`설계/기준페이지_이름표.md`** | **이름의 원천**(사전에 옮길 글자) — 0장 · 2장이 이번 일 · 3장(«화면 값 바꾸기» 단계) · 7장 «옛 값 옮기기» 단계는 나중 일이라 손대지 않는다 |
| 6 | `설계/기준페이지_분류.md` 2 · 3장 | 페이지마다 하는 일 · 새 화면 분류 순서 — 판단이 필요할 때만 |
| 7 | `설계/기준페이지_개념.md` 7장 | 위험(픽커 «배정 취소»는 이미 막혀 있음 등) — 배경 |

- `설계/기준페이지_사전표.md` 는 사전 + 정의 표에서 뽑은 **생성 파일**이다 — 고치지 않는다(`pnpm gen:pages doc`). 이름표 0 · 2 · 6장이 이 파일을 가리킨다.
- `설계/콜상태_전수조사.md` 는 이번 커밋(A · B · C)에 필요 없다 — 그 뒤 «콜 상태 정의» 일의 재료다.
- 🔴 **`reviews/` 의 `기준페이지_*` · `콜상태_*` 파일은 읽지 않는다** — 리뷰를 거치며 고친 옛 판이라, 나중에 틀렸다고 바로잡은 문장이 그대로 들어 있다. 최신은 이 `설계/` 폴더뿐이다.

## 이미 정해진 것 — 다시 묻지 않는다

| 어디서 | 답 | 뜻 |
|---|---|---|
| «개념» 9장 | 1가 2가 3가 4가 | «확정»을 없애고 다섯으로 · 서버 낱말 표 옛 «확정» 줄은 그대로 · 인성플렉스 손 수락은 이번에 함께(커밋 B) · 인성 정의 표 바로잡기는 개념 바꾸기 뒤에 따로 |
| «분류» 8장 | 1가 2-1가 2-2가 3가 | 이름 다섯 · 부속 팝업은 한 번만 정의(커밋 A) · 팝업 배지 이름 바꾸기는 5단계에 그림 먼저 · 옛 낱말 줄 1,410개는 이번엔 그대로 |
| «이름표» 8장 | 1나 2가 3가 4가 | `RUN_*` 그대로 · 팝업 한글 «콜 상차지 · 콜 하차지 · 콜 적요 팝업» · 두 낱말 진행 이름은 갈 자리만 정함 · `LIST_COMPLETED` 는 나중 «화면 값 바꾸기» 단계에서 없앰 |
| «실행계획» 7장 | 사전 가 · 1가 2가 3가 4가 | 기준 페이지 사전을 커밋 A 에 · 이 계획으로 시작 · 운영센터 이상 기록 낱말 칸을 한글로(커밋 A) · 이 인계 문서 · 옛 판은 `reviews/` 로 |
| 구현 방법(계획서 4장) | ⓑ · ② | 팝업 이름 칸은 배차망 말 그대로 + 자리 `slot` · 사전 글자를 TS · `gen-pages.mjs` · 원달앱 짝 검사 셋이 같은 정규식으로 읽음 · 원달앱 화면 정의는 `base` 한 칸 |

## 하지 말 것

- push · 서버 배포는 기사님이 먼저 말씀하실 때만 — 그때도 올리기 직전에 «지금 운행 중이신가»를 묻는다. 원달앱 판 올리기(폰 설치)도 운행 중에는 하지 않는다.
- 이번에 손대지 않는 것: 서버로 가는 화면 값(`ScreenContext`) · 화면 종류(`StandardScreen`) 이름 · `RUN_*` · DB 옛 낱말 줄 · 관제웹 화면(팝업 배지 이름은 5단계).
- 이름표 11장 · `설계/콜상태_전수조사.md` 0장의 **운행에 닿는 찾은 것 셋**(서버가 먼저 안전취소로 적음 · 알람 모드 결재석 카드가 시간으로 사라짐 · 방출 콜 되돌리기)은 이번 커밋에서 고치지 않는다 — 운행 동작이라 기사님 합의 거리다(`routes/detail.ts` · `routes/orders.ts` 를 열다 고치고 싶어지는 자리).
- 소스 글자 세기 검사를 새로 만들지 않는다 — 새 규칙은 동작 검사 · 타입 파생으로만.
- 문서 · 규칙(README · CLAUDE.md · `배차망_모드표.md` 등)을 고칠 때는 고친 사본을 `code --diff 지금파일 사본` 디프 탭으로 먼저 보여 드리고 답을 받은 뒤 고친다(커밋 A′).
- 새 폴더를 만들지 않는다(필요하면 묻는다). 새 이름을 짓지 않는다 — 사전 · 이름표에 없는 이름이 필요하면 멈추고 여쭌다.
- 만들다 계획서와 달라지면 그 자리에서 멈추고 무엇이 왜 달라지는지 먼저 말씀드린다.
- 파일 · 표 지우기 · `git reset` · 떠 있는 `pnpm dev` 끄기는 기사님 몫이다.

## 첫 걸음

1. 위 «읽을 차례» 1~5를 읽는다.
2. 계획서의 줄 번호는 다른 세션의 커밋으로 낡을 수 있다 — 고치기 전에 `grep -n` 으로 다시 확인한다. 새 폴더 `설계/` 는 README 「구성」에 이미 올라 있다(`layoutListed` 초록).
3. 계획서 커밋 A 의 **A-1 첫 파일(`onedal-web/shared/src/pageFields.ts`) «어느 줄 → 무엇으로»**를 기사님께 올리고 답을 받는다(«계획서 승인은 구현 승인이 아니다»).
4. 답을 받으면 한 줄로 되짚고 시작한다. 커밋 A 는 한 커밋이라 크다 — 커밋 전에 다른 세션의 줄 단위 교차 리뷰를 한 번 받는다(리뷰를 맡았던 세션은 `ListAgents` 로 찾는다 · 이름은 바뀔 수 있다).
5. 만드는 도중에는 검사를 돌리지 않는다 — 빨간불 확인 한 번 · 커밋 직전 게이트 한 번(루트 CLAUDE.md). 커밋은 내 줄만(`git diff --cached` 로 줄까지 확인) · 게이트는 계획서 «커밋 A 끝 조건» 그대로 한 Bash 줄에서 차례로.
6. 폰 시험은 로컬 서버 + A24(새 원달앱 디버그 설치) + 시뮬레이터 — 계획서 끝 조건대로. 원달앱 디버그 설치 · 판 올리기는 앞례 커밋 `c0c330a7`(«원달앱 판 78 · 2.9.13-isflex»)과 `phone-e2e-test/` 실행기를 보고 같은 꼴로 · 결과는 시험 장부에. 시험 전에 기사님께 «제 준비 · 기사님 준비 · 하실 일 · 예상 결과»를 먼저 드린다.
