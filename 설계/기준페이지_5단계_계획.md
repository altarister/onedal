# 기준 페이지 5단계 — 인성설명서로 인성 정의 표 바로잡기 · 계획서

원천: 개념 문서 2장(인성설명서가 보여 주는 인성의 페이지) · 개념 6장 «5단계» · 사전표 2장의 인성 «?» 칸.
방향 승인: 개념 9장 ④ «가» — 개념 바꾸기(커밋 A~C) 뒤에 따로 커밋으로 한다. 원달앱이 화면을 알아보는 법이 바뀌는 것은 그 승인 안이다. 이 계획서는 그 방향의 **구현 순서와 끝 조건**이다.
나누기: 계획서는 onedal-91c639 · 코드는 onedal-89(e57856) · 커밋마다 91c639 가 줄 단위 리뷰.

> 사업자가 없어 인성 앱은 설치할 수 없다. 이 단계의 근거는 **인성설명서 영상의 화면**이고, 원달앱 시험은 **시뮬레이터 인성 화면**으로만 한다.
> 영상 글자는 눈으로 읽은 글자다 — 접근성으로 읽히는 글자(예: «확정(10)» 이 «확정» 으로 읽히는지)는 실물 첫날 다시 본다.

## 1. 이 수정이 기사님 하루에 무엇을 하나

어긋남은 실물 인성에서만 난다(시뮬레이터 완료 탭은 지금도 맞게 읽힌다) — 아래는 **실물 첫날부터**의 이야기다.

| | 무엇이 | 어떻게 |
|---|---|---|
| 좋은 콜 | 늚 | 목록 차종 칸이 «용/소»(장면 1719)인 콜 줄은 지금 원달앱에 **아예 안 보인다**(차종 낱말 표에 없으면 줄이 콜로 묶이지 않는다). 낱말을 표에 넣어 줄이 콜로 보이게 한다 — 차종은 «모름»이라 요금은 최소 금액만 본다(7장 정한 것 1). **차종 거르기가 비어 있을 때의 이야기다**(지금 DB 값) — 거르기를 켜면 «모름» 차종은 안 맞아(`InsungParser.kt:201-202`) 지금처럼 못 잡는다(나빠지지는 않는다) |
| 노이즈 | 줆 | 실물 «완료» 탭에도 «신규 · 빠른설정» 이 있어 원달앱이 완료 탭을 **신규 목록**으로 읽는다. 원달앱은 신규 목록에서만 콜 줄을 읽고 누르므로(`HijackService.kt:1481`), 지금은 **이미 잡은 콜 줄을 새 콜로 읽어 필터에 태우고 자동 모드면 누를 수 있다**. 그 길이 닫힌다 — 운행 동작이 바뀌는 것이고, 개념 9장 ④ «가»가 그 승인이다 |
| 기사님 손 | 늚(좋은 쪽) | 손으로 확정한 인성 **착불** 콜은 내 콜 화면의 «고객에게 받을 금액» 에서 요금이 찬다(신용 콜은 화면에 총액이 없어 지금처럼 비어 있다 — 경고는 서버 로그에만 남고 관제웹에는 표시가 없으며, 매출 합계에 0 으로 든다 · 5-3). 잠금이 켜져 콜이 안 열릴 때 원달앱이 «잠금 팝업»으로 알아본다(지금은 모르는 화면) |
| 기사님 손 | 그대로 | 원달앱이 누르는 단추는 늘지 않는다 — 새로 이름을 아는 상세 두 꼴(배차수신 · 지도형)과 팝업에서는 아무것도 누르지 않는다 |

새 설정값 · 새 저장 칸은 없다.

## 4. 순위 검산 — 둘 이상을 나란히

**4-1. 완료 탭을 어떻게 가르나**

| 안 | 바꾸는 곳 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| **가. 완료 탭 `all: [완료, 장터게시판]` · 신규 목록 `all: [신규, 빠른설정], none: [장터게시판]`**(추천) | 두 줄의 알아보는 글자 | 영상이 보여 주는 실제 차이 하나(«잠금» 자리의 «장터게시판»)로 가른다 · 두 줄이 서로 배타라 줄 차례에 기대지 않는다 · 짧은 낱말(«해제»)을 화면 전체에서 찾지 않아 콜 적요 글자에 흔들리지 않는다 | 시뮬레이터 머리를 실물대로 고쳐야 한다 · 판별 사례 «시뮬 완료 탭»(`screenCases.json:100-104`)을 새 글자로 바꿔야 한다 |
| 나. 완료 탭 `none: [잠금, 해제]` · 신규 목록 `any: [잠금, 해제]` | 두 줄 | 배타 | «해제» 같은 짧은 낱말을 화면 전체에서 찾아, 콜 줄 적요에 그 글자가 오면 완료 탭이 신규 목록으로 되돌아간다 — 고치려는 그 오류 |
| 다. 완료 탭 줄을 먼저 맞춰 보게 차례만 바꾼다 | 줄 차례 | 한 줄 | 신규 목록에도 «완료» 가 있어 완료 탭 줄이 신규 목록을 먹는다 |
| 라. 고른 탭 표시(밑줄 · 색)로 가른다 | 원달앱 읽기 | 정확 | 접근성 글자에 고른 탭이 오는지 실물로 모른다 |

**4-2. 정의 표의 근거 칸 — 사진 이름 바꾸기와의 차례**

이름표 10장 «상태 자리 이름은 «진행 상태 / 콜의 성질» 정의 뒤 확정한다 — 그 뒤, 5단계 전에 사진 이름을 한 번에 바꾼다» 와,
5단계를 지금 하는 것이 부딪힌다 — 상태 정의가 아직 없어 사진 이름을 지금 못 바꾼다.

| 안 | 좋은 점 | 나쁜 점 |
|---|---|---|
| **가. 근거 칸에 지금 있는 실제 경로(`ex_images/인성/인성설명서/영상_0526.jpg`)를 적고, 사진 이름 바꾸기는 상태 정의 뒤로 미룬다**(정함) | 다른 줄과 같은 꼴 · 바로 열린다 · 근거 경로 검사(`networkPages.test.ts:162-166` — `ex_images/` 로 시작하면 파일이 있는지 문다)가 초록 · 나중에 사진 이름을 바꿀 때 끝 시각 `영상_(\d{4})` 이 남으므로 정의 표 · 개념 2장을 한 번에 같이 바꾼다 | 사진 이름을 바꾸는 날 정의 표도 함께 바꿔야 한다 |
| 나. 상태 정의 → 사진 이름 바꾸기 → 5단계 차례를 지킨다 | 바꾸기가 한 번 | 5단계가 리뷰 이후 일(상태 정의)에 묶여 무기한 밀린다 |
| 다. 근거 칸에 «폴더 + 영상 시각»만 적는다 | 사진 이름과 떨어진다 | 근거 경로 검사가 빨강(파일이 아니다) |

→ **가로 정한다.** 다만 `ex_images/인성/인성설명서/`(사진 98장 · 15MB)는 git 에 없다 — 근거 경로 검사(`networkPages.test.ts:163-168` · `existsSync`)는 새로 받은 사본에서 빨갛게 된다.
픽커 실물 사진(`ex_images/카카오픽커/실물_2026/`)과 같은 꼴로 한다: `.gitignore` 에 그 폴더를 올리고, 검사의 면제 줄(`networkPages.test.ts:123` `ignored()`)에 그 접두를 더한다 — 근거 경로는 정의 표에 남고, 사진이 없는 기계에서는 검사가 건너뛴다. 영상 캡처 15MB 를 이력에 영구히 넣지 않는다. 5-1 커밋에서 함께 한다.
이름표 10장의 «5단계 전에» 문장은 5-1 커밋에서 «상태 정의 뒤(5단계와 따로)»로 같이 고친다(디프 탭 먼저) — 두 문서가 다른 말을 하는 채로 5단계를 돌지 않는다.

**4-3. 영상에 안 나온 메뉴 줄**

개념 6장 «메뉴 줄을 영상 메뉴와 맞춘다(전표 · 로그인 → 영상에 없음)» 와 이 계획서 5-2 «지우지 않는다» 가 다르다.
**이 계획서대로 정한다** — 영상에 없다는 것은 실물에 없다는 근거가 아니다(못 본 것을 «없음»으로 적지 않는다는 사전표 규칙과 같은 까닭). 개념 6장 그 줄은 5-2 커밋에서 디프 탭으로 같이 고친다.

## 5. 단계와 끝 조건

- 한 단계 = 한 커밋 · 정의 표와 시뮬레이터 인성 화면을 **같은 커밋**에서 바꾼다(시뮬레이터가 실물과 같은 글자를 내야 폰 시험이 뜻이 있다).
- 단계마다 코드 전에 «어느 파일 어느 줄 → 무엇으로»를 올리고 답을 받는다.
- 판별 사례는 `onedal-web/shared/src/screenCases.json`(글 → 화면 종류 · 원달앱 `ScreenTableDetectTest` 가 푼다), 칸 읽기 사례는 `onedal-web/shared/src/pageReadCases.json`(글 → 칸 값 · 원달앱 `PageFieldReadTest` · shared `networkPages.test.ts` 가 푼다)이다.
- 시뮬레이터를 바꾸는 단계(5-1 · 5-2)는 README 게이트에 더해 `onedal-sim` 검사(머리 글자 · «빠른설정» 을 쓰는 화면 검사와 스냅샷)도 초록이어야 끝이다.
- **단계 끝은 판별 · 칸 읽기 사례와 검사로 닫는다. 폰에서 보는 확인은 모두 5-7 에 모으고, 원달앱 판은 5-7 에서 한 번만 올린다**(단계마다 게이트는 gradle 까지 돌린다).

**5-3. 내 콜 화면 요금 · 결재 근거**
- 내 콜 화면 요금 칸 읽는 법에 «고객에게 받을 금액 N» 을 더한다(«요금 :» 은 그대로). «실운임 :» 은 **읽지 않는다** — 수수료를 뺀 값이라, 요금 칸에 넣으면 총액인 다른 콜과 섞여 오늘 · 이번 달 매출 합계(`statService.ts:30,42`)가 틀어지고, 착불 미수금(`milestones.ts:196`)이 받을 돈보다 적게 잡힌다.
- 신용 콜은 화면에 총액이 없다. 수수료율로 되돌려 세면 짐작이므로 하지 않는다 — 지금처럼 요금 0 · «못 읽음» 경고. 목록을 읽은 콜은 목록 요금이 먼저라 이 길을 타지 않는다.
- 결재 «취소» 단추의 근거에 1621 · 1743 을 적는다.
- 새 콜 화면 요금 칸은 그대로 «요금 :»(영상의 확정 전 상세는 «요금 : …» — 0938 · 0532). 알아보는 글자 `any: [요금, 실운임]` 의 «실운임» 은 확정 전 상세에 근거가 없으므로 근거를 찾아보고, 없으면 그대로 두고 «모을 것»에 적는다.
- 자리 기록에 «모을 것»으로: 내 콜 화면 머리의 «27:23» 숫자(1743) · 목록 보라색 줄의 뜻(1719) · 신용 콜 총액을 읽을 자리.
- 끝: 칸 읽기 사례 — 착불 글 «고객에게 받을 금액 45,000 / 실운임 : 34,650(착불)» → 45,000 · 신용 글 «실운임 : 22,330(신용)» → 못 읽음 — 초록.

**5-4. 새 콜 화면의 다른 두 꼴 — 이름만 알아본다** (화면 종류 없는 줄)

## 7. 정한 것

**1. 인성 목록 차종 «용/소» — 라로 정함** (장면 1719 · 자막에 설명 없음 · 기사님: «용달/소형 같은 느낌인데 정확히 모름»)
지금 원달앱은 차종 낱말 표에 없는 낱말이 오면 **그 콜 줄을 아예 콜로 읽지 않는다**(기록도 없음). 차종을 짐작으로 맞추지는 않는다(틀린 차종 = 틀린 요금 바닥 = 틀린 색).
- 가. 표에 넣지 않고 «모을 것»으로만 둔다 — «용/소» 콜은 실물 첫날에도 원달앱에 안 보인다.
- 라. 낱말은 넣고 차종은 «모름»으로 둔다(이미 있는 «14t · 18t» 꼴) — 줄이 콜로 보이고, 요금 바닥만 못 센다. 원달앱이 그 콜 상세를 열면 서버가 상세 글 원문을 남기므로, 상세에서 풀려 나오는 차종 글로 나중에 뜻을 확인한다
  - 원달앱 코드로 본 라의 모습: 원달앱이 서버에 보내는 차종 값은 화면 낱말 그대로(«용/소»)이고, 표의 차종은 차종 거르기(`InsungParser.kt:201-202`)에서만 쓴다 — 거르기는 허용 목록이 비면 통과한다(`:249-251` · 지금 DB 값). 요금 바닥은 `FareFloor.rateOf`(`core/engine/FareFloor.kt:20-35`)가 단가 표 열쇠에 맞추는데 «용/소» 는 어느 열쇠에도 안 맞아 단가 계산을 끄고 최소 금액만 본다(`:319-323`). 그래서 «용/소» 를 승용차 등으로 짐작해 세는 일은 원달앱에서 생기지 않는다. 서버가 주는 판정 색은 «어느 파일 어느 줄» 때 확인한다.

## 8. 찾은 것 (고치지 않음)

- 알아보지 못한 콜(낱말 표에 없는 차종 등)을 관제웹 상황판에 보이면 기사님이 놓치는 콜을 바로 아신다(기사님 생각). 관제웹 화면이 느는 새 기능이라 지금은 기록만 한다.
- 인성 신용 손 확정 콜의 요금 0 은 서버 로그(`detail.ts:256-262`)에만 남고, 매출 합계는 0 으로 더한다 · 관제웹 표시는 새 기능이라 안 한다.
- 신용 콜 총액을 수수료율로 되돌려 세는 길은 기사님이 고르실 거리다: 영상 두 장면이 정확히 떨어지고(22,330 ÷ 0.77 = 29,000 · 34,650 ÷ 0.77 = 45,000) DB 수수료율 23 과 같다. 위험은 DB 수수료율이 실제 계약과 달라지면 조용히 틀리는 것이다.
- 판정의 적정 금액(`PricingEngine.ts:26`)은 수수료를 뺀 값인데 견주는 콜 요금은 총액이다 — 뜻이 맞는지 기사님께 여쭐 거리(고치지 않음).
