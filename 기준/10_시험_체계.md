# 10 시험 체계

## 1. 하는 일

사업자가 없어 인성 · 화물24시 콜은 전부 시뮬레이터가 만든 가짜이고, 실물은 카카오 픽커뿐이다. 그래서 «고쳤다»를 믿으려면
**책상에서 도는 시험 여러 층**이 필요하다. 이 문서는 층마다 무엇을 잡고 무엇을 못 잡는지, 언제 돌리는지, 폰 시험(`phone-e2e-test/`)이
어떻게 짜여 있는지를 적는다.

🔴 명령 하나하나의 «잡는 것 · 못 잡는 것 · 검수»는 `onedal-web/CLAUDE.md` 의 **검증 스크립트 표가 원천**이다. 여기서는 그 표를 다시 적지 않고, 층과 순서만 적는다.
🔴 **초록불은 «잡는 것» 칸만 맞다는 뜻이다** — 늘 «못 잡는 것»을 먼저 읽는다.

## 4. 지도 — 층마다 무엇을 보나

아래 «잡는 것 · 못 잡는 것»의 자세한 문장은 `onedal-web/CLAUDE.md` 표를 본다. 여기는 **층의 경계**만 적는다.

| 층 | 명령 | 덮는 구간 | 대표적으로 못 잡는 것 |
|---|---|---|---|
| 타입 · 규칙 | `tsc` · `npx jest` · `pnpm test:web` · `lint:gate` · `audit:dead` · `audit:socket` · `audit:docs` | 함수 · 규칙 · 문서 ↔ 코드 · 소켓 이벤트 짝 | 화면에 무엇이 찍히나 · 콜 생애 끝까지 |
| 서버 콜 생애 | `pnpm scenario` | 실제 서버로 선점 → 6단계 → 장부 · 복구 · 적재 · 정산 | 주행 중 순서 · GPS 도착 · `/api/scrap` (`drive` 몫) |
| 주행 | `pnpm drive` · `pnpm drive e2e` · `pnpm drive e2e kakao` | GPS 재생으로 모든 정거장 · 경로 순서 · 도착 감지 · 궤적. e2e 는 로그인 · 폰 토큰 · 결재 전달 · 운영센터 · 세션 충돌 · 계정 막힘 | 진짜 원달앱 · 실제 GPS 흔들림 · 카카오 끔이면 판정 색 |
| 화면 | `pnpm lab` · `pnpm shot` | 실험실 문제 버튼을 눌러 두 자리 글자 대조 · 폰 폭 사진 | 실물 화면 전체 · 기종별 모양 |
| 앱 구간 | `pnpm e2e:app` (+ `onedal-sim`) | 원달앱이 화면을 읽고 → 필터 → 터치 → 확정 | 픽커(잡지 않으므로) · 실물 배차망 |
| 실폰 | `phone-e2e-test/runner.py` | A24 · S23 두 폰 · 블루투스 · 관제앱 단추 · 모의 GPS 로 하루 일과 | 아래 5-3 «못 잡는 것» |
| 실주행 | 기사님 운전 (승용차) | 실제 길 · GPS · 통신 끊김 | 적재 · 톨비 (승용차라 실전과 다르다) · 실물 인성 · 화물24시 |

GitHub 이 push 때 도는 것은 첫 층의 일부(서버 tsc · 서버 jest · 관제웹 tsc -b · `test:web`)뿐이다 (`.github/workflows/deploy.yml` `check`).
나머지는 커밋하는 사람이 지킨다.

## 5. 흐름

### 5-1. 버그 하나 고칠 때

1. 진단 → 잡았을 검사를 먼저 만든다 → **빨간불을 본다** (안 뜨면 진단이 틀렸다)
2. 고친다 → 초록불
3. 같은 모양이 두 번이면 구조를 바꿔 그 모양이 못 생기게 하고 검사로 잠근다
4. 커밋 직전 게이트 + 건드린 것에 따른 추가 검사 (3장 5번)
5. 고친 파일만 이름으로 담는다

### 5-2. 시뮬레이터

- `cd onedal-sim && pnpm dev` (포트는 README 표의 시뮬레이터 자리 — 시뮬 앱이 그 번호로 붙으니 바꾸지 않는다)
- 시뮬레이터 안내는 `onedal-sim/README.md`
- 서버의 시뮬 문(`/api/sim/*`)은 로컬에서만 열린다 (라이브 서버 404)
- 실서버의 `rehearsal.` 주소도 같은 시뮬레이터 화면이다 — 그 화면의 콜을 잡으면 콜은 **실서버 DB** 에 쌓인다 (9장)

### 5-3. 폰 시험 `phone-e2e-test/`

| 파일 | 하는 일 |
|---|---|
| `problems.json` | 문제지 — 장면(`scenes`)마다 체크 줄. `about` · `vocab` · `places` · `routes` · `cannotSee`(못 보는 것) · `needsHow`(장면이 기대는 사실) · `decideHow`(고르는 자리) |
| `make_result.py` | 문제지로 빈 결과지(`out/result_시각.json`)를 만든다 · 최근 5개 · 관제웹 dev 서버 `/e2e-test/phone/` 장면 표의 «새 판» 단추도 이것을 부른다 |
| `runner.py` | 실행기 — 장면 · 줄 차례로 돌며 스크립트 줄은 `day.py` 의 동작 · 기다림 · 확인을 부르고, 사람 줄은 장면 표에서 체크될 때까지 기다린다. 틀리면 `onFail`(stop / continue). `--dry` · `--only` · `--from` |
| `day.py` | 하루 일과 실행기 — `day1.json` 을 읽어 단계마다 do → wait → check → 판정. 단계는 코드에 박지 않는다 |
| `run.py` | 폰 손 — adb 누름 · 사진 · 화면 색 확인 · 서버/앱 로그 표시(`srv_mark` 등) |
| `find.mjs` | S23 관제앱 웹뷰에 개발자 도구로 붙어 단추를 글자로 찾고 화면 자리만 돌려준다 (누르지 않는다). `see:` · `spot:` · `seat:` · `aria:` · `in:` |
| `taps.json` | 누를 자리 사전 — 이름 → 폰 · 좌표 · 색 확인 · 기대 화면(`expect`) · `skipIf`. 화면이 바뀌면 여기 한 곳만 고친다 |
| `sheet.py` | 문제지 · 장소표 · 하루 경로를 읽는 한 벌 (`runner.py` · `lint.py` 공용) |
| `lint.py` | 판 전에 문제지 · 장소표 · 경로끼리 어긋난 곳을 찍는다 (폰 · 서버 불필요) |
| `joy_check.py` | 가짜 JoyStick 으로 «설 때까지 기다림» 흐름 검사 (폰 불필요) |
| `g.py` | 틈 장면(실패해도 판 계속) |
| `set_filter.mjs` | 시험용 필터 맞추기 — 관제앱 «서버 저장»과 같은 소켓 길 · 로컬 서버 우회 로그인 |
| `ledger.py` · `ledger.json` | 시험 장부 — 판을 덧붙인다(덮어쓰지 않는다) |
| `day1.json` · `onedal-day1-all.gpx` | 장소 표 · 하루 경로 |

판 순서: `lint.py` → `make_result.py` → `runner.py` → 장면 표에서 사람 줄 체크 → `ledger.py` 로 장부에 붙임.
폰 시험의 «못 잡는 것»은 `problems.json` `cannotSee` 가 원천이다 — 지금은 시뮬 개별콜의 착불 결제 칸 · 진짜 GPS 흔들림 · 터널 · 통신 끊김 · 적재 · 톨비 · 실물 인성 · 화물24시 화면.
장면 수는 `python3 -c "import json;print(len(json.load(open('phone-e2e-test/problems.json'))['scenes']))"` 로 센다.

## 8. 하지 말 것

- 시험 때문에 기사님 필터 · 설정을 바꾸시라고 하지 않는다
- 시험 도구가 기사님이 누르지 않은 버튼 · 방향을 누르지 않는다
- 실물 픽커 콜을 시험으로 수락하지 않는다
- 폰에서 `uiautomator dump` 를 쓰지 않는다
- 떠 있는 `pnpm dev` 를 끄거나 다시 켜지 않는다 (묻는다)
- 시험하려고 push 하지 않는다 · 시험 콜을 실서버에 넣지 않는다
- 변이 측정과 검사를 같은 작업 트리에서 동시에 돌리지 않는다 — 필요하면 worktree
- 소스 글자를 세는 검사를 새로 만들지 않는다
- 콜 수 · 분포를 실측인 척 인용하지 않는다 — 시뮬레이터 콜이다
