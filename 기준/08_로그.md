# 08 · 로그

로그가 **어디에 남고 · 어떤 꼴이고 · 누가 서버로 올리고 · 무엇이 걸러지는지**를 한 장으로 적는다.
로그를 **넣을 때** 지킬 것(태그 고르기 · 바뀔 때만 · 한 사실은 한 줄 · 도구가 읽는 문구)은 루트 [README.md](../README.md) 「로그를 넣을 때 — 나중에 한 줄로 찾히게」 장을 본다. 여기서 다시 적지 않는다.

---

## 1. 하는 일

로그는 장부(DB)에 안 남는 흐름 — **누가 언제 무엇을 보고 눌렀나** — 를 운행이 끝난 뒤 되짚는 재료다.
궤적 · 콜 단계 · 판정 · 결재 결과는 DB 에 있다(`pnpm db`). 로그는 «그 사이에 무슨 일이 있었나»를 맡는다.

세 곳이 찍고, 한 파일로 모인다.

| 찍는 곳 | 찍는 함수 | 쌓이는 곳 |
|---|---|---|
| 서버 | `slog(태그, …)` · `logRoadmapEvent(태그, …)` · 그냥 `console.log/warn/error`(로거가 가로챔) | 터미널 + `onedal-web/server/logs/server-YYYY-MM-DD.log` |
| 관제웹(관제앱 안 웹 포함) | `logRoadmapEvent(태그, '웹', …)` · `logStateChange(태그, 키, 값)` · 그냥 `console.*`(가로채 올림) | 브라우저 콘솔 전부 + **걸러진 줄만** 서버 파일(`🖥️ [관제웹 …]` 줄) |
| 원달앱 | `AppLogger.d/i/w/e(로그캣 태그, LogTag.…, 글)` · `AppLogger.roadmap(LogTag.…, 글)` · 운행 기록 `AppTrace` | 로그캣 + 폰 파일 `Android/data/com.onedal.app/files/logs/1dal-날짜.log` + (roadmap · 운행 기록 · 누른 버튼은) 서버 파일(`📱 [원달앱 폰이름]` 줄) |

## 2. 용어 풀이

| 말 | 뜻 |
|---|---|
| 태그 | 줄이 **무엇을 바꾸나**를 말하는 낱말. 시각 다음 첫 토막에 `#콜단계` 처럼 붙는다. 기계(검색)용 |
| 태그 목록 | shared `onedal-web/shared/src/logTags.ts` 의 `LOG_TAGS` ↔ 원달앱 `onedal-app/.../core/LogTag.kt` — 짝(`LogTagPairTest`) |
| `#없음` | 태그 없이 찍힌 줄에 로거가 붙이는 표지(`NO_TAG`). 목표는 0 |
| `#경고` | 태그 없는 WRN · ERR 줄에 로거가 붙이는 태그 |
| 중계 | 관제웹 · 원달앱이 HTTP 로 서버에 로그 줄을 보내 서버 파일에 남기는 것(`POST /api/logs` · `/api/logs/app`) |
| 중계 유지 무늬(RELAY_KEEP) | 관제웹 줄 가운데 서버 파일에 실을 줄을 고르는 정규식. 안 맞는 줄은 브라우저 콘솔에만 남는다 |
| 운행 기록(AppTrace) | 원달앱이 켜진 동안 배차망 화면 글자 전문 · 누른 버튼을 모아 서버로 올리는 것 |
| 이모지 | 눈으로 빠르게 훑는 표지(🎨 판정 · 🌱 출생 · 🔌 소켓 …). 태그와 별개로 그대로 둔다 |

태그 열 개(실제 목록은 `logTags.ts` 가 원천):

| 태그 | 붙는 줄 |
|---|---|
| `#콜단계` | 잡음 · 도착 · 완료 · 취소 · 출생(🌱) |
| `#판정` | 점수 · 색 · 합짐 방향 · 요율 |
| `#결재` | KEEP · CANCEL · ACK · 심사석 버튼 |
| `#필터` | 상차 · 하차 목록 · 국면 · 반경 · 필터 변경 · 하차 완료 뒤 적재 회복 · 영업일 전환 |
| `#누름` | 터치 발사 · 성공 · 실패 · 안 먹힘 |
| `#화면` | 화면 종류 바뀜 · 상세 진입 · 복귀 |
| `#위치` | GPS · 정차 · 모의 주행 |
| `#통신` | 보고 · 응답 · 소켓 연결 · 해제 · HTTP 수신 |
| `#경고` | WRN · ERR · 이상 징후 |
| `#부팅` | BUILD · 로그 파일 · 복구 |

## 3. 지금 규칙

| 번호 | 규칙 | 까닭 | 코드 자리 |
|---|---|---|---|
| L1 | 서버 파일 한 줄의 꼴: `시:분:초.밀리 수준 #태그 본문 [@기사]`. 수준 칸은 공백 셋 · `WRN` · `ERR` | `pnpm log` 가 앞머리 자리를 읽는다 — 앞머리를 바꾸면 도구가 깨진다 | `server/src/utils/fileLogger.ts` `initFileLogger` · `decorateFileLine` |
| L2 | 터미널 출력은 원문 그대로, 파일은 **추가**. 원래 출력을 먼저 하고 파일에 쓴다 | 파일 쓰기가 실패해도 터미널은 살아야 한다 | 같은 파일 |
| L3 | 파일 쓰기는 스트림(비동기). `appendFileSync` 금지 | 이벤트 루프가 막혀 사고가 난 적이 있다 | 같은 파일 |
| L4 | 한국 날짜마다 파일 하나. 자정이 지나 첫 줄을 쓸 때 새 파일을 열고 첫 줄에 `#부팅 📄 [로그 파일] 날짜가 바뀌어 새 파일 — 앞 파일 …` | 하루 한 파일로 찾기 쉽게 | `openDailyLog` · `nextKstMidnightOf` |
| L5 | 포트가 다르면 파일도 다르다 — 4000 은 `server-날짜.log`, 그 밖은 `server-날짜-포트.log` | 시나리오 · 부팅 스모크 · 재현 서버의 줄이 섞이지 않게 | `logFileNameOf` |
| L6 | 파일 하나가 `MAX_BYTES` 를 넘으면 그 파일 기록을 멈추고 🚨 한 번 알린다(터미널은 계속) | 디스크 보호 | `fileLogger.ts` `MAX_BYTES` · `append` |
| L7 | `KEEP_DAYS` 지난 파일(수정 시각 기준)은 **서버가 뜰 때 한 번** 지운다 | 디스크가 조용히 차는 것을 막는다 | `sweepOld` · `initFileLogger` |
| L8 | 파일에 쓰는 줄은 휴대폰 번호(010 계열) 가운데 넉 자리를 가린다. 유선 · 대표번호는 그대로. 누구의 일인지 알면 줄 끝에 `@기사` | 개인정보 · 누구 일인지 | `decorateFileLine` · shared `mask.ts` `maskPhone` · `utils/logContext` `whoNow` |
| L9 | `slog` 는 목록 밖 태그가 오면 `#없음` 으로 떨어뜨린다 | `#undefined` 같은 가짜 태그를 막는다 | `fileLogger.ts` `slog` |
| L10 | ERR 줄은 쓰는 순간 «오늘 오류 수»로 센다 → 운영센터 점검 «서버 오늘 오류 수» | | `utils/errorTally` `noteError` |
| L11 | 자주 두드리는 문(`/api/scrap` · `/api/devices` · `/api/sim` · `/api/health` · `/api/logs`)은 HTTP 수신 줄을 안 찍는다. GET 도 안 찍는다 | 1~1.5초마다 오는 줄이 나머지를 덮는다. **새 문이 1초 주기면 목록에 더한다** | `server/src/index.ts` `LOG_MUTED_PATHS` |
| L12 | 중계는 HTTP 다(소켓 아님). 받자마자 응답하고 그다음 파일에 쓴다 | 소켓이 끊긴 걸 소켓으로 보낼 수 없다 · 로그 때문에 화면이 멈추면 안 된다 | `server/src/routes/logs.ts` |
| L13 | 관제웹 중계 `POST /api/logs` 는 **인증이 없다** | 로그인 전 화면도 남겨야 한다 | `index.ts` `app.use("/api/logs", …)` 주석 |
| L14 | 원달앱 중계 `POST /api/logs/app` 은 연결된 폰 토큰이 맞아야 받는다. 줄 머리는 폰 표시 이름 | 남의 폰 흉내 막기 · id 는 못 읽는 난수 | `logs.ts` `authDevice` · `deviceLabelOf` |
| L15 | 한 번에 받는 줄 수 상한 `MAX_LINES`, 넘친 것은 잘라 받고 «N줄을 잘랐습니다» 경고 한 줄. 한 줄 길이: 관제웹 `MAX_LEN` · 원달앱 `MAX_APP_LEN`(화면 글자 전문이라 넉넉히) | 조용히 버리지 않는다 · 화면 덤프가 파일을 채우지 않게 | `logs.ts` |
| L16 | 보낸 쪽이 줄 맨 앞에 `#태그 ` 를 실어 오면 떼어 서버 태그 칸으로 올린다. 없거나 목록 밖이면 `#없음` | 태그가 세 곳에서 같은 꼴 | `logs.ts` `splitTag` |
| L17 | **관제웹 줄은 `RELAY_KEEP` 무늬에 맞는 것만 서버 파일에 싣는다.** 원달앱 줄은 거르지 않는다 | 그리기 · GPS · 지도 · 시트 나레이션이 «수상한 줄»을 묻는다 | `logs.ts` `RELAY_KEEP` |
| L18 | 관제웹에 새 로그 줄을 넣고 서버 파일에 남겨야 하면 **그 무늬를 `RELAY_KEEP` 에 더한다** — 안 더하면 서버 파일에 0줄 | 아래 4장 표 | `logs.ts` 주석 |
| L19 | 관제웹 `logRoadmapEvent(…, '서버', …)` 는 서버로 되돌려 올리지 않는다 | 서버 파일에 이미 있다 — 두 벌이면 세는 사람이 헷갈린다 | `client-app/src/lib/roadmapLogger.ts` |
| L20 | 관제웹은 줄을 모아 2초마다 · 20줄마다 올리고, 묶음은 64KB 아래(`batchOf`). 실패하면 묶음을 되돌려 놓고 2 → 4 → … → 30초로 물러서며 다시 건다. 들고 있는 상한 `MAX_BUFFER` 를 넘으면 **오래된 것부터** 버리고 «N줄을 버렸습니다» 한 줄 | 끊긴 구간이야말로 나중에 봐야 할 자리 · 브라우저는 keepalive 본문 64KB 초과를 거절 | `roadmapLogger.ts` `flush` · `schedule` |
| L21 | 탭이 가려지거나 닫히면 남은 줄을 밀어 넣는다(`visibilitychange` · `pagehide`) | 주행 끝 마지막 줄 | 같은 파일 |
| L22 | 관제웹 `console.*` 도 가로채 올리되, ① `[ROADMAP` 사본은 건너뛰고 ② 자기 실패 알림(`🖥️ [로그`)은 건너뛰고 ③ 초당 상한(`PER_SEC_CAP`)을 넘으면 세어서 한 줄로 | 되먹임 · 루프 폭주 방지 | `roadmapLogger.ts` `installConsoleCapture` |
| L23 | 관제웹 메모리 줄은 30초마다. 한계의 8할을 넘으면 ⚠️ 를 붙여 `#경고` 로 — 그때만 중계 무늬에 걸린다 | 크롬 렌더러 죽음의 까닭 가리기 | `roadmapLogger.ts` `startMemoryWatch` |
| L24 | 원달앱 운행 기록: 누른 버튼 줄은 늘, 화면 글자 전문은 켜진 동안만. 끝 버튼을 누르거나 켠 지 5시간이면 끈다. 한 번에 올리는 줄 수는 서버 `express.json()` 한도(100KB) 아래 | 밖에서는 logcat 을 못 본다 · 413 이면 묶음이 영영 못 올라간다 | `onedal-app/.../core/AppTrace.kt` `MAX_MS` · `SEND_BATCH` |
| L25 | 원달앱 로그캣의 1DAL 줄은 폰 파일의 사본이다. 읽을 때는 파일을 본다 | 로그캣 나머지는 폰 시스템 줄 | `AppLogger.kt` |
| L26 | 원달앱 roadmap 줄은 폰 파일과 서버 파일에 함께 남는 것이 뜻이다(「한 사실은 한 줄」의 예외) | 밖에서는 logcat 을 못 본다 | README 「로그를 넣을 때」 |

상수 값은 숫자로 외우지 말고 읽는다:
`grep -nE '^const (KEEP_DAYS|MAX_BYTES)' onedal-web/server/src/utils/fileLogger.ts` ·
`grep -nE '^const (MAX_LINES|MAX_LEN|MAX_APP_LEN|RELAY_KEEP)' onedal-web/server/src/routes/logs.ts` ·
`grep -nE '(FLUSH_LINES|FLUSH_MS|MAX_BUFFER|MAX_BACKOFF_MS|PER_SEC_CAP|MEMORY_TICK_MS) =' onedal-web/client-app/src/lib/roadmapLogger.ts`

## 4. 로그 지도

### 4-1. 서버 파일 한 장에 섞이는 줄

| 줄 머리 | 누가 | 걸러지나 |
|---|---|---|
| (머리 없음) `#태그 이모지 [이름] …` | 서버 자신 | 거르지 않음(HTTP 수신 줄만 L11) |
| `🖥️ [관제웹 기기id앞24자] 보낸시각 …` | 관제웹 중계 | `RELAY_KEEP` 에 맞는 줄만 |
| `📱 [원달앱 폰이름] 보낸시각 …` | 원달앱 roadmap · 운행 기록 · 누른 버튼 | 거르지 않음 |

시각은 둘이다 — 줄 맨 앞은 서버가 쓴 시각, 머리 뒤는 보낸 쪽이 찍은 시각.

### 4-2. 관제웹 줄 중 서버 파일에 남는 것 (RELAY_KEEP)

무늬 전체는 `grep -n '^const RELAY_KEEP' onedal-web/server/src/routes/logs.ts` 로 본다. 뜻으로 묶으면:

| 남는 것 | 무늬 예 |
|---|---|
| 경고 · 오류 | ⚠️ ❌ 🚨 💥 🔴 · WARN · ERROR · Error · Geolocation |
| 기사님 손 | 심사석 · 국면 · 필터 변경 · 반경 |
| 콜 수신 | `[웹 수신]` |
| 다녀옴 · 주행판정 | 다녀옴 · 주행판정 |
| 판정 못 함 | ⚪ |
| 어느 코드인가 | 관제웹 코드 |
| 단계 시트 전화 | 단계 시트 전화 |

**브라우저 콘솔에만 남는 것**(서버 파일 0줄): 경로 재료 · 모의 GPS 이동 · 지도 영역 · 필터 갱신 수신 · 평소 메모리 · 시트 · 그리기 · 소리 · 추천 노출 · 소켓 유지 전달 등 — 위 무늬에 안 걸리는 모든 줄.

### 4-3. 어떤 질문에 어느 명령

| 질문 | 명령 |
|---|---|
| 오늘 요약(부팅 · 소켓 · 수상한 줄 · 콜별 장부 대조 · 태그별 줄 수 · `#없음` 수) | `cd onedal-web && pnpm log` |
| 한 콜의 흐름(서버 줄 / 관제웹 줄) | `pnpm log call <콜 id 앞부분>` |
| 한 종류만 | `pnpm log --tag 결재` (여러 번 주면 합친다) |
| 한 콜의 한 종류 | `pnpm log call <id> --tag 누름` |
| 날짜 · 포트 · 시간 · 파일 · 대조 DB | `--date YYYY-MM-DD` · `--port 4012` · `--since 04:20 --until 05:00` · `--file <경로>` · `--db <파일>` |
| «복귀를 언제 눌렀나» | `pnpm log --tag 결재` (버튼 줄) |
| «이 콜이 왜 안 잡혔나» | `pnpm log call <id> --tag 필터` + 원달앱 파일 |
| «같은 버튼을 두 번 눌렀나» | `--tag 누름` |
| «앱이 왜 죽었나» | `--tag 경고 --tag 부팅` (폰 시스템 줄은 여전히 로그캣) |
| 실서버 로그 | `ssh onedal-live` 뒤 서버 폴더의 `server/logs/` (쓰기는 기사님 손) |

`pnpm log` 는 로그에 «🌱 출생»이 찍힌 단계가 장부에 없으면 🔴 exit 1. 장부 대조는 포트 4000 ↔ `server/local.db`(또는 `--db`)일 때만. 잡는 것 · 못 잡는 것은 [onedal-web/CLAUDE.md](../onedal-web/CLAUDE.md) 스크립트 표.

## 5. 데이터 흐름

```
서버 코드 ── slog / console.* ──▶ fileLogger(가로채기)
                                   ├─▶ 터미널(원문)
                                   └─▶ 태그 붙이기 → 전화 가림 → @기사 → 한국 날짜 파일(스트림)

관제웹 ── logRoadmapEvent / logStateChange / console.* ──▶ 브라우저 콘솔(전부)
        └─ 버퍼(#태그 실음) ── 2초·20줄 · 64KB 묶음 ──▶ POST /api/logs (인증 없음)
                                                         └─ RELAY_KEEP 에 맞는 줄만 ──▶ 서버 파일

원달앱 ── AppLogger ──▶ 로그캣 + 폰 파일
        └─ roadmap · AppTrace(운행 기록 · 누른 버튼) ──▶ POST /api/logs/app (폰 토큰)
                                                         └─ 전부 ──▶ 서버 파일

서버 파일 ──▶ pnpm log (읽기만) · 운영센터 «서버 오늘 오류 수»(ERR 세기)
```

## 6. 고칠 때 같이 볼 것

## 8. 하지 말 것

- 서버 파일 줄의 앞머리(시각 · 수준 · `#태그`)를 바꾸지 않는다 — 바꾸면 읽는 도구를 같은 커밋에서 모두 고친다.
- 태그 낱말을 새로 지어 쓰지 않는다 — `LOG_TAGS` 에서만.
- 파일 쓰기를 동기로 바꾸지 않는다.
- 중계 문에서 응답 전에 파일 쓰기를 기다리지 않는다.
- 관제웹 줄을 서버 파일에 남기려고 `RELAY_KEEP` 을 «전부»로 넓히지 않는다 — 수상한 줄이 묻힌다. 필요한 무늬만 더한다.
- 관제웹이 `platform: '서버'` 줄을 서버로 다시 올리게 하지 않는다.
- 매초 · 매 스캔 줄을 남기지 않는다(README 「로그를 넣을 때」).
- 로그를 DB 표로 옮기지 않는다 — 로그는 조회가 아니라 grep 대상이다.
- 실서버 로그 파일을 지우거나 고치지 않는다(지우기는 기사님이 먼저 말씀하실 때만).
- 라이브 중에 폰에서 `uiautomator dump` 로 화면을 뜨지 않는다 — 접근성이 내렸다 붙어 서버가 «앱 꺼짐»으로 본다.
