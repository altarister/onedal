# 02 콜 필터 — 원달앱이 콜을 집기 전에 거르는 것

> 이 한 장만 읽고 콜 필터를 이해하고 고칠 수 있게 쓴 기준 문서다.
> 다루는 것: 상차 목록 · 하차 목록 · 최소 금액(+ 단가 · 상한) · 예약콜 · 제외어 · 오늘만 · 자동 반경.
> 다루지 않는 것: 서버가 콜을 집은 뒤에 매기는 판정 색·점수(판정 기준) — 그건 별개의 설정이고, 콜 필터와 섞지 않는다.

---

## 1. 이 기능이 하는 일 (기사님 하루의 말로)

기사님 폰(스캔폰)의 원달앱은 배차망 목록 화면을 계속 읽는다. 목록에 콜이 한 줄 올라올 때마다
원달앱이 **«이 콜을 열어 볼 가치가 있나»**를 0.1초 안에 가른다. 이것이 콜 필터다.

- 통과한 콜만 원달앱이 상세로 들어가고(인성·화물24시는 시뮬레이터에서 선점까지, 카카오 픽커는 알람만), 서버가 수익성을 판정해 관제앱에 올린다.
- 떨어진 콜은 열지 않는다 — 열면 30초 안전취소 시계가 돌고 취소 횟수가 쌓이며, 기사님 화면에 노이즈가 뜬다.
- 그래서 콜 필터의 목적은 둘이 맞서 있다: **좋은 콜을 놓치지 않는다**(느슨하게) · **노이즈를 열지 않는다**(엄하게).
  애매하면 놓치지 않는 쪽으로 기운다 — 단, 예약콜(내일 콜)만은 예외로 «확실히 거른다»(되돌릴 수 없는 계약이라서).

기사님의 하루로 보면:
- 아침에 관제웹 🔍 필터 창에서 **도착 희망 지역 · 최소 금액 · 반경 · 제외어 · 예약콜**을 정한다(또는 평소 설정 그대로 둔다).
- 서버가 지금 위치와 목적지로 **상차 목록(어디서 실을 수 있나)**과 **하차 목록(어디로 가면 좋나)**을 동 이름으로 만들어 원달앱에 내려 준다.
- 차가 움직이면(0.5km 마다) 상차 목록이 다시 만들어지고, 콜을 잡아 경로가 생기면 하차 목록이 그 경로를 따라 다시 만들어진다.
- 그날 바꾼 값은 «오늘만»이면 자정(영업일 전환)에 평소 설정으로 돌아간다.

## 2. 용어 풀이

| 말 | 뜻 | 코드 이름 |
|---|---|---|
| 콜 필터 | 원달앱이 **집기 전에** 거르는 조건 묶음. 서버가 **집은 뒤에** 쓰는 «판정 기준»과 완전히 다른 설정이다 | `AutoDispatchFilter`(shared) · `FilterConfig`(원달앱) |
| 상차 목록 | 상차지가 이 읍·면·동 이름 중 하나에 걸려야 통과. 서버가 «지금 내 위치 둘레»로 만든다 | `pickupKeywords` |
| 하차 목록 | 하차지가 이 읍·면·동 이름 중 하나에 걸려야 통과. 첫짐이면 «내 위치 원 ∪ 목적지 원 ∪ 마름모», 합짐이면 «경로 띠 ∪ 목적지 원 ∪ 마름모» | `destinationKeywords` |
| 함정 낱말 | 키워드로 시작·끝나는 더 긴 다른 지명(«남동» → «남동구», «도림동» ← «신도림동»). 부분 글자 오탐을 막는다 | `keywordTraps` |
| 이름이 같은 다른 지역 동 | «고덕동»이 서울 강동구에도 평택시에도 있을 때, 동 바로 앞에 다른 시·군·구가 보이면 다른 곳으로 본다 | `destinationDongSigungu` |
| 최소 금액 | 요금이 이 값보다 작으면 탈락. 0 이면 끈 것. 세 배차망이 한 값을 쓴다 | `minFare` · `FareFloor` |
| 단가 | 요금 ≥ 배송거리 × 차종별 km당 단가. 서버가 콜할인율을 반영해 내려 준다 | `ratePerKm` |
| 상한 | 요금이 너무 크면 탈락. 1~999,999 사이일 때만 건다(100만 = 상한 없음) | `maxFare` |
| 예약콜 | 목록·상세에 «낼·내일·내상·모레·M/D·N일)» 같은 날 표시가 붙은 콜 | `reserved` · `reservedDay`(0=오늘, 1=내일, null=날 모름) |
| 예약콜 설정 | 오늘 콜만 · 내일 콜도 · 내일 콜만 | `reservationMode` = `today` · `tomorrowToo` · `tomorrowOnly` |
| 제외어 | 콜 글자에 이 낱말이 있으면 탈락(예: 착불·까대기) | `excludedKeywords` |
| 오늘만 | 필터 창에서 바꾼 값을 «오늘 하루만» 쓰고 영업일이 바뀌면 평소 설정으로 돌린다 | `activeFilter`(오늘 값) ↔ `baseFilter`(평소 설정, DB) |
| 앞으로 계속 | 바꾼 값을 평소 설정(DB `user_filters`)에도 저장한다 | `saveAsDefault` |
| 자동 반경 | 목적지까지 거리 ÷ 기준 거리 배율로 반경 넷(상차·하차·경유·목적지)을 늘리고 줄인다. **그날 첫짐에 한 번** 재고 위치가 바뀌어도 다시 줄이지 않는다 | `radiusAuto` · `radiusDistanceKm` · `radiusScaleOf` |
| 영업일 | 한국 시각 자정 기준의 날. 진행 중 콜이 있으면 콜을 다 마칠 때까지 전환을 미룬다 | `businessDayKey` · `session.businessDay` |
| 블루투스 공급 | 서버 → 관제앱 → (블루투스) → 원달앱으로 필터 원문을 넘기는 길 | `SUPPLY {filter, filterVersion}` · `FilterStore.applySupplied` |
| 콜 잡기 보류 | 만석 · 필터 고장일 때 서버가 싣는 까닭. 픽커는 이 칸만 보고 알람을 멈춘다 | `captureHold` |
| 채운 뒤 필터 | 상세 화면 글자·사진으로 콜 칸을 채운 다음 같은 축으로 한 번 더 거르는 문 | `passesFilterAfterFill` |

용어의 원천은 `onedal-web/server/tests/rules/glossary.test.ts` 다. 옛말을 쓰면 그 검사가 문다.

## 3. 지금 규칙

각 줄: 규칙 — 까닭 한 줄 — 코드 자리.

### 3-1. 공통 (세 배차망)

1. **필터 원문 읽기는 한 곳이다.** 인성·화물24시·픽커·앱 화면이 모두 `FilterStore.parse/current` 로 읽는다.
   — 칸마다 읽는 규칙이 두 벌이면 배차망마다 판정이 갈린다. — `onedal-app/app/src/main/java/com/onedal/app/core/FilterStore.kt`
2. **필터를 한 번도 못 받았거나 깨졌으면 `FilterConfig()` 기본값이다** — `isActive=false` · `minFare=30000` · `pickupRadiusKm=10` · 하차 목록 빈 것.
   — 서버 미응답 때의 안전망이다. — `onedal-app/.../models/SharedModels.kt` 의 `data class FilterConfig`
3. **최소 금액은 한 식이다:** `minFare <= 0 || fare >= minFare`.
   — 기사님 «세 배차망 모두 공통으로». 0 이 «끔»이다. — `onedal-app/.../core/engine/FareFloor.kt`
4. **예약콜은 두 문으로 거른다.** 목록(`passesList`)은 **확실한 다른 날**만 막고, 날 모름은 상세까지 들인다.
   채운 뒤(`passesAfterFill`)는 날 모름도 막는다. 모르는 값이면 «오늘 콜만».
   — 목록에서 날 모름을 막으면 오늘 예약콜을 놓치고, 끝까지 들이면 내일 콜을 오늘 계약하는 사고가 난다. — `onedal-app/.../core/engine/ReservationGate.kt`
5. **예약 글자는 상차 쪽 칸만 읽는다.** «낼·내일·내상»=1 · «모레»=2 · «오늘·당일·당상·지금상»=0 · M/D · N일). **시각만 있으면 오늘 콜**(지금보다 이른 시각을 내일로 짐작하지 않는다). «N:NN까지»는 예약이 아니다.
   — 원문 전체에서 «낼»을 찾으면 «보낼»에 걸린다. 하차 쪽 시각은 도착 약속이다. — `onedal-app/.../core/ReservationText.kt`
6. **자동 모드는 오늘 콜만 확정을 누른다** (`ReservationGate.isToday`). 내일 콜은 미리보기까지.
7. **지명 대조는 한 규칙이다** (원달앱 `RegionMatch.kt` ↔ 서버 `shared/src/regionMatch.ts`, 문제지 `shared/src/regionMatchCases.json`):
   - 키워드 뒤에 함정 꼬리가 붙거나 바로 «구·시·군»이 이어지면 다른 곳 («남동» ⊄ «남동구»)
   - 키워드 앞에 함정 머리가 붙으면 다른 곳 («도림동» ⊄ «신도림동»)
   - 동 바로 앞에 칸의 시군구가 아닌 시군구가 보이면 다른 곳(이름이 같은 다른 지역 동). 앞이 시도뿐이거나 안 보이면 **통과**
   - 같은 글의 다른 자리는 다시 본다
   — 실사고: «남동»(광주 쪽 동)이 «인천 남동구»에 걸려 인천행 콜을 잡았다. 미탐이 오탐보다 아프므로 «모르면 통과». — `onedal-app/.../plugins/RegionMatch.kt`
8. **상차 목록이 비면 고장 → 안 잡는다.** 칸 자체가 없으면(null, 옛 서버) 상차 반경 km 비교로 돌아간다.
   — 빈 목록을 «제한 없음»으로 읽으면 필터가 느슨해지는 게 아니라 없어진다. — `onedal-app/.../plugins/PickupListFilter.kt` · 서버 `shared/src/dispatchFilter.ts` `callFilterBlocker`
9. **상차 목록에는 읍·면·동·가·리 이름만 들어간다** (시·구·군 빼고). 0.5km 움직이면 다시 만든다(`PICKUP_LIST_MOVE_KM`).
   뒤쪽은 «경로 몇 km»가 아니라 «지금 내 위치 둘레»로 뺀다. — 되돌아가는 길에 다시 지날 동을 «지나왔다»며 빼면 앞길 위 좋은 콜을 막는다. — `onedal-web/shared/src/pickupList.ts`
10. **필터는 두 모음뿐이다** — 상차 목록에 있고 하차 목록에 있으면 올린다. 경로 순서(거꾸로 가는가) 검사는 없다.
11. **판정은 파서 안 한 곳에서 센다.** 목록 순회(`HijackService`)에서 필터를 다시 읽지 않는다.
    — 성적표와 «떨어진 까닭»이 두 벌이 된다. — 각 파서의 `judge` / `shouldClick` / `decideAxes`

### 3-2. 서버 쪽 (필터를 만드는 곳)

12. **오늘만 / 앞으로 계속.** 관제웹이 보낸 값은 늘 오늘 값(`activeFilter`)을 바꾸고, `saveAsDefault` 일 때만 평소 설정(DB `user_filters`)까지 바꾼다. 오늘 값은 그 영업일 줄에도 적어 서버가 다시 떠도 그날 안에는 남는다.
    — 기사님 «아침에 오늘 콜이 많이 나올 곳으로 바꾸고, 그 값으로 돌아오게». — `onedal-web/server/src/state/filterManager.ts` `applyWebFilter` · `recordFilterToday`
13. **영업일이 바뀌면 오늘 필터 전체가 평소 설정으로 돌아간다** (하차 목록 파생값 · 자동 반경 잰 거리도 비운다). `isActive` 는 평소 설정 값을 그대로 따른다.
    — 어제 경로에서 나온 지역으로 오늘 콜을 거르면 안 된다. — `onedal-web/shared/src/dispatchFilter.ts` `resetToBaseFilter`
14. **콜이 다 끝나 첫짐 대기로 돌아오면** 합짐 사이클이 만든 파생값(하차 목록·경유·수동 고정)만 되돌리고, 기사님이 오늘 정한 값(목적지·최소 금액·반경·제외어)은 남긴다. — `filterManager.ts` `updateActiveFilter`
15. **자동 반경:** 배율 = 목적지까지 거리 ÷ 기준 거리(상한 없음). 잰 거리는 들고 있으면 다시 재지 않는다.
    비우는 때: 그날 처음 · [↻ 다시 구하기] · 목적지를 바꿀 때 · 영업일 전환 · 서버 재시작. [↻ 다시 구하기]는 **넓히기만** 한다(가까워졌으면 옛 거리 유지). 못 재면 배율 1(손대지 않음).
    — 기사님 «위치가 바뀐다고 바뀌면 나중에 관내콜을 할 수가 없다». — `onedal-web/shared/src/phases.ts` `radiusScaleOf` · `heldRadiusDistanceKm` · 서버 `state/filterNet.ts` `holdRadiusDistance`
16. **내일 콜의 상차 반경은 줄이지 않은 기본 상차 반경**이고, 상차 목록은 집 둘레 동 목록(`reservedPickupKeywords`)이다. — 내일 콜은 내일 집에서 떠난다. — `phases.ts` `reservedPickupRadiusKmOf`
17. **원달앱에 내려가는 칸은 표 하나**(`APP_FILTER_KEYS`)다. 관제웹 화면용 `destinationGroups` 는 일부러 안 보낸다(응답이 무거워진다). — `onedal-web/shared/src/dispatchFilter.ts`
18. **서버도 집은 뒤에 한 번 더 본다:** 제외어는 배차망별 «제외어 찾는 칸»(인성 적요·결제 괄호 / 화물24시 화물정보·결제방법 / 픽커 물품정보·유의사항)에서만 찾는다. 첫짐일 때 최소 금액을 다시 본다(픽커처럼 앱이 연 콜은 건너뜀).
    — `onedal-web/server/src/core/engine/OrderEvaluator.ts`(제외어 · `skipFareFloor`) · `shared` `excludeScanTextOf`

## 4. 배차망별 차이

| 축 | 인성 (`InsungParser.judge`) | 화물24시 (`Hwamul24Parser.shouldClick`) | 카카오 픽커 (`KakaoPickerParser.decideAxes`) |
|---|---|---|---|
| 실물/시뮬 | 시뮬레이터만 | 시뮬레이터만 | **실물 앱** |
| 필터 꺼짐 처리 | `isActive=false` → 판정 안 함(«locked») | 같다 | `isActive` 를 **안 본다**. `captureHold` 가 있으면 알람·상세 열기를 멈춘다 |
| 예약 | `passesList` | `passesList` | `passesList` · 상세 사진 «내일 14:00 픽업예약»이 이긴다 |
| 차종 | `allowedVehicleTypes` (비면 전체) | 같다(배차망 낱말을 우리 차종으로 바꾼 뒤 «같은지») | **축 없음** |
| 최소 금액 | `FareFloor` | `FareFloor` | `FareFloor` |
| 단가 | 단가표·차종·배송거리 다 있을 때 | 같은 식이지만 **배송거리를 아직 안 읽어** 실제로는 꺼져 있다 | **축 없음**(배송거리 없음) |
| 상한 | `maxFare` 1~999,999 | 같다 | **축 없음** |
| 상차 | 상차 목록(있으면) · 없으면 반경 km · 합짐이면 반경 무시. 상세에서는 «출발지~도착지» 사이만 대조 | 상차 목록(있으면) · 없으면 반경 | **오늘 콜은 상차 목록을 안 쓰고 목록 줄의 픽업거리 km ≤ 반경**. 내일 콜은 집 둘레 동 목록 |
| 하차 | 하차 목록 비면 **탈락**(필터 고장) | 비면 **탈락** | 비면 **통과**(제한 없음). 하차를 못 읽은 도보 목록도 통과 → 채운 뒤 다시 봄. 줄임 표기(«정자3»·«수정»)는 토막 대조 |
| 제외어 | 원문 전체(`rawText`)에 포함되면 탈락 | 원문 전체(적요 포함) | **목록에서 안 본다** — 서버가 집은 뒤에 본다 |
| 계약 | 시뮬에서 선점 | 시뮬에서 선점 | 계약 버튼을 누르지 않는다(알람만) |

## 5. 데이터 흐름

```
관제웹 🔍 필터 창 (OrderFilterModal.tsx)
  │  update-filter {값…, saveAsDefault?}      ← 필터 창의 일부 저장은 늘 saveAsDefault=true
  ▼
서버 filterManager.applyWebFilter
  ├─ saveAsDefault → saveBaseFilter → DB user_filters (평소 설정)
  ├─ updateActiveFilter → session.activeFilter (오늘 값 · 메모리)
  │     └ recalculateDerivedFields · refreshDetourIfNeeded · refreshKeywordTraps
  │        → 하차 목록 · 함정 낱말 · 이름 겹침 동 · 상차 목록(rebuildPickupList)
  └─ recordFilterToday → 영업일 줄 (서버 재기동에도 그날 값 유지)
  ▼
서버 appFilter 조립 (APP_FILTER_KEYS 만 · captureHold · 내일 콜 칸 얹음)
  ▼
관제앱 (폰) ── 블루투스 SUPPLY {filter, filterVersion} ──► 원달앱
  ▼
원달앱 FilterStore.applySupplied → prefs activeFilter (원문 그대로 저장)
  │   판이 바뀌면 지금 목록을 다시 판정
  ▼
각 파서 판정 (목록) → 상세 → 채운 뒤 필터 → 서버 /api/scrap → 판정 → 관제앱 결재
```

- 원달앱은 필터 원문을 **되말지 않고 그대로** 저장한다 — 되말면 null 칸이 사라져 «칸 없음(옛 판정)»과 «빈 목록(고장)»의 구분이 무너진다.
- 서버의 0.5km 이동 재생성: `filterManager.maybeRebuildPickupList`.
- DB 칸 기본값: `onedal-web/server/src/db.ts` 의 `user_filters`(`min_fare` 30000 · `max_fare` 1000000 · `excluded_keywords` '[]' · `reservation_mode` 'today' · `radius_auto` 0).

## 7. 아직 정하지 않은 것 (기사님 결정 필요)

1. **최소 금액 한 값을 요금 체계가 다른 배차망에 건다.** 픽커는 5천~1만 원대, 인성·화물24시는 2만 원 이상이 보통이다. 지금은 실물이 픽커뿐이라 막대를 픽커 요금대에 두면 된다. 인성·화물24시가 실물이 되는 날 «배차망별 최소 금액»을 둘지 정해야 한다.
2. **하차 목록이 빌 때 픽커만 «제한 없음».** 인성·화물24시는 «고장 → 탈락». 픽커를 같은 규칙으로 맞출지(노이즈 ↓ · 관내콜 놓칠 위험 ↑).
3. **픽커 오늘 콜의 상차 축이 상차 목록이 아니라 픽업거리 km.** 다른 두 배차망과 같은 상차 목록으로 맞출지.
4. **제외어를 어디서 찾나 — 원달앱은 원문 전체, 서버는 «제외어 찾는 칸»만.** 원달앱도 서버와 같은 칸으로 좁힐지(주소에 걸려 좋은 콜을 놓치는 것을 막는다).
5. **내일 콜의 판정 색** — 가 «집 기점·예약 시각으로 색» / 나 «시간당 금액만». 계획만 있음(코드 없음 여부는 서버 `OrderEvaluator` 에서 확인 필요).
6. **화물24시 단가 판정** — 배송거리를 읽게 되면 저절로 켜진다. 실물 화면이 생기면 «목록에 배송거리가 있나»부터 확인.
7. **자동 반경 상한 없음** — 목적지가 멀면 반경이 기준보다 커진다(기사님 확정 사항). 아주 먼 목적지에서 노이즈가 늘면 다시 볼 자리.
8. **밤샘 운행 중 서버를 다시 띄우면** 세션이 오늘 날로 태어난다(영업일 전환 미룸이 끊긴다) — 빈칸으로 남아 있다.

## 8. 하지 말 것 (함정과 까닭)

- **빈 목록을 «제한 없음»으로 바꾸지 않는다.** 상차·하차 목록이 비면 고장이다. «아무 데나 좋다»로 열면 `isActive` 가 켜진 채 지역 제한만 사라진다. (픽커 하차는 예외로 남아 있다 — 7-2)
- **«칸 없음(null)»과 «빈 목록([])»을 합치지 않는다.** null 은 옛 서버(반경 판정으로), [] 는 고장(안 잡음). `FilterStore` 에서 원문을 되말거나 `orEmpty()` 하면 둘이 섞인다.
- **지명을 `contains` 로 대조하지 않는다.** 반드시 `RegionMatch.anyHit` — «남동»⊂«인천 남동구» 사고가 그대로 돌아온다.
- **「앞 글자가 한글이면 막는다」 같은 글자 종류 규칙을 넣지 않는다.** 칸 사이 공백이 빠진 정상 주소(«인천남동구논현동»)가 전부 막힌다.
- **예약 «낼»을 원문 전체에서 찾지 않는다** — «보낼»에 걸린다. 이미 떼어 낸 상차 쪽 칸·태그만.
- **시각만 있는 콜을 내일로 짐작하지 않는다.** 날 표시가 있을 때만 내일이다.
- **목록에서 «날 모름» 예약을 막지 않는다** — 상세에서 날을 읽으면 오늘 예약콜일 수 있다. 막는 곳은 채운 뒤 필터다.
- **목록 순회(`HijackService`)에 필터 판정을 하나 더 두지 않는다** — 성적표와 «떨어진 까닭»이 두 벌이 된다.
- **반경·정수 칸을 `Int` 로 두지 않는다** — 자동 반경이면 서버가 `4.55` 를 보내고, Gson 이 응답 전체를 버려 새 필터도 모드도 못 받는다.
- **자동 반경을 위치마다 다시 재지 않는다** — 목적지 가까이서 반경이 0 가까이 줄어 관내콜·가는 길 좋은 콜을 못 받는다.
- **영업일 전환을 «자정 정각»으로 고정하지 않는다** — 진행 중 콜이 있으면 다 마칠 때까지 미룬다.
- **상태·단계 이름(`dispatchPhase === 'STANDBY'` 같은)으로 가르는 조건을 새로 만들지 않는다** — 각 부품이 자기 사실(콜이 있나, 출발했나)을 직접 보게 한다. 옛 자리가 남아 있어도 늘리지 않는다.
- **시험 때문에 기사님께 필터를 바꾸시라고 하지 않는다** — 문제지를 지금 서버 값에 맞춘다.
- **판정 기준(집은 뒤)과 콜 필터(집기 전)를 한 창·한 값으로 합치지 않는다** — 판정 기준에는 «오늘만»이 없다.
