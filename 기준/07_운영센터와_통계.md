# 07 · 운영센터와 통계

처음 이 영역을 고치는 에이전트가 이 한 장으로 «무엇이 있고, 왜 그렇게 생겼고, 무엇을 건드리면 안 되는지»를 알게 하는 문서다.
앱 안의 세부 규칙은 [onedal-web/ops/CLAUDE.md](../onedal-web/ops/CLAUDE.md) 가 원천이다. 여기와 다르면 그 파일과 코드가 맞다.

---

## 1. 하는 일

**운영센터**(`onedal-web/ops/`)는 관리자가 PC · 폰 브라우저로 여는 화면이다. 기사가 쓰는 관제웹(`client-app`)과 다른 앱이고, 같은 서버(`/api/ops/*`)를 부른다.

1DAL 은 인성 같은 «배차 플랫폼»을 지향한다. 그래서 운영센터는 플랫폼 운영자가 하는 일 가운데 **법적 자격이 필요 없는 것만** 한다.

| 운영센터가 하는 것 | 운영센터가 하지 않는 것 |
|---|---|
| 회원 승인 · 정지 · 탈퇴 처리 · 허락과 기한 | 오더 등록 · 콜 배정 · 회원 간 콜 넘기기 |
| 통화 도우미(KEEP 한 콜의 상차지 · 하차지에 대신 전화하고 결과 적기) | 수수료 · 충전금 · 운임 정산 대행 · 자체 결제 (주선업 · 전자금융 자격이 필요) |
| 회원 위치 · 폰 연결 · 배차망 화면 이상 보기 | 기사의 필터 · 판정 기준 · 결재(KEEP/CANCEL) 바꾸기 |
| 공지 · 약관 등 페이지 글 · 앱(APK) 배포 | |
| 시장 통계(목록에 뜬 실물 콜의 흐름) | |

회원 사이의 «콜 연계»가 생기더라도 **알림 + 연락처까지만**이다(계획만 있음(코드 없음)).

**통계**는 두 갈래다.
- 운영센터 «통계» 메뉴 — 관리자가 보는 시장 통계(`GET /api/ops/stats`).
- 관제웹 아침 카드(뉴스레터 자리) — 기사가 아침에 보는 «오늘 이 요일 · 이 시간대에 어디서 어디로 콜이 많았나»(`GET /api/stats/flows` → `client-app/src/lib/morningCard.ts` · `components/dashboard/MorningCard.tsx`).

## 2. 용어 풀이

용어 원천은 `onedal-web/server/tests/rules/glossary.test.ts` 다. 이 문서에서 쓰는 말만 풀어 둔다.

| 말 | 뜻 |
|---|---|
| 운영센터 | `onedal-web/ops/` 앱. 포트 3002(`pnpm dev:ops`). 관리자용 |
| 관리자 | `users.ops_allowed_at` 칸이 채워진 계정. 기사님은 기사이면서 관리자다(겸직) |
| 회원 | 1DAL 을 쓰는 기사 계정(`users` 한 줄) |
| 사실 칸 | 상태 이름 대신 «언제 그 일이 있었나»를 적는 시각 칸 — `approved_at` · `suspended_at` · `withdrawn_at` · `paid_until` · `auto_allowed_at` · `stats_allowed_at` 등 |
| 허락 + 기한 | 기사마다 기능 차이를 내는 유일한 길. 기능은 모두 같고, 허락 시각과 기한만 다르다 |
| 통화 도우미 | 진행 중 KEEP 콜을 «통화 필요 먼저 · KEEP 이 오래된 순»으로 보이고, 관리자가 전화한 결과(짐 단위 · 수량 · 약속 시각 · 메모)를 적는 화면 |
| 상대 취소 표시 | 통화 도우미에서 «상대가 취소했다»를 **정보로만** 적는 것. CANCEL 결재가 아니다 |
| 열람 기록 | 관리자가 회원의 위치 · 콜 · 현황판 · 이상 기록 사진을 «봤다»는 줄. `ops_audit` 표 |
| 이상 기록 | 원달앱이 배차망 화면을 못 읽었을 때 남기는 줄(`telemetry_anomalies`) + 처음 보는 화면 글자(`screen_words`) — «배차망 리뉴얼 신호» |
| 원문(intel) | 원달앱이 보고한 목록 줄 그대로(`intel` 표, `type='INTEL_BULK'`) |
| 콜 흐름 통계 | 원문을 하루 × 시 × 출발 시군구 × 도착 시군구로 묶은 표(`stats_flows`) |
| 실물 / 시뮬 | 보고의 `source` 칸. `'real'` 은 실제 배차망 앱, `'sim'` 은 시뮬레이터, NULL 은 옛 앱 |
| 같은 콜 | 통계에서 «같은 일감» — 기사 · 배차망 · 상차 · 하차가 같고 직전에 본 때부터 30분 안 |
| 영업일 | 한국 시각 기준 하루(`businessDayKey`) |
| 안 잡은 콜 | 그날 판정은 받았으나 잡지 않은 콜(알림 · 미리보기 · 체험 · 잡았다 무른 콜) |
| 버린 콜 | 판정 전에 원달앱 필터가 거른 목록 줄(`intel.verdict` 에 까닭) |

## 3. 지금 규칙

| 번호 | 규칙 | 까닭 | 코드 자리 |
|---|---|---|---|
| R1 | 운영센터에는 기사 운행 값(필터 · 판정 기준 · 결재) 버튼이 없다. 서버 `/api/ops` 에도 그 쓰기 문이 없다 | 운행 값은 기사 몫. 관리자가 대신 누르면 기사가 모르는 사이 운행이 바뀐다 | `ops/CLAUDE.md` · `server/src/routes/ops.ts` 머리 주석 |
| R2 | 관리자의 쓰기마다 `ops_audit` 한 줄. `audit()` 한 함수로만 쓴다 | 누가 무엇을 했나를 남긴다(동의의 짝) | `routes/ops.ts` `audit()` |
| R3 | 보는 것도 기록한다 — 회원 상세(3초 안 중복 안 적음) · 현황판 · 위치(60초 묶기) · 이상 기록 사진 | 위치 · 콜은 개인정보다 | `routes/ops.ts` `auditBoardView` · `BOARD_VIEW_GAP_MS` · `/anomalies/:id/shot` |
| R4 | 회원 상태는 이름 칸이 아니라 사실 칸에서 글로만 만든다 | `if (status === …)` 같은 상태 이름 조건문 금지(루트 CLAUDE.md) | `ops/CLAUDE.md` · `routes/ops.ts` 회원 문 |
| R5 | 정지 둘 — «끝난 뒤 정지»는 연결을 안 끊고, «즉시 정지» · «탈퇴 처리»는 그 회원의 관제웹 소켓을 끊는다. 폰은 폰 문(`core/accountGate`)이 막는다 | 즉시 정지는 KEEP 해 둔 콜의 안전취소도 멈춘다 — 계정 도용 같은 때만 | `routes/ops.ts` `/members/:id/suspend` · `/withdraw` · `ops/src/pages/MemberDetail.tsx` 확인 창 |
| R6 | 자기 계정은 정지 · 탈퇴할 수 없다 | 기사님은 관리자이자 기사 — 실수로 자기 운행을 끊지 않게 | `routes/ops.ts` `memberWrite` 의 `selfBlock` |
| R7 | 승인하면 비어 있는 자동 잡기 · 통계 허락을 지금 시각으로 켠다(기한 없음) | 기사는 모두 같은 기능이 기본 | `/members/:id/approve` |
| R8 | 제3자 정보(상대 전화 등)는 서버가 가려서 준다. 화면은 가리거나 풀지 않는다 | 가림 규칙 한 곳 | `server/src/services/mask.ts` · shared `maskPhone` |
| R9 | 서버가 안 되면 `ErrorBand`(«서버 응답이 없습니다 — 다시»). 예시 자료로 대신 그리지 않는다 | 장애를 가리면 노이즈가 된다 | `ops/CLAUDE.md` |
| R10 | 운영센터는 관제웹 파일을 가져오지 않고, 관제웹도 운영센터를 가져오지 않는다. 부품은 `@onedal/ui` | 기사 폰이 받는 파일에 운영센터 코드가 섞이지 않게 | `opsIsolated` 검사 |
| R11 | 들어오는 문은 `requireAuth` + `requireOps` 한 번. 화면은 role 을 읽지 않고 서버 403 으로 «허락 없는 계정»을 안다 | 문지기 한 곳 | `server/src/index.ts` `/api/ops` 세 줄 · `opsLogin` 검사 |
| R12 | 이상 기록 사진은 가리지 않은 원본이라 `/api/ops/anomalies/:id/shot` 한 문으로만 열고, 열 때마다 기록 | 사진에 상대 정보가 그대로 있다 | `routes/ops.ts` · `core/anomalyShots` |
| R13 | 회원 위치는 폰이 보낸 진짜 GPS(`lastFixSource === 'gps'`)만. 모의 주행 · 손으로 찍은 점은 안 섞는다 | 거짓 위치를 «지금 어디 있나»로 보이지 않게 | `routes/ops.ts` `locationsOf` |
| R14 | 통계 재료는 원문 가운데 `source='real'` 목록 줄(`INTEL_BULK`)뿐. 시뮬 · 옛 앱은 원문에만 남고 통계에서 빠진다 | 사업자가 없어 인성 · 화물24시 콜은 전부 시뮬 — 실측인 척 세지 않는다 | `server/src/services/callFlowStats.ts` 머리 |
| R15 | 상세까지 간 콜이 아니라 **목록에 뜬 콜**을 센다 | 상세만 세면 «기사님 필터를 통과한 흐름»만 쌓여 치우친다 | 같은 파일 |
| R16 | 같은 콜 = 상차 + 하차 + 30분 창(요금은 지문에 안 넣는다) | 픽커는 시간이 지나면 요금을 올린다 — 요금을 넣으면 한 콜이 둘로 세진다. 앱의 «이 줄을 다시 판정할까»(상차+하차+요금)와 일부러 다르다 | `SAME_CALL_WINDOW_MS` · `groupSameCalls` |
| R17 | 모르는 값(앱이 0 으로 적은 요금 등)은 합 · 최소 · 최대에 안 넣고, 평균은 아는 콜 수로 나눈다 | 0 원이 평균을 끌어내린다 | `callFlowStats.ts` |
| R18 | 묶기는 «그날 지우고 다시 넣기» 한 트랜잭션. 서버가 뜰 때 + 1시간마다 «어제까지 안 묶은 날»을 묶는다 | 되풀이해도 같은 결과. 영업일 전환에 넣으면 한 기사의 보고를 붙잡는다 | `callFlowStats.ts` `setInterval(run, 3_600_000)` |
| R19 | 기사별 줄은 90일까지, 그 뒤는 기사 칸을 뺀 합친 줄로 | 표 크기가 기사 수에 비례하지 않게 | `PER_DRIVER_DAYS` |
| R20 | 읽는 문 둘 — 관제웹 · 아침 카드용(`/api/stats/flows`, 통계 허락이 살아 있어야 함, 기사 칸 없음, 남이 섞인 칸은 남의 기사 3명 이상일 때만 합계) / 관리자용(`/api/stats/flows/admin`, 기사 칸 있음) | 합친 통계로도 한 사람이 드러나지 않게 | `server/src/routes/stats.ts` |
| R21 | 시각은 ISO 칸(`timestamp`, UTC)만 읽고 SQLite `localtime` 칸은 통계에 안 쓴다 | 서버 시간대가 바뀐 날을 경계로 두 기준이 섞인다 | `callFlowStats.ts` 머리 |
| R22 | 판정 때 콜 내용 · 그때의 서버 필터 요약을 판정 장부 detail 에 함께 적고, 회원 상세가 «오늘 판정받은 콜»로 보인다. 필터는 **서버가 판정할 때의 필터**다 | «안 잡은 콜이 어떤 필터로 왜 그 색이었나»에 답하려고. 새 DB 칸 없이 detail JSON 안에 | `server/src/core/engine/judgmentRecord.ts` · `routes/ops.ts` `todayJudgedOf` |
| R23 | 메뉴 표는 한 곳 `ops/src/ui.tsx` `NAV`. 줄마다 «들어올 때의 궁금증 · 할 수 있는 것»을 함께 적고 쪽 제목 아래 `PagePurposeBar` 가 그린다 | 모든 쪽 맨 위에 «이 화면에서 할 수 있는 것» 한 줄 | `ui.tsx` |
| R24 | 옛 주소는 새 자리로 넘긴다 | 즐겨찾기가 깨지지 않게 | `ops/src/App.tsx` · `opsShell` 검사 |

## 4. 화면 · 메뉴 지도

메뉴 수는 `grep -c "{ to: '" onedal-web/ops/src/ui.tsx` 로 센다. 주소는 `ops/src/App.tsx`.

| 메뉴 · 주소 | 들어올 때의 궁금증 | 보이는 것 · 할 수 있는 것 | 서버 문 |
|---|---|---|---|
| 홈 `/` | 전체가 괜찮나? 지금 할 일은? | 회원 수 · 일하는 사람 · 지역 · 접속 · 못 읽는 배차망 화면 · 지금 할 일. 숫자를 누르면 그 쪽으로 | `GET /api/ops/home` 한 번 |
| 통화 도우미 `/calls` | 지금 전화할 콜이 있나? | 진행 중 KEEP 콜. 통화 결과 적기 · 상대 취소 표시(잘못 누름 지우기에 확인 창) | `GET /calls` · `POST /calls/:id/note` |
| 회원 `/members` | 누가 있고 누가 승인 · 허락이 필요한가? | 목록 · «매달 멤버 대조» 탭(`?tab=check`, **예시 자료** — 서버 문 없음) | `GET /members` |
| └ 회원 상세 `/members/:id` | 이 사람은 지금 일하나? 폰은? 왜 콜을 안 잡았나? | 칸: 기본 · 폰 · 필터(`MemberPhoneFilter`, 보기만) · 오늘 콜 · 오늘 판정받은 콜 · 버린 콜(오늘) · 동의 · 기록. 승인 · 정지(끝난 뒤 / 즉시) · 정지 풀기 · 탈퇴 · 허락과 기한 | `GET /members/:id` · `POST …/approve·suspend·resume·withdraw·allow·paid-until` · `GET /board/member·phones·filter·intel` |
| 지도 `/map` | 회원들이 지금 어디 있나? | 진짜 GPS 마지막 점 · 시 · 구 묶음. 보기만(열람 기록) | `GET /locations` |
| 점검 `/inspect` | 고장 났나? 배차망이 바뀌었나? | 서버(부팅 · 커밋 · 오늘 오류 수) · 폰 접속 · 카카오 사용량 · 이상 기록 · 새 화면 글자 | `GET /board/server` · `/phones` · `/board/kakao` · `/anomalies` |
| 운영 `/manage` | 알릴 것 · 올릴 앱 | 탭 셋: 공지 · 페이지 글(약관 등) · 앱 배포(APK 올리기 · 최소 판) | `/notices` · `/contents/:kind` · `/releases` · `/releases/minimum` |
| 통계 `/stats` | 장사가 잘 되나? | 시장에 뜬 실물 콜 흐름 · 버린 콜. 실물이 없으면 빈 화면 | `GET /api/ops/stats` |
| 기록 `/audit` | 누가 무엇을 했나? | `ops_audit` 줄. 보기만 | `GET /audit` |

옛 주소 → 새 자리: `/board` · `/phones` · `/anomalies` → `/inspect`(회원을 고른 `/board` 는 그 회원 상세의 폰 칸) · `/notices` · `/contents` · `/releases` → `/manage?tab=…` · `/members/check` → `/members?tab=check`.

서버 문 전체는 `grep -nE 'router\.(get|post|put)\(' onedal-web/server/src/routes/ops*.ts` 로 본다.

관제웹 쪽 통계 자리: 대시보드의 아침 카드(`MorningCard`). 같은 요일 · 지금부터 3시간 창의 흐름을 «내 폰이 본 목록 기준»으로 보이고, 묶인 날이 없으면 «아직 쌓인 날이 없다» 한 줄.

## 5. 데이터 흐름

```
원달앱(배차망 목록 읽음) ──POST /api/scrap (source: real|sim)──▶ intel 표(INTEL_BULK · verdict)
                                                                  │  서버 부팅 + 1시간마다, 어제까지 안 묶은 날
                                                                  ▼
                                               stats_flows (영업일 · 시 · 배차망 · 출발/도착 시군구 · 차종 · 기사)
                                                 │                                │
                              GET /api/stats/flows (기사 칸 없음 · 허락)   GET /api/ops/stats · /api/stats/flows/admin
                                                 ▼                                ▼
                                    관제웹 아침 카드                       운영센터 «통계»

서버 판정 ──▶ order_judgments (색 · 점수 · 축 까닭 + detail.call · detail.filter) ──▶ 운영센터 회원 상세 «오늘 판정받은 콜»
orders (KEEP 한 콜) ──▶ 통화 도우미 · 홈 «지금 할 일» · 메뉴 숫자(/counts — 홈 숫자와 같은 함수)
사용자 세션(메모리) lastFix ──▶ /locations · /board/member (peek — 세션을 새로 만들지 않는다)
관리자 쓰기 · 열람 ──▶ ops_audit ──▶ «기록»

```

- 원문(`intel`) 지우기는 **코드 없음**. 묶기가 잘 돈 뒤 기사님께 여쭙고 켜기로 되어 있다.

## 8. 하지 말 것

- 운영센터에 필터 · 판정 기준 · KEEP/CANCEL 버튼을 만들지 않는다. 관리자 소켓에서 결재 · 단계 보고를 받지 않는다.
- «상대 취소» 표시를 CANCEL 결재로 잇지 않는다 — 콜을 버리는 것은 기사님만 한다.
- 회원 상태 이름 칸(`status`)을 만들지 않는다. 사실 칸 + 기한으로만.
- 관리자 쓰기 · 열람을 `audit()` 밖에서 처리하지 않는다.
- 화면에서 전화번호를 가리거나 풀지 않는다(서버가 한다).
- 서버가 안 될 때 예시 자료로 대신 그리지 않는다.
- 시뮬레이터 콜을 통계 · 아침 카드에 넣지 않는다. 표본이 적으면 적다고 쓴다 — 숫자를 실측인 척하지 않는다.
- 통계에 SQLite `localtime` 칸을 읽지 않는다.
- 운영센터에서 관제웹 파일을 가져오거나 그 반대를 하지 않는다.
- 운영 중(기사님 운행 중)에 운영센터만 고쳤다고 push 하지 않는다 — 실서버가 다시 뜬다.
- 운행 수수료 · 충전금 · 운임 정산 · 콜 배정 기능을 만들지 않는다.
