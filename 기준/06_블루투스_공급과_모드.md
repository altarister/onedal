# 06. 블루투스 공급 · 인터넷 받침 · 모드

이 한 장은 «서버가 정한 값(필터 · 모드 · 결재 · 빨리 접기)이 스캔폰의 원달앱까지 어떻게 가나»와
«길이 끊기면 원달앱이 무엇을 하나»를 다룬다. 처음 보는 사람이 이것만 읽고 고칠 수 있게 쓴다.
줄 번호는 쓴 때의 자리다 — 고치기 전에 이름으로 grep 해서 다시 찾는다.

---

## 1. 하는 일 — 기사님 하루의 말로

- 기사님은 차에 폰 둘을 둔다. **스캔폰(A24)의 원달앱**이 배차망 화면을 읽고 콜을 누르고, **관제앱(S23)**에서 기사님이 판정을 보고 결재한다.
- 기사님이 관제앱에서 필터를 바꾸거나 모드 단추를 누르거나 KEEP · 거절을 누르면, 서버가 저장 · 계산한 뒤
  **관제앱이 블루투스로 스캔폰에 곧바로 넘긴다**(1초 안). 이것을 «공급»이라 한다.
- 관제앱은 화면을 꺼도 상단 알림 «1DAL 관제 중»을 띄운 채(포그라운드 서비스) 공급을 계속한다. 끄려면 로그아웃이다.
- 블루투스가 끊기거나, 관제앱이 서버와 끊기거나, 안전취소가 걸려 있으면 원달앱이 **인터넷으로 서버에 1초마다 직접 묻는다**(인터넷 받침).
- 결재할 사람이 없을 것 같으면(관제웹 없음 · 블루투스 끊김 · 서버 응답 없음) 원달앱은 **«자동»을 «알람»으로 내려** 확정을 누르지 않는다.
  콜은 소리로 알리고, 확정은 기사님 손으로 한다. 결재 없는 확정은 안전취소(배차망 취소 횟수 +1 · 인성은 10번마다 페널티)로 끝나기 때문이다.
- 길이 다시 살아나면 다음 공급부터 기사님이 고르신 모드로 저절로 돌아온다. 저장된 모드는 상황 때문에 바뀌지 않는다.

## 2. 용어 풀이

| 말 | 뜻 |
|---|---|
| 스캔폰의 원달앱 | A24 에 깔린 1DAL 앱(`onedal-app`). 접근성 서비스로 배차망 화면을 읽고 누른다. 블루투스에서는 **받는 쪽**(GATT 서버 · 광고를 낸다) |
| 관제앱 | S23 에 깔린 1DAL 앱(`onedal-web/client-app`, Capacitor = 웹 화면을 감싼 안드로이드 앱). 블루투스에서는 **거는 쪽**(검색해서 붙는다) |
| 관제웹 | 관제앱 안의 웹 화면(또는 PC 브라우저). 기사님이 판정 · 결재 · 모드를 누르는 화면 |
| 공급 | 서버 → 관제앱 → 스캔폰으로 가는 «폰이 돌 값»: 필터 · 이 폰 몫(모드 · 심사 중 · 울릴 콜) · 결재 · 빨리 접기 |
| 공급 소켓 | 관제앱 네이티브 서비스(`SupplyService.java`)가 서버 이름공간 `/supply` 에 붙은 socket.io. 웹 화면 소켓과 **다른 연결**이다 |
| 웹 화면 소켓 | 관제웹(JS)이 서버에 붙은 socket.io. 서버는 이것으로 «결재할 관제웹이 있다»(`activeWebSession`)를 안다 |
| 인터넷 받침 | 원달앱 `InternetSupply` 가 `GET /api/devices/:deviceId/supply` 를 1초마다 부르는 길. 공급과 같은 원천 · 길만 다르다 |
| 명령(저장 값) | 기사님이 모드 단추로 고른 값. `user_devices.mode`(+ 옛 칸 `no_contract`)에 폰마다 저장 |
| 보낼 모드 | 서버가 명령 + 서버가 아는 상황(허락 · 관제웹 · 다른 폰 자동)으로 셈한 값. `modeSentToPhone` |
| 받은 모드(supplied) | 원달앱이 공급으로 마지막에 받은 모드. 원달앱 저장소 `suppliedMode` 에 남는다 |
| 도는 모드 | 원달앱이 실제로 쓰는 모드 = 받은 모드 + 원달앱이 아는 상황(블루투스 · 관제앱의 서버 숨 · 보고 응답). `TargetApp.runningMode` |
| 자동 · 알람 · 직접 · 체험 | `AUTO`(원달앱이 확정까지 누름) · `ALARM`(상세까지 열고 소리 · 확정은 기사님 손) · `MANUAL`(아무것도 안 누름) · `SIMULATION`(자동처럼 열지만 확정 누르기를 막음) |
| 숨(BREATH) | 블루투스로 1초마다 오가는 «살아 있음». 관제앱 → 폰 숨에는 «관제앱이 서버에 붙어 있나» 1바이트가 실린다 |
| 주고받기 증명 | CHALLENGE → HELLO → PROOF. 같은 기사님의 관제앱인지 짝 서명(pairSig)으로 서로 증명한다. 증명 전 공급은 버린다 |
| 데드맨 | 서버가 폰 보고(HTTP)를 일정 시간 못 받으면 그 폰을 «끊김(OFFLINE)»으로 보는 규칙 |
| 받았음(ACK) | 원달앱이 결재를 실행한 뒤 보내는 확인. 서버는 받았음이 올 때까지 결재를 지우지 않고 다시 준다 |

## 3. 지금 규칙 — 번호 · 까닭 · 코드 자리

**① 한 값은 한 길(공급)로만 받는다.** 보고(`/api/scrap`) 응답에는 필터 · 모드 · 결재 · 빨리 접기 · 심사 중이 **없다**.
- 까닭: 두 길로 같은 값이 오면 어느 쪽이 맞는지 모른다 — 폰마다 다른 판으로 돌던 일이 있었다.
- 인터넷 받침은 «두 번째 길»이 아니라 **같은 원천(`phoneSupplyOf`)을 다른 선으로** 받는 것이다. 처리도 같은 손(`supplyIn*`)이다.
- 자리: 서버 `server/src/state/phoneSupply.ts` `phoneSupplyOf`(:118) · `phoneSupplyFor`(:145) · `flushSupply`(:158) · 라우트 `server/src/routes/devices.ts:230`(공급) · `:245`(받았음).

**② 서버는 바뀔 때만, 그리고 1초 주기로 공급한다.** 기사님 손이 만든 바뀜(모드 문 · 필터 저장 · 결재 · 받았음)은 그 자리에서 `flushSupply` · 나머지는 1초 주기가 안전망.
- 같은 글자면 안 보낸다(`lastSupplyJson`). 공급 소켓이 없으면 아무것도 안 하고 «보낸 판»도 기억하지 않는다.
- `flushSupply` 는 **던지지 않는다** — 결재 · 모드 문 한가운데서 불리므로 공급이 터져도 부른 쪽 일은 끝까지 간다.

**③ 자동은 결재할 사람이 있을 때만.** 서버 쪽 셈 `modeForPhone(명령, 허락, 관제웹, 다른 폰 자동)`(`shared/src/allowance.ts:18`):
명령이 AUTO 인데 ⓐ 자동 잡기 허락이 안 살았거나 ⓑ 관제웹이 없거나 ⓒ 같은 기사님의 다른 폰도 AUTO 명령이면 ALARM.
- 관제웹 있음 = 웹 화면 소켓이 붙어 있거나, 끊긴 지 `WEB_GAP_MS`(`phoneSupply.ts:37`) 안(`webAttachedOf` :40). 새로고침 · 짧은 끊김에 자동을 잃지 않게.
- **공급 소켓만 살아 있는 것은 «관제웹 있음»이 아니다**(웹 화면 소켓만 본다). 그래서 관제앱 화면을 끄면 웹 화면 소켓이 1분 안에 끊기고 자동이 알람으로 내려간다. 기사님 결정 «나»(지금 그대로).
  공급 소켓이 웹 화면 자리를 넘겨받지 못하게 twin 찾기에서 뺀다(`server/src/socket/socketHandlers.ts:735` 부근).
- 자동은 한 폰만 — 자동을 누르면 같은 기사님의 다른 자동 폰은 알람으로 옮겨진다(`server/src/state/deviceRegistry.ts:80` `demoteOtherAutoPhones`).
- 바뀔 때만 로그 한 줄: `🛑 [관제웹 없음]` · `🔁 [자동은 한 폰]`(`phoneSupply.ts:49-74`).

**④ 원달앱은 사실 넷으로 도는 모드를 정한다.** `TargetApp.runningMode(받은 모드, 블루투스 붙음, 관제앱 서버 숨, 보고 응답)`(`onedal-app/.../core/TargetApp.kt:45`):
- 받은 모드가 없으면(새 폰) `MANUAL`(`MODE_BEFORE_REPLY` :31).
- 셋 중 하나라도 거짓이면 `modeWithoutServer`(:37) — **자동만 알람**, 나머지는 그대로. 알람 · 픽커 소리는 끊김 중에도 계속된다.
- 그 다음 배차망 화면으로 한 번 더: 확정 버튼이 없는 배차망(픽커)이면 자동 → 알람(`effectiveMode` :26).
- 받은 모드는 저장한다(`TelemetryManager.kt:27` `PREF_SUPPLIED_MODE` · :264 `onSuppliedMode`). 원달앱이 다시 뜨면 저장된 값으로 시작하고, 아직 관제앱이 안 붙었으니 자동이면 알람(:262).
- 블루투스가 끊기면 «관제앱 서버 붙음»도 거짓으로 지운다 — 다시 붙은 관제앱의 숨으로만 다시 켠다(:274-279). 옛 값이 남아 다시 붙자마자 자동이 될 뻔한 일 때문이다.
- 🔴 **인터넷 받침이 돌아도 블루투스가 끊겨 있으면 자동은 알람이다** — `runningMode` 의 `linked` 는 블루투스 사실이다. 인터넷 받침은 필터 · 결재 · 접기를 잇는 길이지 자동을 살리는 길이 아니다.

**⑤ 확정 직전에 한 번 더 본다.** 목록에서 콜을 누를 때 «확정까지 누를지»를 정하지만, 상세에 들어간 1.7~2.2초 사이 도는 모드가 알람으로 바뀌면 확정을 안 누르고 미리보기로 올린다(`core/engine/PreConfirmSequence.kt` `appContractsOnOpen` 을 지금 모드로 다시 부름).

**⑥ 인터넷 받침을 켜는 사실은 셋 — 시간 짐작은 없다.** `InternetSupply.wanted(linked, serverAlive, armed) = !linked || !serverAlive || armed`(`InternetSupply.kt:39`).
- 블루투스 끊김 · 관제앱의 서버 끊김 · 안전취소 걸림(그 콜의 결재를 놓치면 취소 횟수가 쌓이므로 두 길로 받는다).
- 1초마다(`POLL_MS` :34) · 한 번 묻기 시한 3초(`TIMEOUT_MS`) · 묻는 중이면 다음 차례는 건너뛴다.
- 필터 · 이 폰 몫 · 빨리 접기는 **바뀐 것만** 넘기고, 결재는 오는 대로 넘긴다(받았음 전까지 서버가 다시 주므로).
- 끈 뒤 온 답은 버린다(:83). 켤 때마다 «마지막 값» 기억을 비운다(:66).
- 배선: `HijackService.kt:651-660`.

**⑦ 결재는 두 길로 와도 집행은 한 번.** `DecisionReplay.stepOf`(`core/DecisionReplay.kt:15`):
이미 실행한 콜 → REPLAY(실행 안 함 · 받았음만 다시) · 지금 열린 콜도 안전취소가 지키는 콜도 아님 → GHOST(버림) · 아니면 EXECUTE.
- 받았음은 **온 길로** 돌려준다(블루투스면 `bleLink.ack` · 인터넷이면 `ackDecisionOverNet` — `HijackService.kt:400-434`). 서버 `ackDecision` 은 두 번 와도 한 번 처리.
- 무엇을 누르나는 `DecisionPlan.of`(`core/DecisionPlan.kt:29`) — 모르는 값은 아무것도 안 함 · 체험 결재는 버튼 없이 뒤로 · 원달앱이 계약한 콜만 «닫기»/«취소».

**⑧ 블루투스 — 근처 기기가 «자동»이나 KEEP 을 넣지 못한다.**
- 관제앱이 CHALLENGE → 폰 HELLO(HMAC) → 관제앱 PROOF. PROOF 가 맞기 전에는 그 연결의 공급을 다 버리고 «공급 연결»도 켜지 않는다(`BleLink.kt:247` `checkProof`). 머리말(«hello|» · «proof|»)이 달라야 되비추기를 막는다.
- 광고에는 기사님 · 영업일로 센 4바이트 표시만(`phoneSupply.ts:100` `bleAdTagOf` · [오늘, 어제]). 관제앱은 그 표시가 맞는 폰에만 붙는다.
- 짝 서명은 서버 비밀값으로 «기사님|폰»을 그때그때 센다(`pairSigOf` :95) — 저장하지 않는다.

**⑨ 블루투스 틀.** `shared/src/bleProtocol.ts:110-137` 가 원천 · 관제앱 `BleProtocol.java` 와 서버 `tests/rules/bleProtocolPair.test.ts` 가 짝을 문다.
- 쓰기 한 번 최대 512 바이트(`BLE_MAX_WRITE`) — 넘기면 받는 앱이 죽었다. 콜백 · 쓰기는 모두 감싼다(원달앱 접근성 서비스가 죽으면 스캐너 전체가 멈춘다).
- 숨 1초(`BLE_BREATH_MS`) · 5초(`BLE_SILENT_MS`) 동안 아무것도 못 들으면 끊고 다시 붙는다(원달앱 `BleLink.kt:346` · 관제앱 `SupplyService.java:681`).
- 관제앱은 폰을 최대 «MAX_PHONES»(`SupplyService.java:78`)까지 붙인다.

**⑩ 관제앱 서비스는 포그라운드 서비스 안에서 돈다.** `SupplyService.java:150-173` — 저장된 서버 주소 · 토큰이 없으면 내린다 · 블루투스 허락이 거둬진 채 다시 뜨면 내린다 · 그 밖에는 «START_STICKY».
- 까닭: 서비스 없이는 화면 뒤로 가는 순간 1분 안에 안드로이드가 앱을 얼린다. 웹 화면(JS) 소켓도 화면을 끄면 1분 안에 끊긴다 — 그래서 공급 · 결재 · 받았음은 웹 화면을 거치지 않고 서비스가 직접 서버와 주고받는다.
- 서버가 끊긴 동안의 받았음은 서비스가 들고 있다가 다시 붙을 때 보낸다(`pendingAcks` :102 · :538). 빨리 접기도 폰마다 남은 시간 동안 들고 있다가 그 폰이 다시 붙으면 남은 ms 로 보낸다(:274-286).
- 클라이언트 켜고 끄기 한 곳: `client-app/src/lib/supply.ts`(로그인이면 `start` · 로그아웃이면 `stop` · PC 웹에서는 아무것도 안 함).

**⑪ 폰은 토큰으로 자기를 밝힌다.** `server/src/core/deviceAuth.ts:48` `authDevice` — 보고 · 인터넷 공급 · 받았음이 같은 문을 지난다.
연결 안 된 폰 401 · 토큰 틀림 401 · 계정 막힘 403. 🔴 **토큰이 없으면 아직 통과**(옛 앱 · 기기마다 로그 한 줄) — 강제는 기사님 폰 재연결 뒤.

**⑫ 데드맨 — 보고가 `DEADMAN_TIMEOUT_MS`(`deviceRegistry.ts:138`) 동안 없으면 그 폰은 끊김.**
- `lastSeen` 은 **HTTP 보고(`/api/scrap`)만** 갱신한다(`deviceSessions.ts:198` · `routes/scrap.ts` `touchDeviceSession`). 블루투스 숨 · 인터넷 공급 묻기는 갱신하지 않는다.
- 끊김이 되는 순간 한 번: 그 폰의 미리보기(심사석 콜)를 치운다(`deviceSessions.ts:529` `cleanPreviewOfDevice`). 모드는 건드리지 않는다.
- 공급의 폰 줄은 살아 있는 폰만이다(`livePhonesOf` :52 → `sentModesOf`). 끊김이 된 폰에는 PHONE(모드)이 안 간다 — 폰은 저장된 받은 모드로 돈다.

## 4. 끊김 경우의 수 — 원달앱이 무엇을 하나

| 경우 | 원달앱이 아는 사실 | 도는 모드(명령이 자동일 때) | 필터 · 결재 | 이미 계약한 콜 | 관제웹 표시 |
|---|---|---|---|---|---|
| 평소(모두 붙음) | 블루투스 ○ · 서버 숨 ○ · 응답 ○ | 자동 | 블루투스로 1초 안 | 결재대로 | 그 모드 |

| 화면이 픽커 | — | 알람(확정 버튼 없음) | — | — | «이 배차망에서는 알람» |

겹치면 «덜 자동» 쪽이 이긴다 — 자동이 알람으로 내려갈 까닭이 하나라도 있으면 알람. 알람 · 직접 · 체험은 어떤 상황에서도 바뀌지 않는다(새 폰만 예외 — 모두 직접).
상황 표의 원천은 `shared/src/modeTable.ts` `situations`(beforeReply · normal · picker · autoNotAllowed · noWeb · otherAuto · noReply · noLink · noServerBreath)이고,
서버 쪽은 shared `modeTable.test.ts`, 원달앱 쪽은 `ModeTablePairTest.kt` 가 같은 표를 읽어 견준다.

## 5. 데이터 흐름

```
기사님 누름(관제웹) ──웹 화면 소켓──▶ 서버(저장 · 셈)
                                     │ flushSupply (바뀔 때 + 1초)
                                     ▼
                     /supply 공급 소켓 ──▶ 관제앱 SupplyService(포그라운드)
                                                  │ 블루투스(증명된 폰에만)
                                                  ▼
                                         스캔폰 원달앱 BleLink ─▶ supplyIn* ─▶ 필터 · 모드 · 결재 집행
                                                  │ ACK · STATUS · 숨
                                                  ▼
                     관제앱 ──phone-decision-ack · phone-status──▶ 서버

  [받침] 원달앱 InternetSupply ──GET /api/devices/:id/supply (1초)──▶ 서버 ─▶ 같은 supplyIn*
         받았음 ──POST /api/devices/:id/decision-ack──▶ 서버
  [기록] 원달앱 ──POST /api/scrap(목록 · 화면 · 받은 모드 · 블루투스 붙음)──▶ 서버 (lastSeen 갱신 · 공급 값은 안 실음)
```

**공급 소켓 사건**(`bleProtocol.ts:10-23` `SUPPLY_EVENTS`)

| 사건 | 방향 | 실은 것 |
|---|---|---|
| `phone-supply` | 서버 → 관제앱 | 필터(기사님 단위) · 필터 판 · 폰마다 {모드 · 심사 중 · 울릴 콜 · 짝 서명} · 서버 표지 · 광고 표시 |

## 7. 아직 정하지 않은 것 — «기사님 결정 필요»

1. **«결재할 관제웹이 있다»를 공급 소켓으로도 볼까** — 지금은 웹 화면 소켓만(화면을 끄면 1분 안에 자동이 알람). 공급 소켓까지 보려면 서비스가 «판정 왔음» 소리 · 상단 알림을 띄우는 일이 먼저 서야 한다. 계획만 있음(코드 없음).
2. **원격(관제앱에서 «잡기»)** — 단추 다섯(자동 · 원격 · 알람 · 직접 · 체험) 순서는 기사님 확정. 저장 값 · «잡아라» 블루투스 명령 · 결재석 «잡기» 버튼은 **계획만 있음(코드 없음)** — `DEVICE_MODES` 는 넷이다.
3. **체험을 단추 하나로** — 지금은 «자동 + 계약 안 함» 두 칸(`no_contract`)이라, 알람에서 자동을 누르고 계약 안 함을 켜기 전 그 사이 진짜 자동이 될 수 있다. 바꾸는 안은 계획만 있음(코드 없음).
4. **한 번도 모드를 고른 적 없는 폰의 처음 명령** — 지금 `resolveDefaultMode`(`deviceRegistry.ts:97`)는 필터가 켜져 있으면 자동. «알람»으로 할지.
5. **허락이 꺼진 폰의 «자동» 단추** — 흐리게 할지, 지금처럼 체험으로 돌지.
6. **토큰 없는 폰 막기** — 지금은 통과(⑪). 기사님 폰 재연결 뒤 강제할 때.
7. **관제웹이 소리 없이 죽은 뒤 서버가 알기까지의 빈틈**(socket.io 핑 시한) — 기사님 «그대로». 바꾸려면 다시 여쭌다.
8. **원달앱 «결재 대기 1초 보고»** — 결재는 공급으로 오지만 이 보고가 관제웹 심사 막대의 진행 핑을 싣는다. 막대를 공급 쪽 사실로 옮길 때 같이 뺀다(미룸).
9. **스캔폰 → 관제앱 폰 칸 값도 블루투스로** — 지금은 HTTP 보고 → 서버 → 관제웹. 나중 일(계획만 있음 · 코드 없음).

## 8. 하지 말 것

- **보고 응답에 필터 · 모드 · 결재를 다시 싣지 않는다** — 한 값 두 길. 블루투스가 끊겨도 «그때만 HTTP» 같은 갈래를 두지 않는다. 받침은 같은 원천 `phoneSupplyOf` 로만.
- **인터넷 받침으로 자동을 살리지 않는다** — 블루투스가 끊겼다는 것은 관제앱이 곁에 없다는 사실일 수 있다(결재할 사람 없음).
- **모드 이름으로 가르는 조건을 새로 만들지 않는다** — 원달앱은 `ModeActs.of` 의 사실(tapsList · contracts · blocksAccept)을, 서버는 표의 사실을 본다.
- **저장된 명령을 상황 때문에 바꾸지 않는다** — 내려보내는 값만 바꾼다(데드맨이 모드를 MANUAL 로 떨어뜨리던 옛 일은 돌아오지 않았다).
- **결재 집행 판단에 «지금 모드»를 쓰지 않는다** — 체험인지는 결재 종류(`SIMULATED_*`)로만. 안전취소 타이머도 모드를 안 본다.
- **증명(PROOF) 전 공급을 받아들이지 않는다** — 근처 기기가 «자동»이나 KEEP 을 넣을 수 있다.
- **블루투스 쓰기를 512 바이트 넘게 · 동시에 둘 하지 않는다** — 앱이 죽거나 감시가 연결을 끊는다. 콜백은 다 감싼다.
- **공급 소켓을 웹 화면 세션 판단(창 하나만 · twin · takeover)에 넣지 않는다.**
- **`flushSupply` 안에서 던지지 않는다 · 1초 주기 안에 계산 · 로그 · 쓰기를 늘리지 않는다.**
- **시험하려고 폰에서 `uiautomator dump` 를 쓰지 않는다** — 접근성 서비스가 내려갔다 붙어 블루투스 GATT 서버도 닫힌다.
