# 01 배차망 화면 읽기 — 페이지 정의 · 사진 판독 · 리뉴얼 감지 · 시뮬레이터 화면

이 한 장으로 «원달앱이 배차망 앱 화면을 어떻게 알아보고 읽는가»를 이해하고 고칠 수 있게 쓴다.
문장이 코드와 다르면 코드가 맞다 — 이 문서를 고친다. 코드에 없고 계획만 있는 것은 «계획만 있음(코드 없음)»으로 적었다.

## 1. 이 기능이 하는 일

- 기사님이 배차망 앱(인성 · 화물24시 · 카카오 픽커)을 켜 두면, 원달앱이 안드로이드 접근성으로 그 화면의 글자를 읽는다.
- 원달앱은 글자로 «지금 어느 페이지인가(홈 · 목록 · 상세 · 확정 · 내 오더 …)»를 알아보고, 페이지마다 정해진 일(목록에서 콜 고르기 · 상세 채우기 · 확정 · KEEP · 취소 단추 누르기)을 한다.
- 상세 화면에서 글자로 요금 · 상하차 주소가 모자라면 화면 사진을 찍어 글자를 판독해 채운다(지금은 카카오 픽커만).
- 배차망 앱이 리뉴얼되어 늘 있던 칸이 사라지거나, 처음 보는 화면 · 낱말이 나오면 서버 로그 · 운영센터에 남겨 우리가 먼저 알게 한다.
- 인성 · 화물24시는 실물 앱이 없어 시뮬레이터(`onedal-sim`) 화면으로만 돈다. 카카오 픽커만 실물이다.

## 2. 용어 풀이

| 말 | 뜻 |
|---|---|
| 배차망 | 콜을 주는 앱. 지금 셋 — `insung` · `hwamul24` · `kakaopicker` (shared `targetApps.ts` `TARGET_APPS`) |
| 정의 표 | 배차망마다 화면 사실(페이지 · 알아보는 글자 · 단추 글자 · 칸 · 읽는 법)을 적은 표. shared `networkPages.ts`(공통) + `networkPages.insung.ts` · `networkPages.hwamul24.ts` · `networkPages.kakaopicker.ts`(배차망별 `/*JSON*/` 블록) |
| 페이지(screen 줄) | 배차망 앱의 화면 한 장. 정의 표 `screens` 의 한 줄 — `name` · `match`(알아보는 글자) · `standard`(서버로 보내는 화면 값) · `bases` · `buttons` · `listReturn` · `landsAfterAccept` · `overlays` · `seen` · `evidence` |
| 기준 페이지 | 배차망과 상관없이 같은 «일의 자리» 여섯 — `home` · `list` · `detail`(확정 전 상세) · `confirm`(확정 직후) · `myorders`(내 오더 리스트) · `myorder`(내 오더 콜 한 건). 페이지 줄의 `bases` 칸에 적는다 |
| 덧칸(overlay) | 페이지 위에 뜨는 팝업 · 시트 · 띠 · 토스트 · 알림. 페이지 줄의 `overlays`. `action` 이 있으면 원달앱이 할 일(팝업 채우기 · 오류 · 건너뛰기 SKIP) |
| 없는 페이지(`absentPages`) | 그 배차망에 그 기준 페이지가 없다는 기록과 까닭. 픽커 `confirm`(수락하면 확정 화면 없이 바로 내 오더) |
| 서버로 보내는 화면 값(`standard`) | `HOME` · `LIST` · `DETAIL_PRE_CONFIRM` · `DETAIL_CONFIRMED` · `MY_ORDERS` · `RUN_*` · `UNKNOWN` 등. 관제웹 폰 줄 이름표(shared `screenLabels.ts`)가 이것을 읽는다 |
| 목록 복귀(`listReturn`) | 이 페이지에 오면 «목록으로 돌아왔다»로 본다 — 서버가 심사 중 콜을 치우고 원달앱이 진행을 처음부터 한다. 원달앱 안에서는 `LIST_COMPLETED` 로 갈린다 |
| `landsAfterAccept` | 손으로 수락한 뒤 배차망이 보내는 페이지. 원달앱 `HandAccept` 가 «직전 프레임이 확정 전 상세 → 지금 이 페이지»면 손 수락으로 본다 |
| 단추 글자(`buttons`) | 배차망 화면에 있는 글자 — `accept`(확정) · `filterOut`(필터 탈락 때 물러나는 단추) · `keep` · `cancel`. 원달앱이 그 단추를 누를지는 플러그인이 정한다 |
| 칸(field) · 페이지 칸(`pages`) | 한 페이지에서 읽는 값 하나(요금 · 상차 · 하차 · 물품 · 적요 …). `NetworkFieldSpec` — `field` · `where` · `sample` · `seen` · `handling`(READ · DROPPED · UNUSED) · `read`(정규식) · `part` · `presence` |
| presence | 칸이 실물 캡처에 얼마나 나오나. `ALWAYS`(모든 실물 캡처에 있음) · `SOMETIMES`(일부) · `ONCE`(한 건) · `UNKNOWN`(실물 캡처 없음 · `seen` 이 REAL 아님). 근거는 `presenceEvidence`(본 콜 수 / 전체 · 캡처 이름) |
| `seen` | 그 사실을 어디서 봤나 — `REAL`(실물 캡처) · 시뮬레이터 · `UNKNOWN` |
| 사진 판독 | 상세 화면 사진을 찍어 ML Kit 로 글자 줄을 뽑고(공통), 줄을 칸으로 나누는 것(지금 픽커 전용 `PickerScreenOcr` · `PickerDetailOcrParser`) |
| `[사진]` 머리표 | 서버로 가는 상세 글에서 «여기부터는 사진 판독 줄»이라는 표시. 원달앱 `PhotoDetailText.of` 가 붙인다 |
| 미등록 화면 | 정의 표의 어느 페이지 · 덧칸에도 안 맞는 화면(`UNKNOWN`). 원달앱이 보고 + 사진을 서버로 보낸다 |
| 새 글자 | 원달앱이 화면에서 모은 낱말 중 서버 `screen_words` 표에 처음 나온 것. 서버 로그 «📰 새 글자» |
| 늘 있던 칸이 없다 | `presence: ALWAYS` 칸이 이 상세의 접근성 글 + 판독 줄 어디에도 없을 때. 리뉴얼 신호 |
| 스캔폰의 원달앱 | 배차망 앱이 깔린 폰(A24 등)에서 도는 1DAL 앱 |

## 3. 지금 규칙

1. **배차망 화면 사실은 shared 정의 표 한 곳에만 적는다.** 까닭: 서버와 원달앱이 같은 사실을 두 벌로 갖고 있으면 한쪽만 고쳐져 판정이 갈린다.
   - 자리: `onedal-web/shared/src/networkPages.ts`(공통 타입 · 기준 페이지 · `NETWORK_PAGES`) · `networkPages.{insung,hwamul24,kakaopicker}.ts`
2. **원달앱은 손으로 적지 않고 생성 파일을 읽는다.** `pnpm gen:pages`(onedal-web 에서)가 `scripts/gen-pages.mjs` 로 세 JSON 블록을 합쳐 `onedal-app/app/src/main/java/com/onedal/app/plugins/insung/InsungPages.kt` 등 배차망마다 하나 를 뽑는다. 까닭: 코틀린이 TypeScript 를 못 읽는다 — 뽑은 것과 표가 같은지 검사로 묶는다.
   - 자리: `onedal-web/scripts/gen-pages.mjs` · 원달앱 `core/PageSpec.kt` · 검사 `onedal-app/app/src/test/java/com/onedal/app/core/NetworkPagesPairTest.kt`
3. **페이지 판별은 표의 차례대로, 처음 맞는 페이지.** 맞는 페이지가 없으면 덧칸 글자로 주인 페이지를 찾고(주인이 여럿이면 직전 페이지 먼저), 그래도 없으면 `UNKNOWN`. 까닭: 인성 출발지 팝업처럼 페이지 글자를 덮는 팝업이 있다. 그래서 **표의 줄 순서가 동작이다** — 더 좁은 줄을 위에 둔다(예: 화물24시 «배차신청 뒤 화물상세정보»가 «화물상세정보»보다 위).
   - 자리: `onedal-app/.../core/engine/ScreenDetector.kt` `detect`
4. **`ScreenDetector` 에는 배차망 글자가 없다.** 글자는 표에만. 까닭: 배차망이 늘어도 판별 코드는 그대로.
5. **배차망은 모두 같은 순서로 돈다 — 다른 것은 표의 인자다.** 읽기 → 채우기 → 모자라면 사진 → 채운 값으로 필터 → 요건 미달이면 서버로 안 보냄 → 보고. 까닭: 배차망만의 흐름을 만들면 고칠 곳이 셋이 된다.
   - 자리: `onedal-app/.../core/engine/PreConfirmSequence.kt`
6. **단추 글자는 표의 `buttons`, 누를지는 플러그인.** 인성 확정 전 상세 `accept «확정»` · `filterOut «취소»` / 확정 뒤 상세 `keep «닫기»` · `cancel «취소»` · 화물24시 `accept «배차신청»` · `filterOut «돌아가기»` · 픽커 `accept «수락하기»` · `filterOut «넘기기»` · 픽커 픽업 출발 `cancel «배정 취소»`. 픽커 플러그인은 `acceptButtons = null` — 원달앱은 픽커 수락을 누르지 않는다. 까닭: 픽커는 수락이 곧 계약이라 기사님 손으로만 한다.
   - 자리: 플러그인 (배차망마다 하나 — `plugins/insung/InsungPlugin.kt` 등) `acceptButtons` · 결재 글자 `core/DecisionWord.kt` · 필터 탈락 `PreConfirmSequence.kt`
7. **결재 KEEP · 취소는 «그 배차망 confirm 기준 페이지의 단추 글자가 지금 화면에 있나»로 찾는다.** 없으면 KEEP 은 끝 · 취소는 «못 누름» 보고. 까닭: 확정 페이지와 내 오더 콜 페이지는 글자로 못 가른다 — 가를 필요 없이 단추만 본다. 화물24시 confirm 페이지에는 `buttons` 가 없다 → 원달앱은 화물24시 취소를 누르지 못한다.
   - 자리: `core/DecisionWord.kt` · 검사 `DecisionWordTest.kt`
8. **필터 탈락 물러남은 detail 기준 페이지의 `buttons.filterOut`, 없으면 «뒤로».** 까닭: 인성 «취소»는 확정 전엔 물러남이라 뒤로 대신 그 단추를 누른다.
9. **원달앱이 결재 «취소»를 누르는 것은 원달앱이 확정한 콜뿐이다(`contractedByApp`).** 까닭: 인성 결재 «취소»와 필터 탈락 «취소»가 같은 글자 — 결재 중에는 목록 누름이 막혀 있다(`ListTapPick` 바쁨 · `DecisionRun.busy`).
10. **사진 판독은 «요건이 모자라다»가 방아쇠이고, 판독기가 있는 배차망만 찍는다.** `!OrderRequirement.meetsDetail(order) && plugin.ocrParser != null`. 인성 · 화물24시는 `ocrParser = null` 이라 요건 미달이면 콜을 버린다(`dropUnfilledCall`). 까닭: 인성 · 화물24시는 «접근성으로 다 읽힌다»가 지금까지 근거(시뮬레이터뿐).
    - 자리: `PreConfirmSequence.kt:119` · `:135`
11. **사진 판독이 못 채우면 목록 줄 값으로 대신 보내지 않고 버린다.** 까닭: 서버가 지어낸 값으로 판정하면 노이즈 · 잘못 잡기. 
    - 자리: `PreConfirmSequence.kt` `dropUnfilledCall("사진 판독 실패 …")` · `("사진 에러 …")` · `("사진으로 채운 값이 요건 미달 …")`
12. **픽커 판독 사진은 위 40% 를 잘라 버리고 아래 60% 만 읽는다.** 까닭: 위는 지도라 글자가 섞인다.
    - 자리: `plugins/kakaopicker/PickerDetailOcrParser.kt:45-48` `crop`
13. **서버로 가는 상세 글 = 접근성 글 + `[사진]` 머리표 + 판독 줄(위에서 아래 순).** 칸 나누기는 서버가 한다. 같은 칸이 접근성과 판독 줄에 둘 다 있으면 접근성 값이 이긴다. 까닭: 실물 픽커는 하차 줄 · «HH:MM까지 배송» · 거리를 접근성으로 안 내놓는다. 판독기가 틀리게 읽은 줄이 접근성 값을 덮으면 안 된다.
    - 자리: `core/engine/PhotoDetailText.kt` · `PreConfirmSequence.kt:355-356` · 서버 `onedal-web/server/src/routes/detail.ts` `detailRecordOf` · shared `pageRead.ts`
14. **칸 읽는 법(`read` 정규식)은 서버와 원달앱이 같은 문제지를 푼다.** 까닭: 같은 원문에 같은 답.
    - 자리: 문제지 `onedal-web/shared/src/pageReadCases.json` · 검사 `onedal-web/shared/src/networkPages.test.ts` · 원달앱 `PageFieldReadTest.kt`
15. **`presence` 는 실물 캡처로만 매긴다 — 시뮬레이터로 «늘 있음»을 매기지 않는다.** «모든 실물 캡처에 있음 = ALWAYS / 일부 = SOMETIMES / 한 건 = ONCE / 실물 없음 = UNKNOWN / 잘려 안 보인 캡처는 세지 않음». 까닭: 시뮬레이터는 우리가 그린 것이라 리뉴얼을 알려 주지 못한다.
16. **늘 있지만 값이 비어 올 수 있는 칸은 ALWAYS 로 매기지 않는다.** 까닭: 읽는 법은 값을 읽으니 값이 빈 날 «사라짐» 거짓 경고가 난다(인성 물품이 그 예).
17. **`presence` 는 서버 · shared 만 읽는다.** 원달앱 생성 파일과 `NetworkPagesPairTest` 비교에는 넣지 않는다. 까닭: 원달앱 런타임이 안 쓴다.
18. **늘 있던 칸이 없으면 서버가 로그 한 줄 — 같은 배차망 · 같은 빠짐은 하루 한 번.** 판정은 그대로. 까닭: 리뉴얼이면 모든 콜이 같은 빠짐을 내 로그를 덮는다.
    - 자리: `server/src/routes/detail.ts:110-118`(`missingAlwaysOf` · `missingAlwaysLogged`) · shared `pageRead.ts:54`
19. **미등록 화면은 보고 + 사진, 같은 화면 지문은 하루 한 번.** 상세 사진 판독 중 · 안드로이드 11 미만 · 0.4초 안 연속은 안 찍는다. 사진은 서버에 30일 두고 지운다(줄은 남음).
    - 자리: 원달앱 `core/UnknownScreenReport.kt` · `core/UnknownScreenShot.kt` `whyNot` · 서버 `anomalyShots`
20. **낱말 안의 시각 · 거리 · 금액은 접어서 모은다(«15:00까지 픽업» → «<시각>까지 픽업»).** 까닭: 안 접으면 시각마다 «새 글자»가 울린다.
    - 자리: `core/ValueShape.kt` · `core/ScreenWords.kt` · 서버 `server/src/services/screenWords.ts`
21. **판독 사진은 폰에만 최근 20장.** 서버로 올리지 않는다.
    - 자리: `core/ScreenReader.kt` `KEEP_SHOTS = 20`
22. **실물 배차망 앱은 패키지 이름으로 가른다.** `TargetApp.REAL_NETWORK_PACKAGES` = 픽커(`com.kakaomobility.flexer`) 하나. 배차망 가르는 패키지 글자는 표의 `packageKeywords`(인성 `insung` · 화물24시 `logione` · `carrier` · 픽커 `flexer`). 보고의 출처(`real` · `sim`)가 여기서 나온다.
    - 자리: `core/TargetApp.kt:52,61,69`
23. **서버의 «상세를 떠났나» 목록(`DETAIL_SCREENS`)에 내 오더 콜 · 운행 단계를 넣지 않는다.** 까닭: 넣으면 수락한 뒤에도 미리보기가 남는다.
    - 자리: shared `onedal-web/shared/src/screenKinds.ts:99` · 읽는 곳 서버 `server/src/state/deviceSessions.ts`
24. **시뮬레이터는 실물 순서를 흉내 낸다 — 첫 화면 → 목록 → 상세 → 뒤로.** 인성 첫 화면 «인성퀵화면분할»(«실행»을 누르면 목록) · 화물24시 «전국24시콜화물»(«화물정보»를 누르면 목록). 상세 → 뒤로 = 목록. 화물24시는 배차신청하면 같은 «화물상세정보»에 머물고 위에 «배차취소하기» 막대가 시간 동안 뜬다(막대 시간은 시뮬레이터 상수 · 실측 없음).
    - 자리: `onedal-sim/packages/ui-simulators/src/{insung,hwamul24,kakaopicker}/` · `nets.ts`

## 8. 하지 말 것

- **생성 파일 (`plugins/insung/InsungPages.kt` 등 배차망마다 하나) 를 손으로 고치지 않는다** — 다음 `pnpm gen:pages` 가 덮고 `NetworkPagesPairTest` 가 빨갛게 된다.
- **`ScreenDetector` · 공통 순서에 배차망 이름 · 글자를 넣지 않는다** — 그 글자는 표의 칸이다. `if (app == "kakaopicker")` 갈래가 생기면 배차망이 늘 때마다 셋을 고친다.
- **표의 줄 순서를 무심코 바꾸지 않는다** — 처음 맞는 줄이 이긴다. 넓은 줄이 위로 가면 좁은 줄이 죽은 줄이 된다.
- **`ocrParser != null` 조건만 빼지 않는다** — 판독기 없이 사진 길에 들어가면 «즉시 중단»으로 콜을 버린다(`PreConfirmSequence.kt:282-284`). 공통 판독기를 먼저 세운다.
- **판독 줄 값이 접근성 값을 덮게 하지 않는다** — ML Kit 가 틀리게 읽은 글자가 요금 · 주소가 된다.
- **판독 실패를 목록 줄 값으로 메우지 않는다** — 서버가 지어낸 값으로 판정한다.
- **시뮬레이터로 `presence: ALWAYS` 를 매기지 않는다** · 값이 빌 수 있는 칸에 ALWAYS 를 주지 않는다 — 거짓 리뉴얼 경고.
- **원달앱이 픽커 «수락하기»를 누르게 하지 않는다** — 수락이 곧 계약이고, 픽커는 «취소 불가» 콜이 많다. 집에서는 콜 확정 전까지만 시험한다.
- **화물24시 «배차신청 뒤» 페이지를 `bases: detail` 로 돌리지 않는다** — 토스트의 «배차신청» 글자 때문에 확정 전 상세로 읽혀 손 수락을 놓친다(«화물상세정보» 줄의 `none` 이 막는다).
- **서버 `DETAIL_SCREENS` 에 내 오더 콜 · 운행 단계를 넣지 않는다** — 수락 뒤에도 미리보기가 남는다.
- **실물 폰에서 `uiautomator dump` 를 쓰지 않는다** — 접근성 서비스를 내렸다 붙여 서버가 «앱 꺼짐»으로 판정을 버린다.
- **새 규칙을 소스 글자 세기 검사로 만들지 않는다** — 동작 검사 · 타입 파생으로.
