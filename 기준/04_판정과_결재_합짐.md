## 1. 하는 일 — 기사님 하루의 말로

- 기사님은 아침에 집을 나와 **노선 콜 3개**를 차례로 잡아 한 방향으로 나가고, 마지막 쯤에 **귀가 단추**를 눌러 집 쪽 **복귀 콜 3개**를 잡아 돌아온다. 중간에 근처 짧은 **관내 콜**을 하나 끼우면 7콜이다. 노선과 복귀는 방향만 다르고 같은 일이다.
- 원달앱(스캔폰의 1DAL 앱)이 배차망 목록에서 필터에 맞는 콜을 **선점**하면, 서버가 그 콜을 **판정**한다 — «지금 잡은 짐들에 이 콜을 얹으면 몇 분 더 돌고, 얼마 벌고, 이미 잡은 약속이 깨지나, 차에 들어가나».
- 판정 결과는 **색 하나와 점수 하나**다. 기사님은 운전 중 곁눈질 1~2초로 색만 보고 누른다.
  - 색 = **지금 내가 무엇을 해야 하나** (그냥 잡는다 / 확인한다 / 전화해야 한다 / 그대로는 못 잡는다)
  - 점수 = **얼마짜리인가** (꿀 경계를 넘으면 🔵)
- 기사님이 관제앱 결재석에서 **KEEP**(잡는다) 또는 **취소**를 누르면, 서버가 그 결재를 관제앱 → 블루투스 → 스캔폰으로 보내고, 원달앱이 배차망 화면에서 확정·취소 단추를 대신 누른다.
- 인성 · 화물24시는 잡은 뒤 일정 시간 안에 위약금 없이 무를 수 있는 **안전취소**가 있다. 그 시간 안에 결재가 없으면 서버가 안전취소를 내린다. 카카오 픽커는 수락이 곧 계약이라 안전취소가 없다.
- KEEP 한 콜은 **예약**이다 — 실제 짐은 상차해야 실린다. 그래서 적재는 «잡은 콜을 다 더한 것»이 아니라 «경로를 따라 실렸다 내렸다 할 때 가장 많이 실린 순간»으로 센다.
- KEEP 하면 그 콜의 **콜 진행 6단계**(상차지 통화 → 상차지 도착 → 상차 완료 → 하차지 통화 → 하차지 도착 → 하차 완료)가 생기고, 기사님은 통화하며 짐·방법·약속을 적는다.

## 2. 용어 풀이

용어의 원천은 `onedal-web/server/tests/rules/glossary.test.ts` 다. 옛말(사냥 · 데스밸리 · 눈높이 · 회랑 · 본콜 · 종착지 …)을 쓰면 그 검사가 빨간불을 낸다.

| 말 | 뜻 |
|---|---|
| 콜 필터 | 원달앱이 콜을 **집기 전**에 거르는 조건(상차 목록 · 하차 목록 · 콜할인율 등). 앱에 내려간다 |
| 판정 기준 | 서버가 콜을 **집은 뒤** 색·점수를 내는 기준. 앱에 내려가지 않는다. DB `user_judgment` 표에 산다 |
| 선점 | 원달앱이 배차망에서 콜을 먼저 눌러 잡아 둔 상태(상태값 `ORDER_PRE_SECURED`). 결재 전이다 |
| 결재 · 결재석 | 기사님이 관제앱에서 KEEP / 취소를 누르는 일과 그 화면 |
| KEEP | 잡기로 결재 — 콜이 `ORDER_CONFIRMED` 가 된다. «예약»이지 «적재»가 아니다 |
| 안전취소 | 잡은 뒤 정한 시간 안에 위약금 없이 무르는 것(상태값 `SAFE_CANCEL`). 시간은 배차망마다 DB 값(README 짝 표 `waitTimes`) · 안전취소도 배차망 취소 횟수에 든다 |
| 첫짐 / 합짐 | 빈 차에 처음 싣는 콜 / 이미 잡은 콜이 있는 경로에 얹는 콜. 호칭은 `callName`(`shared/src/judgment.ts:487`) — 타겟명+첫짐/합짐N+콜 |
| 노선 / 복귀 / 관내 | 집에서 나가는 방향 콜 / 귀가 단추 뒤 집 쪽 콜 / 근처 짧은 콜 |

| 투트랙 | 복귀 켬 뒤 복귀 콜이 잡히기 전까지 하차 목록이 «기존 목적지 + 집» 둘 다 열린 상태 |
| 우회 (한계 우회) | 새 콜을 얹어서 **늘어나는** 주행 분·km. 앞서 잡은 콜의 시간은 안 뒤집어쓴다 |
| 약속 | «도착 시각». 상차 약속(잡은 시각 + DB 상차 약속 분 · 통화 약속이 이긴다)과 하차 약속(상차 완료 + 단독 배송 × DB 비율) |
| 콜 시한 | 하차 약속의 다른 이름 — 상차 완료 시각 + 단독 배송 주행 × `deadline.ratioPct` (`callDeadlineMs`) |
| 버퍼 3종 | 상차버퍼(상차지에서 더 기다릴 수 있는 분) · 경유버퍼(배송 중 남는 분) · 경로 버퍼(경로 전체에서 가장 빠듯한 약속까지의 여유 = 최솟값). 버퍼는 합짐에 쓸 수 있는 **예산**이다 |
| 라면박스 | 적재 단위. 내 1t 트럭의 그릇 = `TRUCK_CAPACITY_SLOTS`, 차종별 짐 크기 = `VEHICLE_CAPACITY`(`shared/src/vehicles.ts`) |
| 함께 실리는 최대 | 경로를 따라 실은 짐 − 내린 짐의 최댓값(`peakLoadPoints`, `shared/src/cargoUnits.ts:216`) |
| 미확인 | 모르는 값을 흔한 값(일반값)으로 채웠다는 딱지. 불리하게 가정해 떨어뜨리지 않는다(README 규칙 ⑤-2) |
| 잴 수 없음 | 재료(좌표 · 카카오 경로 등)가 없어 점수를 못 낸 것 → 🔴. «나쁘다»가 아니라 «모른다» |
| 벨 | 점수가 벨 점수 이상이면 관제웹이 소리를 낸다(`judge.ts` `bell`) |
| 빨리 접기 | 앱이 알람으로 연 상세에서 🔴 이거나 벨 미만인 콜을 `QUICK_FOLD_SEC` 뒤 목록으로 접는 것 |

## 4. 색 · 점수 · 시한 · 버퍼 — 계산을 말로

식은 코드에 있다. 여기는 뜻만 적는다. 값은 전부 **DB judgment config**(표 `user_judgment`, 기본값 `DEFAULT_JUDGMENT` = `shared/src/judgment.ts:234`, 칸 목록 `JUDGMENT_FIELDS :280`)에서 온다. 지금 값은 DB 를 읽는다:
`sqlite3 onedal-web/server/local.db "SELECT * FROM user_judgment"` (실서버는 읽기만).

### 4-1. 점수
1. 기준마다 «점수(0~100) / 잴 게 없음 / 잴 수 없음(재료 없음 · 추정)»을 낸다.
2. 역할이 «점수»인 기준(돈 · 노동강도 · 운전 · 콜 대기)만 가중평균한다. 가중치는 DB `weights.*`.
3. 역할이 «곱하기»인 지리 기준이 그 평균에 배수를 곱한다(목적지 쪽으로 가면 1, 멀어지면 줄어든다 · DB `destBonus.*`).
4. 천장을 말한 기준이 있으면 그 아래로 누른다.
5. 결과가 점수다. 재료가 없으면 점수는 `null`(0 이 아니다).

**돈 기준**(`criteria.ts:91`)은 «이 시간 써서 얼마 버나» — 운임을 추가로 드는 분(우회 주행 + 상하차 정차)으로 나눈 시급을 목표 시급(DB `target.*`)에 견준다. 우회가 길면 J6 의 감쇠가 곱해진다. 기름값은 `fuelCost.ts` 가 뺀다.
**노동강도**(`:273`)는 손으로 드는 분(수작업 박스 × 박스당 분) + 보호 분을 «흔한 상차 두 번치»(DB 상차 미확인 일반값의 두 배)에 견준다.

### 4-2. 색 (위에서부터 먼저 걸리는 것)
1. 관문 기준 중 하나라도 hardFail(약속 깨짐 · 자리 없음 · 같이 못 싣는 짐 · 제외 낱말) 또는 재료 없음 또는 점수 없음 → 🔴 사고
2. 전화하면 잡을 수 있는 기준이 있음(`needsCall`) → 🟡
3. 추정이라 못 믿는 기준이 있음(`guessed`) → 🟢 (점수가 높아도 🔵 아님)
4. 점수 ≥ 꿀 경계(DB `color.honeyMin`) → 🔵 · 아니면 🟢

🔴 옆에도 점수는 그대로 보인다 — «좋은 콜이니 다른 걸 취소할까»를 기사님이 판단하시게.

### 4-3. 약속 · 콜 시한
- **상차 약속** = 통화 약속 › 적요의 상차 시각 › (잡은 시각 + DB `unknown.pickupPromiseMin`). 앞이 있으면 앞이 이긴다.
- **하차 약속(콜 시한)** = 상차 완료 시각 + 단독 배송 주행 × DB `deadline.ratioPct` (`callDeadlineMs`, `judgment.ts:421`). 단독 배송을 모르면 `null` — 지어내지 않는다. 기산점은 «지금»이 아니라 «상차 완료»다.
- 시각은 밀리초로 더하므로 자정을 넘어도 계산 자체는 이어진다. 날 경계를 쓰는 곳은 영업일 키(`businessDayKey`, `timing.ts:335`)와 일과 종료(`businessDayEnd :386`, 하차 마감 기본값 `defaultDropoffDeadline :401`)이며, 서버 시간대는 `ecosystem.config.cjs` 의 `TZ` 와 `server/src/config/timezone.ts` 가 한국으로 맞춘다.

### 4-4. 버퍼
- 경로 타임라인(`deriveRouteTimeline`, `timing.ts:1094`)이 정거장마다 예상 도착과 약속을 놓고 «늦는 분 / 남는 분»을 낸다.
- **버퍼의 진실은 최솟값** — 콜 하나가 +60분 남아도 다른 콜 약속이 +6분이면 합짐에 쓸 수 있는 시간은 6분이다(`minRouteBuffer :1394`).
- 약속 기준(`criteria.ts:542`)은 새 콜을 얹은 뒤 기존 콜 중 하나라도 늦으면 hardFail(🔴) 또는 늦는 분이 작으면 «전화해서 미루면 된다»(🟡). 경계는 DB `slack.*`.
- 콜 대기 기준(`:422`)은 «이 콜이 시간을 얼마나 남겨 주나».
- 상차버퍼(콜 대기)와 경유버퍼(배송)는 다른 값이다 — 새 상수를 만들지 말고 `timing.ts` 를 먼저 읽는다(README ⑤-5).

## 7. 아직 정하지 않은 것 — 기사님 결정 필요

1. **6단계를 KEEP 때 여섯 칸 다 만들기** — 방향은 «가»를 받았으나 **계획만 있음(코드 없음)**: `birthAllSteps` · `save-step-plan` · «driver_fields» 가 레포에 없다(`grep -rn birthAllSteps onedal-web` 0 건). 남은 결정 셋:
   - 새 저장 칸 «driver_fields»(단계 표마다 «기사님이 미리 고친 계획 칸 이름» 목록) — README ⑤-4 다섯을 놓고 합의가 필요하다(대안: `planned_source` 에 «직접» 값 하나 — 칸 하나만 고쳐도 행 전체가 안 따라오는 단점)
   - 관제앱 시트에서 계획 칩을 여섯 칸 모두 살리는 화면 바뀜 — 그림을 먼저 여쭌다
   - README 규칙 ⑥ «한 번에 한 단계씩만 넘긴다»를 «사실(도착 · 완료)은 한 칸씩 · 계획 값은 KEEP 때 여섯 칸에 채워 두고 미리 고친다»로 바꾸는 문장
   - 같이 정리할 서로 다른 주석: `dispatchEngine.ts` «KEEP 하면 여섯 단계가 생긴다» ↔ «첫 행만 낳는다» · `stepTables.ts` «행은 KEEP 때 생긴다» ↔ `db.ts` «첫 행은 KEEP 때 태어나고»
2. **현장 변수(코드 없음)** — 모두 새 기능이라 «지금은 리팩터링만» 원칙과 부딪힌다. 할지 말지부터 기사님 몫:
   - 적요 «계단 · 까대기 · 빌라 · 층» 같은 낱말로 정차 분을 더하기(지금은 방법 = 지게차/수작업 × 박스만 본다)
   - 대형 물류센터 · 공단 하차지의 입고 대기 분
   - 합짐 순서의 후입선출(먼저 실은 짐이 안쪽이라 먼저 못 내림) — 지금 순서 규칙은 «실지 않은 짐은 먼저 못 내린다»뿐
   - 비 · 금요일 오후 정체 보정, 수급에 따라 목표 시급을 움직이는 것
3. **우회 감쇠 눈금 · 목표 시급 · 꿀 경계** — 값은 기사님이 판정 기준 탭에서 정하신다(묻지 않는다). 다만 실주행 표본이 쌓이면 «3~4시간 우회 콜이 몇 점으로 뜨나»를 로그로 대조해 올린다.
4. **거리대별 속도 일반값** — 근거 표본이 접근 구간(현위치 → 상차지) 위주이고 배송 구간 표본이 적다(`judgment.ts` `speed` 주석). 실주행 뒤 다시 볼 값.

## 8. 하지 말 것

- 점수가 낮다고 🟡 을 만들지 않는다 — 🟡 은 «전화하면 잡을 수 있다» 하나다.
- 못 잰 것을 0점 · 🟢 로 지어내지 않는다 — `null` 과 🔴 «잴 수 없음».
- 엔진(`judge`)에서 «이 기준이 돈이면…»처럼 기준 이름으로 가르지 않는다 — 기준이 스스로 hardFail · needsCall · guessed · ceiling 을 말한다.
- 상태 · 단계 이름(`phase === …`)으로 가르는 조건문을 새로 만들지 않는다 — 개별 사실로 가른다.
- 서버가 콜을 스스로 버리거나 취소하지 않는다(안전취소 타이머 예외 J16 뿐). 손으로 누른 콜에 타이머를 걸지 않는다.
- `isActive=false` 를 «만석» 말고 다른 뜻으로 쓰지 않는다.
- 결재를 `decide` 밖에서 쓰지 않고, «받았음» 전에 지우지 않는다.
- 상태 목록을 손으로 적지 않는다 — `shared/src/callStatus.ts` 의 목록을 쓴다.
- 판정 기준을 앱에 내려보내지 않는다 — 콜 필터와 판정 기준은 따로 돈다.
- 카카오 HTTP 오류(한도 등)에 다시 보내기를 늘리지 않는다.
- 새 시간 상수를 만들지 않는다 — `timing.ts` 를 먼저 읽는다.
- 설정 기본값을 코드 `?? 숫자` 로 늘리지 않는다 — DB 칸 `DEFAULT` 에 둔다.
- 잡은 콜을 다 더해서 적재를 세지 않는다 — «함께 실리는 최대».
