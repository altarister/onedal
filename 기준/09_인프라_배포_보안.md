# 09 인프라 · 배포 · 보안 · 법률선

## 1. 하는 일

실서버 한 대가 기사님 하루의 판정 · 결재 · 장부를 쥔다. 이 문서는 그 서버가 **어디서 어떻게 돌고, 어떻게 새 코드로 바뀌고,
실패하면 어떻게 되돌아가고, 누구를 들이고 누구를 막는가**, 그리고 서비스가 넘지 말아야 할 법률상의 선을 한 자리에 적는다.
포트 번호의 원천은 루트 `README.md` 「포트」 표다 — 여기서는 번호를 다시 적지 않고 그 표를 본다.

## 2. 용어 풀이

| 말 | 뜻 |
|---|---|
| 실서버 · 라이브 서버 | AWS EC2 한 대에서 PM2 로 도는 서버. DB 파일은 `data.db`. 관제웹 · 운영센터 · 리허설 배차망 화면도 같은 서버가 내준다 |
| 로컬 서버 | 개발 PC 의 `pnpm dev`. DB 는 `server/local.db` |
| 라이브(운행) | 기사님이 실제 차로 운행하는 날. 「라이브 서버」와 다른 말이다 — 라이브 서버는 운행이 없는 날에도 떠 있다 |
| 자동 배포 | `main` 에 `onedal-web/**` · `onedal-sim/**` · 배포 설정 파일이 바뀐 push 가 오면 GitHub 이 검사 → 실서버 배포를 한다 |
| 운행 중(바쁨) | 서버 메모리에 «끝나지 않은 잡은 콜 · 심사 중 콜 · 결재 기다림 · 기다림 타이머» 중 하나라도 있는 상태. 배포가 이것을 묻는다 |
| 되돌리기 | 배포 도중 실패하면 시작할 때의 판(커밋)으로 코드 · 화면 폴더를 되돌리고 서버를 다시 띄우는 것. DB 는 되돌리지 않는다 |
| 기기 토큰 | 원달앱 폰을 계정에 붙일 때 서버가 주는 비밀 글자. 폰은 요청마다 머리 `X-Device-Token` 으로 싣고, 서버는 sha256 만 저장한다 |
| 접근 토큰 · 갱신 토큰 | 관제웹 · 관제앱 로그인 토큰(JWT). 접근 토큰이 만료되면 갱신 토큰으로 새로 받는다 |
| 우회 로그인 | 개발용 문 `/api/auth/bypass`. 로컬에서만 열리고 라이브 서버에서는 404 |
| 리허설 배차망 | `rehearsal.` 으로 시작하는 주소로 들어오면 실서버가 시뮬레이터(`onedal-sim`) 화면을 내준다 |
| 운영센터 | 관리자 화면(`onedal-web/ops`). `ops.` 으로 시작하는 주소로 들어오면 실서버가 그 화면을 내준다 |

## 3. 지금 규칙

## 4. 지도 — 무엇이 어디서 도나

```
기사님 폰 둘                         실서버(EC2 · PM2 프로세스 하나)
 스캔폰(A24) 원달앱 ── REST ─────▶  80 → 4000 (iptables, deploy.sh 가 넣음)
   └─ 블루투스 ◀── 관제폰(S23)      Express + Socket.IO + better-sqlite3(data.db, WAL)
 관제폰 관제앱 ── https + 소켓 ──▶   ├─ /api/*            모든 주소에서
                                     ├─ rehearsal.*      onedal-sim/dist (리허설 배차망)
 브라우저 관제웹 · 운영센터 ───────▶  ├─ ops.*            onedal-web/ops/dist (운영센터)
                                     └─ 그 밖            onedal-web/client-app/dist (관제웹)
GitHub Actions ── ssh ──▶ deploy.sh (실서버 안에서 돈다)
```

- 서버 주소의 원천: 관제앱은 `client-app/src/lib/serverTarget.ts` `TARGETS` · 원달앱은 `MainViewModel.kt` 의 라이브 주소와 설정창의 «개발 PC IP» (관제앱이 블루투스로 원달앱에 주소를 싣기도 한다 — `BleLink.kt`)
- 원달앱 → 서버는 REST 만 쓴다. 서버 → 원달앱은 관제앱을 거친 블루투스 공급이다 (루트 README 「구성」의 «통신»)
- 서버는 `tsx` 로 TypeScript 를 그 자리에서 돌린다 (`ecosystem.config.cjs` `args`) — 미리 빌드한 js 가 아니다
- 메모리 1G 를 넘으면 PM2 가 다시 띄운다 (`max_memory_restart`)
- 실서버 접속 방법은 이 문서에 적지 않는다 — 기사님 손 · 메모리 기록에 있다

## 5. 흐름

### 5-1. 배포 한 번

1. 누군가 `main` 에 push (기사님 말씀 뒤에만)
2. GitHub `check` — 설치 → 서버 tsc → 서버 jest → 관제웹 tsc -b → `pnpm test:web`. 하나라도 빨간불이면 끝 (실서버는 그대로)
3. GitHub `deploy` — ssh 로 실서버에 붙어 `git fetch` 뒤 **새 판의** `deploy.sh` 를 임시 파일로 꺼내 돌린다 (돌던 스크립트를 git 이 갈아 끼우지 않게)
4. `deploy.sh`
   1. 운행 중인가 — 서버 자신에게 `/api/health/busy` 를 묻는다. 바쁘면 1분마다 다시 · 4시간 넘으면 배포 멈춤 · 서버가 답하지 않으면 바로 진행
   2. DB 세 파일 백업 (최근 5벌)
   3. `git reset --hard origin/main`
   4. 가상 메모리 2GB 켜기 · 80 → 4000 포워딩 확인
   5. `pnpm install` · 네이티브 모듈 다시 빌드
   6. 관제웹을 새 폴더에 빌드 → 바꿔 끼움 (실패하면 되돌리기)
   7. 운영센터 · 리허설 배차망 빌드 (실패해도 계속)
   8. `pm2 reload` — **몇 초 끊긴다** (무중단이 아니다). 메모리의 콜 상태가 사라지고 서버가 DB 에서 되살린다
   9. `/api/health` 를 2초마다 15번까지 묻는다. 답이 없으면 되돌리기
5. 되돌리기 — 시작 판으로 `git reset` · 설치 · 화면 폴더 되돌림 · 서버를 건드렸으면 다시 띄우고 살아났는지 본다. DB 는 그대로 (백업 파일만 남는다)

### 5-2. 손 배포

GitHub 화면의 «Run workflow»(수동 실행). «운행 중이어도 올림»을 체크하면 운행 여부를 묻지 않는다 — 급할 때만.

### 5-3. 폰 하나가 보고할 때

`/api/scrap` 등 → `authDevice(deviceId, X-Device-Token)` → 연결 안 됨 401 · 토큰 틀림 401 · 토큰 없음 통과(로그) · 계정 막힘 403 → 옛 판이면 426 → 처리.

### 5-4. 관제웹 · 관제앱 로그인

구글 로그인 → 접근 토큰 30일 · 갱신 토큰 14일 (`server/src/routes/auth.ts`, 갱신 토큰은 해시로 저장) → REST 는 `requireAuth` · 소켓도 같은 «이 서버 유저인가» 판단 → 운영센터는 `requireOps` 를 더 지난다.

| GitHub `check` 단계 | 루트 README 「커밋 전 필수」 — GitHub 은 그중 일부만 돌린다 (`audit:dead` · `lint:gate` · `scenario` · `drive` · 원달앱 gradle 은 GitHub 에서 안 돈다) |

## 8. 하지 말 것

- `pm2 delete all` · 실서버에서 `git reset` 을 손으로 · `data.db` 지우기 — 기사님 말씀 없이 하지 않는다
- 운행 중에 «운행 중이어도 올림»으로 배포하지 않는다 — 메모리의 결재 기다림 · 안전취소 타이머가 사라진다
- 실서버 쓰기(SQL · 파일)를 에이전트가 하지 않는다 — 기사님 손
- `isLiveServer()` 로 **동작을 가르지 않는다** (로컬은 이렇게, 라이브는 저렇게). 막을까 말까에만 쓴다
- 비밀값 · 서버 IP · 키를 문서 · 코드 · 커밋 메시지에 적지 않는다. 비밀값은 `server/.env`(git 밖)와 GitHub secrets 에만
- `server/.env` 의 `VITE_API_URL` 같은 주소를 로컬 관제웹 `.env` 에 적지 않는다 — Vite 프록시가 깨진다
- 서버가 켜질 때 조건을 보고 표를 지우는 코드를 새로 만들지 않는다 (루트 README 「지금은 테스트 단계다」)
- 수락 뒤 픽커 화면 · 남의 주소 · 전화가 보이는 사진을 git 에 담지 않는다
- 법률선 — 아래를 넘는 기능을 만들지 않는다
  - **운임 정산 대행 · 중개 수수료 없음** — 기사 사이 콜 넘기기(연계)는 알림 + 연락처만. 실제 배차 취소 · 신청은 원래 배차망 안에서 한다 (화물자동차 운수사업법의 주선 허가를 피하는 선)
  - **배차망 서버에 직접 요청하지 않는다** — 화면에 이미 그려진 글자만 읽고, 누름은 화면 좌표 탭 한 번 (업무방해 · 악성 프로그램 혐의를 피하는 선). 배차망 앱의 코드 · 메모리 · 통신을 건드리지 않는다
  - **배차망 약관은 자동화 프로그램을 금지한다** — 계정 정지 위험은 기사님(사용자)이 안다. 남에게 나눠 줄 때는 위험 고지와 동의를 먼저 받는다 (가입 · 동의는 서버 문 `/api/join` 만 있고 부르는 화면은 아직 없다 · 약관 글 `routes/contents.ts`)
  - **개인정보** — 화주 · 수령인 이름 · 전화 · 주소는 운행에 필요한 만큼만 서버에 둔다. 사진 · 캡처는 레포 밖 폴더. 탈퇴 뒤 파기는 관리자 손이다
  - **집에서는 콜 확정 전까지만** — 실물 픽커 콜을 시험으로 수락하지 않는다 (루트 `CLAUDE.md`)
