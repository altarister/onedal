# 03. 콜을 잡는 순간 — 목록 → 상세 → 채우기 → 확정 → 결재 → 집행 · 안전취소

이 한 장만 읽고 «원달앱이 콜을 어떻게 잡고, 언제 확정(계약)하고, 언제 무르나»를 이해하고 고칠 수 있게 쓴다.
배차망 × 모드 표 전체는 루트 `배차망_모드표.md` 가 원천이다 — 원달앱의 누르기 · 화면 처리를 고치면 그 표도 같은 커밋에서 고친다.

---

## 1. 하는 일 — 기사님 하루의 말로

- 기사님은 차를 몰고, 원달앱 폰(스캔폰)은 대시보드 거치대에서 배차망 앱(인성 · 화물24시 · 카카오 픽커)을 띄워 둔다. 관제앱(관제웹)은 다른 폰에 켜 둔다.
- 원달앱은 배차망 **목록**을 읽고, 필터를 통과한 콜 가운데 **요금이 가장 높은 하나**를 눌러 **상세**로 들어간다.
- 상세에서 모자란 값(전체 주소 · 요금)을 **채운다** — 인성은 팝업 3장(적요 → 출발지 → 도착지)을 열어 읽고, 픽커는 글자가 깨져 있으면 화면 사진을 읽는다.
- 채운 값으로 필터를 한 번 더 건다(채운 뒤 필터). 떨어지면 상세에서 나온다(확정 전이라 배차망에 아무 일도 없다).
- 통과하면 서버에 **선점 보고**를 하고,
  - **자동 모드 · 인성/화물24시 · 오늘 콜**이면 원달앱이 **확정 단추를 누른다** — 이것이 «계약»이다. 되돌릴 수 없는 유일한 누름이다.
  - 그 밖(알람 · 체험 · 직접 · 픽커 · 내일 콜)은 확정을 누르지 않고 **미리보기**로 판정만 받는다. 확정 · 수락은 기사님 손이다.
- 서버가 판정해 관제앱 결재석에 띄우고, 기사님이 **KEEP**(지킨다) 또는 **거절**을 누른다.
- 원달앱이 확정한 콜은 결재대로 확정 뒤 화면의 «닫기»(KEEP) 또는 «취소»(계약 무름)를 누른다.
- 기사님이 **안전취소 시간**(기본 30초 · 기사님 설정창) 안에 아무것도 안 하시면 원달앱이 스스로 «취소»를 누른다 — **안전취소**. 이것도 배차망 **취소 횟수**에 들어간다(인성은 취소 10번마다 페널티).
- 카카오 픽커는 «수락하기»가 곧 계약이고 취소 창이 없다(전화로만 · 하루 몇 번). 그래서 원달앱은 **픽커에서 수락을 절대 누르지 않는다** — 알람으로 상세까지 열어 판정을 보여 주고, 수락은 기사님 손.

## 2. 용어 풀이

용어 원천은 `onedal-web/server/tests/rules/glossary.test.ts` 다. 여기 쓰는 말만 풀어 둔다.

| 말 | 뜻 |
|---|---|
| 목록 | 배차망의 신규 콜 줄 화면(인성 신규 콜 목록 · 화물24시 화물정보 · 픽커 신규 리스트) |
| 상세(확정 전) | 목록에서 콜 한 줄을 눌러 연 화면 — 아직 계약이 아니다. 여기의 «취소»(인성) · «돌아가기»(화물24시) · «넘기기»(픽커)는 그냥 나오는 것 |
| 확정 페이지 | 확정 직후 한 건의 화면 — 인성 «확정 뒤 상세», 화물24시는 같은 화물상세정보 위에 «배차취소하기» 막대, 픽커는 없음(수락하면 곧바로 내 오더 리스트). 여기의 «취소»는 **계약을 무르는 것**(취소 횟수) |
| 채우기 | 상세에서 필수 요소(요금 · 상차 전체 주소 · 하차 전체 주소)가 모자라면 배차망 수단으로 채우는 일. 인성 팝업 3장 · 픽커 사진. 화물24시는 수단 없음 |
| 필수 요소 | 요금 · 상차 전체 주소 · 하차 전체 주소. 전체 주소 판정은 `AddressForm`(서버 지도 명부 대조) |
| 채운 뒤 필터 | 채운 값으로 목록과 같은 필터를 한 번 더(`passesFilterAfterFill`) + 배차망 덧규칙(`passesDetailFilter` — 인성 주의 동네) |
| 선점 보고 | 원달앱 → 서버 `POST /api/orders/confirm`. 서버는 «심사 중» 줄을 세운다 |
| 상세 보고 | 원달앱 → 서버 `POST /api/orders/detail`. 서버가 판정을 시작한다 |
| 확정 · 계약 | 원달앱(또는 기사님 손)이 배차망의 확정(인성 «확정» · 화물24시 «배차신청» · 픽커 «수락하기»)을 누르는 것 |
| 미리보기 | 원달앱이 확정하지 않고 확정 전 상세에서 판정만 받는 콜(`session.isPreview`). 서버는 이 표시가 있어야 심사한다 |
| 결재 | 관제앱 결재석에서 기사님이 누르는 KEEP · 거절. 체험 콜은 `SIMULATED_KEEP` · `SIMULATED_CANCEL` |
| 안전취소 | 원달앱이 확정한 콜에 결재가 안전취소 시간 안에 안 오면 원달앱이 확정 페이지의 «취소»를 누르는 것. 취소 횟수에 든다 |
| 상세 대기 시간 | 원달앱이 확정하지 않는 콜에서 상세에 머무는 시간 — 지나면 뒤로 나온다. 인성 · 화물24시는 안전취소 시간을 같이 쓰고, 픽커는 픽커 상세 대기 시간 |
| 모드 넷 | 자동(`AUTO` · 원달앱이 확정) · 체험(`AUTO`+계약 안 함 → 명령 `SIMULATION` · 확정 안 함 · 연습 콜) · 알람(`ALARM` · 상세까지 열고 소리) · 직접(`MANUAL` · 원달앱이 목록을 안 누름) |
| 도는 모드 | 저장된 명령에서 «덜 자동» 쪽으로만 내려간 지금 실제 모드. 자동만 알람으로 내려간다 |
| `openedByApp` | 원달앱이 목록에서 눌러 이 상세를 열었다(세션 사실) |
| `contractedByApp` | 원달앱이 이 콜의 확정 단추를 누른다(세션 사실) — 서버로는 `matchType` 으로 간다 |
| 손 수락 · 손 확정 | 기사님이 상세에서 직접 확정 · 수락을 누른 것. 서버는 심사 없이 바로 KEEP |

| D5 | 여러 폰을 동시에 자동으로 | 지금은 한 폰만 자동(R11). «계약 허락 한 문(서버 `contractFactsOf`) + 폰끼리 블루투스로 즉시 거둠»은 **계획만 있음(코드 없음)** — 같은 순간 두 확정의 틈을 원리상 못 없애 접어 둠 | 블루투스로 필터 · 모드를 빨리 넘기는 일만 다음 차례 |
| D6 | 픽커 · 알람 미리보기도 «심사 중»으로 세어 다른 자동 콜 누르기를 막나 | 폰마다 자기 줄만 본다 | 가: 안 센다(추천 · 픽커 알람 동안 인성 좋은 콜을 지킴) / 나: 센다 — 계획만 있음 |
| D7 | 안전취소 시간 하나가 «계약 뒤 무를 수 있는 시간»과 «알람 · 체험 상세 머묾» 두 질문의 답 | 같은 칸 하나 | 기사님 확정으로 묶여 있다 — 하나를 늘리면 다른 것도 는다는 것만 알고 쓴다 |
| D8 | 상세 보고 실패 시 곧바로 CANCEL(R26) | 약한 LTE 에서 원달앱이 확정한 콜을 곧바로 무른다(취소 횟수) | 기사님 확정 규칙이나, 라이브 망 품질에서 횟수가 얼마나 나는지 센 뒤 다시 볼 것 |

## 8. 하지 말 것 — 함정과 까닭

- 🔴 **픽커에 원달앱이 «수락하기»를 누르는 길을 열지 않는다** — `acceptButtons` 를 채우거나 픽커 `modes` 에 자동을 더하면 되돌릴 수 없는 계약이 생긴다. 두 겹(R6) 중 하나만 남기지도 않는다.
- 🔴 **모드 이름으로 가르지 않는다** — `if (mode == "AUTO")` 대신 `contractedByApp` · `openedByApp` · `isPreview` 같은 낱개 사실로. 모드 이름을 읽는 곳은 목록 누르기 성공 자리 한 곳과 확정 직전 다시 묻기뿐이다.
- 🔴 **확정을 못 눌렀는데 상세 보고를 보내지 않는다** — 서버가 계약으로 알고 안전취소가 없는 «취소»를 찾는다(R5).
- 🔴 **안전취소 셈을 서버 시계로 하지 않는다** — 원달앱이 실제로 누른 뒤에만 센다(R16 · R18). 못 누른 계약을 «취소됨»으로 세면 페널티 셈이 틀린다.
- 🔴 **원달앱 안전취소 시계(30초)를 없애지 않는다** — 서버 · 관제웹이 모두 죽어도 계약을 무를 마지막 장치다. 끄는 곳은 `SafeCancelTimer.cancel` 하나.
- 🔴 **미리보기에 안전취소를 걸지 않는다** — 아직 계약이 아니라 무를 것이 없다. 미리보기를 끄는 기준은 «폰이 상세를 떠났나» 하나다.
- 🔴 **미리보기 표시는 벗겨지기만 한다** — 보통 콜을 미리보기로 되돌리면 취소 셈이 샌다.
- 🔴 **«심사 중» 칸을 기사님 단위로 바꾸지 않는다** — `/confirm` 의 «같은 폰 앞 콜 정리»(R28)가 다른 폰의 콜을 지운다. 넓히려면 읽는 곳만 넓힌다.
- 🔴 **같은 «취소» 글자라도 페이지를 먼저 본다** — 확정 전 상세의 «취소»는 나오기, 확정 뒤 상세의 «취소»는 계약 무름. 화면 판별 표의 줄 차례(R30)를 바꾸지 않는다.
- 🔴 **선점 보고를 채우기 앞으로 당기지 않는다** — 채우기 실패 · 채운 뒤 필터 탈락 때 서버에 심사 줄이 남아 치우는 길이 늘고 선점 보고의 뜻이 바뀐다.
- 🔴 **두 폰 겹침을 «서버에 묻고 기다리기»로 막으려 하지 않는다** — 확정이 서버 왕복만큼 늦어 경쟁 콜을 잃는다. 지금 답은 «자동은 한 폰만»이다.
- 🔴 **시험 도구가 실물 픽커에서 수락을 누르지 않는다** — 집에서는 콜 확정 전까지만. «수락한 뒤» 화면은 onedal-sim 으로 흉내 낸다.
- 🔴 **화면을 모를 때 계약을 만드는 누름(목록 줄 · 팝업 열기 · 확정)과 뒤로를 하지 않는다** — 미뤄 찍기는 발사 순간 화면이 예약 때와 다르면 쏘지 않는다(`AutoTouchManager` · `TapInFlight`). 터치 관리자 밖에서 `dispatchGesture` · `performGlobalAction` 을 부르지 않는다.
